## 2. 진료과별 차트 구조 비교

### 2.1 현재 Hospital RUN vs 주요 시스템

| 진료과 | 차트 형식 | Hospital RUN 현재 | Epic | 삼성DARWIN | 도입 필요성 |
|--------|----------|------------------|------|-----------|------------|
| **내과** | SOAP + POMR | ✅ SOAP 구현 | SOAP + 문제별 SOAP | SOAP + 코드화 | ⬆ POMR 방식 도입 |
| **외과** | Op Note (15개 구조화 필드) | ⚠ opNote: Text (자유텍스트) | OpTime (구조화) | 구조화 Op Note | 🔴 구조화 필수 |
| **소아과** | 성장차트 + 발달선별 + 예방접종 | ❌ 없음 | Stork/소아 모듈 | 성장차트 별도 | 🔴 신규 필요 |
| **산부인과** | 산전기록 (연속방문 테이블) | ❌ 없음 | Stork OB 모듈 | 산전수첩 연동 | 🔴 신규 필요 |
| **정신과** | MSE + 척도검사 | ❌ 없음 (GAD-7만 시딩) | Behavioral Health | MSE 전용 폼 | 🟡 템플릿으로 대응 가능 |
| **응급** | KTAS + ATLS | ⚠ KTAS 기본만 | ASAP (ESI) | KTAS 5단계 | 🟡 ATLS 추가 |
| **재활** | FIM + ADL + ROM 측정 | ❌ 없음 | 재활 모듈 | FIM 별도 | 🟡 스코어링 추가 |
| **ICU** | 플로우시트 (시간별 그리드) | ⚠ I/O만 구현 | ICU Flowsheet | AMIS 플로우시트 | 🔴 그리드 뷰 필요 |
| **간호** | Focus Charting (DAR) | ✅ 구현 완료 | 동일 | 동일 | ✅ 완료 |

### 2.2 주요 차이점 상세

#### A. 수술기록 (Op Note) — 현재 vs 표준

```
현재 Hospital RUN                    국제 표준 (Epic OpTime 기준)
─────────────────                    ──────────────────────────
opNote: String (자유텍스트)            15개 구조화 필드:
preOpDiagnosis: String               ├── 수술 전 진단
postOpDiagnosis: String              ├── 수술 후 진단
findings: String                     ├── 수술명 (코드)
complications: String                ├── 집도의 / 보조 / 마취의
anesthesiaType: String               ├── 마취 방법
anesthesiaNote: String               ├── 소견 (Findings)
                                     ├── 검체 (Specimens)
                                     ├── 추정실혈량 (EBL)
                                     ├── 수액/수혈
                                     ├── 삽입물/기기 (Implants)
                                     ├── 배액관/패킹 (Drains)
                                     ├── 합병증
                                     ├── 수술 시간 (절개~봉합)
                                     └── 상세 기술 (Narrative)
```

```

지각장애 (Perception)      | 환청/환시 없음
```

## 4. 도입 우선순위 평가

### 4.1 평가 기준

- **임상 필요성**: 해당 진료과 운영에 필수적인가?
- **구현 복잡도**: 기존 아키텍처에서 얼마나 쉽게 추가 가능한가?
- **EMR 인증 영향**: 인증 지표에 포함되는가?

### 4.2 우선순위 매트릭스

| 순위 | 도입 항목 | 필요성 | 복잡도 | 근거 |
|:----:|----------|:------:|:------:|------|
| **1** | 구조화 수술기록 (Op Note) | 🔴 높음 | 중 | 현재 자유텍스트 → 15개 필드 구조화. Surgery 모델 확장 |
| **2** | ICU 플로우시트 | 🔴 높음 | 높음 | 시간축 그리드 UI + 별도 모델. ICU 운영 핵심 |
| **3** | 소아 성장차트 + 발달선별 | 🔴 높음 | 중 | WHO/CDC 성장곡선, 예방접종 추적. 소아과 필수 |
| **4** | 산전기록 (산모수첩) | 🔴 높음 | 중 | SOAP과 다른 격자형 연속 기록. 산부인과 필수 |
| **5** | 정신과 MSE 템플릿 | 🟡 중간 | 낮음 | EncounterTemplate으로 구현 가능. 12개 항목 구조화 |
| **6** | 의사 진료과 필드 | 🟡 중간 | 낮음 | User.department 추가 → 템플릿 자동 선택 |
| **7** | SmartLink (자동 데이터 삽입) | 🟡 중간 | 중 | `@환자명@`, `@최근바이탈@` 등 토큰 치환 |
| **8** | POMR (문제별 SOAP) | 🟡 중간 | 중 | 기존 SOAP + ProblemList 연계 강화 |
| **9** | FIM/ADL 스코어링 (재활) | 🟡 중간 | 낮음 | FormEngine으로 구현 가능 |
| **10** | SmartSet (질환별 처방묶음) | 🟡 중간 | 중 | 처방 템플릿 그룹. 빈용 처방 간소화 |
| **11** | AI Ambient Documentation | 🟢 낮음 | 높음 | 음성→SOAP 자동 생성. 미래 Phase |
| **12** | OpenNotes (환자 열람) | 🟢 낮음 | 낮음 | 환자 포털 + 기록 공개. 규정 준비 |

## 5. 도입 계획 (Phase별)

### Phase 1: 필수 진료과 차트 구조화 (우선순위 1~4)

```
1. 구조화 수술기록 — 2-3일
   ├── Surgery 모델 확장 (15개 구조화 필드)
   ├── Op Note 전용 입력 폼
   └── 수술기록 PDF 출력

2. ICU 플로우시트 — 3-5일
   ├── FlowsheetEntry 모델 (시간축 데이터)
   ├── 시간별 그리드 UI (바이탈/인공호흡기/약물주입)
   └── 24시간 트렌드 차트

3. 소아 성장차트 — 2-3일
   ├── GrowthRecord 모델 (키/체중/두위/BMI)
   ├── WHO/CDC 성장곡선 그래프
   ├── 발달선별 (Denver/ASQ) 폼
   └── 예방접종 추적

4. 산전기록 — 2-3일
   ├── PrenatalRecord 모델 (연속방문 격자)
   ├── 산전 방문 테이블 UI
   └── 분만기록 (Partogram)
```

### Phase 2: 진료 효율성 개선 (우선순위 5~8)

```
5. 정신과 MSE — EncounterTemplate 추가 (1일)
6. User.department 필드 + 템플릿 자동 선택 (1일)
7. SmartLink 토큰 (@환자명@, @바이탈@) (2-3일)
8. POMR 연계 (ProblemList → SOAP 태깅) (2일)
```

### Phase 3: 고급 기능 (우선순위 9~12)

```
9. FIM/ADL 스코어링 폼 (1일)
10. SmartSet 질환별 처방묶음 (2-3일)
11. AI Ambient Documentation (별도 프로젝트)
12. OpenNotes 환자 포털 (별도 프로젝트)
```

## 8. 결론 및 권고

### 즉시 도입 권고 (ROI 높음)

1. **구조화 수술기록** — Surgery 모델 확장으로 빠르게 구현 가능, 외과 운영 필수
2. **User.department + 템플릿 자동 선택** — 최소 변경으로 UX 대폭 개선
3. **정신과 MSE 템플릿** — EncounterTemplate 시딩만으로 즉시 사용 가능

### 중기 도입 권고

4. **ICU 플로우시트** — 별도 모델+UI 필요하나 ICU 운영에 필수
5. **소아 성장차트 + 산전기록** — 해당 진료과 개설 시 필수

### 장기 검토

6. **AI Ambient Documentation** — 기술 성숙도 확인 후 도입
7. **SmartLink/SmartSet** — 사용자 피드백 기반으로 점진 도입

| **소아청소년과** | Well-child + 성장차트 | SOAP이 아닌 연령별 발달 평가 | Denver, ASQ, K-DST, 성장백분위 | ❌ 없음 |
| **산부인과** | 산전기록 (격자형) | 연속방문 테이블 + 분만기록 | Bishop, APGAR, NST 해석 | ❌ 없음 |
| **정신과** | SOAP + MSE | O섹션을 MSE(12항목)로 대체 | PHQ-9, GAD-7, MMSE, C-SSRS | ⚠ 템플릿만 |
| **응급** | KTAS + 시간축 | 시간 기반 기록, 트리아지 선행 | KTAS, GCS, NIHSS, qSOFA | ⚠ KTAS 기본만 |
| **중환자(ICU)** | 플로우시트 | 시간별 그리드 (SOAP 아님) | APACHE II, SOFA, RASS, CAM-ICU | ⚠ I/O만 |
| **마취과** | 마취기록지 | 시간축 그래프 + 약물/가스 기록 | ASA, Mallampati, STOPBANG | ❌ 없음 |
| **재활의학과** | SOAP + 기능평가 | ROM/근력 테이블, 기능점수 추적 | FIM, Barthel, Berg, MBI | ❌ 없음 |
