## 2. 지금 있는 기계 — 무엇이 되고 무엇이 안 되나

| 기능 | 상태 |
|---|---|
| 단건 자동 매핑 (`auto-map`) | ✅ 동작 |
| AI 제안 미리보기 (`auto-map/suggest`) | ✅ 동작(관리자) |
| **일괄 매핑** (`auto-map/bulk` + 배치 추적) | ✅ 동작 · 1회 최대 100건 · rate limit 설정값 |
| 승인 대기 큐 (`pending-mappings`) | ✅ 확정/반려 |

| 매핑 이력·감사 (`mapping-audit`) | ✅ |
| **커버리지 대시보드** | ⚠️ 있으나 **분모가 전체 코드** |
| **우선순위 정의** | ❌ **없다** |
| **완료 기준** | ❌ **없다** |

### 🔴 이번에 함께 고친 것

- **집계가 상태를 뭉치고 있었다** — `else failed++` 하나라 "해당 사항 아님"과 "AI 가 죽어 수행 못 함"이
  같은 숫자에 들어갔다. 결과가 실제보다 나쁘게 보였고 **무엇을 다시 돌려야 하는지 알 수 없었다.**
  → 확정 / 승인대기 / 해당없음 / 후보없음 / 신뢰도미달 / **오류(재시도 대상)** 로 분리.
- **화면이 서버가 하지 않는 일을 약속**했다 — "Confidence ≥ 0.90 자동 확정".
  대조할 표준 코드 사전이 없어 **AI 제안은 자동 확정되지 않는다**(규칙 결과만 확정).
  화면이 그대로 말하게 고쳤다.

## 3. 🔴 근본 제약 — 대조할 사전이 없다

이 저장소에는 **SNOMED CT·LOINC·MedDRA 코드 사전이 없다**(마스터 모델 자체가 없음).
그래서 AI 가 낸 코드가 **실재하는지 확인할 방법이 없다.**

- 그래서 AI 결과는 **전부 사람 승인 대기**로 간다(2026-08-26 변경).
- 즉 **사람 검수 용량이 전체 처리 속도의 상한**이다. 기계를 아무리 돌려도 대기열만 쌓인다.
- 사전을 넣으면 규칙 기반 자동 확정이 가능해져 **사람 검수량이 급감**한다.

🔴 **사전 도입은 라이선스가 걸린 사람 결정이다**(SNOMED CT 는 회원국 라이선스 · LOINC 는 무료 등록 ·
MedDRA 는 유료 구독). 이것이 이 축 전체를 좌우한다.

## 4. 방안 — 분모를 바꾼다

### 4.1 대상을 "쓰이는 코드"로 정의한다

우선순위를 셋으로 나눈다:

| 등급 | 정의 | 대략 규모(현재) |
|---|---|---:|
| **P0 필수** | 최근 12개월 실제 사용 + 원내 처방집 ACTIVE + 법정 보고에 쓰이는 코드 | 수백 |
| **P1 예비** | 진료과 표준 세트·약속처방(CP)에 들어 있는 코드 | 수천 |
| **P2 나머지** | 등재만 되어 있고 쓰인 적 없는 코드 | 대부분 |

🔴 **P2 를 "미매핑"으로 세지 않는다.** 쓰이지 않는 코드의 매핑은 갭이 아니라 **하지 않기로 한 일**이다.
지금 대시보드는 그것까지 분모에 넣어 커버리지를 0.07% 로 보이게 한다.

### 4.2 표준별로 목적을 먼저 정한다

**무엇에 쓸 것인지 정하지 않은 표준은 매핑하지 않는다.**

| 표준 | 쓰임 | 지금 필요한가 |
|---|---|---|
| SNOMED CT | 상호운용·CDS·연구 | 사람 결정 |
| LOINC | 검사 결과 교환(FHIR) | **검사코드에 한정해 필요** |
| ICD-10/11 | 청구·통계 | 이미 진단코드가 보유 |
| MedDRA | 이상사례 보고(KIDS) | 보고 대상 항목만 |
| ICD-10-PCS | 시술 분류 | 국내 청구는 EDI 라 **필요성 불명** |
| ICF | 기능 상태 | 재활 영역만 |

🔴 **표를 채우는 것이 목표가 아니다.** 쓰임이 없는 매핑은 유지보수 부채다.

### 4.3 처리 흐름

```
P0 대상 추출(사용 이력·처방집) → 일괄 매핑(규칙 우선) → 규칙 확정 / AI 제안은 대기
   → 임상 검토 큐(진료과별 배정) → 확정 → 커버리지 재계산
```

- 🔴 **일괄은 "전체"가 아니라 "P0 부터"** 돌린다. 1회 100건 상한은 그대로 두되 대상이 좁아진다.
- 🔴 **오류(ERROR)만 재시도 대상**이다 — 해당 없음·후보 없음을 다시 돌리면 비용만 든다.
- 검토는 **진료과별 배정**(`clinical-review/:id/assign`)으로 나눈다 — 한 사람에게 몰면 멈춘다.

### 4.4 커버리지를 정직하게 잰다

- 분모 = **P0 대상 코드 수**(전체 코드 아님) · 분자 = 확정된 매핑
- 🔴 **분모와 함께 낸다**(`ratioOf`/`<Ratio>` 규약) · 분모 0이면 `산출 불가`
- **표준별로 따로** 낸다(SNOMED 80% · LOINC 40% 를 합쳐 60% 라 하면 아무 뜻이 없다)
- 🔴 **"해당 없음"은 분자에도 분모에도 넣지 않는다**

## 8. 코드 마스터 강화 — 실 의료기관이 실제로 쓰는 기능

사람 지시(2026-08-26): "병행으로 코드 마스터의 기능을 더 강화하고, **실 의료기관에서 사용할 수 있는
기능들을 더 도출**할 것."

### 8.1 이미 있는 것 (실측)

| | 상태 |
|---|---|
| 진단(KCD/ICD)·수가(EDI)·약품·간호 코드 CRUD | ✅ |
| **유효기간**(`validFrom`/`validTo`) | ✅ 진단·수가 모두 보유 |
| **수가 이력(temporal)** — `@@unique([code, validFrom])` | ✅ **개정 이력 구조가 이미 있다** |
| 표준 매핑·자동 매핑·승인 큐·임상 검토 큐 | ✅ |
| 매핑 감사 이력 | ✅ |
| 원내 처방집(Formulary) 연동 표시 | ✅ |

🔴 **버전·유효기간 뼈대는 이미 있다.** 아래 항목들은 "새로 만들기"가 아니라 **그 위에 얹는 일**이다.

### 8.2 🔴 없는 것 — 실 의료기관에서 반드시 걸리는 순서대로

### 8.3 우선순위 판단

🔴 **F1·F2 가 먼저다.** 나머지는 편의지만 이 둘은 **틀리면 청구와 진료가 깨진다**.

- **F1 없이는 개정 때마다 수작업**이고, 수작업은 누락된다(수가 166,744건).
- **F2 없이 코드를 중지하면** 그 코드를 쓰던 약속처방·오더세트가 조용히 실패한다 —
  이 저장소가 이미 겪은 "어휘가 갈라져 게이트가 죽은" 유형과 같다.

🔴 **F7(신설 승인)은 사람 결정이 선행**한다 — 누가 승인할지 정해지지 않으면 화면만 늘어난다.

### 8.4 설계 원칙

- 🔴 **개정 반영은 덮어쓰기가 아니라 새 버전**이다 — `@@unique([code, validFrom])` 구조를 그대로 쓴다.
  과거 진료의 수가는 그때 값으로 남아야 한다(소급 변경 금지).
- 🔴 **차이 리포트를 먼저 보여주고 사람이 적용한다** — 파일을 올리면 바로 반영하지 않는다.
  (신설 N · 변경 N · 폐지 N · 충돌 N 을 분모와 함께)
- 🔴 **폐지는 삭제가 아니다** — `validTo` 를 채우고 `successor` 를 잇는다. 과거 기록이 해석 가능해야 한다.
- 🔴 **영향 분석 없이 중지 버튼을 주지 않는다**(F2 가 F8 보다 먼저인 이유).
- 🔴 **자동 병합하지 않는다**(F6) — 후보를 보여주고 사람이 고른다. 잘못 병합하면 되돌릴 수 없다.

착수 전 나는 "지금도 관리자가 **버튼으로** 코드를 중지할 수 있다"고 적었다. 🔴 **틀렸다** —
실측하니 `/admin/codes` 화면에는 **중지 버튼이 없다**(`deleteMut` 호출부 0).
그러나 `DELETE /api/v1/codes/*` **EP 는 열려 있어** API 로는 중지된다. 위험은 실재하되 위치가 달랐다.

그래서 방어선을 **서버에** 두었다:
- `GET /api/v1/codes/:table/:id/usage` — 사용처 조회. 🔴 참조 목록을 **손으로 적지 않고
  Prisma 메타데이터(DMMF)에서 유도**한다. 손으로 세었을 때 `FamilyHistory`·`PreOrder.medicationCodeId`
  **두 개를 놓쳤다** — 하나라도 빠지면 "사용처 없음"이라 말하고 중지하게 된다.
- `DELETE` 가 중지 전에 사용처를 확인한다. 사용 중이면 `CODE_IN_USE`,
  🔴 **세지 못했으면 `CODE_USAGE_UNKNOWN`** 으로도 막는다("없음"과 "못 셈"은 다른 사실이다).
  폐지해야 하는 코드는 폐지할 수 있어야 하므로 `force` 를 두되 **사유 없이는 통하지 않는다**.
- 화면은 **코드 상세에 사용처를 표시**한다(도달 가능한 자리). 중지 버튼이 없으므로
  🔴 **중지 경고를 화면에 붙이지 않았다** — 도달하지 않는 코드를 남기면 다음 사람이 있다고 믿는다.

## 9. C4-a 실측 — 약어는 "안 나오는" 것이 아니라 **다른 것이 나왔다**

운영 `diagnosis_codes` 18,199행 실측(2026-08-26). `name_en` 은 **18,199/18,199 전량** 채워져 있어
영문 검색은 이미 된다. 문제는 **약어와 구어**였다.

| 질의 | 지금 건수 | 1위 결과 | 단어 단위 |
|---|---:|---|---:|
| `AMI`(급성심근경색) | 248 | 일반 성인 의학적 검사(ex**AMI**nation) | 0 |
| `DM`(당뇨병) | 271 | 신생아 약물 중독(medica**M**ent) | 0 |
| `HTN`(고혈압) | 11 | **벼락**의 영향(lig**HTN**ing) | 0 |
| `PE`(폐색전) | 7,592 | — | 0 |
| `RA`(류마티스) | 5,525 | — | 0 |
| `맹장염`·`췌장암`·`디엠` | 0 | — | 0 |

🔴 **0건보다 나쁘다.** 화면이 자신 있게 틀린 답을 준다(P1).

### 설계에서 한 번 뒤집은 것

처음에는 "단어 단위로 좁히고, 0건이면 자동으로 되넓힌다"로 만들었다.
🔴 **실측하니 약어의 단어 단위 일치는 거의 전부 0**이라, 자동 되넓힘은 곧 7,592건 노이즈로 되돌아가는
길이었다 — **좁힌 의미가 사라진다.** 그래서 **자동으로 되넓히지 않고 "넓히면 N건"만 말하고
사람이 누르게** 바꿨다(`wide=1`).

### 규칙

- 🔴 **승인한 동의어만 검색에 쓴다** — 동의어가 틀리면 다른 병을 고른다.
- 🔴 **배포분 사전은 전부 검토 전**이고, **관리자가 눌러야** 등재된다(배포만으로 검색이 달라지지 않는다).
- 🔴 **어느 코드인지 지목하지 않는다**(`code = null`) — `DM` 을 어느 당뇨 코드로 볼지는 임상 판단이다.
  지목형도 가능하되 원내가 등록·승인한 것만이고, 그때는 **목록에 섞지 않고 위에 따로** 낸다
  (섞으면 총 건수·페이지가 어긋난다).
- 🔴 **확장어가 실제로 무엇을 찾는지 재고 담았다** — 아무것도 못 찾는 확장어는 담지 않았다.
- 🔴 **좁히지 못했으면 좁혔다고 말하지 않는다** · **넓힘 건수를 못 세면 `null`**(0 이 아니다).

## 10. C4-b 실측 — F4 의 전제가 틀렸다

계획서 §8.2 는 F4 를 "원내 검사·처치를 **담을 자리가 없다**"로 적었다. 🔴 **틀렸다.**

- `NonCoveredItem`(비급여) — 모델·모듈·`/admin/non-covered`·홈페이지 고지·수납·영수증까지 **전부 배선**돼 있다(운영 16행).
- `LabTestCode` 35행은 **EDI·LOINC 가 전건 채워져** 있다(미매핑 0).

그래서 새 모델을 만들지 않았다 — **정본이 둘이 되면 갈라진다.**

### 🔴 진짜 갭은 내가 C2 에서 만든 것이었다

고시 반영 미리보기는 "파일에 없는데 살아 있는 코드 N건"을 **폐지 후보**로 센다.
**원내에서 만든 코드는 고시 파일에 없는 것이 정상**인데 거기 섞인다 — 사람이 그것을 보고 원내 항목을 지운다.

→ 세 코드 모델에 `origin`(`HIRA` · `LOCAL` · `null`).
- 고시 반영이 건드린 행에 `HIRA`, 사람이 화면에서 만든 행에 `LOCAL`.
- 🔴 **기존 209,000행을 일괄로 `HIRA` 라고 찍지 않았다** — 그 행들이 어디서 왔는지 우리는 모른다.
  화면 필터의 '표기 없음'은 **모른다**는 뜻이고, 그렇게 적어 두었다.
- 미리보기가 **원내 건수를 따로 세어 "폐지 후보로 읽지 마세요"**라고 말한다(0이면 그리지 않는다).

## 11. C5 실측 — F6 전제도 틀렸다(이 축에서 **세 번째**)

기획서 §8.2 는 F6 를 "수기 등록이 쌓이면 같은 개념이 둘로 갈린다"로 적었다.
명칭으로 세어 보니 **수가 8,535 그룹 · 약품 666 그룹 · 진단 22 그룹**이 나왔다. 표본을 열어 보니:

| 축 | 사례 | 실제 |
|---|---|---|
| 진단 | `V19.4`·`V29.4`·`V59.4`·`V79.4` 명칭 동일 | 자전거·오토바이·승용차·버스 **탑승자**(다른 사고) |
| 수가 | 한 마취 행위명에 **240개 코드** | HIRA 종별·시간 가산 체계 |
| 약품 | 생리식염수 **14개 코드** | 포장 단위별 보험코드 |

🔴 **전부 정상이다.** "중복 8,535건"을 화면에 그렸다면 누군가 가산 코드를 병합해 **청구를 망가뜨렸을** 것이다.

→ 탐지 범위를 **원내 등록분(`origin='LOCAL'`)** 으로 좁혔다. 고시 마스터는 HIRA 가 정본이고
우리가 판단할 자리가 아니다. 지금 원내 코드가 0건이라 **검사 대상이 0**이며,
🔴 그때 화면은 "중복 없음"이 아니라 **"검사할 원내 등록 코드가 없습니다 — 중복이 없다는 뜻이 아닙니다"**라고 말한다.

🔴 **병합 EP 를 만들지 않았다.** 병합은 "하나를 폐지하고 후속 코드를 잇는 것"이고 그 정본은 C3 에 있다.

### F9 — 조용히 자르지 않는다

수가 166,744건은 한 번에 담기지 않는다. **장 단위(2만 건)로 내보내고 전체 건수·다음 장 유무를 함께** 준다.
일부를 전부로 제출하면 그 코드집은 근거가 되지 못한다. 곁: CSV 주입 방어(`=`·`+`·`-`·`@` 접두)와
엑셀 한글용 BOM — **깨진 코드집은 제출할 수 없다.**

### F7 — 만들지 않고 물었다

"누가 승인하는가"가 정해지지 않은 채 승인 화면을 만들면 **화면만 늘고 아무도 누르지 않는다.**
→ `/admin/decisions` 에 `codes.newCodeApproval` 등재(원내 위원회 층).
🔴 **지금 원내 코드가 0건이라 지금이 정하기 가장 쉬운 때**라는 것도 함께 적었다
