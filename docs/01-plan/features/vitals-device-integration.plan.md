## 0. 이 문서가 푸는 문제

환자 모니터·전자혈압계·SpO₂·체온계·체중계·혈당계·인공호흡기에서 나온 값을 HIS 가 받으려면
**"어디로 받을 것인가"**가 먼저 정해져야 한다. 지금은 그 자리가 없다 — 다섯 군데가 있고, 그래서 없다.

이 문서는 **새 기능을 늘리는 계획이 아니라, 받을 자리를 하나로 만드는 계획**이다.

## 1. 현행 실측 (2026-08-19 · 통일 대상의 분모)

### 1.1 활력이 저장되는 곳 — 다섯 벌

| 저장소 | 쓰는 서비스 | 용도 | 사람 필드 |
|---|---|---|---|
| `PreVisitVitals` | `VitalsService.record` | 외래·간호·원격·음성 **공용 정본** | `nurseId` **NOT NULL** |
| `FlowSheetEntry` | `NursingService.addFlowSheetEntry` | 입원 병동 정본 | `nurseId` **NOT NULL** |
| `IcuRecord` | `IcuService` | 중환자 | `recordedBy` **NOT NULL** |
| `EarlyWarningScore` | `PatientSafetyService.calculateAndSaveEws` | NEWS2 파라미터 사본 | `nurseId` **NOT NULL** |
| `NursingAssessment` | `NursingService` | 간호 사정(일부 활력) | `nurseId` **NOT NULL** |

`VitalsService` 는 2026-07-30 에 "정본 쓰기 경로"로 통합됐지만 **그 정본은 `PreVisitVitals` 하나에만 적용된다.**
입원·중환자 경로는 각자 저장하고 각자 부가 로직을 돈다.

> 🔴 이 분기가 실제로 사고를 냈다. 2026-08-18 에 `VitalsService` 에서 봉합한 결함
> (미관측 `supplementalO2` 를 `false` 로 접어 NEWS2 를 2점 낮게 법정기록에 박던 것)이
> **`FlowSheetEntry` 경로에는 그대로 남아 있었고**, 2026-08-19 에 따로 다시 고쳐야 했다.
> **한 곳만 고치면 갈라진다** — 기기 연동은 이 분기를 여섯 번째로 늘리는 일이 되어선 안 된다.

### 1.2 세 가지 구조적 부재 (기기 연동이 지금 불가능한 이유)

| # | 부재 | 왜 막히는가 |
|---|---|---|
| **1** | **주체가 사람으로 고정** — 다섯 저장소 전부 `nurseId`/`recordedBy` NOT NULL | 기기가 측정한 값을 **누구의 이름으로도 적을 수 없다.** 아무 간호사 ID 를 넣으면 그 순간 원장이 거짓이 된다 |
| **2** | **기기 식별 필드 없음** — `deviceId`·`source`·`method` 가 어느 모델에도 없다 | 수기 입력과 기기 측정을 **구분할 수 없다.** 나중에 "이 값 어디서 왔나"를 물으면 답이 없다 |
| **3** | **측정 시각과 수신 시각이 미분리** | `PreVisitVitals.measuredAt` 은 **기본값이 `now()`** 다. 모니터가 5분치를 몰아 보내면 전부 수신 시각으로 박힌다. (`FlowSheetEntry` 만 `recordedAt`/`createdAt` 을 분리해 뒀다 — 이쪽이 옳은 형태다) |

> 🔴 3번은 이 저장소가 이미 아는 함정이다. **"모르는 시각은 원장에 박지 않는다."**
> 기기 연동에서는 이것이 규칙이 아니라 **설계 제약**이 된다.

### 1.3 이미 있어서 새로 만들지 않을 것

| 있는 것 | 어디 | 연동에서의 역할 |
|---|---|---|

| FHIR R4 표면 | `modules/fhir`·`fhir-full`·`fhir-lab` | §4.2 외부 표현 |

## 2. 설계 원칙 — 전부 이 저장소가 이미 대가를 치르고 배운 것

| 원칙 | 기기 연동에서의 뜻 |
|---|---|
| **미관측은 0이 아니다** | 센서가 값을 못 낸 것을 `0`·`false`·정상값으로 접지 않는다. 결측은 결측으로 저장한다 |
| **외부 보고값은 재반올림하지 않는다** | 기기가 보고한 값을 HIS 표시 정책으로 **다시 반올림해 저장하지 않는다**(보고값 변조). 표시할 때만 정책을 적용 |
| **모르는 시각은 원장에 박지 않는다** | 기기가 측정 시각을 안 주면 `measuredAt` 을 **추정하지 않는다**. 수신 시각만 기록하고 그 사실을 표시 |
| **전송을 흉내내지 않는다** | 기기와의 연결이 미구축이면 `LOCAL_RECORDED` 로 남기고 재시도 가능하게. "연동됨"으로 표시하지 않는다 |
| **어휘는 한 곳에서 접는다** | 기기별 코드·단위·상태 문자열을 **어댑터에서 한 번만** 정본 어휘로 접는다(ACVPU 어휘가 두 벌이었던 전례) |
| **정본이 둘이면 갈라진다** | 수집 포트는 **하나**. 기기 경로가 별도 저장소를 새로 만들면 6번째 분기가 된다 |
| **기기는 사람이 아니다** | 주체 표현을 사람과 분리한다(§5). 사람 ID 를 빌려 쓰지 않는다 |
| **거짓 경보는 진짜 경보를 죽인다** | 기기 아티팩트(체동·커프 오류)를 경보로 올리지 않는다. **"얼마나 참인가"**를 재고 올린다 |

## 3. 아키텍처 — 단일 수집 포트

```
[기기/게이트웨이]
      │  (HL7 v2 ORU^R01 · IHE PCD-01 · 벤더 REST · BLE 게이트웨이 · FHIR Observation)
      ▼
┌─────────────────────────────────────────────────────────────┐
│ 1. Device Adapter  (벤더별 · 유일하게 벤더를 아는 층)         │
│    - 원문 보존(raw payload) · 기기 식별 추출 · 시각 추출      │
│    - 벤더 코드 → 정본 어휘 · 벤더 단위 → UCUM               │
│    - 🔴 여기서 값을 해석·보정·반올림하지 않는다               │
└─────────────────────────────────────────────────────────────┘
      ▼  VitalsObservation[] (정규 DTO · UCUM 단위 · 3-시각 · 결측은 null)
┌─────────────────────────────────────────────────────────────┐
│ 2. Ingestion Port  (VitalsIngestService — 새 진입점 1개)     │
│    - 멱등(중복 수신 무시) · 순서·역행 검사 · 신뢰도 판정      │
│    - 환자 결속(기기↔병상↔재원 바인딩) · 미결속은 보류함으로   │
└─────────────────────────────────────────────────────────────┘
      ▼
┌─────────────────────────────────────────────────────────────┐
│ 3. Canonical Store  (기존 저장소 재사용 — 새 테이블 최소화)   │
│    외래=PreVisitVitals · 입원=FlowSheetEntry · 중환자=IcuRecord│
│    + 출처(VitalsSource) 공통 필드 (§5)                        │
└─────────────────────────────────────────────────────────────┘
      ▼  기존 파생이 그대로 붙는다 (새로 만들지 않는다)
   evaluateVitals(이상치) · scoreNews2 · 경보 · 여정 이벤트 · FHIR 출력
```

### 3.1 어댑터가 **하는 일 / 하지 않는 일**

| 한다 | 하지 않는다 |
|---|---|
| 원문(raw) 보존 · 재처리 가능하게 | 값 보정·평활화·결측 보간 |
| 기기 식별(시리얼·MAC·MDC) 추출 | 환자 추정(이름 유사도 매칭 등) |
| 단위를 UCUM 으로 변환(가역·검증됨) | 표시 자릿수 적용·반올림 |
| 기기 시각을 그대로 전달 | 시각이 없을 때 **지어내기** |
| 벤더 상태코드를 정본 어휘로 접기 | 접히지 않는 코드를 임의 대응 |

### 3.2 멱등성과 순서

- **멱등 키** = `(deviceId, deviceMeasuredAt, metricCode)` 해시. 같은 키 재수신은 **무시**(재처리는 raw 로).
- 🔴 **시각 역전은 부호가 아니라 격차를 잰다.** 기기 NTP 오차 수 초는 아티팩트고, 수 분은 사건이다.
  임계는 감이 아니라 **그 기기 축의 과거 실측(p95×2)**에서 뽑는다(`data-freshness` 도구가 쓰는 방식과 동일).
- 늦게 도착한 과거 측정(backfill)은 **거부하지 않는다.** 대신 `receivedAt` 으로 늦음을 드러낸다.

### 3.3 환자 결속(binding) — 가장 위험한 지점

기기 값을 **엉뚱한 환자에게 붙이는 것**이 이 연동의 최대 위험이다.

- 결속은 **명시적 행위**여야 한다: 병상↔기기 배정, 또는 손목밴드 스캔(BCMA 경로 재사용).
- 🔴 **추정 결속 금지.** "그 병실에 한 명뿐이니까"는 결속 근거가 아니다.
- 미결속 측정은 **버리지 않고 보류함(unbound queue)**에 쌓고 화면에 띄운다
  (버리면 "데이터 0행"이 되어 아무도 모른다).
- 결속 해제(퇴실·전실)는 **자동 4경로**로 이미 다루는 패턴이 있다(ER 베드 보드) — 그 구조를 따른다.

## 4. 표준 정합

### 4.1 코드와 단위 — LOINC + UCUM

| 항목 | LOINC | UCUM | 내부 필드 |
|---|---|---|---|
| 수축기혈압 | `8480-6` | `mm[Hg]` | `systolicBp` |
| 이완기혈압 | `8462-4` | `mm[Hg]` | `diastolicBp` |
| 혈압 패널 | `85354-9` | — | (component 2종) |
| 맥박 | `8867-4` | `/min` | `heartRate` |
| 호흡수 | `9279-1` | `/min` | `respiratoryRate` |
| 체온 | `8310-5` | `Cel` | `temperature` |
| SpO₂(맥박산소측정) | `59408-5` | `%` | `spo2` |
| 체중 | `29463-7` | `kg` | `weight` |
| 신장 | `8302-2` | `cm` | `height` |
| BMI | `39156-5` | `kg/m2` | `bmi` |
| 통증(NRS 0-10) | `72514-3` | `{score}` | `painScore` |

- 🔴 **UCUM 은 확인한 단위에만 선언한다.** 이 표의 단위는 `@lhncbc/ucum-lhc` 로 **기계 검증한 뒤**
  `fhirQuantity` 에 등재한다. 검증 못 한 것은 `system` 을 선언하지 않고 표시 단위만 낸다(허위 표기 금지 — 전례 있음).
- 🔴 **IEEE 11073-10101(MDC) 숫자 코드는 이 문서에 적지 않는다.** 벤더 문서·표준 원본으로 확인한 것만
  매핑표에 넣는다. 지금 적으면 그것이 확인된 사실처럼 굳는다(§12).

### 4.2 FHIR R4 표현

| 리소스 | 용도 | 현행 |
|---|---|---|
| `Observation`(profile `vitalsigns`) | 측정값 | 읽기 존재 · **기기 유래 쓰기 미정의** |
| `Device` | 기기 정체 | **없음** → `Equipment` 를 투영 |
| `DeviceMetric` | 채널·교정 상태 | **없음**(선택) |
| `Provenance` | 누가/무엇이 만들었나 | **없음** → §5 출처를 투영 |

- `Observation.device` → `Device`(=`Equipment` 투영), `Observation.effectiveDateTime` = **기기 측정 시각**,
  `Observation.issued` = 수신 시각. 🔴 이 둘을 같은 값으로 채우지 않는다.
- 결측은 `dataAbsentReason` 으로 낸다 — **0 으로 채우지 않는다.**
- 신뢰도 낮음(교정 만료·아티팩트 의심)은 `Observation.status = 'preliminary'` + `note`.

### 4.3 수신 프로토콜 — 세 갈래를 전부 같은 포트로

| 갈래 | 대상 | 어댑터 |
|---|---|---|
| **IHE PCD-01 / HL7 v2 ORU^R01** | 병동·중환자 모니터(레거시 다수) | v2 파서 → 정규 DTO |
| **FHIR Observation POST** | 최신 기기·게이트웨이 | 프로파일 검증 → 정규 DTO |
| **벤더 REST/BLE 게이트웨이** | 체중계·혈당계·웨어러블 | 벤더별 어댑터 |

- 어느 갈래든 **§3 의 포트 하나로 들어온다.** 갈래마다 저장소를 만들지 않는다.
- 🔴 미구축 갈래는 **"연동됨"으로 표시하지 않는다**(전송 흉내 금지). 상태는 `NOT_CONFIGURED` 다.

### 4.4 openEHR 내부 패턴과의 관계

내부 임상 모델은 openEHR 패턴을 따른다(CLAUDE.md). 이 계획은 **외부 경계(FHIR)와 수집 포트**만 정하고,
내부 저장 형태는 기존 모델을 재사용한다 — 내부 모델을 새로 그리는 일은 이 문서의 범위가 아니다.

## 5. 스키마 제안 (🔴 사람 승인 필요 · `db push` 는 승인 후)

**원칙: 새 저장소를 만들지 않고, 다섯 저장소에 공통 출처 필드를 더한다.**

### 5.1 공통 출처 필드 (5개 모델 공통)

| 필드 | 형 | 뜻 |
|---|---|---|
| `source` | enum `MANUAL\|DEVICE\|IMPORT\|PATIENT_REPORTED` | 🔴 **수기와 기기를 구분** |
| `deviceId` | `uuid?` → `Equipment` | 어느 기기가 냈나 |
| `measuredAt` | `timestamptz` | **기기가 측정한 시각**(모르면 `null`) |
| `receivedAt` | `timestamptz` | 서버가 받은 시각 |
| `recordedBy` | `uuid?` → `User` | 🔴 **nullable 로 완화** — 기기 측정은 사람이 없다 |
| `reliability` | enum `OK\|CALIBRATION_EXPIRED\|ARTIFACT_SUSPECT\|UNVERIFIED` | §6 |
| `rawRef` | `uuid?` | 원문 보관 참조 |

- 🔴 `recordedBy` NOT NULL 완화는 **이 연동의 선행 조건**이다. 완화하지 않으면 기기 값을 적을 자리가 없고,
  아무 사람 ID 를 빌려 쓰면 원장이 거짓이 된다.
- `measuredAt` nullable 화도 마찬가지다 — **모르는 시각을 `now()` 로 채우지 않기 위한 자리**다.
- 기존 행 마이그레이션: `source='MANUAL'`, `measuredAt=기존값`, `receivedAt=createdAt`(있으면).

### 5.2 새 모델 (최소)

| 모델 | 필요 이유 |
|---|---|
| `DeviceBinding` | 기기↔환자/병상 결속 이력(시작·해제·해제 사유). 부분 유니크 인덱스로 동시 결속 차단(ER 베드 패턴 재사용) |
| `VitalsIngestLog` | 수신 원문·멱등 키·처리 결과. 🔴 **실패를 삼키지 않기 위한 자리**(성공 로그는 증거가 아니다) |
| `UnboundMeasurement` | 환자 미결속 측정 보류함(버리지 않는다) |

`Device` 모델은 **만들지 않는다** — `Equipment` 가 이미 정본이다. FHIR `Device` 는 투영으로 낸다.

## 6. 신뢰성·안전

### 6.1 교정 만료 기기

`Equipment.nextCalibration` 이 이미 있다. 경과한 기기의 측정값은:

- 🔴 **버리지 않는다.** 임상적으로는 값이 있는 편이 낫다.
- `reliability = CALIBRATION_EXPIRED` 로 저장하고 **화면에 표식**한다.
- 🔴 **자동으로 경보를 올리지도, 자동으로 정상 판정하지도 않는다**(§6.5).
- 관리 화면은 "교정 만료 기기에서 들어온 측정 N건"을 **줄어드는 목록**으로 낸다.

### 6.2 아티팩트 — "얼마나 참인가"

체동·커프 오류·프로브 이탈은 흔하다. 단발 이상값으로 경보를 올리면 **진짜 경보가 묻힌다.**

- 판정은 **지속성**으로 한다(예: N초 이상 지속·연속 M회). 임계는 그 축의 과거 실측에서.
- 아티팩트 의심은 `ARTIFACT_SUSPECT` 로 저장하고 **경보 대상에서 제외하되 화면에는 보인다.**
- 🔴 제외한 것은 **제외했다고 말한다**(자르면 잘랐다고 말한다).

### 6.3 기기 시계

- 기기 시각과 서버 시각의 오차를 수신 시마다 기록한다(§3.2 임계).
- 🔴 컨테이너 OS 는 UTC 이고 KST 는 pm2 TZ 가 유일 소스다(기존 함정) — 어댑터는 **오프셋 있는 시각**만 받는다.

### 6.4 결측·단절

- 연결이 끊긴 것을 **`0` 으로 그리지 않는다.** 화면은 `연결 끊김 (마지막 수신 hh:mm)` 이라고 말한다.
- 기기 상태(연결·배터리·교정)는 **측정값과 별개 축**으로 보여준다.

### 6.5 경보는 기기가 아니라 HIS 가 낸다

- 기기 자체 알람은 병상에서 울린다. HIS 가 그것을 **중복해서 다시 울리지 않는다**(경보 예산).
- HIS 의 역할은 **기기가 못 보는 것**을 보는 것이다: 추세·NEWS2·미확인 위급값·통보 대상 부재.
- 판정 임계는 `VITALS_THRESHOLDS`(+config) **하나**를 쓴다. 기기 임계를 화면에 하드코딩하지 않는다.

## 8-a. ✅ 수집 판정이 화면까지 간다 (2026-08-20 · 회수 완료)

### 무엇이 문제였나
수집 포트(`VitalsIngestService`)는 `STORED`/`DUPLICATE`/`PENDING`·`timeFlags`·`dedupeChecked` 를
**이미 판정하고 있었다.** 그런데 `VitalsService.record()` 가 **저장된 행만** 돌려줬다 —
저장되지 않으면 `null`. 컨트롤러는 그것을 `{ data: null }` 로 **200 응답**에 실었다.

🔴 그래서 화면은 200 을 받고 "활력징후가 기록되었습니다"·"바이탈 저장 완료"를 띄웠다.
**저장되지 않았는데 저장됐다고 말했다.** 사유는 서버 로그에만 있었고 입력한 사람은 보지 못했다.
진료 화면 하나(`InternalMedicineEncounterLayout`)는 아예 `catch {}` 로 실패를 통째로 삼켰다.

이 문서의 종전 서술("출처 스키마와 함께 오는 P1")은 **틀렸다** — 수집 판정은 런타임 값이라
스키마를 기다릴 이유가 없었다. 스키마가 필요한 것은 *출처 메타 저장*이지 *판정 전달*이 아니다.

### 무엇을 했나
| 층 | 변경 |
|---|---|
| 서비스 | `record()` 반환을 `{ vitals, ingest }` 로 확장(`VitalsRecordOutcome`) |
| 컨트롤러 | `POST /api/v1/vitals` · `POST /api/v1/nurse-station/vitals/:queueId` → `{ data, meta.ingest }` |
| voice-emr | 저장 실패 사유를 **추측**("중복 또는 미결속")하던 것을 포트의 실제 판정으로 교체 |
| FE 정본 | `lib/vitals-ingest-notice.ts` — 판정 → 문장. 🔴 화면마다 다시 쓰면 어휘가 갈라진다 |
| FE 쓰기 4경로 | QuickClinicalEntry · NurseChart · InternalMedicine 진료 · `useRecordVitals` |

### 🔴 지킨 규칙
- **`dedupeChecked === false` 는 "중복 없음"이 아니라 "판정 불가"** 다(측정 시각을 모르면 중복을 잴 수 없다).
  화면 문구도 "확인하지 못했습니다"로 쓴다
- **모르는 시각을 수신 시각으로 채워 돌려주지 않는다**(`measuredAt: null`)
- **사유가 없으면 "사유 미상"**이라 말한다 — 지어내지 않는다
- **`meta` 자체가 없으면 "저장됨"이라 단정하지 않는다**(화면 기본 문구에 맡긴다)
- **임상 입력을 새로 막지 않는다**(막으면 방치된다) — 저장되지 않았으면 창을 닫지 않아 다시 넣게 한다
- 진료 화면은 활력 실패가 **진료 저장을 막지 않되**(그건 옳다) 조용히 삼키지도 않는다

### 가드
`api/test/vitals/vitals-record-outcome.spec.ts` 3건 · `web/test/lib/vitals-ingest-notice.spec.ts` 12건.
재주입 2종(서비스가 행만 반환 / DUPLICATE 를 `stored:true` 로) 실패 확인.

### 남은 것
- `useRecordVitals` 는 **소비처가 없다**(고아 훅). 지우지 않고 정직하게 만들어 뒀지만
  **배선할 화면이 정해지면 그 화면까지가 한 벌**이다
- PACU 활력(`POST /api/v1/pacu/:id/vitals`) — **확인 완료(2026-08-20)**. 수집 포트를 지나지 않고
  `pacuRecord.vitalSigns` **JSON 배열**에 따로 쌓는다. 판정도 자체 임계치다.
  · 🔴 **임계치는 통일하지 않았다** — PACU 가 정본보다 **더 엄격**하다(SpO2 92 vs 90 ·
    HR 50/120 vs 40/130 · RR 24 vs 30). 회복실은 마취 각성 중이라 좁게 보는 것이 임상 판단이고,
    정본으로 맞추면 **경보가 느슨해진다**. 두 벌인 사실을 코드 주석에 적어 뒀다.
  · ✅ **봉합**: `v.spo2 > 0`·`v.hr > 0`·`v.rr > 0` 조건이 **측정된 0 을 버리고 있었다.**
    DTO 는 `@Min(0)` 으로 0 을 받고 화면은 빈칸을 `undefined` 로 보내므로 도착한 0 은 실측값이다.
    회복실에서 HR 0 · RR 0 · SpO2 0 은 가장 놓치면 안 되는 값인데 **경보가 하나도 없었다.**
    0 은 진단하지 않고(프로브 이탈일 수 있다) **확인을 요구**하도록 했다.
    가드 `api/test/pacu/pacu-vital-zero.spec.ts` 6건 · 재주입 실패 확인.
  · **남은 것**: PACU 활력은 환자 활력 시계열(`preVisitVitals`)에 **나타나지 않는다.**
    통합하려면 저장 모델을 바꿔야 하므로 스키마·설계 결정이다
- 출처 메타(기기·신뢰도) **저장**은 여전히 §5 스키마 승인 대기

## 10. 검증 계획 (가드 — 결함을 재주입하면 실패해야 한다)

1. **포트 우회 금지 가드** — 활력 저장이 `VitalsIngestService` 를 거치지 않는 신규 코드가 생기면 실패(구조 가드)
2. **미관측 보존 가드** — 결측을 `0`·`false`·정상값으로 접으면 실패(오늘 NEWS2 축에서 쓴 방식)
3. **시각 가드** — `measuredAt` 이 `receivedAt` 과 같은 값으로 채워지면 실패(기기 시각 미상 케이스)
4. **단위 가드** — `ucum-lhc` 로 검증되지 않은 단위에 `system` 을 선언하면 실패(기존 P5 가드 확장)
5. **재반올림 금지 가드** — 기기 보고값이 저장 전에 `roundBy` 를 타면 실패
6. **멱등 가드** — 같은 멱등 키 재수신이 행을 두 개 만들면 실패
7. **결속 가드** — 미결속 측정이 임의 환자에게 붙으면 실패 · 보류함으로 가는지 확인

- 🔴 **확인하지 않은 표준 코드를 적지 않는다.** LOINC 는 표준 vital-signs 패널에서 인용했고,

- 이 계획은 **값을 바꾸지 않는다**(보정·예측 없음). 그 경계가 무너지면 규제 등급이 함께 올라간다는 것을 §7 이 명시한다.
