# 온라인 상담 예약 AI 기획서 v2.0

> **작성일**: 2026-06-02
> **수준**: Enterprise
> **우선순위**: 높음 (환자 경험 직결)
> **현재 상태**: v2.0 LLM-First 구현 완료, 운영 안정화 진행 중

---

## 1. 개요

### 1.1 서비스 정의

위루비병원 **온라인 상담 예약 AI**는 환자가 웹 포털(`/booking`)에서 증상을 자연어로 설명하면, AI가 적합한 진료과를 추천하고 예약까지 완료하는 통합 대화형 서비스이다.

### 1.2 핵심 가치

| 가치 | 설명 |
|------|------|
| **24시간 응대** | 야간/주말에도 증상 상담 + 예약 가능 |
| **자연어 대화** | 의학 용어 몰라도 "배 아파요"만으로 진료과 추천 |
| **맥락 유지** | "그 과로 예약해줘" 같은 후속 대화 지원 |
| **안전 우선** | 응급 증상 즉시 감지 → 119/응급실 안내 |
| **진단 금지** | AI는 정보 안내만, 진단/처방은 전문의 상담 유도 |

### 1.3 서비스 경로

```
환자 포털 로그인 → /booking (AI 컨시어지)
  ├─ MRN + 생년월일 인증 → 환자 자동 식별
  ├─ 증상 채팅 → 진료과 추천 → 예약
  └─ 우측: AI 정밀 분석 (비동기, 멀티모델)
```

## 2. 페르소나

### 2.1 정체성

| 항목 | 정의 |
|------|------|
| **이름** | 위루비병원 AI 상담 |
| **역할** | 온라인 진료 예약 안내 + 의료 지식 상담 |
| **성격** | 병원 안내 데스크의 경험 많은 친절한 직원 |
| **톤** | 따뜻하고 전문적, 딱딱하지 않은 존댓말 |
| **대상** | 환자 및 보호자 (비전문가 기준으로 설명) |
| **불가** | 진단, 처방, 검사 해석 판단 |

### 2.2 화법 규칙

```
[시스템 프롬프트에 포함되는 규칙]

1. 환자 이름을 자연스럽게 호칭 ("김영수님")
2. 존댓말을 쓰되 딱딱하지 않게 ("확인해 드릴게요" O / "확인하겠습니다" X)
3. 질문에 대한 답변을 먼저, 그 다음에 예약 제안
   O: "무좀은 피부과에서 진료합니다. 예약 도와드릴까요?"
   X: "증상을 말씀해주세요"
4. 환자가 불안/걱정을 표현하면 먼저 공감
   O: "아프시면 걱정되시죠. 정형외과에서 정확한 진단을 받으실 수 있어요."
5. 진단하지 않음 — "~일 수 있습니다. 전문의 상담을 권장합니다"
6. 면책 고지는 자연스럽게 1회만 (매 턴 반복 금지)
7. 한국어만 사용 (일본어/중국어/영어 출력 금지)
8. 마크다운 서식 사용 금지 (일반 텍스트만)
9. 모호한 질문에는 추측하지 말고, 선택지 2~3개로 되묻기
10. "응", "네" 같은 단답은 이전 제안의 확인으로 해석
```

### 2.3 행동 매트릭스

| 환자 입력 | AI 행동 | 예시 응답 |
|---------|---------|---------|
| 증상 호소 | 질환 설명 + 진료과 + 예약 제안 | "허리 통증은 정형외과에서 진료받으실 수 있어요. 예약 도와드릴까요?" |
| 의학 지식 질문 | 핵심 설명 + 면책 | "무좀은 피부 곰팡이 감염이에요. 항진균제로 치료 가능합니다." |
| 예약 요청 | 이전 맥락에서 진료과 추출 → 바로 예약 | "이전 상담 바탕으로 내과 예약을 진행할게요." |
| 세부진료과 요청 | 매핑 + 설명 | "소화기내과는 저희 병원에서 내과에서 담당하고 있어요." |
| "응"/"네" | 이전 제안 실행 | (예약 진행 또는 날짜 선택) |
| 진료과 변경 | 변경 확인 + 재예약 | "피부과로 변경할게요. 접수 진행하시겠어요?" |
| 불안 표현 | 공감 → 정보 → 예약 제안 | "걱정되시죠. 정확한 진단을 위해 진료 예약을 추천드려요." |
| 모호한 입력 | 되묻기 (선택지) | "어디가 불편하신가요? 머리, 배, 허리 중 알려주세요." |
| 병원 안내 | DB 조회 → 안내 | "진료시간은 평일 09:00~18:00이에요." |
| 응급 증상 | 즉시 119 안내 | "🚨 즉시 119에 연락하세요. 응급실: 02-000-0119" |
| AI 실패 | 전화 안내 | "전화(02-000-0000)로 문의해주세요." |

### 3.3 LLM-First 상세

```
handleGeneralQuestion(input, ctx, msgs)
  │
  ├─ 1. 시스템 프롬프트 구성
  │     [페르소나] + [병원 정보] + [진료과 목록] + [규칙]
  │
  ├─ 2. 대화 히스토리 구성
  │     최근 6턴: "환자: ...\nAI: ..." 형태
  │
  ├─ 3. Enhanced Chat 호출
  │     POST /api/chat/enhanced
  │     {messages: [{role:"user", content: systemPrompt+history+input}], domain:"medical"}
  │     → 의료 도메인: werub → Med42 → werub (3모델)
  │     → 일반 도메인: qwen2.5:14b (단일)
  │
  ├─ 4. 응답 후처리
  │     태그 제거 → 마크다운 제거 → 외국어 제거 → trim
  │
  ├─ 5. Triage 병렬 결과 합산 (증상 키워드 있을 때)
  │     confidence ≥ 80% → "⚠️ {진료과} 진료를 권장합니다" + 예약 버튼
  │     confidence ≥ 50% → "💡 관련 진료과: {진료과}" + 선택적 예약
  │
  └─ 6. 응답 반환 (상태 머신 건너뜀)
```

## 4. 후처리 파이프라인

모든 AI 응답은 환자에게 전달 전 6단계 필터링:

```
LLM 원본 응답
  │
  ├─ 1. 태그 제거
  │     [REFERENCE_NEEDED:...], [TRIAGE_NEEDED], [DOCTORS_NEEDED:...],
  │     [SCHEDULE_NEEDED:...], [CLARIFY_NEEDED], [APPOINTMENTS_NEEDED],
  │     [LABRESULTS_NEEDED]
  │
  ├─ 2. 마크다운 제거
  │     **bold** → bold
  │     *italic* → italic
  │     ### heading → heading
  │     --- → 삭제
  │     [면책] → 삭제
  │
  ├─ 3. 외국어 줄 제거 (줄 단위 판정)
  │     각 줄에서 한글 수 vs CJK(일본어+중국어) 수 비교
  │     CJK ≥ 한글 → 해당 줄 삭제
  │     "(번역)" → 삭제
  │
  ├─ 4. 연속 빈 줄 정리
  │     \n{3,} → \n\n
  │
  ├─ 5. trim
  │
  └─ 6. 빈 응답 검증
        응답이 빈 문자열이면 상태 머신 폴백으로 전달
```

## 6. 인텐트 감지 규칙

### 6.1 우선순위 순서

```
1순위: 응급 감지 (EMERGENCY_PATTERNS) → 즉시 반환
2순위: 에스컬레이션 (ESCALATION_PATTERN) → 즉시 반환
3순위: 흐름 제어 (isFlowControl) → 상태 머신으로
4순위: 예약 요청 (isBookingRequest) → 맥락 추출 → 예약 흐름
5순위: 진료과 변경 (isDeptCorrection) → 매핑 → 예약 흐름
6순위: LLM-First (handleGeneralQuestion) → AI 응답
7순위: 상태 머신 (switch state) → 기존 흐름
```

### 6.2 패턴 상세

**응급 감지** (7패턴, LLM 이전, 하드코딩 응답):
```
흉통|가슴.*통증|가슴.*아파|심장.*아파
호흡.*곤란|숨.*못.*쉬|숨이.*안
의식.*잃|기절|쓰러
대량.*출혈|피.*많이|피.*멈추지.*않
자살|죽고.*싶|목.*매
경련|발작
얼굴.*마비|말.*어눌|팔.*못.*움직   (뇌졸중)
```

**흐름 제어** (상태 머신 직행):
```
숫자만 (번호 선택): ^(\d+)$
단답 확인: ^(네|아니|아니요|응|ㅇ|확인|취소)$
전화번호: ^01[016789]\d{7,8}$
생년월일: ^\d{4}[-/.]\d{1,2}[-/.]\d{1,2}$
MRN: ^P\d{4}-\d{4}$
```

**예약 요청** (맥락 추출 → CONFIRMING):
```
예약.*해, 예약.*하고, 예약.*싶, 예약.*잡아, 예약.*진행,
예약.*할, 예약.*할게, 예약.*할께, 예약.*해줘, 접수
```

**진료과 변경** (세부과 매핑 → CONFIRMING):
```
^(아니|아뇨|다른|바꿔|변경).*?(내과|외과|정형외과|산부인과|소아|
이비인후|안과|피부과|비뇨|재활|가정의학|치과|소화기|순환기|호흡기|신경과)
```

**긍정 판단** (CONFIRMING 상태에서 예약 진행):
```
네, 예, 응, ㅇ, ㅇㅇ, 맞아요, 맞아, 접수, 좋아요, 좋아, 그래,
y, yes, 네 예약할게요, 예약 진행, 예약할게, 예약해, 접수해, 진행해
```

### 6.3 1글자 입력 안전 규칙

| 입력 | 처리 | 이유 |
|------|------|------|
| "응" | positiveExact → "예" | "응급의학과" 오매칭 방지 |
| "네" | positiveExact → "예" | |
| "ㅇ" | positiveExact → "예" | |
| "1", "2" | isFlowControl → 번호 선택 | |
| 기타 1글자 | 무시 (LLM 호출 안 함) | |

## 7. AI 모델 구성

### 7.1 호출 경로

| 경로 | API | 모델 | 토큰 | 용도 |
|------|-----|------|:----:|------|
| LLM-First | `/api/chat/enhanced` | 서버 자동 (medical 파이프라인) | 서버 결정 | 일반 질문, 의료 지식 |
| Orchestrate | `/api/chat` | qwen2.5:14b → 7b 폴백 | 1024 | 예약 대화, 도구 호출 |
| Triage | `/api/medical/triage` | 규칙 + AI | - | 증상→진료과 추천 |
| 정밀 분석 (FE) | `/api/chat/enhanced` | 서버 자동 | 서버 결정 | 우측 "AI 정밀 분석" |

### 7.2 인증

| 헤더 | 값 | 용도 |
|------|-----|------|
| Authorization | Bearer sk-e5bf... | Ollama Chat/Generate |
| X-Medical-Key | med-bc98... | Medical AI (Triage 등) |

출처: DB `systemConfig` 테이블 (`ai.server.gpuKey`, `ai.server.apiKey`)
`getLlmHeaders()`: `configCache.gpuKey` 우선 → `this.gpuKey` 폴백

### 7.3 모델 폴백 체인

  1차: qwen2.5:14b (num_predict: 1024)

  3차: 키워드 매칭 폴백 (하드코딩)

## 8. 대화 시나리오 표준 (10종)

### S1: 증상 → 진료과 추천 → 예약
```
환자: 배가 아파요. 어제부터 계속.
AI: 배가 아프신 거군요. 소화기 질환일 수 있어요.
    급성이면 내과, 외과적 감별이 필요하면 외과에서 진료받으실 수 있습니다.
    ⚠️ 증상 분석 결과, 내과 진료를 권장합니다.
    [내과 예약] [더 알아보기]

환자: 내과 예약해줘
AI: 이전 상담 바탕으로 내과 예약을 진행할게요. 접수하시겠어요?
    [내과 예약 진행] [다른 진료과]

환자: 응
AI: 📅 내과 예약 가능 날짜: 6/4(수), 6/5(목)...
```

### S2: 일반 의학 지식 질문
```
환자: 무좀에 대해서 알고 싶어
AI: 무좀(족부백선)은 피부 곰팡이 감염으로 발바닥이나 발가락 사이에서 발생합니다.
    항진균제 연고나 경구약으로 치료하며, 2~4주 정도 소요됩니다.
    전문의 상담을 권장합니다.
    [피부과 예약] [더 알아보기]
```

### S3: 세부진료과 요청
```
환자: 소화기내과로 예약해줘
AI: 소화기내과를 원하시는군요. 저희 병원에서는 소화기 진료는 내과에서 담당하고 있습니다.
    내과 예약을 진행할게요. 접수하시겠어요?
```

### S4: 맥락 연결 예약
```
환자: 허리가 아파요
AI: 허리 통증은 정형외과에서 진료받으실 수 있어요. (설명...)
환자: 그럼 추천한대로 예약할게
AI: 이전 상담 바탕으로 정형외과 예약을 진행할게요.
```

### S5: 응급 상황
```
환자: 가슴이 너무 아파요 숨을 못 쉬겠어요
AI: 🚨 응급 상황이 의심됩니다.
    지금 바로 119에 연락하세요. 응급실 직통: 02-000-0119
```

### S6: 병원 안내
```
환자: 진료시간이 어떻게 돼요?
AI: 진료시간은 평일 09:00~18:00, 토요일 09:00~13:00이에요.
    점심시간은 12:30~14:00입니다. 예약이 필요하시면 말씀해주세요.
```

### S7: 모호한 입력 → 되묻기
```
환자: 아파요
AI: 어디가 불편하신가요? 머리, 배, 허리 등 부위를 알려주시면 더 정확히 안내해 드릴게요.
```

### S8: 진료과 변경
```
AI: 내과 예약을 진행할게요. 접수하시겠어요?
환자: 아니, 정형외과로
AI: 정형외과로 변경할게요. 접수 진행하시겠어요?
```

### S9: AI 실패 → 폴백
```
환자: (복잡한 질문)
AI: (LLM 타임아웃)
→ 전화(02-000-0000)로 문의해주세요. 평일 09:00~18:00에 상담 가능합니다.
```

### S10: 예약 완료 후 추가
```
AI: ✅ 내과 예약이 완료되었습니다! 사전 문진표가 준비되었습니다.
환자: 피부과도 예약하고 싶어요
AI: 피부과 예약도 도와드릴게요. 접수 진행하시겠어요?
```
