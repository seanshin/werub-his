## 1. 기획 배경

### 1.1 현재 상태

- `PatientGuardian` 모델이 이미 존재 (관계/법적근거/접근범위/승인 워크플로우)
- 모바일 앱에 보호자 등록/관리 UI 구현됨
- **하지만** 보호자가 피부양자의 데이터를 실제로 열람하는 기능은 미구현
- 포털에서 보호자 전환(계정 스위칭) 기능 없음

### 1.2 목표

```
보호자가 자신의 계정으로 로그인한 후,
법적으로 허용된 범위 내에서 피부양자(환자)의 의료 정보를 열람할 수 있다.
```

### 1.3 대상 사용자

| 유형 | 예시 | 법적 근거 |
|------|------|-----------|
| **미성년자 부모** | 14세 미만 자녀의 부모 | 민법 제911조 (친권자), 개인정보보호법 제22조 |
| **고령 환자 자녀** | 80세 부모를 돌보는 50대 자녀 | 환자 동의서 기반 위임 |
| **의사 무능력자 보호자** | 의식불명/치매 환자의 법정 대리인 | 민법 제947조, 의료법 제21조 제2항 |
| **사망 환자 유족** | 사망 환자의 배우자/직계존비속 | 의료법 제21조 제2항 제2호 |
| **위임장 기반 대리인** | 환자가 위임장을 작성한 제3자 | 환자 본인 서면 위임 |

## 2. 법적 근거 상세

### 2.1 의료법 제21조 (기록 열람 등)

```
제21조(기록 열람 등)
① 환자는 의료인, 의료기관의 장 및 의료기관 종사자에게
   본인에 관한 기록의 열람 또는 그 사본의 발급 등을 요청할 수 있다.

② 의료인, 의료기관의 장 및 의료기관 종사자는 다음 각 호의 경우를 제외하고는
   환자에 관한 기록을 열람하게 하거나 그 사본을 내주는 등
   그 내용을 확인할 수 있게 하여서는 아니 된다.

   1. 환자의 배우자, 직계 존속·비속, 형제·자매
      (환자의 배우자 및 직계 존속·비속, 배우자의 직계존속이
       모두 없는 경우에 한하여 형제·자매)
      또는 배우자의 직계 존속이 환자 본인의 동의서와
      친족관계를 나타내는 서류를 첨부하는 등
      보건복지부령으로 정하는 요건을 갖추어 요청한 경우

   2. 환자가 지정하는 대리인이 환자 본인의 동의서와
      대리권이 있음을 증명하는 서류를 첨부하는 등
      보건복지부령으로 정하는 요건을 갖추어 요청한 경우

   3. 환자가 사망하거나 의식이 없는 등
      환자의 동의를 받을 수 없는 경우에
      환자의 배우자, 직계 존속·비속, 형제·자매
      (환자의 배우자 및 직계 존속·비속, 배우자의 직계존속이
       모두 없는 경우에 한하여 형제·자매)
      또는 배우자의 직계 존속이
      친족관계를 나타내는 서류를 첨부하는 등
      보건복지부령으로 정하는 요건을 갖추어 요청한 경우
```

### 2.2 열람 범위 제한 (법적 해석)

| 법적 근거 | 허용 범위 | 제한 |
|-----------|----------|------|
| 환자 본인 동의 (21조 ②-1) | 환자가 동의한 범위 내 전체 | 동의서에 명시된 항목만 |
| 대리인 지정 (21조 ②-2) | 위임장에 명시된 범위 | 위임장 유효기간 내 |
| 동의 불가 (21조 ②-3) | 진료 관련 기본 정보 | 정신과/성병 기록 별도 동의 필요 |
| 미성년자 친권자 | 자녀 전체 진료 기록 | 14세 이상은 자녀 동의 권장 |

### 2.3 필수 서류 (보건복지부령)

| 유형 | 필수 서류 |
|------|-----------|
| 친족 (동의 가능) | ① 환자 동의서 + ② 신청자 신분증 + ③ 가족관계증명서 |
| 대리인 (위임) | ① 환자 동의서 + ② 위임장 + ③ 신청자 신분증 + ④ 환자 신분증 사본 |
| 동의 불가 (의식불명 등) | ① 의사 소견서/진단서 + ② 신청자 신분증 + ③ 가족관계증명서 |
| 사망 | ① 사망진단서/사체검안서 + ② 신청자 신분증 + ③ 가족관계증명서 |

## 3. 보호자 계정 유형 (accessScope)

### 3.1 접근 범위 정의

기존 `PatientGuardian.accessScope` (JSON) 필드를 활용합니다.

```json
{
  "level": "FULL" | "MEDICAL" | "BILLING" | "LIMITED",
  "allowedSections": ["appointments", "encounters", "labs", "imaging", "medications", "billing", "documents"],
  "deniedSections": ["psychiatry", "reproductive"],
  "canBook": true,
  "canPay": true,
  "canMessage": true,
  "canConsent": false,
  "canViewVitals": true,
  "canViewNotes": true
}
```

### 3.2 사전 정의 접근 레벨

| 레벨 | 열람 가능 | 조작 가능 | 대상 |
|------|----------|----------|------|
| **FULL** | 전체 진료 기록 | 예약/수납/동의서 | 미성년자 친권자, 법정 대리인 |
| **MEDICAL** | 진료/검사/투약 기록 | 예약만 | 환자 동의 기반 가족 |
| **BILLING** | 수납/서류 발급 | 수납/서류 | 수납 대리인 |
| **LIMITED** | 예약/대기 현황만 | 예약 변경만 | 위임장 기반 제3자 |

### 3.3 민감 정보 별도 처리

다음 진료과/정보는 기본 접근 범위에서 제외하고, 별도 동의가 있어야만 열람 가능합니다:

| 민감 정보 | 사유 | 법적 근거 |
|-----------|------|-----------|
| 정신과 기록 | 사회적 낙인 방지 | 정신건강복지법 제30조 |
| 성병/HIV | 프라이버시 | 감염병예방법 제19조 |
| 생식 건강 (산부인과) | 자기결정권 | 개인정보보호법 제23조 |
| 유전자 검사 | 차별 방지 | 생명윤리법 제46조 |

## 5. 기술 설계

### 5.1 보호자 토큰 (Guardian JWT)

```typescript
// 보호자가 피부양자 전환 시 새 토큰 발급
interface GuardianTokenPayload {
  sub: string;           // 보호자 PatientAccount ID
  pid: string;           // 보호자 Patient ID
  type: 'guardian';      // 토큰 타입 (구분용)
  targetPid: string;     // 피부양자 Patient ID
  scope: AccessScope;    // 허용된 접근 범위
  guardianshipId: string; // PatientGuardian ID
  exp: number;           // 30분 TTL (portal과 동일)
}
```

### 5.2 보호자 인증 Guard

```typescript
// PortalOrPatientGuard 확장
if (payload.type === 'guardian') {
  // 보호자 토큰 검증
  req.portalPatientId = payload.targetPid;  // 피부양자 ID로 설정
  req.guardianAccountId = payload.sub;       // 보호자 ID 별도 보관
  req.guardianScope = payload.scope;         // 접근 범위
  req.isGuardianAccess = true;               // 보호자 접근 플래그
}
```

### 5.3 접근 범위 필터링

```typescript
// 포털 서비스에서 데이터 반환 전 필터링
function filterByScope(data: any, scope: AccessScope, section: string) {
  // 1. 허용 섹션 확인
  if (scope.deniedSections?.includes(section)) throw new ForbiddenException();
  if (scope.allowedSections && !scope.allowedSections.includes(section)) throw new ForbiddenException();
  
  // 2. 민감 정보 필터
  if (section === 'encounters') {
    data = data.filter(e => !SENSITIVE_DEPARTMENTS.includes(e.department));
  }
  
  return data;
}

const SENSITIVE_DEPARTMENTS = ['정신건강의학과', '산부인과', '비뇨의학과'];
```

## 6. 특수 시나리오

### 6.1 미성년자 (14세 미만)

```
부모(친권자) → 자녀 포털 전체 접근 가능 (FULL)
  - 가족관계증명서 자동 검증 (향후 공공데이터 연동)
  - 동의서 대리 서명 가능 (guardianName, guardianRelation 필드 활용)
  - 14세 이상 자녀: 자녀 본인 동의 필요 (개인정보보호법)
```

### 6.2 의식불명/치매 환자

```
법정 대리인 → 환자 포털 접근 (MEDICAL + BILLING)
  - 필수: 의사 소견서 (의식불명 확인) + 가족관계증명서
  - 병원 관리자 수동 승인 필수
  - 정신과 기록은 별도 법정 대리인 서류 제출 시에만
  - 유효기간: 소견서 유효기간에 연동 (기본 6개월)
```

### 6.3 사망 환자

```
유족 → 사망 환자 기록 열람 (MEDICAL 읽기 전용)
  - 필수: 사망진단서 + 가족관계증명서
  - 예약/수납/동의서 조작 불가 (읽기 전용)
  - 유효기간: 1년 (갱신 가능)
```

### 6.4 입원 환자 보호자

```
입원 중 환자의 보호자 → 입원 정보 실시간 열람
  - 보호자 공유 링크 (1회용, 24시간) — 계정 없이도 열람
  - 계정 보호자 — 입원 현황, 바이탈, 회진, 투약, 식단 열람
  - 간호사 호출은 불가 (환자 본인만)
```

### 6.5 위임장 기반 제3자

```
환자가 지정한 대리인 → 제한된 접근 (LIMITED)
  - 필수: 환자 동의서 + 위임장 + 양측 신분증
  - 유효기간: 위임장 기재 기간 (최대 1년)
  - 예약 확인/변경만 가능
```

## 9. 보안 요구사항

### 9.1 접근 통제

| 항목 | 구현 |
|------|------|
| 보호자 토큰 TTL | 30분 (포털과 동일), 비활성 5분 시 재인증 |
| 세션 분리 | 본인 세션 ↔ 보호자 세션 별도 관리 |
| 동시 접근 제한 | 1개 피부양자만 동시 열람 가능 |
| 2차 인증 | 피부양자 전환 시 비밀번호/PIN 재확인 |
| IP 제한 | 보호자 등록 시 IP 기록, 이상 접근 시 알림 |

### 9.2 감사 추적 (Audit Trail)

```
- 모든 보호자 접근은 GuardianAuditLog에 기록
- 환자 본인이 접근 이력을 조회 가능
- 관리자가 전체 보호자 접근 현황 모니터링
- 이상 접근 패턴 감지 (심야 대량 조회, 민감 정보 반복 접근)
- 로그 보존 기간: 5년 (의료법 시행규칙 제15조)
```

### 9.3 Break-the-Glass (비상 열람)

```
응급 상황에서 보호자가 승인 전에 긴급 열람이 필요한 경우:
  - 긴급 열람 버튼 → 사유 입력 필수
  - 24시간 임시 MEDICAL 접근 권한 부여
  - 관리자에게 즉시 알림 → 사후 서류 제출 요구
  - 사후 승인 없으면 자동 차단 + 감사 기록
```
