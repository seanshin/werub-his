# 입력 보조 UX 기획 — 콤보박스·프리셋·예제·프리필·설정값 (2026-08-24)

> 상태: **기획(P0~P3 미착수)** · 근거는 전부 이 날짜의 코드·운영 DB 실측
> 작성 계기: 사람 지시 "콤보박스나 예제, 설정값들을 미리 넣을 수 있는 부분들 교차검증"

## 0. 이 문서의 위치 — 정본이 둘이 되지 않게

UX 정본은 이미 둘 있다. 이 문서는 그 둘이 다루지 않는 **세 번째 축**만 다룬다.

| 문서 | 다루는 것 |
|---|---|
| `docs/03-analysis/ux-consistency-review-2026-07.md` | **표현 부품** — 상태 배지·날짜·금액·환자명·빈상태·폴링 |
| `docs/01-plan/features/clinical-ux-agent-era.plan.md` | **진실성·임상** — 화면은 사실을 말한다·초기값 미선택·경보 예산·에이전트 |
| 이 문서 | **입력 보조** — 사람이 타이핑하는 자리를 어떻게 줄이고, 그때 무엇을 지어내면 안 되는가 |

겹치는 지점의 정본은 기존 문서다 — 특히 **"쓰기 폼의 초기값은 미선택"**(임상 UX §2)은 이 문서가
바꾸지 않는다. 이 문서는 그 규약의 **반대편 절반**을 정한다: *그러면 무엇은 채워도 되는가.*

## 1. 제1원칙 — 채울 수 있는 값은 세 종류뿐이다

입력 보조의 전 항목은 이 3분류 중 하나로 판정한다. **분류가 다르면 처방이 정반대가 된다.**

| 분류 | 정의 | 처방 |
|---|---|---|
| ① **임상 판단 값** | 사람이 환자를 보고 정하는 것 (활력·평가 점수·소견·laterality) | 🔴 **기본값·제안 금지.** placeholder 로도 제안하지 않는다. 빈 채로 시작하고, 라벨에 단위·참고범위만 |
| ② **시스템이 이미 아는 값** | 로그인 사용자·오늘·현재 병동·화면 맥락의 환자 | **프리필이 정직하다.** 아는 것을 다시 타이핑시키는 것이 오히려 오입력을 만든다(옆 환자 선택 등). 단, **수정 가능하게** |
| ③ **자주 쓰는 표현** | 사유·메모 등 자유문자열 중 반복되는 것 | **입력 보조(프리셋)** — 목록에서 고르되 **자유 입력을 막지 않는다**. 정본 전례: `MEAL_UNDELIVERED_REASON_PRESET`(shared `diet.ts` — "허용 목록이 아니라 입력 보조") |

판정이 애매하면 ①로 취급한다(안전측). 근거가 된 사고 유형:
- 간호초기평가가 `명료·독립보행·통증0·정상`으로 시작 → **미평가가 정상으로 저장**(임상 UX §1)
- 전 술식 laterality 필수 강제 → **아무 값이나 골라 통과**(v4.5.0 — "필수로 강제하면 거짓 데이터")
- 급양 미배식 사유를 영문 enum 으로 강제하려다 철회 → **기존 한글 기록이 고아가 됨**(어휘를 지어내 강제하지 않는다)

## 2. 교차검증 실측 (2026-08-24)

규모: `<select>` 사용 파일 **228** · `placeholder` 사용 파일 **303** · `datalist` **3** ·
로컬 옵션 상수(`*_OPTIONS`/`*Options = [`) **34+**.

### 2.1 🔴 부서 콤보 — 정본·EP 가 다 있는데 화면 10+ 개가 각자 하드코딩

| 층 | 실측 |
|---|---|
| DB 마스터 | `department_codes` **36행 전부 활성**(code·nameKo·nameEn·category·sortOrder) |
| 서버 EP | `GET /api/v1/codes/departments` **존재**(code-master.controller:189, category 필터까지) |
| FE 소비 | **0건** |
| FE 로컬 정의 | `const DEPARTMENTS = [...]` 류 **10+ 파일**(front-desk·SelfCheckIn·ReferralTab·clinic-queue·care-teams·staff-management·reception 2·mdt·dept-catalog…) |
| 실사용 어휘 | `staff.department` 는 `간호부 (외과병동)`·`건강검진센터(검사실)`·`경영진`·`CRM` — **마스터에도 로컬 상수에도 없는 값**이 이미 저장돼 있다 |

"EP 를 만들면 부르는 화면까지가 한 벌" + "역할 목록은 shared 정본 하나" 유형의 재발이다.
🔴 단, **실사용 어휘가 마스터와 갈라져 있다는 사실**이 배선보다 먼저다 — 화면을 마스터로 좁히면
기존 저장값(`간호부 (외과병동)`)이 콤보에서 사라져 **선택 불가·표시 불가**가 된다(whitelist 함정).

### 2.2 🔴 임상 수치 입력의 placeholder 가 "정상값"을 제안한다

투석 시작 폼(workstation/therapy:328~): 체온 `placeholder="36.5"` · 수축기 `"140"` · 이완기 `"90"` ·
심박 `"72"`. 전 FE 로 넓히면 숫자 placeholder 상위: `"0"` **9건** · `"72"` 4 · `"36.5"` 3 · `"65.0"` 2 ….

placeholder 는 저장되지 않지만 **바쁜 현장에서 "권장값"으로 읽힌다** — 초기값 미선택 규약을
placeholder 가 우회하는 모양이다. 특히 `placeholder="0"` 은 "측정된 0"과 "미측정"의 경계를 흐린다
(PACU 가 측정된 0 을 버려 HR 0 무경보였던 축과 같은 지대).

### 2.3 placeholder 예제 어휘가 두 계열로 갈라져 있다

- 형식 힌트(명백히 가짜): `010-0000-0000`, `name@hospital.example.org`
- 실데이터형(그럴듯함): `010-1234-5678`, `010-2345-6789`, `hong@example.com`

둘이 혼재한다. 실데이터형은 ①스크린샷·시연에서 실번호로 오독되고 ②급한 입력에서 그대로
타이핑될 수 있다(승인번호 `KIOSK-<ts>` 날조와 같은 "그럴듯함" 문제의 낮은 단계).

### 2.4 사유(自由文) 입력 41+ 곳 — 프리셋 부품이 없다

`placeholder="...사유"` 만 **41곳**(취소·반려·보류·위임·환불·변경 사유…). 급양 축이 이미 정답 모양을
만들었다(`MEAL_UNDELIVERED_REASON_PRESET` + "비어 있으면 안 된다"만 강제) — 그런데 그 모양을 재사용할
**공통 부품이 없어서** 각 화면이 맨 input 이다. `datalist` 사용은 전 FE 에 **3곳**뿐.

### 2.5 설정값 — config 로 뺄 후보

`SystemConfig` 에는 이미 `ui.*` 20키·`er.*` 14·`inpatient.*` 14·`quality.*` 4·`nutrition.*` 4 가 있고
관리 화면도 있다. FE 에 남은 하드코딩 임계·기본값 상수 **13건**(`*_THRESHOLD`/`MAX_*`/`DEFAULT_*`)은
**후보이지 확정이 아니다** — "원내 정책이면 config + 미설정임을 밝힌다, 화면 상수면 그대로" 기준으로
개별 심사한다(기본값을 정책인 척하지 않는다).

## 3. 원칙 — 이 축의 판정 규칙

1. 🔴 **placeholder 는 형식을 말하고 값을 제안하지 않는다.** 임상 수치 input 의 숫자 placeholder 금지.
   단위·참고범위는 라벨/보조텍스트로("mmHg", "참고 60~100") — "여기 140을 쓰라"가 아니라 "이건 혈압 칸이다"
2. **예제는 명백히 가짜로.** 전화 `010-0000-0000`·이메일 `name@example.com` 계열로 통일.
   그럴듯한 예제(`010-1234-5678`)는 만들지 않는다
3. **콤보는 강제가 아니라 보조.** 목록 밖 값을 막으려면 그 값이 **법적/안전 판정에 쓰이는 어휘**일 때만
   (그때는 shared 정본 + 시드까지 기계 대조). 사유·메모류는 항상 자유 입력 열어둔다
4. 🔴 **마스터가 있으면 화면이 그것을 읽는다 — 단, 실사용 어휘부터 실측한다.** 마스터∖실사용,
   실사용∖마스터 양방향 차집합을 먼저 내고, 갈라져 있으면 **정비는 사람 판단**(조직도는 시스템이 못 정한다).
   그동안 화면은 "마스터 + 현재 저장값" 합집합을 보여준다(기존 값이 사라지지 않게)
5. **프리필은 ②분류만, 수정 가능하게.** 채운 값에는 출처를 안다(본인=세션·오늘=시계·부서=프로필) —
   화면이 지어낸 값은 하나도 없어야 한다
6. **프리셋 채택률을 잰다.** 프리셋이 실사용과 갈라지면(자유 입력 비율이 계속 높으면) 프리셋이 틀린 것 —
   목록을 실사용 상위 어휘로 갱신한다(운영 DB 가 알려준다)
