# 간호 스테이션 — 상·하번 교대 기록과 결함 1~10 (2026-09-30)

> 요청: "nurse-station 개선이나 추가 기능은?" → "상하번 간호사의 간호기록 등이 작성될 수 있어야 하지 않나?" → "결함 1~10번과 함께 구현까지 진행하고 배포 후 푸시해".

## 1. 실측 — 교대가 화면에 없었다
- 간호기록은 근무조(`shiftType`)를 저장하지만 **관찰 시각을 고를 수 없었다**. 지난 근무조의 일을 뒤늦게 적으면 지금 시각으로 저장돼 시계열이 틀렸고, 늦게 적었다는 사실도 남지 않았다.
- 하번이 "이번 근무에 무엇을 안 적었는가"를 볼 곳이 없었다. 교대 직전 기억으로 확인했다.
- 상번은 인계를 **확인만** 할 수 있었다. 담당 배정은 하번 이름으로 남아 상번의 "내 담당"은 비고 하번의 "내 담당"은 부풀었다.
- 담당 배정은 해제 경로가 **수동 버튼 하나**뿐이었다. 퇴원·병동 이동 환자가 계속 "내 담당"에 남았고, 같은 배정을 누를 때마다 한 줄씩 쌓였다. 근무조를 보내지 않아 야간 배정도 `DAY` 로 저장됐다.
- 인계 작성자(`fromDoctorId`)를 **화면이 보냈다**. 본문만 바꾸면 남의 이름으로 인계를 쓸 수 있었다.

## 2. 결함 1~10(화면 점검에서 확정)
| # | 결함 | 봉합 |
|---|---|---|
| 1 | MAR 탭이 날짜 없이 입원 전 기간을 받았다. 어제 기록하지 않은 투약은 "오늘 할 일"과 섞이거나 안 보였다. 중단된 처방에도 투여 버튼이 보였다. | `?date=<KST 오늘>&includeOverdue=true`. 지난 미처리분은 `carriedOver`(최근 7일·**이번 입원만**)로 표식한다. 처방이 `ACTIVE` 가 아니면 투여 버튼 대신 안내를 보인다. 보류·거부는 MAR 화면(사유 필수)으로 연결한다. |
| 2 | 상태 배지 기본값이 '예정'이라 **거부(REFUSED)를 예정으로** 말했다. | shared `MED_ADMIN_STATUS_LABEL` + `<StatusBadge domain="medAdmin">`. '미투약'은 안전 어휘라 사람 검수 전까지 미등재한다. |
| 3 | 입원 일차가 경과 일수(floor)라 입원 당일이 0일차였다. 투약 대기는 전 기간 SCHEDULED 였고, 낙상은 초기평가에 딸린 옛 값이었다. Braden 이 없으면 'LOW' 였다. | 서버 재원 요약이 보드와 같은 정의를 쓴다. `stayDays` · 오늘 간호일 `pendingMedCount` + `carriedOverMedCount` · 최신 낙상위험평가 + `fallRiskAssessedAt` · Braden 없으면 `null`. |
| 4 | 병동 보드가 서버에 없는 `bedLabel`·`bed.admission` 을 읽었다. '내 담당만'이면 남의 환자 병상을 **빈 병상**으로 그렸고 병동 필터도 무시했다. | `beds/list?wardId=` · `bedNumber` · 병동+호실로 묶는다. 점유는 **병상 상태**가 정본이다(목록에 없으면 "사용 중 — 환자 정보 없음"). 보드에는 전체 재원 목록을 넘긴다. |
| 5 | 간호기록 시각을 `slice(11,16)`·`slice(0,10)` 로 잘랐다(UTC — 9시간 어긋남, 새벽 기록이 전날 칸). | `kdate`·KST 날짜 키. |
| 6 | 간호기록 목록 조회 실패가 "기록 없음"으로 보였다. | `isError` → `QueryErrorFallback`. |
| 7 | QA 점검 **요청 실패**를 "비활성"으로 말했다. | 실패는 실패로 말한다. 저장에는 영향이 없다고 밝힌다. |
| 8 | 활력·I/O·간호기록 입력창이 **첫 환자로 시작**했다. 고르지 않고 저장하면 엉뚱한 환자에 붙었다. | 미선택으로 시작하고, 고르기 전에는 저장할 수 없다. |
| 9 | 담당 배정 해제가 수동뿐이었고, 중복 활성이 생겼고, 근무조가 없었다. | `admission.closed` 를 받으면 해제한다. **병동이 바뀌는 병상 이동**은 전실 정본(`transferBedInTx`)이 같은 트랜잭션에서 해제한다(같은 병동 전실은 유지). 배정은 멱등으로 처리하고 재원 중인 환자만 받는다. 해제는 조건부다. 화면이 근무조를 보낸다. `assignments/my` 는 재원 중인 환자만 준다. |
| 10 | 인계 작성자를 화면이 보냈다. | 컨트롤러가 `@CurrentUser` 로 덮는다(본문 값은 무시하고 DTO 에서는 선택값). |
| + | 호흡수만 이상 표시 규칙이 없었다(`a: false`). | shared `news2ItemScore('rr')` — NEWS2 호흡수 밴드(정상 12~20) 밖이면 표시한다. |

## 3. 교대 기능
### 교대 창 정본(shared `shiftWindowAt`)
- 시각 → 교대와 그 교대의 [시작, 끝)을 **병원 표준시(KST)** 로 계산한다. 경계는 config `nursing.shift.boundaries`, 기본은 7/15/23이다.
- `shiftOf` 는 실행 환경 시간대(`getHours`)에 기댄다. 운영 서버는 현재 KST(2026-09-30 실측)라 맞지만 서버 판정에는 이 함수를 쓴다.
- 부수 봉합: `handoffs/next-shift-nurses` 가 NIGHT 자정 이후(0~7시)에도 "익일"을 더해 **모레** 근무표를 봤다. 이제 이번 근무조가 끝나는 시각의 날짜를 본다.

### 늦은 기록(shared `isLateNursingEntry`)
- 간호기록 입력에 **관찰 시각**(비우면 지금)을 넣었다. 시각을 고르면 근무조가 따라간다. 미래 시각은 400 `NOTE_RECORDED_AT_FUTURE` 이고, 허용 오차는 5분이다.
- 늦은 기록 = 관찰 시각이 속한 근무조가 **끝난 뒤에** 작성된 기록이다. **막지 않는다**(늦게라도 적는 편이 낫다).
- 목록 응답에 `lateEntry` 를 **파생**해 싣는다. 컬럼에 저장하지 않는다. 경계 설정이 바뀌면 저장된 판정과 갈라지기 때문이다. 스키마 변경은 없다.

### 근무조 마감(하번) — `GET /api/v1/nursing/shift-closeout` (NURSE·ADMIN)
- 내 활성 담당(재원 중) 환자별로 이번 근무조에 남긴 것을 모은다: 내 간호기록(다른 간호사 기록 수·내 미서명 수 별도)·활력·I/O·투약(근무조 시작~지금 예정분 중 미기록)·내가 쓴 인계(인수자·확인 여부).
- **기록 유무만** 센다. 충분한지는 판정하지 않고, 화면도 그렇게 말한다. 막지 않는 줄어드는 목록이다.
- 담당이 0이면 `assignments: 0` 과 빈 목록을 준다. 화면은 이를 "모두 완료"로 그리지 않고, 배정이 없다고 이유와 함께 말한다.
- 화면: '근무조 마감' 탭에서 [기록 화면]·[MAR]·[인계 쓰기]를 누르면 인계 탭에 그 환자를 골라 둔다.

### 상번 인수 — `POST /api/v1/nurse-station/assignments/take-over` (NURSE·ADMIN)
- 인수자는 로그인 사용자다. 그 입원의 **다른 간호사** 활성 배정은 같은 트랜잭션에서 해제된다. 이미 내 것이면 그대로 둔다.
- 화면의 받은 인계에 [인수 확인 + 담당 인수] 버튼이 있다(간호 교대 인계 `NURSING_SHIFT` 에만). **확인이 먼저**이고, 확인이 실패하면 담당을 넘기지 않는다. 담당 인수가 실패하면 "확인은 기록됐다"고 그대로 말한다.
- 자동으로 넘기지 않는다. 인수자가 누를 때만 넘긴다.

## 4. 후속(2026-10-01) — 늦은 기록 유예·활력 이상 표시 기준
### 늦은 기록 유예
- config `nursing.lateEntry.graceMinutes`(0~720 정수 · 기본 `null` = **미설정**). 미설정이면 유예 0, 즉 근무조 종료 시각으로 판정하고 화면은 "유예 규정 미설정"이라 밝힌다. 0분을 규정인 척하지 않는다.
- 서버 `lateEntryRule()` 이 판정 기준을 주고, 간호기록 목록 응답은 `meta.lateEntryRule` 을 싣는다. 판정은 파생값이라 규정이 바뀌면 과거 기록도 다음 조회부터 새 기준으로 표시된다.
- 값은 사람이 정한다. 등록부 키는 `nursing.lateEntry.graceMinutes`(배치 S)이고 선택지는 미설정·30분·60분이며, 설정만 바꾸면 된다.
- 설정 조회가 실패하면 기본값으로 바꿔 말하지 않고 전파한다. 화면은 조회 실패와 미설정을 갈라 말한다.

### 활력 이상 표시 기준 — 화면 하드코딩 회수
- 🔴 간호 스테이션이 임계 숫자(SBP>140·HR>100·BT>38·SpO2<95·통증≥7)를 화면에 따로 적어 두었다. 정본(`vitals-evaluate.VITALS_THRESHOLDS` + 환자안전위 개정 표면 `clinical.vitals.thresholds`) 옆의 **4번째 정본**이었다. 개정해도 이 화면만 옛 기준이었다. 9-30에 넣은 호흡수 NEWS2 밴드도 같은 잘못이라 회수했다.
- 서버 `vitalItemFlags()` 가 항목마다 `CRITICAL`(위급 역치)·`WARNING`(주의 역치)·`NORMAL`·`null`(미측정) 중 하나로 판정한다. `GET nurse-station/vitals/patient/:id` 가 행마다 `flags` 를, `meta.vitalsRule` 에 출처(`CONFIGURED`=개정 반영 / `DEFAULT`=코드 기본값)와 버려진 개정 키를 싣는다. 화면은 그것을 색(위급 빨강·주의 주황)과 기준 출처 한 줄로 그린다.
- 🔴 **같이 드러난 계약 결함(P11)**: 화면이 서버에 없는 `bodyTemperature`·`spO2`·`recordedAt` 을 읽었다. 간호 스테이션의 **체온·SpO2 는 늘 '-'** 였고, 시각은 측정 시각이 아니라 저장 시각이었다. 서버 이름(`temperature`·`spo2`·`measuredAt`)으로 바로잡았다.

## 5. 남은 것
- 근무조 마감 **알림**(교대 30분 전 등)은 없다. 목록만 있다.
- 담당 배정 해제 사유(퇴원·전동·인수·수동)를 구분해 남기는 칸이 없다. 해제 시각만 남는다.
- 다른 화면(입원 상세·PACU 등)에도 임계를 화면에 적은 곳이 있는지는 이번 범위 밖이다(`lib/vital-flags.ts` 규약: 화면에 임계 숫자를 새로 적지 말 것).
