# 원외처방전 발급·진위 확인 — 전자 전송은 사람 결정 (2026-09-30)

> 요청: "원외처방전 전자 전송 진행해". 출발점: 의사 업무 점검(2026-09-30) 남은 항목.

## 1. 실측
- 인쇄물 하단: "이 처방전은 전자처방전입니다 · 위·변조 확인은 하단 QR로 검증하십시오" — **QR 이 없었다**(이전 교정에서 없는 경로라 걷었다) · **약국 전송 코드도 없다**. 거짓 안내였다.
- 교부번호 `RX-<진료일>-<진료 id 끝 6자>` 는 인쇄할 때 계산만 했다 — 어디에도 기록되지 않아 확인할 수 없는 번호.
- 발급 원장(`issued_documents`)·공개 진위 확인(`/verify/document/<번호>`)은 이미 있었다. 다만 범용 발급 EP 는 **화면이 보낸 스냅샷**을 해시해 임의 내용이 진짜 번호를 받을 수 있었고, 공개 확인은 기관명을 상수('위루비병원')로 박았다.
- 국내에는 병원→약국 공용 전송망이 없다. 전송은 제3자 전달 서비스·팩스 등 경로 선택과 법률 검토가 필요하다(조문·사업자는 이 문서에 적지 않는다 — 확인 필요).

## 2. 설계
- 전송 채널 선언 `EPRESCRIPTION_CHANNEL`(implemented: false) — 관제 `/admin/outbound-channels` 에 "미구현"으로 · 어떤 코드도 '전송 완료'를 적을 수 없다.
- `POST /api/v1/encounters/:encounterId/prescription-issue`(의사·간호사·원무·관리자):
  - 서명된 진료(SIGNED·AMENDED)만 · 약 없으면 409
  - 스냅샷은 **서버가 DB 에서** — 인쇄 대상과 같은 집합(원외 있으면 원외만) · 결정적(같은 내용 = 같은 해시)
  - 같은 내용 재인쇄 = 같은 번호 · 내용이 바뀌면 새 번호 + 이전 발급 `SUPERSEDED`(공개 확인에서 무효)
  - 응답 `transmission{implemented:false, transmitted:false, transmittedAt:null, reason}` — 나가지 않았다고 말한다
- 공개 확인: `SUPERSEDED` 무효 · 기관명은 설정 `hospital.name`(없으면 null)
- 인쇄: 교부번호 = 발급 원장 '년 월 일 제 호' · QR·발급번호 · "종이 처방전 — 약국으로 전자 전송되지 않았습니다" · 발급 실패는 "교부번호 없음"(지어내지 않는다) · 교부일 = 발급 시각

## 3. 사람 결정(등록부 배치 P · `decision.registry.batch-2026-09-p.ts`)
- `rx.external.transmission`(허가권자) — 종이만 / 전달 서비스 연동 / 환자 앱으로만
- `rx.external.verifyDisclosure` — 공개 확인이 약품·수량까지 보일지(현행 발급 정보만 → 내용 위조는 확인 불가)

## 4. 남은 것
- 전송 결정 후: 전송 함수·환자 동의·약국 선택(환자 지정)·전송 결과 원장(대외 발신 3조건)
- 환자 포털에 처방전·QR 제공(결정 PATIENT_APP 일 때)
