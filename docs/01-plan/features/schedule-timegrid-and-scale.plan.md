## 1. 목적 · 배경

현행 `/schedule`은 **주간(7일 카드 스택)·월간(셀당 3건+‘+N’)·목록(아젠다)** 3뷰다. 예약이 늘면:
- 하루 100명이면 주간 뷰 1개 열에 카드 100장 → 스크롤 지옥, 시간 파악 불가.
- "언제(시간대) 누가(의사/진료실) 얼마나 차 있나"를 한눈에 볼 수단이 없다.

두 가지를 보완한다: **(A) 시간별 타임그리드 뷰**(시간축 × 의사/진료실 레인), **(B) 하루 100명 규모에서의 성능·가독성 해소 전략**.

## 2. 현황 진단 (As-Is)

| 뷰 | 대량(100/일) 시 문제 |
|---|---|
| 주간 | 한 날짜 열에 카드 수십~100장 세로 적층. 시간 정렬은 되나 밀도·스캔 불가 |
| 월간 | 셀당 3건 미리보기+‘+N’ — 상세는 못 봄. 시간대 파악 불가 |
| 목록 | 시간순 아젠다는 낫지만 100행 단일 스크롤·의사/진료실 병렬 비교 불가 |
| 공통 | **시간대별 혼잡도·의사별 부하·정원 소진**을 시각화하는 뷰 없음 |

데이터는 이미 `GET /appointments/calendar`(주/월 범위)로 오나, **하루 단위 시간축 뷰**와 **집계(히트맵)**가 없다.

## 3. (A) 시간별 타임그리드 뷰 설계

### 3.1 개념 — Day View (리소스 타임그리드)
```
        │ 김순환(가정 1실) │ 박호흡(호흡 2실) │ 이일반(외과 1실) │ …(레인 스크롤)
 09:00  │ ▓09:00 홍길동    │                  │ ▓09:00 김…       │
 09:30  │ ▓09:30 이영희    │ ▓09:30 박…       │                  │
 10:00  │                  │ ▓10:00 …         │ ▓10:00 …         │
  ⋮     │  (30분 행)       │                  │                  │
```
- **세로축 = 시간**(근무 시간대만·기본 30분 행, config `schedule.grid.slotMinutes`).
- **가로축 = 레인**: 기본 **의사**, 토글로 **진료실** 기준. 과 필터 시 해당 과 레인만.
- **예약 블록**: `scheduledAt`~`+duration` 높이만큼 배치. 상태색(신청/확정/접수/진료중). 환자명·유형 표기(밀도 모드에 따라 축약).
- **겹침 처리**: 같은 레인 동시간 블록은 나란히 분할(더블부킹·오버부킹 시각 노출 — 안전).
- **현재시각 인디케이터**(빨간 라인) · 근무외/휴진 시간 음영 · 세션 경계선.
- **정원/혼잡 표시**: 레인 헤더에 `booked/max`(예: 12/30)·잔여 게이지.
- **빈 슬롯 클릭 → 그 의사·시간으로 예약 생성**(new 폼 프리필). 블록 클릭 → 상세/상태변경 팝오버.

### 3.2 레이아웃·상호작용
- 뷰 토글에 **‘일(시간별)’** 추가: 주간/월간/목록/**일**.
- 상단: 날짜 네비(◀ 오늘 ▶) + 과·의사·상태 필터(기존 재사용) + 레인 기준(의사/진료실) 토글 + 밀도(compact/comfortable).
- 레인 가로 스크롤(32의사·30진료실 → 과 필터로 좁히는 걸 권장·기본 안내).
- 드래그 이동/리사이즈(reschedule/duration)는 **P2 이후**(권한·검증 연계). P0는 조회+클릭 생성.

## 4. (B) 하루 100명 규모 해소 전략

### 4.1 데이터·렌더 성능
- **서버 범위 쿼리**: 일 뷰는 `date` 1일치만(이미 buildWhere KST 경계). 100건이면 페이로드 작음 → 클라 렌더가 관건.
- **가상화(windowing)**: 레인/시간 그리드가 커지면 보이는 영역만 렌더(react-window 등). 100건·32레인×근무행에서 DOM 폭증 방지. (P3 성능 단계)
- **집계 API 분리**: 카드 상세와 별개로 **시간대별 count**만 받는 경량 EP(히트맵·미니맵). 상세는 지연 로드.

### 4.2 가독성·밀도
- **밀도 모드**: compact(막대만·툴팁)/comfortable(환자명+유형). 100건은 compact 기본.
- **레인 축소**: 과 필터 미적용 시 32레인 → "과를 선택하세요" 유도 + 상위 N레인만. 진료실 기준 토글로 30레인.
- **‘+N 더보기’ 대신 겹침 분할**: 같은 슬롯 다건은 블록 분할·카운트 배지.
- **미니맵/타임 히트맵**: 하루를 가로 막대로 압축, 시간대별 혼잡(색농도) → 클릭 시 해당 시간 스크롤.

### 4.3 필터·검색 (대량 탐색)
- 과·의사·상태·**시간대(오전/오후/시간범위)**·환자명/MRN 검색. 서버 필터(findAll 이미 지원)로 좁혀 렌더량 축소.
- "확정 대기(SCHEDULED)만", "노쇼 위험(임박·미접수)" 등 **스마트 필터 프리셋**.

### 4.4 집계·운영 인사이트 (혼잡 해소 의사결정)
- **시간대별 히트맵**(과/의사×시간): 어디가 몰리는지 → 근무·정원 조정 근거.
- **정원 소진 경고**: 세션 booked≥max·임계(예 80%) 레인 강조 → 오버부킹 방지·대기자 유도.
- **부하 상위 의사/과 리스트**: 재배정·증설 판단.

### 4.5 부하 분산 (이미 구현분 연계)
- **부하분산 자동배정**(resolveDoctorByLoad)·**가용 슬롯**·**대기자명단(취소 시 자동안내)**·**정원 게이트**(enforce.capacity)는 이미 있음 → 대량 상황에서 **정원 초과를 WARN/BLOCK**·**만석 시 대기 등록**으로 유입을 분산. 본 기획의 뷰가 이를 **가시화**.
- **오버부킹 정책 시각화**: 게이트 WARN/BLOCK 상태를 레인/슬롯에 배지로.

## 5. 백엔드 지원

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/appointments/day?date=&groupBy=doctor\|room&departmentName=` | 일 뷰용 — 레인(의사/진료실)별 예약 + 근무세션(시간범위·정원·booked) 묶음 반환. 기존 availability+calendar 로직 재사용 |
| GET | `/appointments/heatmap?date=&by=hour&departmentName=` | 시간대별 count(혼잡 히트맵). groupBy raw 집계 |
| (기존) | `/appointments/calendar`·`/availability`·`/stats` | 재사용 |

- `day` EP는 근무세션(레인·시간범위·max)과 그 안의 예약을 함께 줘 클라가 그리드를 바로 그림(availability의 세션 + 그 세션의 실제 예약 목록 결합).
- KST 슬롯 정렬은 기존 규약(`+09:00` 명시·@db.Date UTC자정) 준수.

## 6. 프론트엔드 설계 요약
- 뷰 토글에 ‘일’ 추가 → `DayTimeGrid` 컴포넌트(시간행 × 레인열, absolute 블록 배치).
- 블록 배치: `top = (start - dayStart)/slot * rowH`, `height = duration/slot * rowH`. 겹침은 레인 내 열 분할.
- 히트맵/미니맵 컴포넌트(상단). 밀도·레인기준·필터 컨트롤 바.
- 모바일: 일 뷰는 단일 레인(선택 의사)·시간 스크롤로 축약.

## 8. 리스크 · 함정
- **레인 폭증(32의사/30진료실)**: 과 필터 없이는 가로 스크롤 과다 → 기본 "과 선택" 유도 + 상위 N.
- **겹침/더블부킹 시각화**: 블록 분할로 노출(숨기지 말 것 — 안전). TOCTOU 더블부킹(기존 이연)이 여기서 보임.
- **KST/DST 없음**: 슬롯·행 계산은 `+09:00` 고정 오프셋(기존 규약).
- **성능**: 100건×수십레인 DOM. compact 기본 + 가상화(P3)로 대응. 초기엔 과 필터로 렌더량 제한.
- **드래그 이동(P3)**: reschedule 검증(충돌/정원)·권한·낙관적 업데이트 롤백 주의.

## 9. 수용 기준
1. ‘일(시간별)’ 뷰에서 시간축×의사 레인으로 하루 예약을 시각·정원과 함께 확인한다.
2. 하루 100건에서 과 필터·compact로 스크롤 없이 시간대 혼잡을 파악한다.
3. 빈 슬롯 클릭으로 해당 의사·시간 예약 생성이 프리필된다.
4. 시간 히트맵으로 몰리는 시간대를 식별, 정원 소진 레인이 경고된다.
5. 전 기능이 기존 주간/월간/목록과 병존(회귀 없음).
