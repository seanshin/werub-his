### Phase 2: 진료 레이아웃 추가 (B-1 ~ B-4)

#### 2.5 외과 진료 레이아웃 (SurgeryEncounterLayout) — ✅ 구현 완료

4탭: SOAP + 수술 예약 + Op Note + WHO 체크리스트

> **수술 이력 탭(A-3) vs 외과 진료 레이아웃(B-1) 역할 구분:**
> - **수술 이력 탭** (환자 차트 `/patients/:id`): 전체 수술 이력 **조회** 전용 (모든 진료과에서 접근)
> - **외과 레이아웃** (진료 `/encounter/new`): 수술 **예약/기록** — 외과 의사가 진료 중 사용
> - 같은 데이터(Surgery 모델)를 다른 관점에서 표시

#### 2.6 응급의학과 진료 레이아웃 (EmergencyEncounterLayout)

```
5탭:
1. 트리아지 — KTAS 분류 (1~5등급), 내원 사유, 증상 기록
2. 초기 평가 — ABCDE 평가, 바이탈, GCS, 외상 점수
3. 처치 — 응급 처치 기록, 오더, 약물 투여
4. 경과 — 시간별 경과 기록 (타임라인 형태)
5. 처분 — 입원/전원/귀가 결정, 관찰 지시
```

#### 2.7 가정의학과 진료 레이아웃 (FamilyMedicineEncounterLayout)

```
4탭:
1. SOAP + 진찰 — 기본 SOAP + 바이탈
2. 건강검진 — 일반검진/암검진 결과 입력/조회
3. 생활습관 — 흡연/음주/운동/식습관/수면 평가 + AUDIT-C/FTND
4. 예방의학 — 예방접종, 암 검진 이력, 건강위험평가(HRA)
```

#### 2.8 재활의학과 진료 레이아웃 (RehabEncounterLayout)

```
4탭:
1. SOAP + 진찰 — 기본 SOAP
2. 기능 평가 — Barthel/FIM/MMT/ROM 입력 + 추이 차트
3. 치료 계획 — PT/OT/ST 세션 계획 생성
4. 경과 — 치료 세션 이력 + 기능 회복 추이
```

#### 2.11 바이탈→진료 차트 연동 (PreVisitVitals)

encounter/new 페이지에서 해당 환자의 PreVisitVitals를 자동 조회:
- Objective 영역 상단에 바이탈 카드 표시 (읽기 전용)
- 이상 바이탈 빨간 배경 강조
- "바이탈 없음" 시 간호사에게 요청 알림

## 3. API 현황 및 필요

### 기존 API (활용 가능)

| 기능 | API | 상태 | 주의사항 |
|------|-----|------|---------|
| 바이탈 (외래) | `GET /api/v1/nurse-station/vitals/:queueId` | ✅ | queueId 기반 — 환자별 이력 조회 불가 |
| 바이탈 (ICU) | `GET /api/v1/admissions/:id/icu-records` | ✅ | admissionId 기반 |
| 처방 이력 | `GET /api/v1/encounters/:encounterId/prescriptions` | ✅ | **encounter 기반만** — 환자별 전체 조회 없음 |
| 수술 이력 | `GET /api/v1/surgery/schedule` | ✅ | 전체 목록 — patientId 필터 추가 필요 |
| 수술 상세 | `GET /api/v1/surgery/:id` | ✅ | - |
| 입퇴원 | `GET /api/v1/inpatient` | ✅ | **전체 목록만** — patientId 필터 없음 |
| 퇴원 요약 | `GET /api/v1/discharge-summary/:id` | ✅ | admissionId 기반 |
| 간호 기록 | `GET /api/v1/admissions/:id/nursing-notes` | ✅ | admissionId 기반 |
| 응급 | `GET /api/v1/emergency/visits` | ✅ | patientId 필터 확인 필요 |

### 신규 API 필요

| # | API | 설명 | 필요 이유 |
|---|-----|------|----------|
| 1 | `GET /api/v1/vitals/patient/:patientId` | 환자 전체 바이탈 이력 (외래+입원+응급 통합) | PreVisitVitals는 queueId 기반, 환자별 이력 없음 |
| 2 | `GET /api/v1/prescriptions/patient/:patientId` | 환자 전체 처방 이력 (활성+완료) | 현재 encounter 기반만 존재 |
| 3 | `GET /api/v1/prescriptions/active/:patientId` | 활성 처방만 + 약물 상호작용 캐시 | 투약 이력 탭 + 개요 탭용 |
| 4 | `GET /api/v1/inpatient/patient/:patientId` | 환자별 입퇴원 이력 | 현재 전체 목록만 존재 |
| 5 | `GET /api/v1/patients/:id/summary` | 환자 종합 요약 (개요 탭용) | 바이탈+처방+문제+검사+일정+탭 데이터 유무 플래그 |

> **약물 상호작용 캐싱 전략:**
> 처방 변경 시에만 `POST /api/v1/ai/drug-interactions` 호출 → 결과를 DB에 캐싱.
> 차트에서는 캐싱된 결과만 표시 (AI 서버 비용/속도 문제 방지).

> **탭 동적 표시 전략:**
> `GET /api/v1/patients/:id/summary` 응답에 플래그 포함:
> `{ hasSurgeries: true, hasAdmissions: false, hasVitals: true, ... }`
> → 데이터 없는 탭은 숨기되, 개별 API 호출 없이 1회 요청으로 판단.

## 6. 연관 시스템

| 시스템 | 연동 포인트 |
|--------|------------|
| nurse-station | PreVisitVitals → 바이탈 이력 + encounter 연동 |
