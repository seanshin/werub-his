## 1. 현재 상태

현재 사망 처리는 단순 `isDeceased: true` 플래그 토글만 수행.
법적/의료적으로 필요한 프로세스가 누락되어 있음.

---

## 2. 사망 처리 전체 프로세스

```
사망 확인 (의사)
    │
    ├─ 1. 사망 시간 기록
    ├─ 2. 사망 원인 기록 (직접/간접/선행 사인)
    ├─ 3. 사망 진단서 작성
    │     ├─ 사망의 종류 (병사/외인사/기타)
    │     ├─ 사인 체인 (가→나→다→라)
    │     └─ 사망 장소/상황
    ├─ 4. 법적 문서 발급
    │     ├─ 사망 진단서 (의사 서명)
    │     ├─ 시체 검안서 (외인사 시)
    │     └─ 사망 통계 신고서 (통계청)
    ├─ 5. 후속 처리
    │     ├─ 진행 중 처방 전체 중단
    │     ├─ 예약 일괄 취소
    │     ├─ 입원 중이면 퇴원 처리
    │     ├─ 장례식장 안내 (해당 시)
    │     └─ 보호자 연락처 확인
    └─ 6. 행정 처리
          ├─ 사망 신고 안내 (구청/읍면동, 1개월 내)
          ├─ 보험 청구 마감 처리
          └─ 의무기록 봉인 (수정 불가)
```

## 4. 데이터 모델 확장

```prisma
// 기존 Patient 모델에 추가 필드
model Patient {
  // ... 기존 필드
  isDeceased        Boolean   @default(false)
  deceasedAt        DateTime? // 사망 일시
  deceasedInfo      Json?     // 사망 정보 (JSON)
  // deceasedInfo 구조:
  // {
  //   location: 'HOSPITAL' | 'ER' | 'OR' | 'OTHER',
  //   deathType: 'NATURAL' | 'EXTERNAL' | 'OTHER',
  //   causeChain: { a: string, b?: string, c?: string, d?: string },
  //   confirmedBy: string (userId),
  //   confirmedAt: string (ISO),
  //   checklist: {
  //     prescriptionsStopped: boolean,
  //     appointmentsCancelled: boolean,
  //     discharged: boolean,
  //     guardianNotified: boolean,
  //     certificateIssued: boolean,
  //   }
  // }
}
```

## 5. 필요 API

| Method | Endpoint | 설명 |
|--------|----------|------|
| POST | `/api/v1/patients/:id/deceased` | 사망 처리 (정보 포함) |
| GET | `/api/v1/patients/:id/death-certificate` | 사망 진단서 PDF |
| POST | `/api/v1/patients/:id/deceased/stop-all` | 진행 처방 전체 중단 |
| POST | `/api/v1/patients/:id/deceased/cancel-appointments` | 예약 일괄 취소 |

## 6. 구현 우선순위

| Phase | 내용 | 예상 |
|:-----:|------|:----:|
| 1 | 사망 정보 입력 모달 (시간/장소/종류/사인) | 2h |
| 2 | 체크리스트 + 자동 처리 (처방중단/예약취소) | 2h |
| 3 | 사망 진단서 PDF 생성 | 3h |
| 4 | 의무기록 봉인 + 감사 로그 | 1h |
