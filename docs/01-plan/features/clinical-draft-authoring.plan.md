실측: 병렬 에이전트 5기(진료·경과 / 간호 / 수술·마취 / 판독·병리·동의서 / 증명서·보고) +

## 0. 한 줄

**초안은 이미 세 군데에서 제대로 돌고 있다. 그런데 자유 텍스트가 가장 많은 기록들이 그것을 못 쓴다.**
그래서 이 기획은 신설이 아니라 **선례 하나를 정본으로 삼아 전 영역에 배선하는 일**이다.

---

## 1. 전 영역 실측 (2026-08-26)

판정은 **4분류**다 — (a) 서버에 미완성 저장 · (b) 임시저장/자동저장 UI · (c) 클라이언트만 · (d) 없음.

### 1.1 ✅ 초안이 실제로 동작하는 것 (8)

| 기록 | 저장소·상태 | 비고 |
|---|---|---|
| 외래 진료기록(SOAP) | `Encounter` `DRAFT·SIGNED·AMENDED` | 진입 즉시 DRAFT 생성 + "저장(임시)" · **자동저장 없음** |
| 마취전평가 | `PreAnesthesiaEvaluation` `DRAFT·COMPLETED` | 🔴 **가장 완성된 선례** — 임시저장 버튼 + 필수요소 검증 후 확정 + 확정 후 수정 불가 |
| 퇴원요약 | `DischargeSummary` `DRAFT·SIGNED·AMENDED` | 🔴 **저장 후 재편집 불가**(§3-4) |
| 병리 판독 | `PathologyReport`(미서명=초안) | `diagnosis` 필수라 **진단 미정 상태로는 저장 불가** |
| 검진 종합소견 | `CheckupSummary`(미서명=초안) | "소견 저장" / "저장+서명" 분리 · 4-eyes |
| 검진 설명문 | `CheckupExplainerContent` `DRAFT·IN_REVIEW·APPROVED` | 승인본 재수정 시 DRAFT+version+1 |
| RCA 보고서 | `RcaReport` `OPEN·IN_PROGRESS·COMPLETED·APPROVED` | "RCA 내용 저장" |
| 약물이상반응(ADR) | `AdverseReactionReport` 기본 `DRAFT` | 🔴 **DRAFT 수정 EP 없음**(§3-5) |

### 1.2 🔴 초안 저장소는 있는데 **화면이 안 부르는 것** (7) — "만들었는데 작동한 적 없는 것"

| 기록 | 있는 것 | 없는 것 |
|---|---|---|
| **간호기록** | `NursingNote.status DRAFT` · DTO `draft?: boolean` · 서비스 분기 | **`draft:true` 전송 0건**(web·mobile 전수) + **DRAFT 수정 EP 없음**(§3-3) |
| **의뢰서** | `ReferralLetter DRAFT` · `PUT :id`(DRAFT만 수정) | 그 PUT 을 부르는 화면 0건 — AI 생성 초안을 **고칠 방법이 없다** |
| **법정감염병 신고** | `NotifiableDiseaseReport DRAFT` · `POST` EP | 작성 화면 없음(목록·제출만) |
| **PACS 판독 리포트** | 외부 OpenPACS `DRAFT/PRELIMINARY/FINAL` · 프록시 `POST/PATCH` | HIS 화면이 안 부름 — 초안 작성기 없음 |
| **마취기록** | `AnesthesiaRecord` · `POST/PATCH` EP | 🔴 **작성 화면 0개**(초안 이전에 작성 자체가 없다) |
| **경과기록(입원)** | `ProgressNote` · `POST` EP | 작성 화면 0개 · 모델에 status·signedAt 자체가 없음 |
| **검진 과별 판독** | `CheckupInterpretation REQUESTED·IN_REVIEW·COMPLETED` | 화면 0개 · `IN_REVIEW` 전이 코드 확인 못 함 |

### 1.3 ❌ 초안이 없어 **닫으면 사라지는 것** — 자유 텍스트가 많은 순

| 기록 | 자유 텍스트 칸 | 지금 |
|---|---:|---|
| **수술기록**(본체+OpNote) | **12** | 저장 버튼이 "수술 완료 + Op Note 저장" 하나 · 완료 후 수정 EP 없음 |
| 간호기록 화면(DAR/SOAP/SBAR) | 14 | (1.2 참조 — DRAFT 가 도달 불가) |
| 동의서 설명부 | 4 | 생성 후 설명문 수정 EP 없음 |
| **사망진단서** | 4+ | 🔴 게다가 **입력 3종이 저장되지 않는다**(§3-1) |
| 직원 노출사고 보고 | 3 | |
| 영상 판독소견서 | 3 | 모달 배경 클릭이면 소실 · 정정/addendum 경로 없음 |
| 협진 회신 · 전원 소견서 · 인수인계(4) · ICU 경과 · UniversalNursingNote(SBAR) · PACU · 플로우시트 · I/O · 간호 초기평가 · 간호계획 · 사고보고 | 1~4 | 전부 (d) |

**(c) 클라이언트만**: WHO 수술안전 체크리스트 계수 입력(`useState`).

### 1.4 횡단 사실

- 🔴 **"임시저장" UI 문구가 존재하는 화면은 진료기록(SOAP) 계열뿐**이다(전수 grep).
  간호·수술·판독·증명서·보고 계열에는 **한 개도 없다**.
- 🔴 **자동저장(debounce/interval 서버 저장)은 전 화면에 0건.** 전부 수동이다.
- 🔴 **암호화 초안 캐시가 이미 있는데 아무도 안 쓴다** — `TerminalDraftService`
  (Redis · AES-256-GCM · 소유자 전용 · TTL 기본 1800초 · `POST/GET /api/v1/terminal/draft` ·
  web 헬퍼 `saveDraft`/`restoreDraft`) → **소비처 각각 0건**.
- 산재·자보·장애진단서 서식은 **코드에 존재하지 않는다**(보험 종별 코드와 혼동 금지).
- `Prisma` 에 범용 `*Draft` 모델은 **없다**. 초안은 각 모델의 `status` 로 표현돼 왔다.

### 1.5 개인 설정·상용구·양식 — 초안을 **무엇으로 채울 것인가**

초안 기능이 붙어도 **매번 처음부터 타이핑한다면 절반만 해결**이다. 그 자리를 실측했다.

| 층 | 저장소 | 소비처 실측 | 판정 |
|---|---|---|---|
| **원내 표준 차트 양식** | `ChartTemplate`(+`ChartTemplateVersion`) | API 7 · web 10 · 편집기 `/admin/chart-editor` | ✅ **동작한다** |
| 진료과 진료 템플릿 | `EncounterTemplate` | API 5 · **web 1 = DEPRECATED 안내 화면** | 🔴 **폐기 경로** — 차트 에디터로 통합됨(데이터만 보존) |
| **개인 상용구(매크로)** | `TextMacro`(userId·shortcut·content·isShared) + EP 4종 | 🔴 **web 소비처 0** | **EP만 있음** |
| **개인 차트 선호**(기본·최근·즐겨찾기 템플릿) | `UserChartPreference` | 🔴 **API 0 · web 0** | **아무도 읽지도 쓰지도 않는다** |
| 음성 상용구 | `VoiceCustomPhrase`(ALIAS/HABIT/VOCAB/MACRO) | **서버는 실제로 쓴다**(voice-emr 가 조회·hitCount 증가) · CRUD EP 4종 · **web 0** | 🔴 **쓰이는데 만들 화면이 없다** — 사용자가 자기 어휘를 등록할 방법이 없어 사실상 빈 테이블 |
| 간호 상용구 | 🔴 `localStorage['nursing.quickPhrases.v1']` | 화면 1 | **개인 서버 모델이 있는데 클라이언트 사본을 따로 만들었다**(P12) |

🔴 **개인화 층은 사실상 전부 죽어 있다.** 모델과 EP 는 있는데 화면이 없고,
없는 자리를 간호가 localStorage 로 메웠다 — **단말을 바꾸면 사라지고, 다른 직원과 공유되지 않는다.**

## 2. 초안은 한 가지가 아니다 — 세 층으로 나눈다

실측해 보니 "초안"이라는 한 단어가 **성격이 다른 셋**을 가리키고 있었다. 섞으면 설계가 틀어진다.

| 층 | 무엇을 막나 | 수명 | 저장소 | 지금 상태 |
|---|---|---|---|---|
| **L1 유실 방어** | 창을 닫거나 단말이 잠겨 쓰던 게 날아가는 것 | 분~시간 | **이미 있는 Redis 암호화 캐시** | 🔴 만들어졌고 **아무도 안 부름** |
| **L2 이어쓰기** | 오늘 쓰다 만 것을 이따가/내일 이어 쓰는 것 | 일 | 각 모델 `status=DRAFT` | 8곳 동작 · 7곳 도달 불가 |
| **L3 미리 작성** | 발급·요청이 오기 전에 **먼저** 써 두는 것 | 일~주 | 그 문서의 작성 저장소 | 진단서 계열만 해당 · **입구가 없음** |

- **L1 은 전 화면 공통 부품**이다(무엇을 쓰든 날아가면 안 된다).
- **L2 는 기록별**이다(그 기록의 상태 모델을 따른다).
- **L3 는 증명서 계열에만** 해당한다(다른 기록은 "미리" 쓸 일이 없다 — 사건이 있어야 기록이 생긴다).

## 3. 🔴 실측하다 나온 실결함 — 초안과 별개로 지금 고쳐야 하는 것

> 이것들은 "초안이 없다"가 아니라 **틀렸다**. 초안 배선보다 먼저 판단이 필요하다.

1. **사망진단서 입력이 저장되지 않는다** — 코디네이터 재확인.
   DTO 는 `deathLocation`·`deathType`·`causeChain{a,b,c,d}` 를 받고 응답에도 실어 보내는데,
   `patient.update` 는 `isDeceased`·`deathDate`·`deathCause(=causeChain.a)` **셋만** 쓴다.
   `deceasedInfo` 객체는 **반환만 되고 어디에도 저장되지 않는다**(`patient.service.ts:645·702·705`).
   → 사망장소·사망종류·사인 (나)(다)(라)가 **사라진다.** 사망진단서는 법정 서식이다.
2. **미완료 차트 위젯이 남의 진료까지 센다** — `GET /encounters?status=DRAFT&mine=true` 를 부르는데
   `findAll` 은 `patientId·doctorId·page·limit` 만 처리한다(`encounter.service.ts:151`).
   **필터가 조용히 무시된다.** 게다가 재개 링크에 `encounterId` 가 없어
   **기존 DRAFT 를 이어받지 못하고 새 DRAFT 를 또 만든다** → 빈 DRAFT 누적(사후 purge 크론으로 덮고 있다).
3. **간호기록 DRAFT 는 도달 불가이고, 도달해도 이어쓸 수 없다** — `draft:true` 전송 0건 + DRAFT 수정 EP 없음.
4. **퇴원요약은 저장하면 다시 못 고친다** — 코디네이터 재확인.
   `inpatient/[admissionId]/discharge-summary` 는 재편집 진입이 "프리필" 경로에만 있고 그 버튼은
   저장 전에만 렌더된다. **다른 화면인 `workstation/discharge` 도 저장분이 있으면 읽기 전용**으로
   그리고 서명 버튼만 준다. 즉 **두 화면 어디에도 재편집이 없다.** `PUT` EP 는 있는데 아무도 안 부른다.
5. **ADR 보고는 DRAFT 로 저장되는데 수정 EP 가 없다** — 잘못 쓰면 제출하거나 버리는 수밖에.
6. **작성 화면 자체가 없는 기록 3종** — 마취기록 · 입원 경과기록 · 검진 과별 판독.
   🔴 **이것은 초안 문제가 아니라 미구현이다.** 빨간 경보로 섞어 그리면 진짜 경보가 묻힌다 —
   별도 항목으로 등재하고, 이 기획의 성과 지표에 넣지 않는다.

## 4. 설계

### 4.1 L1 — 유실 방어를 전 임상 쓰기 화면 공통으로

이미 있는 것을 배선한다. **새로 만들지 않는다.**

- 공통 훅 `useDraftGuard(key, value)` — 변경 시 디바운스 저장(`saveDraft`), 진입 시 `restoreDraft`.
- 🔴 **복원은 자동으로 덮어쓰지 않는다.** "작성 중이던 내용이 있습니다 — 불러오기/버리기"를 **묻는다**
  (자동 복원은 다른 환자의 내용을 밀어 넣을 수 있다).
- 🔴 **키에 환자·기록 식별자를 포함**한다. 지금은 `draft:${userId}` **하나**라 —
  A환자 SOAP 를 쓰다 B환자로 옮기면 **B의 화면에 A의 문장이 복원된다.** 키 설계 변경이 선행한다(§6-3).
  제안: `draft:v2:${userId}:${recordKind}:${scopeId}`(scopeId = encounterId·admissionId·surgeryId …).
  🔴 **환자 id 를 키에 그대로 넣지 않는다**(Redis 키는 로그·모니터링에 자주 노출된다) — `scopeId` 는
  진료·입원·수술 등 **이미 비식별에 가까운 내부 PK** 를 쓰고, 환자 대조는 값(암호문) 안에서 한다.
- 🔴 **구 키(`draft:${userId}`)는 읽지 않고 버린다.** 소비처가 0이라 살릴 내용이 없고,
  섞인 내용을 복원하면 그것이 곧 사고다(§7 P1 에 폐기 포함).
- 🔴 TTL·PHI: 이미 암호화·소유자 전용·TTL 이다. 값은 `terminal.draft.ttlSec`(기본 1800) —
  **연장 여부는 사람 결정**(§6-1).

### 4.2 L2 — `DRAFT` 계약을 하나로 정하고 도달 가능하게

**정본 선례 = 마취전평가**(`DRAFT·COMPLETED` + 임시저장 + 확정 검증 + 확정 후 수정 불가).
이 계약을 shared 에 문서화하고, 기록별로 아래 4가지를 **전부** 갖춘 것만 "초안이 있다"고 말한다.

1. 서버에 미완성 저장 EP 2. **DRAFT 수정 EP** 3. 화면의 임시저장 진입 4. 확정(서명) 게이트

지금 8곳 중 **4가지를 다 갖춘 곳은 마취전평가뿐**이다(퇴원요약 3번 결여, ADR 2번 결여 …).

### 4.3 L3 — 증명서 미리 작성 (요청이 오기 전에)

`DocumentRequest` 에 **원내 발의**를 추가해 기존 `author`/`sign`/`issue` 파이프라인을 그대로 쓴다.

```
DocumentRequest.origin  PATIENT | STAFF   (신설 · 기본 PATIENT)
DocumentRequest.status  DRAFT             (신설 · REQUESTED 앞)
```

- 진료 중 `📄 진단서` → **[초안 저장]** → `origin=STAFF, status=DRAFT` 로 요청 생성 → 기존 `author` 동작.
- 🔴 `origin=STAFF` 에는 **수수료·SLA·교부 흐름이 발동하지 않아야 한다**(착수 전 실측 필요).
- 환자가 나중에 실제로 신청하면 **기존 초안에 연결**한다(같은 `encounterId`+`type`).
- 🔴 **새 저장소를 만들지 않는다** — `IssuanceArtifact.authoredJson` 이 이미 작성 내용의 정본이다.

### 4.4 발급·확정 시 원천 재대조 (L3 의 핵심 안전장치)

초안 작성 이후 진단·기록이 바뀔 수 있다.

- 초안에 **원천 지문**(진단 코드 집합·`encounter.updatedAt`)을 함께 저장.
- 확정 시 지문을 다시 계산해 **다르면 막지 않고 차이를 보여준다**
  ("초안 작성 이후 진단이 바뀌었습니다: E78 → E78.0").
- 🔴 **막지 않는다**(막으면 우회한다) · 🔴 **조용히 덮지도 않는다**(그러면 옛 진단이 나간다) ·
  🔴 **안 바뀌었으면 조용하다**(거짓 경보는 진짜 경보를 죽인다).

### 4.5 작성 지원 편집기 — 의료진이 자기 어휘·구성을 직접 만든다

초안의 값은 **빈칸을 줄이는 데** 있다. 그래서 초안 기능과 **같은 축**으로 편집기를 넣는다.

**세 범위를 분리한다**(섞으면 개인 설정이 원내 표준을 덮는다):

| 범위 | 누가 만드나 | 저장소 | 지금 |
|---|---|---|---|
| **원내 표준** 양식·필수항목·용어 | 위원회·관리자 | `ChartTemplate`(+버전) | ✅ 편집기 있음(`/admin/chart-editor`) |
| **진료과/직군 공용** 문구·구성 | 과장·수간호사 | `TextMacro.isShared` · `EncounterTemplate` | 🔴 화면 없음 |
| **개인** 상용구·기본 양식·표시 구성 | 각 의료진 | `TextMacro`(userId) · `UserChartPreference` | 🔴 화면 없음(모델만) |

**신설: `/settings/my-templates`(가칭) — 개인 작성 설정 편집기**

1. **상용구**: 단축어 → 본문(`TextMacro`). 입력창에서 `;ekg` 같은 단축어로 펼친다(`expand/:shortcut` EP 이미 있음).
   - 🔴 **공유 전환은 명시적으로**(`isShared`) — 개인 문구가 조용히 과 전체에 퍼지지 않게.
2. **기본 양식·즐겨찾기**: `UserChartPreference`(기본 템플릿 · 최근 · 즐겨찾기) — **지금 아무도 안 쓰는 모델을 살린다.**
3. **구성(레이아웃)**: 그 기록에서 자주 쓰는 섹션 순서·접힘 상태. 🔴 **필수 항목은 숨길 수 없다**(§원칙).
4. **용어 선호**: 같은 개념의 표기 선택(예: 기록 서식 DAR/SOAP/SBAR). 🔴 **코드 값이 아니라 표시만** 바꾼다 —
   어휘 정본(shared)을 개인이 바꾸면 집계가 갈라진다.

**초안과의 접점**: 초안을 새로 열 때 개인 기본 양식으로 시작하고, 상용구는 **본문에 삽입될 뿐**
자동으로 저장되지 않는다(§원칙 "초안 ≠ 확정"은 그대로).

🔴 **하지 않을 것**: 개인 설정으로 **필수 항목을 끄는 것** · **원내 표준 문구를 개인이 덮어쓰는 것** ·
**상용구에 환자 정보를 넣는 것**(다른 환자 기록에 그대로 붙는다 — §9 참조).

### 4.6 파트별 초안 **샘플(견본) 세트** — 빈 화면에서 시작하지 않게

초안 기능이 있어도 **빈 화면**이면 결국 기억으로 쓴다. 파트별로 **무엇을 어떤 순서로 쓰는지**를
견본으로 제공한다.

#### 🔴 샘플은 "내용"이 아니라 "구조"다

이 저장소가 이미 크게 데인 자리다 — **쓰기 폼의 초기값이 `정상`·`명료`·`통증0` 이라
측정하지 않은 것이 정상으로 저장됐다**(간호 초기평가·Apgar `8`·수혈량 `320`).

그래서 샘플에 담는 것과 담지 않는 것을 못박는다:

| 담는다 | 담지 않는다 |
|---|---|
| 섹션 구성과 **순서** | 🔴 임상 값·소견 문장(정상·양호·특이사항 없음 …) |
| 각 칸의 **라벨과 단위** | 🔴 기본 선택된 라디오·체크 |
| **필수/선택** 표시 | 🔴 진단명·처치명 프리필 |
| **예시 문구**(회색 힌트 — 저장되지 않는다) | 🔴 힌트를 실제 값으로 저장하는 동작 |
| 그 파트의 **점검 항목**(빠뜨리기 쉬운 것) | 🔴 자동 체크된 점검 항목 |

→ **샘플을 고르면 빈 칸이 생기지, 값이 생기지 않는다.**

#### 파트 구분

| 파트 | 견본 예 | 저장소 |
|---|---|---|
| 진료과별 외래 SOAP | 내과 만성질환 재진 · 외과 창상 · 정형 통증 · 이비인후 등 | `EncounterTemplate`(진료과) + `ChartTemplate` |
| 수술 파트 | 술식군별 Op Note 뼈대(소견·술기·검체·계수·합병증) | `ChartTemplate` |
| 간호 파트 | DAR · SOAP · SBAR · 인수인계 · 교육기록 | `NursingChecklistTemplate`·`ChartTemplate` |
| 판독 파트 | 모달리티별 소견/결론/권고 뼈대 | `ChartTemplate` |
| 증명서 파트 | 진단서 용도별(보험·학교·직장) **용도 문구만**, 소견은 빈칸 | `IssuanceArtifact` 초안 |
| 보고 파트 | 사고보고·RCA·감염 신고 항목 뼈대 | `ChartTemplate` |

#### 운영 규칙

- **세 범위는 §4.5 와 같다** — 원내 표준(위원회) / 파트 공용(과장·수간호사) / 개인 변형.
- 🔴 **초기 제공분은 "원내 표준"이 아니다.** 시드로 넣은 견본이 표준인 척하면
  **시드가 정책을 정해버린다**(이 저장소의 반복 함정). 초기 세트는 **`검토 전` 표시**로 들어가고,
  위원회가 승인한 것만 표준이 된다.
- **어느 견본에서 시작했는지 기록한다**(`templateId`+버전) — 나중에 "이 양식이 빠뜨리게 했다"를 추적할 수 있게.
  🔴 단 **그것이 작성자 책임을 나누지 않는다**(기록의 책임은 사람이다).
- **견본은 필수 항목을 줄이지 못한다** — 원내 표준의 필수는 견본과 무관하게 강제된다.

### 4.7 기존 데이터를 어떻게 하나

- **빈 DRAFT 누적** — 지금은 `POST /encounters/purge-empty-drafts`(ADMIN·24h)로 사후에 지운다.
  P0 에서 재개 링크를 고쳤으므로 **새로 쌓이는 속도가 줄어든다**. 🔴 **크론을 끄지 않는다** —
  다른 경로(다른 화면에서 새로 만드는 것)가 남아 있는지 확인되기 전까지는 안전망이다.
- **이미 있는 DRAFT** — 상태 값은 그대로 두고 **이관하지 않는다**. L2 는 계약을 맞추는 일이지
  데이터를 바꾸는 일이 아니다(🔴 임상 기록을 코드로 교정하지 않는다).
- **간호 localStorage 상용구** — 서버(`TextMacro`)로 **1회 흡수 제안**을 화면에서 띄우고,
  🔴 **자동 업로드하지 않는다**(내용에 환자 정보가 들어 있을 수 있다 — 사람이 보고 올린다).

### 4.8 실패 모드와 되돌리기

| 실패 | 지금이라면 | 이 설계에서는 |
|---|---|---|
| L1 저장 실패(Redis 장애) | — | **조용히 실패한다**(작성은 계속). 🔴 단 화면 구석에 "임시 보관 중단됨" 표시 — 있는 척하지 않는다 |
| L1 복원 값이 현재 화면과 불일치 | — | 복원하지 않고 **묻는다**(§4.1) |
| L2 DRAFT 저장 실패 | 대부분 토스트 없이 소실 | 실패를 그대로 말하고 **입력을 지우지 않는다** |
| L3 초안이 원천과 어긋남 | — | 확정 화면이 차이를 보여준다(§4.4) · **막지 않는다** |
| 기능을 되돌려야 할 때 | — | L1·L3 는 **설정 게이트로 즉시 OFF**(기본 OFF 로 배포). L2 는 기록별 배선이라 되돌림 단위도 기록별 |

🔴 **기본 OFF 로 배포하고 파일럿 부서부터 켠다.** 임상 쓰기 화면 전체를 한 번에 바꾸지 않는다.

### 4.9 감사·보존 (초안도 PHI 다)

- **감사**: 변이는 기본 감사 ON 규약을 그대로 탄다. 🔴 **L1 캐시 저장은 감사하지 않는다**
  (초당 수십 건이 되어 원장을 덮는다) — 대신 **복원 시점**을 남긴다(누가 무엇을 되살렸는가).
- **보존**: L1 = TTL(설정) · L2·L3 = 확정될 때까지. 🔴 **자동 삭제는 두지 않는다**(§6-2 결정 전).
  대신 **오래된 초안 목록**을 작성자에게 보여준다 — 사라지는 알림이 아니라 **줄어드는 목록**.
- **열람**: 기본은 **작성자 본인**. 확장 범위는 §6-4 결정.

## 5. 원칙 (이 저장소의 규약에서 그대로)

- 🔴 **초안 ≠ 확정.** 화면이 그 사실을 말한다(`<DraftBanner>` 규약 재사용).
- 🔴 **초안에 발급번호·서명을 주지 않는다.** 발급번호는 발급의 증거, 서명은 확정의 증거다.
- 🔴 **초안도 PHI 다** — 감사 대상 · 열람 권한 · 보존기간.
- 🔴 **내용을 지어내지 않는다.** 자동채움은 **기록에 있는 것만**. 임상 판단(향후 소견 등)은 **비워 둔다**.
- 🔴 **대리 작성 금지.** 진단서는 진료한 의사가 쓴다(의료법 §17) — 기존 담당의 검증을 우회하는 입구를 만들지 않는다.
- 🔴 **초안 조회 실패를 "초안 없음"으로 번역하지 않는다.** 두 번 쓰게 되고, 두 번 쓴 기록은 서로 다를 수 있다.
- 🔴 **개인 설정이 원내 표준·필수 항목을 무력화하지 않는다.** 개인은 **표시와 순서**를 정하고,
  **무엇을 반드시 써야 하는가**는 원내 표준이 정한다.
- 🔴 **상용구에 환자 식별정보를 넣지 못하게 한다.** 한 환자의 문구가 다른 환자 기록에 그대로 붙는다 —
  이 저장소가 이미 겪은 "값 날조"와 같은 종류의 사고다.
- 🔴 **샘플은 빈 칸을 만들지 값을 만들지 않는다.** 예시 문구는 힌트(placeholder)이고 저장되지 않는다.
- 🔴 **개인 어휘가 집계를 바꾸지 않는다.** 표기 선호는 화면만 바꾸고 저장 값은 shared 정본을 쓴다.
- 🔴 **확정 후 정정은 덮어쓰기가 아니라 이력**(AMENDED/addendum). 지금 병리는 단일 컬럼 덮어쓰기다 — 별도 과제로 등재.

🔴 **P1 을 P2 보다 먼저** 둔 이유: 유실 방어는 기록별 설계 결정을 기다리지 않고 전 화면에 깔 수 있다.

## 8. 가드 (착수 시 함께 — 전부 결함 재주입으로 검증)

- **초안에 발급번호·서명이 붙지 않는다** — 대조군: 확정된 것에는 붙는다
- **DRAFT 상태로는 발급·제출이 되지 않는다** — 대조군: 확정 후에는 된다
- **L1 복원이 자동으로 덮어쓰지 않는다**(묻는다) · **키가 환자별로 갈린다**(다른 환자 내용이 안 뜬다)
- **`draft:true` 같은 플래그가 화면에서 실제로 전송된다** — 🔴 지금 간호기록이 0건인 상태를 재발 방지
- **DRAFT 를 지원한다고 선언한 기록은 §4.2 의 4가지를 전부 갖췄다**(선언과 실제의 기계 대조)
- **원천이 바뀌면 확정 화면이 차이를 말한다** — 🔴 대조군: **안 바뀌었으면 조용하다**
- 🔴 **초안 조회 실패를 `[]` 로 접지 않는다**
- **자유텍스트 N칸 이상 임상 쓰기 화면에 L1 이 붙어 있다**(신규 화면이 빠지면 실패)
- **개인 설정으로 필수 항목이 사라지지 않는다** — 🔴 대조군: 선택 항목은 숨길 수 있다
- **상용구 본문에 환자 식별정보 패턴(MRN·주민번호·이름 형식)이 저장되지 않는다**
- **개인 표기 선호가 저장 값을 바꾸지 않는다**(집계 정본과 기계 대조)
- 🔴 **샘플을 적용해도 임상 값이 채워지지 않는다** — 대조군: 라벨·순서는 바뀐다
- **미승인 견본이 "원내 표준"으로 표시되지 않는다**(`검토 전` 표시가 붙는다)
- **견본의 예시 문구가 저장 페이로드에 들어가지 않는다**(placeholder 로만 존재)
- 🔴 **`localStorage` 상용구 사본이 남아 있지 않다** — 서버 정본으로 흡수됐는지 전수 확인

## 9. 이 기획이 스스로 조심한 것

- **"기능이 없다"고 먼저 말하지 않았다** — 전 영역을 4분류로 세어 보니 **동작 8 · 도달 불가 7 · 없음 20+**
  였다. 도달 불가 7 은 **만드는 일이 아니라 잇는 일**이다.
- **초안을 한 단어로 두지 않았다**(§2 세 층). 섞으면 Redis 캐시로 "미리 작성"을 하려는 설계가 나온다.
- **미구현과 결함을 갈랐다**(§3-6, P4). 섞어 빨갛게 칠하면 진짜 경보가 묻힌다.
- **인계분을 그대로 쓰지 않았다** — 사망진단서 소실 · 간호 `draft:true` 0건 · 위젯 필터 무시 3건은
  코디네이터가 파일을 다시 열어 확인했다.
- 🔴 **가장 큰 위험은 편의가 아니라 정확성이다.** 미리 쓴 문서는 **확정 시점의 사실과 다를 수 있다** —
  그래서 §4.4(재대조)가 중심이고 편의 기능이 아니다.

- **편집기를 새로 짓지 않았다** — `ChartTemplate` 편집기는 이미 있고, 개인 층은 **모델·EP 가 이미 있는데
  화면만 없다.** 그래서 P3-b 는 "만들기"가 아니라 "살리기"다.
