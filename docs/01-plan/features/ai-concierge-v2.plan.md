## 1. 문제 정의

### 1.1 현재 구조의 한계

```
현재 (v1.0):
  환자: "발가락 무좀은 어디로 가야 하나?"
    ↓
  키워드 매칭 → HOSPITAL_INFO
    ↓
  하드코딩 응답: "서울시 강남구 (Hospital RUN) / 지하철 강남역 3번 출구..."
    → 피부과 안내 없음, 무좀에 대한 설명 없음
```

| 현재 문제 | 원인 | 환자 경험 |
|----------|------|----------|
| 질문에 답을 안 함 | 인텐트 분류 후 DB 데이터만 반환 | "봇이랑 대화하는 느낌" |
| 같은 응답 반복 | GENERAL → 고정 안내 텍스트 | "말귀를 못 알아듣네" |
| 진료과 추천 없음 | 증상→진료과 매핑 로직 부재 | "어디로 가라는 건지 모르겠음" |
| 맥락 없는 병원 안내 | "어디로 가야" → HOSPITAL_INFO 오분류 | "길 안내를 원한 게 아닌데" |

### 1.2 TO-BE: LLM-First 응답

```
TO-BE (v2.0):
  환자: "발가락 무좀은 어디로 가야 하나?"
    ↓
  ① LLM 자연어 응답 생성 (의료 컨텍스트 포함)
    → "발가락 무좀(족부백선)은 피부과에서 진료받으실 수 있습니다.
       항진균제 연고나 경구약으로 치료하며, 보통 2~4주 정도 소요됩니다.
       습한 환경을 피하고 발을 건조하게 유지하시는 것이 중요합니다."
    ↓
  ② 구조화 데이터 보강 (선택적)
    → [피부과 예약하기] [진료시간 확인] [오시는 길]
```

## 2. 핵심 설계 원칙

### 2.1 질의 분류 3-Track 아키텍처

환자 질의는 본질적으로 **3가지 트랙**으로 나뉜다. 이를 정확히 분기하는 것이 v2의 핵심.

```
┌─────────────────────────────────────────────────────────┐
│                     환자 질의 입력                         │
└─────────────────────────┬───────────────────────────────┘
                          ▼
                 ┌──────────────────┐
                 │  ⓪ 응급 감지      │  ← 키워드 즉시 체크 (LLM 이전)
                 │  흉통/호흡곤란/의식 │     → 119 + 응급실 즉시 안내
                 └────────┬─────────┘
                          ▼ (응급 아님)
                 ┌──────────────────┐
                 │  ① LLM 1차 판정   │  ← 질의 성격 분류 + 자연어 응답 동시 생성
                 │  "이 질문은..."    │
                 └────────┬─────────┘
                          │
            ┌─────────────┼──────────────┐
            ▼             ▼              ▼
   ┌─────────────┐ ┌───────────┐ ┌────────────┐
   │ Track A     │ │ Track B   │ │ Track C    │
   │ 일반 의료    │ │ 병원 내부  │ │ 하이브리드  │
   │ 지식 질문    │ │ 데이터    │ │ (일반+내부) │
   └──────┬──────┘ └─────┬─────┘ └──────┬─────┘
          ▼              ▼              ▼
   LLM 응답만      LLM 응답         LLM 응답
   + 액션 버튼     + DB 데이터 조회   + DB 데이터 조회
                   + 구조화 카드     + 구조화 카드
                   + 액션 버튼      + 액션 버튼
```

### 2.2 Track 정의

| Track | 정의 | 예시 질문 | 응답 구성 |
|-------|------|----------|----------|
| **A. 일반 의료 지식** | 환자 개인 데이터 불필요, 의학 상식/증상/진료과 문의 | "무좀은 어디로 가야 하나?", "고혈압 관리법", "MRI 뭐야?" | LLM 답변 + [예약하기] 버튼 |
| **B. 병원 내부 데이터** | 환자 본인의 HIS 데이터 조회 필요 | "내 검사결과", "다음 예약", "수납 내역", "먹는 약" | LLM 설명 + DB 카드/테이블 |
| **C. 하이브리드** | 일반 지식 + 본인 데이터 결합 | "콜레스테롤이 높다는데 어떡해?", "이 약 부작용?" | LLM 답변 + DB 검사결과/투약 카드 |

### 2.3 Track 판정 기준

LLM이 **1회 호출로 응답 생성 + Track 판정을 동시에** 수행한다.

```
LLM 응답 JSON 구조:
{
  "track": "A" | "B" | "C",
  "message": "자연어 응답 텍스트...",
  "dataNeeded": [],                    // Track A: 빈 배열
  "dataNeeded": ["LAB_RESULT"],        // Track B: DB 조회 대상
  "dataNeeded": ["MEDICATION", "LAB"], // Track C: 복수 DB 조회
  "actions": [...]                     // 후속 액션 버튼
}
```

**Track 판정 규칙** (LLM 시스템 프롬프트에 명시):

| 판정 | 조건 | dataNeeded |
|------|------|-----------|
| Track A | "~은 뭔가요?", "~은 어디로?", "~관리법" 등 일반 문의 | `[]` |
| Track B | "내/나의", "지난번", "결과", "예약", "수납" 등 소유격/개인 데이터 키워드 | `["ENCOUNTER"]`, `["LAB"]` 등 |
| Track C | Track A 성격 질문 + 본인 데이터 참조가 답변 품질을 높이는 경우 | `["MEDICATION"]` 등 |
| Track B 불가 | 미인증 상태에서 Track B 질문 | → LLM이 "로그인이 필요합니다" 안내 + 로그인 액션 |

### 2.4 v1.0 vs v2.0 비교

| 항목 | v1.0 (현재) | v2.0 (3-Track) |
|------|-----------|---------------|
| **응답 순서** | 인텐트 분류 → DB 조회 → 템플릿 텍스트 | LLM 응답+Track 판정 → (B/C만) DB 조회 → 조합 |
| **분기 기준** | 키워드 매칭 9종 | LLM 자체 판단 (A/B/C) |
| **일반 질문** | "증상을 말씀해주세요" 반복 | 충분한 의학 상식 답변 |
| **데이터 질문** | DB 데이터만 던짐 | LLM 해석 + DB 데이터 카드 |
| **미인증 시** | 기능 차단 | Track A는 정상 응답, Track B는 로그인 유도 |
| **진료과 추천** | 없음 | LLM이 증상 기반 자동 추천 |
| **폴백** | 고정 텍스트 | 구체적 후속 질문 유도 |

## 3. 응답 생성 파이프라인 (3-Track)

### 3.1 시스템 프롬프트 (Track 판정 포함)

```
당신은 위루비병원의 AI 컨시어지입니다.

[역할]
- 환자의 질문에 정확하고 친절하게 한국어로 답변합니다.
- 증상 문의 시 해당 진료과를 안내하고, 예약을 제안합니다.
- 검사/투약/비용 등 개인 데이터가 필요하면 dataNeeded에 명시합니다.

[의료 안전 원칙]
- 진단/처방은 하지 않습니다. "담당 의사와 상담하세요"로 안내합니다.
- 응급 증상은 즉시 119/응급실을 안내합니다.
- 모든 의료 정보에 "참고용이며 전문의 상담을 권장합니다"를 포함합니다.

[병원 정보]
- 이름: 위루비병원
- 주소: 가상특별자치도 가상시 가상로 126
- 서울사무소: 가상구 가상로 1 가상빌딩 5층
- 전화: 02-000-0000
- 진료과: 내과, 외과, 정형외과, 신경외과, 산부인과, 소아청소년과,
         피부과, 비뇨의학과, 안과, 이비인후과, 재활의학과,
         영상의학과, 마취통증의학과, 응급의학과, 가정의학과

[대화 스타일]
- 환자 이름(~님)을 자연스럽게 사용합니다 (인증 시).
- 존댓말을 쓰되 딱딱하지 않게 합니다. "확인해 드릴게요" ✅ "확인하겠습니다" ❌
- 한 번에 너무 많은 정보를 주지 않습니다. 핵심 1~2개 후 "더 궁금하시면 말씀해주세요."
- 환자가 불안/걱정을 표현하면 먼저 공감한 후 정보를 제공합니다.
- 모호한 질문에는 추측하지 말고, 구체적 선택지(2~3개)로 되물으세요.
- "응", "네" 같은 단답은 이전 제안의 확인으로 해석합니다.
- 주제가 바뀌면 새 주제에 답하면서, 이전 주제와 연결 가능하면 자연스럽게 연결합니다.
- 같은 되묻기를 2회 반복하지 않습니다. 2회째에는 전화 안내로 전환합니다.

[응답 규칙]
1. 먼저 질문에 대한 충분한 답변을 자연어로 작성합니다.
2. 마지막 줄에 반드시 JSON 블록을 추가합니다.

[JSON 블록 형식]
```json
{
  "track": "A|B|C",
  "dataNeeded": [],
  "actions": []
}
```

[Track 판정 규칙]
- Track A (일반 의료 지식): 환자 개인 데이터 없이 답변 가능
  → dataNeeded: []
  예: "무좀 어디로 가야 하나?", "MRI가 뭐야?", "고혈압 관리법"

- Track B (병원 내부 데이터): 환자 본인의 HIS 데이터가 필요
  → dataNeeded: ["ENCOUNTER"|"LAB_RESULT"|"MEDICATION"|"APPOINTMENT"|"BILLING"|"VITAL"|"ADMISSION"]
  예: "내 검사결과", "다음 예약 언제?", "먹는 약 뭐야?", "수납 내역"

- Track C (하이브리드): 일반 지식 답변 + 본인 데이터로 보강 시 더 유용
  → dataNeeded: 해당 항목들
  예: "콜레스테롤이 높다는데 어떡해?" → 일반 답변 + LAB_RESULT
      "이 약 부작용 있어?" → 일반 답변 + MEDICATION

[dataNeeded 항목]
- ENCOUNTER: 진료 이력
- LAB_RESULT: 검사 결과
- MEDICATION: 현재 복용약
- APPOINTMENT: 예약 현황
- BILLING: 수납 내역
- VITAL: 바이탈 사인
- ADMISSION: 입원 정보

[actions 항목]
- type: BOOK(예약), CALL(전화), INFO(병원안내), LOGIN(로그인유도), PORTAL(포털이동)
- label: 버튼에 표시할 텍스트
- department: 진료과명 (BOOK 시)
```

### 3.2 인터페이스 정의

```typescript
// ── LLM 응답 파싱 결과 ──
interface LLMParsedResponse {
  message: string;              // 자연어 응답 (JSON 블록 제거)
  track: 'A' | 'B' | 'C';      // 질의 트랙
  dataNeeded: DataType[];       // DB 조회 대상 (Track B/C만)
  actions: ActionSuggestion[];  // 후속 액션 버튼
}

type DataType = 'ENCOUNTER' | 'LAB_RESULT' | 'MEDICATION' | 'APPOINTMENT'
              | 'BILLING' | 'VITAL' | 'ADMISSION';

interface ActionSuggestion {
  type: 'BOOK' | 'CALL' | 'INFO' | 'LOGIN' | 'PORTAL';
  label: string;
  department?: string;
}

// ── 최종 응답 (FE로 전달) ──
interface ConciergeResponse {
  message: string;                // LLM 자연어 응답
  track: 'A' | 'B' | 'C';        // 어떤 트랙으로 처리됐는지
  actions: ActionSuggestion[];    // 후속 액션 버튼
  dataCards: DataCard[];          // DB 기반 구조화 카드 (Track B/C)
  intent: string;                 // 인텐트 태그 (로깅용)
}

// ── DB 데이터 카드 ──
interface DataCard {
  type: DataType;
  title: string;                  // 카드 제목
  items: Record<string, unknown>[];  // DB 조회 결과
  summary?: string;               // LLM이 데이터를 해석한 요약
}
```

### 3.3 처리 흐름 (Track별 분기)

```
환자 질의 입력
  │
  ▼
┌─ Step 0: 응급 감지 (키워드, LLM 이전) ───────────────┐
│  흉통/호흡곤란/의식저하/대량출혈/자살 → 즉시 119 안내    │
│  (LLM 호출 생략, 하드코딩 응답)                        │
└──────────┬───────────────────────────────────────────┘
           ▼ (응급 아님)
┌─ Step 1: LLM 호출 (1회) ────────────────────────────┐
│  시스템 프롬프트 + 대화 히스토리 + 환자 컨텍스트         │
│  → LLM이 자연어 응답 + JSON(track/dataNeeded/actions) │
│     동시 생성                                         │
└──────────┬───────────────────────────────────────────┘
           ▼
┌─ Step 2: 응답 파싱 ──────────────────────────────────┐
│  1. 마지막 JSON 블록 추출 → track, dataNeeded, actions │
│  2. JSON 제거 → 순수 message 텍스트                    │
│  3. JSON 파싱 실패 시 → Track A 폴백                   │
└──────────┬───────────────────────────────────────────┘
           │
     ┌─────┼──────────────┐
     ▼     ▼              ▼
  Track A  Track B      Track C
     │     │              │
     │     ▼              ▼
     │  ┌─ Step 3: 인증 확인 ──────────────────────────┐
     │  │  환자 인증됨? (세션 토큰/포털 로그인)            │
     │  │  ├─ Yes → Step 4로                            │
     │  │  └─ No  → message에 "로그인이 필요합니다" 추가   │
     │  │          + actions에 LOGIN 버튼 추가             │
     │  │          + dataCards 비움 (Track A처럼 동작)     │
     │  └──────────────────────────────────────────────┘
     │         │
     │         ▼
     │  ┌─ Step 4: DB 데이터 조회 ─────────────────────┐
     │  │  dataNeeded 배열 순회:                         │
     │  │  ├─ ENCOUNTER  → getEncounters(patientId)     │
     │  │  ├─ LAB_RESULT → getLabResults(patientId)     │
     │  │  ├─ MEDICATION → getMedications(patientId)    │
     │  │  ├─ APPOINTMENT→ getAppointments(patientId)   │
     │  │  ├─ BILLING    → getBillings(patientId)       │
     │  │  ├─ VITAL      → getVitals(patientId)        │
     │  │  └─ ADMISSION  → getAdmissionInfo(patientId)  │
     │  │  → Promise.all 병렬 조회                       │
     │  └──────────────────────────────────────────────┘
     │         │
     │         ▼
     │  ┌─ Step 5: 데이터 해석 (Track C만, 선택적) ─────┐
     │  │  Track C일 때: DB 데이터를 LLM에 2차 전달       │
     │  │  "이 검사 결과를 참고하여 보충 설명해주세요"       │
     │  │  → 데이터 기반 맞춤 조언 추가                    │
     │  │                                               │
     │  │  Track B일 때: 2차 LLM 호출 생략               │
     │  │  → DB 데이터를 카드로만 표시                     │
     │  └──────────────────────────────────────────────┘
     │         │
     ▼         ▼
┌─ Step 6: 최종 응답 조합 ─────────────────────────────┐
│                                                      │
│  Track A: message + actions (LLM 1회 호출)            │
│                                                      │
│  Track B: message + dataCards + actions (LLM 1회)     │
│           ※ 데이터는 카드로 표시, LLM 응답은 짧게       │
│                                                      │
│  Track C: message(보강) + dataCards + actions          │
│           (LLM 1~2회: 1차 응답 + 2차 데이터 해석)       │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 3.4 Track별 시나리오

**Track A — 일반 의료 지식**
```
환자: "발가락 무좀은 어디로 가야 하나?"

→ LLM 1회 호출, DB 조회 없음

AI: "발가락 무좀(족부백선)은 피부과에서 진료받으실 수 있습니다.
    진균 감염으로 발생하며, 항진균제 연고나 경구약으로 치료합니다.
    보통 2~4주 정도 소요됩니다.
    ...
    ※ 참고용이며 전문의 상담을 권장합니다."

    [피부과 예약하기] [진료시간 확인]
```

**Track B — 병원 내부 데이터**
```
환자: "내 검사결과 알려줘"

→ LLM 1회 호출 → dataNeeded: ["LAB_RESULT"] → DB 조회

AI: "최근 검사 결과를 확인해드리겠습니다."

    ┌─────────────────────────────────────┐
    │ 🔬 2026-05-25 혈액검사               │
    │ 혈색소: 14.2 g/dL        ✅ 정상     │
    │ 공복혈당: 128 mg/dL      ⚠️ 높음     │
    │ 총콜레스테롤: 242 mg/dL  ⚠️ 높음     │
    └─────────────────────────────────────┘

    "이상 소견이 2건 있습니다.
     다음 진료 시 담당 의사와 상담을 권장합니다."

    [결과 상세보기] [담당의 예약]
```

**Track C — 하이브리드**
```
환자: "콜레스테롤이 높다는데 어떡해?"

→ LLM 1차: 일반 답변 + dataNeeded: ["LAB_RESULT"]
→ DB 조회: 최근 콜레스테롤 수치
→ LLM 2차 (선택): 수치 기반 맞춤 조언

AI: "콜레스테롤 관리를 위해 다음을 권장합니다:
    • 포화지방 섭취 줄이기 (튀김, 가공육)
    • 오메가-3 풍부한 생선 섭취
    • 주 5회, 30분 이상 유산소 운동
    ...

    회원님의 최근 수치를 확인해드렸습니다."

    ┌─────────────────────────────────────┐
    │ 📊 콜레스테롤 추이                    │
    │ 2026-03: 220 → 2026-05: 242 ⚠️ 상승 │
    │ LDL: 158 (목표: <130)               │
    │ HDL: 45 (목표: >40) ✅              │
    └─────────────────────────────────────┘

    "LDL이 목표치보다 높고 상승 추세입니다.
     식이조절과 함께 약물 치료가 필요할 수 있으니
     내과(순환기) 진료를 권장합니다."

    [내과 예약하기] [식이 상담 예약]
```

**미인증 + Track B 질문**
```
환자: "내 예약 확인해줘"

→ LLM 판정: Track B, dataNeeded: ["APPOINTMENT"]
→ 인증 확인: 미인증
→ DB 조회 생략

AI: "예약 확인을 위해서는 본인 인증이 필요합니다.

    환자 포털에 로그인해주세요."

    [본인 인증하기] [포털 로그인] [전화 문의: 02-000-0000]

## 8. 자연스러운 대화를 위한 설계

### 8.1 대화 페르소나

AI 컨시어지는 **"병원 안내 데스크의 경험 많은 직원"** 페르소나를 갖는다.
로봇이 아니라 사람처럼 느끼되, 의료 전문가는 아님을 명확히 한다.

```
[페르소나 규칙 — 시스템 프롬프트에 포함]

화법:
- 환자의 이름(~님)을 자연스럽게 사용합니다 (인증 시).
- 존댓말을 사용하되, 딱딱하지 않게 합니다.
  ✅ "네, 확인해 드릴게요."
  ❌ "확인하겠습니다. 잠시만 기다려 주십시오."
- 한 번에 너무 많은 정보를 주지 않습니다. 핵심 1~2개 + "더 궁금하시면 말씀해주세요."
- 이모지는 카드 제목(📋, 🔬, 💊)에만 사용하고, 본문에는 자제합니다.

금지 화법:
- "저는 AI이므로 ~할 수 없습니다" (대신: "정확한 진단은 전문의 상담이 필요해요")
- "다시 말씀해 주시겠어요?" 반복 (대신: 구체적으로 어떤 부분이 모호한지 안내)
- "죄송합니다" 남발 (필요할 때만)
```

### 8.2 멀티턴 대화 흐름 (연속 대화)

하나의 주제에서 자연스럽게 깊어지는 대화를 지원한다.

```
── 시나리오: 무좀 → 비용 → 예약 (3턴 연속) ──

[턴 1] 환자: "발가락 무좀인 것 같아요"
  Track A | LLM 응답
AI: "발가락 무좀(족부백선)일 수 있겠네요.
    피부과에서 진료받으시면 항진균제로 치료할 수 있습니다.
    보통 2~4주 정도 걸려요.

    피부과 진료를 도와드릴까요?"

    [피부과 예약하기]

────────────────────────────────────

[턴 2] 환자: "비용은 얼마나 들어?"
  Track A (이전 맥락 "무좀 진료"를 이어감) | LLM이 대화 히스토리에서 "무좀" 참조
AI: "무좀 진료 비용은 대략 이렇습니다.

    • 초진료: 약 15,000~20,000원 (건강보험 적용)
    • 항진균제 연고: 5,000~15,000원
    • 경구약 처방 시: 추가 10,000~30,000원

    실제 비용은 검사 여부에 따라 달라질 수 있어요."

    [피부과 예약하기] [전화 문의]

────────────────────────────────────

[턴 3] 환자: "그럼 예약해줘"
  Track B (APPOINTMENT) | "그럼" → 이전 맥락에서 "피부과" 자동 참조
AI: "피부과 예약을 도와드릴게요.

    가능한 시간대:
    • 6/4 (수) 10:00, 14:00
    • 6/5 (목) 09:30, 11:00

    원하시는 시간을 알려주세요."

    [6/4 오전] [6/4 오후] [6/5 오전] [다른 날짜]
```

**핵심**: LLM에 전달하는 대화 히스토리에 **이전 턴의 Track/dataNeeded 정보를 포함**하여, 맥락을 유지한다.

```typescript
// 대화 히스토리 구성 (LLM에 전달)
interface ChatTurn {
  role: 'patient' | 'agent';
  content: string;
  track?: 'A' | 'B' | 'C';        // 이전 턴의 Track (맥락 유지)
  department?: string;              // 언급된 진료과 (맥락 유지)
  dataTypes?: DataType[];           // 조회된 데이터 (맥락 유지)
}
```

### 8.3 모호한 입력 & 되묻기 (Clarification)

환자가 모호하게 말할 때, 추측하지 않고 자연스럽게 되묻는다.

| 모호한 입력 | 나쁜 응답 (v1.0) | 좋은 응답 (v2.0) |
|-----------|----------------|----------------|
| "아파요" | "증상을 말씀해주세요" (반복) | "어디가 아프신가요? 머리, 배, 허리 등 부위를 알려주시면 더 정확히 안내해 드릴게요." |
| "그거" | "무엇을 말씀하시는지..." | (이전 맥락 참조) "말씀하신 콜레스테롤 수치 말씀이시죠? 최근 결과를 확인해 드릴게요." |
| "응" / "네" | "더 궁금한 점이 있으시면..." | (이전 제안 실행) "네, 그럼 피부과 예약 가능한 날짜를 확인해 드릴게요." |
| "몰라" / "잘 모르겠어" | "증상을 말씀해주세요" | "괜찮아요. 혹시 몸에 불편하신 곳이 있으시면 편하게 말씀해주세요. 어디가 불편한지만 알려주셔도 돼요." |
| "뭐가 있어?" | 고정 메뉴 표시 | "제가 도와드릴 수 있는 것들이에요:\n• 예약 확인/변경\n• 검사 결과 확인\n• 복용약 안내\n• 진료비 내역\n• 병원 안내\n어떤 게 궁금하세요?" |

**되묻기 규칙** (시스템 프롬프트에 포함):
```
[되묻기 규칙]
- 환자의 의도를 추측하지 마세요. 확실하지 않으면 되물으세요.
- 되묻기는 구체적이어야 합니다: "어디가 아프세요?" ✅  "다시 말씀해주세요" ❌
- 선택지를 2~3개 제시하여 환자가 쉽게 대답할 수 있게 합니다.
- 같은 되묻기를 2회 연속 하지 않습니다. 2번째에는 전화 안내로 전환합니다.
```

### 8.4 감정 인식 & 공감 응대

환자가 불안/걱정/두려움을 표현할 때, 정보만 주지 않고 먼저 공감한다.

| 감정 표현 | 공감 응대 | 이후 정보 제공 |
|----------|---------|-------------|
| "무서워요" | "걱정되시는 마음 충분히 이해합니다." | "하지만 무좀은 흔한 질환이고, 적절한 치료로 잘 낫는 편이에요." |
| "결과가 나빠서 걱정돼요" | "검사 결과를 보고 불안하실 수 있어요." | "수치가 조금 높지만, 식이조절과 운동으로 개선할 수 있습니다. 담당 선생님과 구체적인 계획을 상의해보세요." |
| "계속 아픈데 나을까요?" | "오래 불편하시면 많이 힘드시죠." | "정확한 원인을 찾으려면 진료를 받으시는 게 좋겠어요. 예약을 도와드릴까요?" |
| "화가 나요" / "불만" | "불편을 드려 죄송합니다." | "어떤 부분이 불편하셨는지 알려주시면, 담당 부서에 전달해드리겠습니다." + [VOC 접수] |

**시스템 프롬프트 추가**:
```
[감정 인식 규칙]
- 환자가 불안, 걱정, 두려움을 표현하면 먼저 공감 문장을 말하세요.
- 공감 후에 정보를 제공하세요. 정보만 바로 던지지 마세요.
- 감정 표현: "무서워", "걱정", "불안", "힘들어", "화나", "짜증"
- 공감 패턴: "~하신 마음 충분히 이해합니다", "~하시면 걱정되실 수 있어요"
```

### 8.5 주제 전환 처리

대화 중 주제가 바뀔 때, 이전 주제를 자연스럽게 마무리하고 넘어간다.

```
── 시나리오: 무좀 대화 중 → 갑자기 예약 확인 ──

[턴 1~2] 무좀 관련 대화...

[턴 3] 환자: "아 참, 다음 주 예약 있던가?"

AI: "네, 예약 확인해 드릴게요.

    📅 다음 주 예약:
    • 6/9 (월) 14:00 | 내과 김내과 전문의 — 정기 진료

    아까 말씀하신 무좀 건도 같이 진료받으시려면
    피부과 예약을 추가로 잡으실 수 있어요."

    [피부과 추가 예약] [예약 변경] [예약 취소]
```

**핵심**: 새 주제에 답하면서, 이전 주제와 자연스럽게 연결할 수 있으면 연결한다.

### 8.6 대화 기억 구조 (세션 내)

LLM에 전달하는 대화 히스토리를 **구조화된 형태**로 관리한다.

```typescript
// 세션 내 대화 상태 (메모리에 유지, LLM 호출마다 전달)
interface ConversationState {
  // 현재 대화 맥락
  currentTopic: string | null;         // "무좀 진료", "검사 결과" 등
  mentionedDepartments: string[];      // ["피부과", "내과"]
  mentionedSymptoms: string[];         // ["무좀", "가려움"]
  
  // 대화 히스토리 (최근 10턴)
  turns: ChatTurn[];
  
  // 환자 감정 상태
  emotionalState: 'neutral' | 'anxious' | 'frustrated' | 'satisfied';
  
  // 되묻기 카운터 (같은 주제로 2회 넘으면 에스컬레이션)
  clarificationCount: number;
}
```

**LLM에 전달하는 히스토리 포맷**:
```
[대화 맥락]
현재 주제: 무좀 진료
언급된 진료과: 피부과
환자 감정: 불안

[대화 히스토리]
환자: 발가락 무좀인 것 같아요
AI: [Track A] 피부과 안내 + 예약 제안
환자: 비용은 얼마나 들어?
AI: [Track A] 무좀 진료 비용 안내
환자: 그럼 예약해줘
→ 현재 질의
```

### 8.7 짧은 응답 / 단답 처리

환자가 한 글자~한 단어로 답할 때의 처리 규칙.

| 입력 | 이전 맥락 | 처리 |
|------|---------|------|
| "응", "네", "그래" | AI가 제안한 게 있으면 | 제안 실행 ("네, 피부과 예약 가능 시간 확인해 드릴게요.") |
| "응", "네" | 제안 없으면 | "더 궁금하신 것이 있으시면 편하게 말씀해주세요." |
| "아니", "괜찮아" | AI가 제안한 게 있으면 | "알겠습니다. 다른 궁금하신 점이 있으시면 말씀해주세요." |
| "고마워", "감사" | 어떤 맥락이든 | "도움이 되셨다니 다행이에요! 다른 궁금한 점 있으시면 언제든 물어보세요." |
| "ㅋㅋ", "ㅎㅎ" | 어떤 맥락이든 | 자연스럽게 대화 이어감 (무시하지 않되 과잉 반응하지 않음) |

### 8.8 대화 실패 복구 (Graceful Degradation)

LLM이 질문을 이해 못 했을 때, 단계적으로 복구한다.

```
1차 실패: LLM 응답이 모호함
  → "혹시 ~에 대해 궁금하신 건가요?" (구체적 선택지 제시)

2차 실패: 같은 주제에서 2회 연속 이해 못 함
  → "정확한 답변을 드리기 어려운 질문이네요.
     전화(02-000-0000)로 문의하시면 더 정확히 안내받으실 수 있어요."
     [전화 연결] [다른 질문하기]

3차 실패: LLM 서버 자체 장애
  → v1.0 키워드 매칭 폴백 (기존 로직)
  → "현재 AI 상담이 원활하지 않습니다.
     전화(02-000-0000)로 문의 부탁드립니다."
```
