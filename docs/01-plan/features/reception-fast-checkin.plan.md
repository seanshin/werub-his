---

## 1. 배경 / 원칙
- **환자 특정이 최우선**(R1): 모든 접수는 "이 사람이 누구인가"를 먼저 확정.
- **빠른 단계**(R9): 클릭 최소화, 한 화면에서 완결, 신환도 즉시 등록.
- 재사용: AI 어시스턴트(신환 인지)·consent-device(태블릿 호출/서명)·블록체인 인증서·journey(길안내)·portal.

---

## 2. 요구사항 → 설계 매핑
| # | 요구 | 설계 |
|---|------|------|
| R1 | 환자 특정 최우선 | 접수 1단계 = 환자 선택/검색. 확정 전 다음 단계 비활성 |
| R2 | 선택=접수환자 확정 / 미검색=신환 어시스턴트 인지 | 검색 0건 → "신규 등록" CTA → 어시스턴트가 신환 모드(전화·주소 수집) |
| R3 | 주소 편리 입력(동 검색) | **Daum(카카오) 우편번호 서비스** 임베드 AddressSearch 컴포넌트(동 검색→도로명/지번 자동) |
| R4 | 접수사유 = 어시스턴트 분석 또는 간단 입력 | 수동 입력 + 어시스턴트 대화에서 증상 자동 도출(구조화 반환, 기구현) |
| R5 | 초진 동의서 태블릿 호출·서명 | 초진 접수 시 필요 동의서 생성 → consent-device 디스패치 → 서명 수집 |
| R6 | 신환 등록번호 발급 + 태블릿에 환자앱 QR | 신환 MRN 발급 → 태블릿에 **환자앱 설치/연동 QR** 표시 |
| R7 | QR로 다음 진료/장소 이동 안내 | QR → 환자앱/웹에서 **길안내(journey/floor 연계)** |
| R8 | 예약접수=기존환자 QR/검색 후 접수 | QR 스캔 or 검색 → 즉시 접수, 환자앱 인지 |
| R9 | 빠른 접수 | 단일 화면·키보드 우선·자동 진행 |
| R10 | 포털 셀프 체크인(의료진 선택) | 환자 포털에 셀프 접수 + 진료과/의사 선택 |

---

## 3. 재사용 vs 신규
| 자산 | 활용 |
|------|------|
| AiReceptionChat / agent-session | 신환 인지·증상 도출(기구현 보강) |
| consent / consent-device | 초진 동의서 생성·태블릿 디스패치·서명(R5) |
| BlockchainCertificate / consent QR | 신환 환자앱 QR(R6) |
| journey / floor API | QR 후 길안내(R7) |
| patient portal | 셀프 체크인(R10) |
| **신규: AddressSearch** | Daum 우편번호 임베드(R3) — 재사용 컴포넌트 |
| **신규: 신환 빠른등록 폼** | 환자 선택 0건 시 인라인 등록(전화·주소·성별) |
| **신규: 포털 셀프 체크인 페이지** | R10 |
