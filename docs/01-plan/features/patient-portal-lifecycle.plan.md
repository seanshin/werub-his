## 1. 기획 배경

### 1.1 현재 상태

환자 포털은 **외래 환자 중심**으로 설계되어 있음:
- 예약/대기, 검사결과, 수납 — 모두 외래 시나리오
- 입원 환자가 포털에 접속해도 외래와 동일한 홈 화면
- HIS에서 접수/입원/퇴원 상태가 변해도 포털이 실시간 반응하지 않음

### 1.2 목표

```
환자의 병원 이용 상태(원외 → 접수 → 외래 → 입원 → 퇴원 → 원외)에 따라
포털이 자동으로 최적화된 화면을 제공한다.
```

### 1.3 환자 생애주기 (Patient Lifecycle)

```
┌──────────────────────────────────────────────────────────────────┐
│                                                                  │
│  ① 원외        ② 접수/대기      ③ 외래 진료      ④ 입원         │
│  (Idle)       (Reception)    (Outpatient)    (Inpatient)       │
│                                                                  │
│  ⑤ 입원 중     ⑥ 퇴원 준비      ⑦ 퇴원          ⑧ 사후 관리    │
│  (Admitted)   (Pre-Discharge) (Discharge)   (Post-Discharge)   │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘

상태 전이 트리거 (HIS → 포털):
  ① → ② : 접수(Reception) 생성 또는 예약 당일 도착
  ② → ③ : 의사가 진료 시작 (Encounter STARTED)
  ③ → ④ : 입원 오더 발행 (Admission ORDER)
  ④ → ⑤ : 입원 확정 (Admission ADMITTED)
  ⑤ → ⑥ : 퇴원 예정일 D-1 또는 퇴원 오더 발행
  ⑥ → ⑦ : 퇴원 확정 (Admission DISCHARGED)
  ⑦ → ⑧ : 퇴원 후 30일 이내
  ⑧ → ① : 30일 경과 또는 추적 관찰 종료
```

### 1.4 생애주기 8단계 상세 설명

> 아래는 각 단계별로 **환자가 처한 상황**, **환자의 심리**, **포털이 해결해야 할 문제**, **실제 시나리오**를 설명합니다.
> 이 문서를 읽는 개발자/기획자/의료진 모두가 "왜 이 화면이 필요한가"를 이해할 수 있도록 작성되었습니다.

#### Phase ① IDLE — 원외 건강관리

**상황**: 환자가 병원 밖에서 일상생활을 하고 있음. 가까운 시일 내 병원 방문 예정 없음.

**환자 심리**:
- "내 건강 상태가 괜찮은 건지 궁금하다"
- "약을 빼먹지 않고 잘 먹고 있는지 확인하고 싶다"
- "지난 검사 결과가 어떤 의미인지 알고 싶다"

**포털이 해결할 문제**:

| 문제 | 해결 방법 |
|------|-----------|
| 만성질환 환자가 병원 밖에서 건강 상태를 파악하기 어려움 | AI 건강 점수 + 검사 추이 시각화 |
| 복용약을 빼먹거나 잘못 복용함 | 복용 체크리스트 + 주간 복용률 |
| 자가 측정 데이터(혈압/혈당)를 기록할 곳이 없음 | 건강 기록 입력 + 추이 그래프 |
| 예방 검진 시기를 놓침 | 나이/성별/이력 기반 검진 권장 알림 |
| 다음 방문까지 건강 관리 지침이 없음 | AI 건강 코칭 (생활습관 조언) |

**시나리오 예시**:
> 60세 당뇨 환자 박씨. 매일 아침 포털에서 혈당을 기록하고, 메트포르민 복용 체크를 한다.
> AI가 "이번 주 혈당 평균이 130mg/dL로, 목표(120)보다 약간 높습니다. 저녁 탄수화물 섭취를 줄여보세요"라고 조언한다.
> 6개월간의 혈당 추이 그래프에서 점진적 개선을 확인하며 다음 외래 방문(2주 후)을 기다린다.

**핵심 화면 요소**: AI 건강 점수 게이지, 복용 체크리스트, 자가 건강 기록 입력, 검사 추이 차트, 예방 검진 카드

---

#### Phase ② PRE_VISIT — 방문 전 준비 (D-7 ~ D-0)

**상황**: 예약일이 7일 이내로 다가옴. 병원 방문을 위한 사전 준비가 필요한 시점.

**환자 심리**:
- "뭘 준비해 가야 하지?"
- "금식해야 하나? 약은 먹어도 되나?"
- "병원 어디로 가야 하지?"
- "문진표를 미리 작성해두면 빨리 끝나겠지"

**포털이 해결할 문제**:

| 문제 | 해결 방법 |
|------|-----------|
| 검사 전 금식 여부를 모름 | D-1 자동 알림: "내일 혈액검사 — 자정부터 금식" |
| 문진표/동의서를 현장에서 작성하면 대기 시간 증가 | 사전 작성 체크리스트 + 완료율 표시 |
| 진료실 위치를 모름 | 건물/층/진료실 번호 안내 + 길찾기 링크 |
| 준비물을 빠뜨림 | 방문 준비 체크리스트 (보험증, 복용약 등) |

**시나리오 예시**:
> 45세 직장인 이씨. 내과 정기 진료가 이틀 후다.
> 포털이 "D-2: 문진표 미작성, 금식 검사 있음"을 알린다.
> 이씨는 퇴근 후 포털에서 문진표를 작성하고, 내일 자정부터 금식임을 확인한다.
> D-0 아침, "오늘 09:30 내과, 본관 3층 진료실 302. 주차장 B2 이용 권장" 알림을 받는다.

**자동 알림 타임라인**:
```
D-7  예약 리마인더 + 문진표 링크 전송
D-3  동의서 미완료 시 재알림
D-1  금식 안내 + 준비물 체크리스트 + 약 복용 주의
D-0  출발 알림 + 교통/주차 + 진료실 위치
```

**핵심 화면 요소**: 방문 준비 체크리스트(프로그레스 바), 금식/복용 주의사항 카드, 길찾기 카드

---

#### Phase ③ OUTPATIENT_TODAY — 당일 외래

**상황**: 환자가 병원에 도착하여 접수/대기/진료/수납 과정을 거치는 중.

**환자 심리**:
- "내 순서가 언제 오지? 얼마나 기다려야 하지?"
- "진료실이 어디지?"
- "진료 끝나면 뭘 해야 하지? (검사? 수납? 약?)"

**포털이 해결할 문제**:

| 문제 | 해결 방법 |
|------|-----------|
| 대기 시간을 알 수 없어 불안함 | 실시간 대기 번호 + 예상 시간 + 풀스크린 |
| 진료 후 다음 단계를 모름 | 접수→대기→진료→수납 여정 타임라인 |
| 검사실 위치를 헤맴 | 검사 순서 + 위치 안내 카드 |
| 처방전을 어디서 받는지 모름 | 처방전 약국 전송 + 가까운 약국 안내 |

**시나리오 예시**:
> 이씨가 병원에 도착하여 접수한다.
> 포털 홈이 자동으로 "오늘의 진료 여정" 카드로 전환된다.
> "대기 번호 127 · 앞에 3명 · 약 15분" — 풀스크린 대기 화면을 켜놓고 기다린다.
> 진료 후 "혈액검사(2층 검사실) → 수납(1층)" 순서 안내가 나타난다.
> 수납 완료 후 "처방전 → 근처 약국 전송" 버튼이 활성화된다.

**핵심 화면 요소**: TodayJourneyCard (기존), 풀스크린 대기 화면 (기존), 검사 순서 카드, After Visit Summary

---

#### Phase ④ PRE_ADMISSION — 입원 전 준비

**상황**: 의사가 입원을 결정하고 입원 오더를 발행함. 실제 입원 전까지의 준비 기간.

**환자 심리**:
- "입원하면 뭘 가져가야 하지?"
- "수술이 있다면 어떤 준비를 해야 하지?"
- "비용은 얼마나 들까?"
- "회사에 며칠 쉬어야 하지?"

**포털이 해결할 문제**:

| 문제 | 해결 방법 |
|------|-----------|
| 입원 절차를 모름 | 입원 안내문 (병동/호실/준비물/면회 시간) |
| 수술 전 준비사항을 모름 | 수술 전 검사 일정 + 금식/약물 중단 안내 |
| 동의서를 현장에서 작성하면 시간 소요 | 사전 전자 서명 (입원/수술 동의서) |
| 예상 비용을 알 수 없음 | 예상 입원비 안내 (진단별 평균) |
| 보호자 연락처 미등록 | 보호자 정보 사전 등록 폼 |

**시나리오 예시**:
> 김씨(55세)가 무릎 수술을 위해 3일 후 입원 예정이다.
> 포털이 "입원 D-3" 카드를 표시한다.
> 체크리스트: 입원 동의서(서명 완료), 수술 동의서(미서명), 사전 의료의향서(미확인).
> 수술 전 주의: "아스피린 3일 전 중단 → 오늘부터 중단하세요", "6/6 수술 전 혈액검사 예약됨".
> 준비물: 신분증, 세면도구, 편한 옷, 실내화. 귀중품 반입 금지.

**핵심 화면 요소**: 입원 안내 Hero 카드, 입원 준비 체크리스트, 수술 전 주의사항, 준비물 안내

#### Phase ⑤ INPATIENT — 입원 중

**상황**: 환자가 병동에 입원 중. 매일 회진, 투약, 검사, 식사가 반복되는 일상.

**환자 심리**:
- "오늘 무슨 검사가 있지? 회진은 언제 오시지?"
- "지금 맞고 있는 약이 뭐지?"
- "점심 메뉴가 뭐지? 바꿀 수 있나?"
- "의사 선생님이 뭐라고 하셨지? (회진 내용 기억 안 남)"
- "입원비가 지금까지 얼마나 나왔지?"
- "간호사 선생님 좀 불러야 하는데..."

**포털이 해결할 문제**:

| 문제 | 해결 방법 |
|------|-----------|
| 오늘 일정(검사/회진/치료)을 파악하기 어려움 | 시간대별 일정 타임라인 |
| 투약 시간/약물명을 모름 | MAR 기반 투약 현황 (투여 완료/예정) |
| 회진 내용을 기억하지 못함 | 회진 기록 요약 카드 (환자 공개용) |
| 식단을 미리 알 수 없음 | 당일 식단 카드 + 변경 요청 |
| 바이탈 추이를 확인하고 싶음 | 입원 이후 활력징후 그래프 |
| 입원비 누적 현황을 모름 | 중간 정산 카드 |
| 긴급 시 간호사 호출이 어려움 | 포털 내 간호사 호출 버튼 |
| 보호자에게 상태 공유가 번거로움 | 1회용 상태 공유 링크 생성 |

**시나리오 예시 — 입원 3일차 하루**:
> 아침 7:00 — 포털에 "오늘 일정" 카드가 갱신된다:
>   08:00 투약, 09:00 혈액검사, 10:30 회진, 14:00 물리치료
>
> 08:10 — 투약 카드에 "메트포르민 500mg 투여 완료" 표시.
>
> 09:30 — 검사 후 "혈액검사 — 결과 대기 중" 카드 표시.
>
> 10:45 — 회진 후 "김내과 교수 회진 기록" 카드 등장:
>   "혈당 안정 추세. 내일 재검사 후 퇴원 여부 결정."
>
> 12:00 — 식단 카드: "점심 — 밥 + 된장찌개 + 생선구이 (당뇨식)"
>   → "생선 알레르기 있어서 변경 요청" 버튼 탭.
>
> 15:00 — 검사 결과 도착: "혈당 108 (정상 범위 내)" 카드.
>
> 17:00 — 보호자에게 "오늘 상태 공유" 링크를 카카오톡으로 전송.
>   보호자가 링크를 열면: 바이탈, 식사, 투약, 회진 기록 요약 표시.
>
> 22:00 — 수면 전 투약 "수면유도제(PRN) — 필요 시 간호사 호출" 안내.

**핵심 화면 요소**: 입원 현황 Hero, 오늘 일정 타임라인, 투약 현황(MAR), 식단 카드, 회진 기록, 검사 결과, 중간 정산, 간호사 호출 FAB

#### Phase ⑥ PRE_DISCHARGE — 퇴원 준비

**상황**: 의사가 퇴원을 결정하고 퇴원 오더를 발행함. 퇴원 당일 또는 전날.

**환자 심리**:
- "퇴원하면 약은 뭘 먹어야 하지?"
- "집에서 주의할 점이 뭐지?"
- "다음에 언제 병원에 와야 하지?"
- "퇴원 수속은 어떻게 하지?"
- "보험 청구는 어떻게?"

**포털이 해결할 문제**:

| 문제 | 해결 방법 |
|------|-----------|
| 퇴원 절차를 모름 | 퇴원 체크리스트 (약 수령 → 예약 → 수납 → 서류) |
| 퇴원 약이 바뀌었는지 모름 | 퇴원 약 목록 + 신규 약 강조 + 복용법 안내 |
| 집에서 주의할 점을 기억 못 함 | 퇴원 후 주의사항 카드 (식이/운동/제한/응급 증상) |
| 다음 외래 예약을 잊음 | 자동 예약 안내 + 예약 버튼 |
| 보험 청구 방법을 모름 | 퇴원 서류 + 보험 청구 가이드 |

**시나리오 예시**:
> 김씨의 퇴원이 내일로 결정되었다.
> 포털 홈이 "퇴원 준비" 모드로 전환된다.
>
> 체크리스트:
>   ✅ 퇴원 처방 확인 → "리피토 20mg 신규 추가" 강조 표시
>   ☐ 퇴원 약 수령 → 약국 위치 안내
>   ☐ 다음 외래 예약 → "2주 후 내과" 자동 제안, [예약 확인] 버튼
>   ☐ 퇴원 수납 → 총 입원비 안내
>   ☐ 만족도 조사 → 간단 5문항
>
> 퇴원 후 주의사항:
>   식이: 저당/저지방 식단 유지
>   운동: 하루 30분 걷기
>   제한: 무거운 물건 들기 1주 금지
>   응급: "심한 어지러움, 호흡곤란, 고열 시 즉시 내원"
>
> 처방전 약국 전송: [가까운 약국 선택] → 전송 완료.

**핵심 화면 요소**: 퇴원 안내 Hero, 퇴원 체크리스트, 퇴원 약 목록(신규 강조), 주의사항 카드, 다음 예약 카드

---

#### Phase ⑦⑧ POST_DISCHARGE — 퇴원 후 사후 관리

**상황**: 퇴원 후 30일 이내. 자택에서 회복 중이며, 복약과 추적 관찰이 필요한 시기.

**환자 심리**:
- "이 증상은 정상인 건가? 병원에 다시 가야 하나?"
- "약을 제대로 먹고 있는지 확인하고 싶다"
- "추적 검사 날짜가 언제였지?"
- "보험 청구 서류가 필요한데..."

**포털이 해결할 문제**:

| 문제 | 해결 방법 |
|------|-----------|
| 퇴원 후 이상 증상 판별이 어려움 | 응급 증상 안내 카드 + 주치의 메시지 |
| 복약 순응도가 떨어짐 (특히 신규 약) | 복용 체크 + 주간 복용률 + 리마인더 |
| 추적 검사 일정을 잊음 | 추적 관찰 캘린더 + D-day 알림 |
| 회복 상태를 파악하기 어려움 | 자가 기록(체온/혈당/체중) + 추이 비교 |
| 퇴원 서류(요약서/진단서)가 필요함 | 퇴원 서류 다운로드 + 보험 청구 안내 |
| 재입원 위험 감지 못 함 | AI 이상 징후 모니터링 ("혈당이 3일 연속 200 이상") |

**시나리오 예시 — 퇴원 D+7**:
> 김씨가 퇴원 후 1주. 매일 아침 혈당을 포털에 기록한다.
>
> 포털 홈:
>   "퇴원 후 D+7" 배너 — 퇴원 진단: 제2형 당뇨병
>
>   복약 관리: 이번 주 복용률 92% (메트포르민 100%, 리피토 85%)
>     → "리피토를 어제 빼먹었습니다. 저녁 식후 복용해주세요"
>
>   회복 추적: 혈당 추이 그래프 — 퇴원 시 112 → 이번 주 평균 118
>     → "혈당이 약간 상승 추세입니다. 식이 조절을 권장합니다"
>
>   추적 일정: "6/14 추적 혈액검사 (D-7)" 카드
>
>   주치의 메시지: "혈당 기록 잘 하고 계십니다. 다음 외래 때 조절 여부 확인하겠습니다."

**자동 알림 타임라인 (퇴원 후)**:
```
D+1   "퇴원 약 복용 시작하셨나요?" + 복용법 재안내
D+3   복용률 70% 미만 시 리마인더
D+7   회복 상태 확인 + 자가 기록 독려
D+14  추적 검사 리마인더 (예약 확인)
D+21  다음 외래 D-7 리마인더
D+30  사후 관리 종료 → IDLE 전환 (만성질환은 지속)
```

**핵심 화면 요소**: 퇴원 후 D+N 배너, 복용 체크+복용률, 회복 추적 그래프, 추적 일정 카드, 응급 증상 안내, 퇴원 서류 다운로드

### 1.5 Phase 전환 시 사용자 경험

환자는 Phase 전환을 **의식하지 않습니다**. 포털이 HIS 상태를 자동 감지하여 화면이 자연스럽게 바뀝니다.

**전환 시 UX 원칙:**

| 원칙 | 설명 | 예시 |
|------|------|------|
| **자동 전환** | HIS 이벤트 발생 → 포털 홈 자동 갱신 | 입원 확정 → 홈이 입원 모드로 전환 |
| **소프트 알림** | 상태 변경 시 카드 애니메이션 + 토스트 | "입원이 확정되었습니다 — 5병동 502호" |
| **이전 정보 보존** | 이전 Phase 정보도 접근 가능 | 입원 중에도 "내 건강" 탭에서 외래 검사 결과 조회 |
| **점진적 공개** | 필요한 정보만 우선 표시, 상세는 탭하면 확장 | 투약 카드: 오늘 약 3개 → 탭하면 시간별 상세 |
| **이중 안전장치** | 자동 전환 + 수동 새로고침 지원 | 풀다운 새로고침 또는 1분 폴링 |

**전환 시각화:**

```
환자가 병원 도착, 접수

  포털 홈 (기존 IDLE 카드들)
      ↓ fade-out
  🔔 "접수되었습니다 — 내과 127번"
      ↓ fade-in
  포털 홈 (OUTPATIENT 카드들)
    ├─ 오늘의 진료 여정 (접수→대기→진료→수납)
    ├─ 대기 번호 127 · 앞 3명
    └─ 예상 대기 15분


의사가 입원 결정

  포털 홈 (OUTPATIENT 카드들)
      ↓ fade-out
  🔔 "입원이 결정되었습니다 — 5병동 502호"
      ↓ fade-in
  포털 홈 (INPATIENT 카드들)
    ├─ 입원 현황 Hero (병동/주치의/입원일)
    ├─ 오늘 일정 타임라인
    └─ 투약/식단/회진
```

### 1.6 Phase 간 관계도

각 Phase는 단순히 선형이 아니라, 상황에 따라 분기/복귀가 발생합니다.

```
                    ┌──────────────┐
                    │   ① IDLE     │ ←───────────────────────────┐
                    │  (원외 관리)  │                              │
                    └──────┬───────┘                              │
                           │ 예약 D-7                             │
                    ┌──────▼───────┐                              │
                    │ ② PRE_VISIT  │                              │
                    │  (방문 전)    │                              │
                    └──────┬───────┘                              │
                           │ 당일 접수                            │
                    ┌──────▼───────┐                              │
                    │ ③ OUTPATIENT │                              │
                    │  (당일 외래)  │──── 외래로 끝남 ─────────────┘
                    └──────┬───────┘        (수납 후)
                           │ 입원 결정
                    ┌──────▼───────┐
                    │④ PRE_ADMIT   │
                    │  (입원 전)    │
                    └──────┬───────┘
                           │ 입원 확정
                    ┌──────▼───────┐
              ┌────│ ⑤ INPATIENT  │────┐
              │    │  (입원 중)    │    │
              │    └──────┬───────┘    │
              │           │ 퇴원 결정   │ 전동(병동 이동)
              │    ┌──────▼───────┐    │ → INPATIENT 유지
              │    │⑥ PRE_DISCH   │    │
              │    │  (퇴원 준비)   │◄──┘
              │    └──────┬───────┘
              │           │ 퇴원 확정
              │    ┌──────▼───────┐
              │    │⑦⑧ POST_DISCH│
              │    │  (사후 관리)  │──── 30일 경과 ──→ ① IDLE
              │    └──────┬───────┘
              │           │ 재입원
              └───────────┘

  * 응급 재입원: ①→⑤ 직행 (PRE_VISIT/OUTPATIENT 건너뜀)
  * 당일 입원: ③→⑤ 직행 (PRE_ADMISSION 건너뜀)
  * 만성질환: ⑧→① 전환 없이 IDLE에서 지속 관리
```

### 1.7 Phase별 하단 탭 동작

3탭(홈/내건강/더보기) 구조는 모든 Phase에서 동일하지만, **홈 탭의 카드 구성**이 Phase에 따라 바뀝니다.

| Phase | 홈 탭 | 내 건강 탭 | 더보기 탭 |
|-------|-------|-----------|----------|
| IDLE | 건강 점수, 복용 체크, 자가 기록, 예방 검진 | 검사 추이, 복용약, 예방접종 | 동일 |
| PRE_VISIT | 방문 준비 체크리스트, 금식 안내, 길찾기 | 동일 | 동일 |
| OUTPATIENT | 진료 여정, 대기 번호, To-Do | 동일 | 동일 |
| PRE_ADMISSION | 입원 안내, 준비 체크리스트, 수술 전 주의 | 동일 | + 입원 안내문 |
| **INPATIENT** | **입원 현황, 일정, 투약, 식단, 회진, 중간정산** | **+ 바이탈 추이, 간호 기록** | **+ 간호사 호출, 보호자 공유** |
| PRE_DISCHARGE | 퇴원 체크리스트, 퇴원 약, 주의사항 | 동일 | + 퇴원 서류 |
| POST_DISCHARGE | 복용 체크, 회복 추적, 추적 일정, 응급 안내 | + 회복 추이 비교 | + 퇴원 서류, 보험 청구 |

### 4.2 Lifecycle Evaluator (신규 서비스)

```typescript
// apps/api/src/modules/portal/lifecycle-evaluator.service.ts

interface LifecycleStatus {
  phase: 'IDLE' | 'PRE_VISIT' | 'OUTPATIENT_TODAY' | 'PRE_ADMISSION'
        | 'INPATIENT' | 'PRE_DISCHARGE' | 'POST_DISCHARGE';
  admission?: AdmissionInfo;
  todaySchedule?: ScheduleItem[];
  pendingActions?: string[];
  alerts?: Alert[];
}

// 이벤트 리스너
@OnEvent('admission.admitted')
handleAdmission(payload) {
  // 1. 포털 상태 → INPATIENT로 전환
  // 2. 입원 안내 카드 데이터 준비
  // 3. SSE/FCM 푸시: "입원이 확정되었습니다"
}

@OnEvent('admission.discharged')
handleDischarge(payload) {
  // 1. 포털 상태 → POST_DISCHARGE로 전환
  // 2. 퇴원 체크리스트 카드 생성
  // 3. 퇴원 후 D+1, D+7, D+30 알림 스케줄링
}

@OnEvent('round.completed')
handleRound(payload) {
  // 1. 입원 포털에 "회진 기록" 카드 갱신
  // 2. 환자 푸시: "회진 기록이 등록되었습니다"
}

@OnEvent('mar.administered')
handleMedication(payload) {
  // 1. 입원 포털 투약 카드 갱신
  // 2. PRN 약물일 경우 추가 안내
}
```

### 4.4 포털 FE 상태 관리

```typescript
// 포털 진입 시
const { data: lifecycle } = useQuery({
  queryKey: ['portal-lifecycle'],
  queryFn: () => fetch('/api/v1/portal/lifecycle-status'),
  refetchInterval: 60000, // 1분 폴링 (SSE 백업)

// SSE 수신 시 자동 갱신
useEffect(() => {
  const es = new EventSource('/api/v1/portal/events/stream');

  return () => es.close();
}, []);

// Phase에 따라 홈 카드 스트림 자동 전환
function HomeTab({ lifecycle }) {
  switch (lifecycle.phase) {
    case 'IDLE': return <IdleCards />;
    case 'PRE_VISIT': return <PreVisitCards />;
    case 'OUTPATIENT_TODAY': return <OutpatientCards />;
    case 'PRE_ADMISSION': return <PreAdmissionCards />;
    case 'INPATIENT': return <InpatientCards />;
    case 'PRE_DISCHARGE': return <PreDischargeCards />;
    case 'POST_DISCHARGE': return <PostDischargeCards />;
  }
}
```
