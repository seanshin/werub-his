# 상호작용 전수 점검 (Interaction Sweep) — 눌러보고, 넣어보고, 되돌린다

> 발의: 사람 지시(2026-08-26) — *"각 화면의 기능들을 모두 클릭하고 데모 및 시드 데이터를 입력하는
> 방식으로 전체적인 기능의 완성도와 오류를 점검하는 프로세스를 병렬로 체크하고 수정하는 기획서."*
> 상태: **초안 · 미착수**

---

## 0. 기존 두 축과 무엇이 다른가

| 축 | 질문 | 상태 |
|---|---|---|
| 화면 실사용 점검(W0~W9) | **화면이 사실을 말하는가** — 열어서 **읽는다** | 완주(254화면·950결함) |
| 시드 흐름 전수 검토 | **흐름이 이어지는가** — 데이터를 **따라간다** | 완주(10흐름·27결함) |
| 🔴 **이 축(누르기)** | **눌렀을 때 실제로 일어나는가** — **쓰고 되돌린다** | 신규 |

읽기 축이 이미 세 번 같은 것을 말했다:
> **"데이터 0행"을 믿기 전에 쓰기 경로를 눌러본다** — 폼이 막혀 있던 사례 **3건**
> (배너 '추가' 버튼에 `onClick` 부재 · 등록 폼 미렌더 2건).

세 번 나왔다는 것은 **읽기 축의 사각지대**라는 뜻이다. 그 사각지대만 겨냥한다.

### 🔴 이 축이 아니면 못 잡는 것 (이미 나온 실적)

- 버튼에 `onClick` 이 없다 — 화면은 완벽해 보인다
- 저장은 200 인데 **필드가 whitelist 로 조용히 삭제**된다(성공 토스트 + 데이터 소실 · 실적 다수)
- 서버가 400 을 주는데 **단위 테스트는 통과**한다(수술기록 `ebl` · 개통 이래 저장 0건)
- 게이트가 켜져 있는데 **발동한 적이 없다**(퇴원 미납 차단 · DUR 43룰)
- 오더는 저장되는데 **실행 경로가 옛 값을 읽는다**(고단백식 처방 → 일반식 배식)

## 1. 🔴 시작 전 반드시 통과해야 하는 다섯 가지 (Pre-flight)

**하나라도 미확인이면 착수하지 않는다.** 누르는 축은 되돌릴 수 없는 것을 만들 수 있다.

| # | 확인 | 왜 |
|---|---|---|
| **PF1** | **대외 발신이 실제로 막혀 있는가** — 리허설 모드에서 `CrmChannelService.send()` 가 `SIMULATED` 인지 **눌러서** 확인 | 🔴 문자·메일이 나가면 되돌릴 수 없다. **모드 설정만 믿지 않는다** — v4.8.0 에서 발신 차단이 **한 지점뿐**이고 `integration-outbox` 는 안 탄다고 이미 적어 두었다 |
| **PF2** | **기관 전송 채널이 전부 미구현/OFF 인가** — `/admin/outbound-channels` 실측 | NIMS·HIRA·KIDS·HIE 로 나가면 기관 기록이 된다 |
| **PF3** | **DB 백업이 오늘 있는가** — `/admin/go-live` `security.dbBackup` 이 판정 | 🔴 되돌리지 못하는 조작이 나오면 백업이 마지막 수단이다. 백업 크론은 **89일 죽어 있던 전력**이 있다 |
| **PF4** | **테스트 환자·테스트 계정 집합이 정해졌는가** | 🔴 실환자처럼 보이는 데이터를 만들지 않는다. 이 DB 는 가상 병원이지만 **시드 표식 4종**으로 구분 가능해야 한다 |
| **PF5** | **원복 절차가 문서로 있는가** — 조작별 되돌리기 | 되돌릴 수 없는 것은 **누르지 않고 등재만** 한다 |

## 2. 🔴 부작용 반경(Blast Radius)을 먼저 적는다

시드 흐름 축에서 배운 것 그대로다 — **응급 처분 버튼 하나가 청구까지 생성**했고, 원복해야 했다.

**누르기 전에 그 버튼이 무엇을 만드는지 나열한다.** 나열하지 못하면 누르지 않는다.

### 반경 등급

| 등급 | 뜻 | 규칙 |
|---|---|---|
| **B0 조회** | 읽기만. 감사 로그만 남는다 | 자유롭게 |
| **B1 원내 기록** | 원내 DB 에 행이 생긴다. 되돌리기 가능 | 누른다 · **원복까지 한 벌** |
| **B2 연쇄** | 다른 도메인에 파생 생성(처분→청구·오더→작업목록) | 🔴 **파생을 먼저 나열**하고 누른다 · 원복은 역순 |
| **B3 대외/법정** | 밖으로 나가거나 법정 기록이 된다(전송·보고·발급·서명) | 🔴 **누르지 않는다.** 미구현/차단 확인만 하고 **등재** |
| **B4 비가역** | 되돌릴 수 없다(마약류 폐기·서명 봉인·해시 체인·삭제) | 🔴 **절대 누르지 않는다.** 코드로 경로만 확인 |

🔴 **등급은 화면이 아니라 EP 기준으로 매긴다.** 같은 화면에 B0 과 B4 가 섞여 있다.

## 3. 데모·시드 데이터 투입 규칙

### 🔴 만들면 안 되는 것

- **실환자처럼 보이는 데이터** — 이름·주민번호·연락처가 그럴듯하면 나중에 실데이터와 섞인다
- **임상적으로 불가능한 값** — 시드 생성기가 저지른 전력이 있다(HbA1c 2%·QI 역산 273/300)
- **정상값으로 채운 기록** — 🔴 "정상"으로 채우면 **탐지기가 작동하는지 알 수 없다**

### 규칙

- 🔴 **테스트 표식을 남긴다** — 이름 접두 `TEST-` 또는 결정적 UUID. **나중에 지울 수 있어야 한다**
- 🔴 **표본을 일부러 남긴다** — 전건을 정상으로 채우면 게이트가 도는지 모른다.
  각 축마다 **정상 / 경계 / 위반** 세 건을 넣는다
- 🔴 **넣은 것을 기록한다** — 무엇을·어디에·언제. 지우지 못하면 축이 끝나도 쓰레기가 남는다
- **기존 시드를 고치지 않는다** — 시드 데이터 품질 결함은 코드 결함이 아니다.
  🔴 다만 **생성기가 틀렸으면 생성기를 고친다**(데이터는 손대지 않는다)

## 4. 판정 규칙 — 무엇이 결함인가

| 관찰 | 판정 |
|---|---|
| 버튼을 눌렀는데 **아무 일도 안 일어남** | 🔴 **결함**(`onClick` 부재·핸들러 미배선) |
| 저장 성공 토스트인데 **값이 안 들어감** | 🔴 **결함**(whitelist·DTO 미매핑) — 이 저장소 최다 유형 |
| 400/500 이 뜨는데 **화면이 이유를 안 말함** | 🔴 **결함**(예외 payload 소실 — 54개소 전력) |
| 게이트가 켜져 있는데 **위반을 넣어도 안 막힘** | 🔴 **결함**(탐지기 사망) |
| 막혔는데 **왜 막혔는지 모름** | 🔴 **결함**(사유 미표시) |
| 기능이 아예 없음 | **미구현** — 결함 아님. 등재하고 넘어간다 |
| 권한이 없어 못 누름 | **정상일 수 있다** — 🔴 nav 가 열어놓고 API 가 막으면 결함 |
| 데이터가 없어 화면이 빈다 | **시드 부재** — 🔴 단, **"0"이라 단언하면 결함** |

🔴 **결함 0건도 유효한 결과다.** 축을 돌고 아무것도 안 나오면 그렇게 적는다.

## 5. 병렬 운영 규격

사람 지시가 **병렬**이다. 이 저장소가 병렬에서 실제로 다친 것들을 규격으로 못박는다.

> 🔴 병렬에서 겪은 것: **스키마를 나눠 갖지 못한다**(코디네이터가 먼저 확정해야 했다) ·
> **인계를 그대로 믿었다가 옛 상태를 읽었다** · **API 과부하로 6→2 로 줄였다** ·
> **에이전트가 "범위 밖"이라 남긴 것을 코디네이터가 회수**해야 했다.

---

### 5.1 역할 — 코디네이터 1 · 레인 N

| 역할 | 할 수 있는 것 | 🔴 절대 하지 않는 것 |
|---|---|---|
| **코디네이터** | 레인 배분 · 재실측 · 병합 · **커밋/배포** · 스키마 확정 · System Scale 동결 · CLAUDE.md 편집 | 레인 작업을 대신하지 않는다(대신하면 재실측할 사람이 없다) |
| **레인** | 자기 도메인 화면을 누른다 · 자기 테스트 환자에만 쓴다 · 보고서를 낸다 | 🔴 **커밋·배포·스키마 변경·config 쓰기·다른 레인 환자 조작** |

🔴 **커밋과 배포는 코디네이터 단독이다.** 레인이 배포하면 다른 레인의 관측이 그 순간 무효가 된다
(pm2 재시작 · 웹 번들 교체).

---

### 5.2 레인 계약 (Lane Contract)

레인 하나를 띄울 때 **이 여섯 줄이 다 채워져야** 시작한다. 하나라도 비면 시작하지 않는다.

```
LANE:        L3-응급
SCOPE:       /emergency/* · /workstation/emergency · /admin/er-beds(조회만)
PATIENTS:    TEST-ER-01 ~ TEST-ER-03  (다른 레인 환자 금지)
FORBIDDEN:   B3·B4 전부 · config 쓰기 · 커밋/배포 · 스키마
BASELINE:    관측 시작 시각(KST) + 그 시점 배포 커밋 해시
DELIVERABLE: findings.jsonl (§5.6 형식) + 원복 로그
```

🔴 **`BASELINE` 이 없으면 보고를 병합할 수 없다.** 같은 화면을 두 레인이 다른 배포본에서 보면
서로 다른 것을 말하고, 코디네이터는 어느 쪽이 맞는지 알 수 없다.

---

### 5.3 레인 분할 — 🔴 화면이 아니라 **도메인**으로

같은 환자·같은 오더를 두 레인이 동시에 만지면 **서로의 상태를 밟고, 그것을 결함으로 오판**한다.

| 레인 | 범위 | 전용 테스트 환자 | 겹침 주의 |
|---|---|---|---|
| **L1** 외래·접수 | 접수·대기·진료실·수납 | `TEST-OPD-*` | 수납은 L5 처방과 이어진다 → **처방 없는 환자**로 |
| **L2** 입원·병동 | 입원·병상·간호·급양 | `TEST-IPD-*` | 병상은 L3 과 같은 테이블 → **병동 type=GENERAL 만** |
| **L3** 응급 | 트리아지·처치·퇴실 | `TEST-ER-*` | 병상은 **EMERGENCY 병동만** |
| **L4** 검사·영상 | 오더·시행·결과·판독 | `TEST-DX-*` | 오더는 L1/L2 에서도 생긴다 → **자기 환자 오더만** |
| **L5** 약제 | 처방·조제·DUR(B4 마약류 제외) | `TEST-RX-*` | — |
| **L6** 관리·설정 | 마스터·설정·게이트·관제 | (환자 무관) | 🔴 **전역 영향** — §5.5 |

---

### 5.4 공유 자원 — 🔴 직렬화하지 않으면 서로를 깨뜨린다

| 자원 | 왜 위험한가 | 규칙 |
|---|---|---|
| **스키마** | 두 레인이 각자 바꾸면 배포가 갈린다 | 🔴 S0 에서 **코디네이터가 한 번에 확정·배포**. 이후 스윕 중 **스키마 동결** |
| **`system_configs`** | 임계 하나 바꾸면 **모든 레인의 판정**이 바뀐다 | 🔴 레인은 **읽기만**. 변경은 L6 단독 구간에서만 |
| **배포(pm2)** | 재시작 순간 다른 레인 관측이 무효 | 🔴 코디네이터 단독 · **배포 창(window)** 을 공지하고 그때 레인 일시정지 |
| **git** | 동시 커밋 충돌 | 🔴 레인은 커밋하지 않는다. 보고서만 낸다 |
| **CLAUDE.md · System Scale lock** | 단일 파일 | 🔴 코디네이터만 편집·동결 |
| **시드 롤포워드 크론(매일 09:00 KST)** | 데이터 시각이 통째로 이동 | 🔴 **크론 전후를 같은 관측으로 묶지 않는다.** 보고에 관측 시각 필수 |
| **테스트 환자** | 서로 밟으면 오판 | 레인 접두로 격리(§5.3) |

---

### 5.5 동기화 지점 (Barrier) — 여기서는 전원 멈춘다

병렬은 **막을 곳을 정해야** 병렬이다.

| # | 지점 | 왜 멈추나 |
|---|---|---|
| **B-0** | S0 종료(Pre-flight·스키마 확정·테스트 환자 생성) | 🔴 하나라도 미완이면 아무 레인도 시작하지 않는다 |
| **B-1** | 자동 스캔 A1~A5 결과 배분 | 후보를 나눠 갖고 시작해야 중복 조사를 안 한다 |
| **B-2** | **배포 창** — 코디네이터가 봉합분을 배포할 때 | 재시작 중 관측은 버린다 |
| **B-3** | 레인 종료 → **코디네이터 재실측** | 🔴 재실측 전에는 어떤 결함도 "확정"이 아니다 |
| **B-4** | L6(설정) 단독 구간 | 🔴 설정이 바뀌면 앞선 판정이 흔들린다 — **L6 은 반드시 마지막** |
| **B-5** | S6 테스트 데이터 정리 | 정리 전에 축을 끝내지 않는다 |

---

### 5.6 보고 형식 — 🔴 기계로 병합 가능해야 한다

레인이 산문으로 보고하면 코디네이터가 **다시 다 읽어야** 하고, 그러면 병렬이 아니다.
레인은 `findings.jsonl` 한 줄에 하나씩 낸다.

```json
{"lane":"L3","observedAt":"2026-08-26T14:03+09:00","build":"309fb165",
 "screen":"/emergency/triage","control":"[분류 저장] 버튼","blast":"B1",
 "expected":"KTAS 3 저장 후 목록에 반영","actual":"성공 토스트·목록 미반영",
 "reread":"목록·DB 둘 다 확인함","verdict":"DEFECT","pattern":"저장 성공인데 값 없음",
 "rollback":"삭제함","evidence":"screenshot|sql|log 경로"}
```

**필수 필드와 그 이유**

| 필드 | 없으면 |
|---|---|
| `observedAt` · `build` | 🔴 어느 배포본을 봤는지 몰라 **재실측이 불가능**하다 |
| `blast` | 반경을 안 매기고 눌렀다는 뜻이다(§2 위반) |
| `reread` | 🔴 **저장 후 다시 읽지 않은 보고는 이 축에서 무효**다(§6-5) |
| `verdict` | `DEFECT` / `NOT_IMPLEMENTED` / `SEED_ABSENT` / `OK` — **OK 도 낸다**(결함 0건도 결과) |
| `rollback` | B1/B2 인데 비어 있으면 **정리 대상이 남았다**는 뜻 |

---

### 5.7 코디네이터 루프 (라운드마다 반복)

1. **수집** — 레인별 `findings.jsonl` 을 모은다
2. **중복 제거** — `screen+control` 로 접는다. 🔴 **레인이 다르면 같은 결함도 다르게 쓴다**
3. **재실측** — 🔴 `verdict:DEFECT` 는 **코디네이터가 직접 다시 눌러본다.**
   *(전례: 병렬 레인의 인계를 그대로 믿었다가 동시 수정분을 옛 상태로 읽었다.
   그리고 내가 넘긴 가설도 오탐일 수 있다.)*
4. **회수** — 레인이 "범위 밖"이라 남긴 것을 **코디네이터가 가져온다**(전례 3건)
5. **봉합·가드·배포** — 위험순. **배포 전 B-2 공지**
6. **부하 조정** — API 가 느려지면 **동시 레인을 줄인다**(전례 6→2)

---

### 5.8 실패 격리

- 레인 하나가 막혀도 **다른 레인은 계속한다**(`Promise.all` 이 아니라 `allSettled` 의 사람 버전)
- 막힌 레인은 **막혔다고 보고**한다 — 🔴 조용히 빈 보고서를 내면 "결함 없음"으로 읽힌다
- 🔴 **부작용을 되돌리지 못한 레인은 즉시 멈추고 코디네이터를 부른다.** 계속 누르면 반경이 겹친다

## 6. 한 화면을 어떻게 훑는가 (레인 내부 절차)

1. **컨트롤 목록을 만든다** — 버튼·링크·폼·토글·드롭다운. 🔴 **접힌 것·모달 안까지**
2. **각 컨트롤에 반경 등급을 매긴다**(§2). B3·B4 는 누르지 않는다
3. **B0 부터 누른다** — 조회가 깨지면 그 아래는 볼 필요가 없다
4. **B1/B2 는 세 건씩** — 정상 / 경계 / 위반
5. **저장 후 반드시 다시 읽는다** — 🔴 **성공 토스트는 증거가 아니다.** 목록·상세·DB 로 확인
6. **원복한다** — 원복도 눌러서 한다(원복 경로 자체가 결함일 수 있다)
7. **기록한다** — 화면·컨트롤·반경·기대·실제·판정

### 🔴 5번이 이 축의 핵심이다

이 저장소의 최다 결함 유형이 **"성공했다는데 안 들어간 것"**이다.
`whitelist:true` 가 DTO 에 없는 키를 조용히 지우고 200 을 돌려준다.
**저장 → 다시 읽기**를 하지 않으면 이 축은 아무것도 못 잡는다.

## 7. 자동화로 미리 좁히기 (사람이 누르기 전에)

전부 손으로 누르면 254화면 × 컨트롤 수십 개다. **기계가 먼저 후보를 좁힌다.**

| 도구 | 무엇을 찾나 | 비고 |
|---|---|---|
| **A1 `onClick` 없는 버튼 스캔** | 눌러도 아무 일 없는 버튼 | 정적 스캔 · 🔴 오탐 많음(form submit·label) — 후보일 뿐 |
| **A2 FE 전송 키 ↔ DTO 키 기계 대조** | whitelist 로 사라질 필드 | 🔴 **최다 유형 정면 조준** |
| **A3 쓰기 EP 중 화면 호출부 0** | 만들었는데 아무도 안 부르는 EP | 고아 EP |
| **A4 게이트 ON 인데 위반 로그 0** | 탐지기 사망 후보 | DUR 43룰·퇴원 게이트가 이렇게 잡혔다 |
| **A5 `@Body` 인라인·교차타입 DTO** | 검증이 실행되지 않는 EP | 기준선 이미 동결됨 — 신규만 |

🔴 **A1~A5 는 후보를 내는 도구지 판정기가 아니다.** 확정은 눌러서만 한다.
그리고 🔴 **내 스캔 도구가 먼저 거짓말한다** — 이 저장소에서 주석을 코드로 센 사례 **3회**,
괄호 균형 없이 세어 래퍼를 호출부로 센 사례 1회. **히트를 세기 전에 그 줄이 코드인지 본다.**

S0  Pre-flight · 스키마 확정·배포 · 테스트 환자 6세트 · 원복 절차      [코디네이터 단독]
                                   │
                              ─── B-0 ───
                                   │
S1  자동 스캔 A1~A5 → 후보 배분                                        [코디네이터 단독]
                                   │
                              ─── B-1 ───
                     ┌────┬────┬────┼────┬────┐
S2                  L1   L2   L3   L4   L5        ← 🔴 **동시 실행**
                     └────┴────┴────┼────┴────┘
                              ─── B-3 ───

                                   │
                              ─── B-5 ───

|---|---|---|
| **S0** | 착수 가능 판정 | 단독 |
| **S1** | 레인별 후보 목록 | 단독 |
| **S2** | 레인별 `findings.jsonl` | 🔴 **L1~L5 병렬** |

## 9. 사람이 정해야 하는 것

| # | 결정 | 왜 사람인가 |
|---|---|---|
| 1 | **어디서 돌릴 것인가** — 운영(리허설) DB vs 별도 인스턴스 | 운영에서 돌리면 되돌려도 흔적이 남고, 별도면 "운영에서 되는가"를 못 본다 |
| 2 | **B3(대외·법정)을 정말 안 누를 것인가** — 안 누르면 그 경로는 끝까지 미검증으로 남는다 | 검증 안 된 채 개시할지, 기관 협의로 시험 전송할지 |
| 3 | **테스트 데이터를 개시 전에 전량 삭제할 것인가 격리할 것인가** | 삭제하면 재현이 안 되고, 남기면 실데이터와 섞인다 |
| 4 | **병렬 레인을 몇 개까지** 돌릴 것인가 | API·DB 부하와 **재실측 역량**. 🔴 레인을 늘려도 재실측은 코디네이터 한 사람이라 **거기가 병목**이다 |
| 5 | **레인을 사람이 맡나 에이전트가 맡나** | 에이전트면 §5.6 형식을 강제할 수 있고, 사람이면 화면을 눈으로 본다. 🔴 섞으면 보고 품질이 갈린다 |

🔴 **결정 1 이 미결이면 S0 을 통과할 수 없다** — 어디서 누를지 모르는 채 누를 수는 없다.

## 10. 성공 판정

이 축은 **"결함 N건"으로 성공을 재지 않는다.** 다음 넷으로 잰다.

1. **컨트롤 커버리지** — 반경 등급을 매긴 컨트롤 / 전체 컨트롤 (분모를 함께)
2. **저장 후 재확인율** — 눌러본 쓰기 중 **다시 읽어 확인한** 비율
3. **원복 성공률** — B1/B2 조작 중 되돌린 비율
4. **잔여 테스트 데이터** — 🔴 **0 이어야 한다**(아니면 그 목록을 남긴다)
5. **재실측률** — `DEFECT` 보고 중 코디네이터가 **직접 다시 눌러 확인한** 비율.
   🔴 **100% 여야 한다** — 재실측하지 않은 것은 확정이 아니다
6. **레인 보고 무효율** — `reread` 가 빈 보고의 비율. 🔴 높으면 §6-5 가 지켜지지 않은 것이다

🔴 **커버리지에 분모를 붙이지 않으면 이 축도 "안전 화면의 초록"이 된다.**

## 11. 1회차 실행 기록 (2026-08-26) — S0·S1 및 파생 봉합

사람 지시로 **S0 Pre-flight → S1 자동 스캔(5레인 병렬)** 을 실제로 돌렸다.
그 뒤 사람이 화면을 훑으며 신고한 것들이 S2(누르기) 를 대신했다.

### S0 Pre-flight 결과 — 🔴 **PF2 가 실패했고, 그것이 이 축의 첫 소득이었다**

| # | 결과 |
|---|---|
| PF1 실효 모드 | ✅ `HIS_MODE=REHEARSAL`(런타임 미설정 → 빌드 상한) |
| **PF2 대외 발신 차단** | 🔴 **실패** — `VoucherEmailService` 가 `CrmChannelService`(모드 차단 지점)를 거치지 않고 **Resend API 를 직접** 호출. 운영에 `email.provider=RESEND` + 실제 키가 설정돼 있어 **리허설에서 검진권·딜러 메일이 진짜로 나가고 있었다** |
| PF3 백업 | ✅ 당일 3본(최신 15MB) |
| PF4·PF5 | S1(조회 전용)에는 불요 — S2 착수 전으로 이연 |

🔴 **Pre-flight 이 제 일을 했다.** 이것을 확인하지 않고 S2(발송 버튼 누르기)에 들어갔다면
실제 메일이 나갔을 것이고, 되돌릴 수 없었다.
v4.8.0 에 "발신 차단은 `CrmChannelService.send()` **한 지점뿐**"이라고 적어 둔 그대로였다.

### S1 자동 스캔 — 5레인 병렬 실적

| 레인 | 분모 | 후보 | 특기 |
|---|---|---|---|
| A1 `onClick` 부재 | 버튼 3,589 | 8 | 오탐 3,583 자진 제외(미리보기 렌더·의도적 disabled·dnd 스프레드) |
| A2 FE↔DTO 대조 | 쓰기 호출 1,112(매칭 1,090) | 15 확정(6 HARD_FAIL·8 SILENT_DROP) | 🔴 **AST 로 import 체인까지 해소** |

### 🔴 이 회차에서 배운 것

- **레인이 자기 도구의 거짓말을 스스로 잡았다** — A2 는 이름 충돌로 9건, 캐스트 미인식으로 12건의
  **유령**을 냈다가 자진 철회했고, A3 는 세 번(베이스 URL·변수 조립·동명 메서드) 거짓말했다고 보고했다.
  🔴 **자진 철회를 보고에 남기게 한 것이 이 축의 핵심 장치**였다.
- **A4 가 "무발동"이라 단정하지 않은 것이 가장 값졌다.** 임상 쓰기 원장이 2026-08-18 에 멈춰 있고
  서비스 계층을 거치지 않은 시드라, 대부분의 "위반 0"은 **잴 것이 없었다**는 뜻이었다.
  분모를 재지 않았으면 거짓 경보 19건을 냈을 것이다.
- 🔴 **가드가 레인의 봉합 주석을 위반으로 셌다**(E1 보고). 주석 제외 스캔으로 고쳤다 —
  안 그러면 **실패를 피하려 설명을 지우게 된다.** 이 저장소에서 주석을 코드로 센 다섯 번째다.
- 🔴 **코디네이터가 없는 결함을 하나 고쳤다** — 엑셀 CSV BOM 처리. **재주입해도 가드가 실패하지 않아**
  `.trim()` 이 이미 지운다는 것을 알았다(실측 확인). 되돌리고 그 사실을 테스트에 못박았다.
  **정당 판정에 억지 가드를 만들지 않는다**의 실례다.

### S2(누르기)는 사람이 대신했고, 같은 유형이 네 번 나왔다

`/handoffs`·`/consultations`·`/nutrition`·`/rounds` — **서버에 등록 EP 가 있는데 그 이름을 단 화면은
조회·확인만** 할 수 있었다. A3(고아 쓰기 EP 234) 가 가리키던 것과 같은 축이다.
🔴 **자동 스캔이 후보를 냈고, 사람이 눌러 확정했다** — 이 축의 설계 그대로다.
