## 0. 한 줄

**두 축이 이미 다 만들어져 있는데 서로 묶여 있지 않다.** 자리(어디에 있는 PC 인가)는
브라우저가 자기 말로 주장하고, 서버는 그 말을 **검증하지 않는다**.

---

## 1. 지금 있는 것 — 축이 셋이다

| 축 | 모델 | 무엇을 정하나 | 화면 |
|---|---|---|---|
| **단말 보안** | `TerminalRegistry` | `PUBLIC`/`PRIVATE` · 전담 사용자 · 잠금 타임아웃 · 격리(`QUARANTINED`) · 비콘 | 단말 등록·오버라이드·데일리 PIN |
| **자리·주변기기** | `WorkstationProfile` + `PeripheralDevice` | 이 자리의 기본 라벨/문서 프린터 | 상단 바 워크스테이션 배지 |
| **논리 스테이션** | `WorkstationConfig` | 검사실 워크리스트 라우팅(`orderCodes`) | 검사·영상 워크스테이션 |

세 축은 각각 동작한다. 🔴 **문제는 1번과 2번을 잇는 고리다.**

### 1.1 고리는 설계돼 있다 — 그런데 운영에서 한 건도 성립하지 않는다

`workstation-setup/resolve` 는 `X-Device-UUID` → `TerminalRegistry` → **`WorkstationProfile.terminalId`
바인딩**을 찾아 `via: 'TERMINAL'`(자동)로 해석한다. 바인딩이 없으면 브라우저가 고른
`code`(localStorage)로 `via: 'CODE'` 가 된다.

**운영 실측(2026-08-26)**

| | 값 |
|---|---:|
| `terminal_registry` 등록 단말 | **5** (그중 `PRIVATE` 1) |
| `workstation_profiles` 자리 | **27** |
| 🔴 그중 단말에 바인딩된 자리(`terminal_id`) | **0** |
| `peripheral_devices` | 46 (전부 활성) |

→ 🔴 **`via:'TERMINAL'` 은 개통 이래 발생할 수 없었다.** 27개 자리는 전부 **브라우저 수동 선택**에만
의존하고 있고, 그 선택은 `localStorage` 에 있다.

## 2. 🔴 보안 관점에서 무엇이 문제인가

### 2-1. 자리 주장이 검증되지 않는다 (핵심)

`POST /workstation-setup/print/order-label` 은 요청 본문의 `code` 로 프린터를 찾는다
(`print.service.ts` `resolvePrinter`). **호출자의 단말이 실제로 그 자리에 있는지 확인하지 않는다.**

- 검체 라벨에는 **환자명·MRN·검사항목**이 실린다.
- 즉 **다른 층 다른 검사실 프린터로 남의 환자 라벨을 출력**시킬 수 있다.
  (악의가 없어도 발생한다 — 브라우저에 옛 선택이 남아 있으면 조용히 그쪽으로 나간다.)
- 🔴 지금 실피해는 확인되지 않았다(리허설·시드 환경). **구조가 열려 있다는 것과 피해가 있었다는 것은 다른 사실**이다.

### 2-2. 단말 보안 등급이 자리에 반영되지 않는다

`TerminalRegistry.mode` 는 사람이 말한 두 형태를 이미 구분한다:

| 형태 | 지금 표현 | 실제 자리 |
|---|---|---|
| **개인화 PC** | `PRIVATE` + `dedicatedUserId` | 진료실 |
| **크루 공용** | `PUBLIC` | 간호사 스테이션 · 응급실 · 검사실 |

🔴 그런데 **자리(`WorkstationProfile`)에는 이 구분이 없다.** 그래서
"이 자리는 공용이니 화면 잠금이 짧아야 한다", "이 자리에서는 전담자 외 인쇄를 막는다" 같은
**자리 기준 정책을 걸 수 없다.**

### 2-3. 격리된 단말이 자리 기능을 계속 쓴다

`TerminalRegistry.status = QUARANTINED`(분실·오염 의심)여도 **자리 해석·인쇄는 그대로 동작한다** —
그 둘이 이어져 있지 않기 때문이다.

### 2-4. ✅ 이번에 봉합한 것 — 전 직군 403

상단 바 배지는 **로그인한 모든 직원** 화면에 렌더되는데 `resolve`·`pick-list` 가 임상 5역할 전용이라
**14역할 중 9역할이 모든 화면에서 403** 을 받고 있었다.
🔴 컨트롤러 주석은 이미 *"정체성 해석(모든 직원)"* 이라 적혀 있었고 **코드가 그 주석을 어기고 있었다.**
2026-08-21 위급검사값 배너와 **같은 결함의 두 번째 발생**이라, 이번에는 역할 목록을
shared 정본(`EVERY_STAFF_ROLE`)으로 올리고 **역할 라벨 정본과 집합 일치를 가드**로 묶었다.

## 3. 보완 정의 — 무엇을 만들 것인가

### B1. 자리를 단말에 묶는다 (선행 · 나머지의 전제)

- `WorkstationProfile.terminalId` 를 **실제로 채운다.** 지금 0건이라 자동 해석 자체가 없다.
- 관리 화면에 **자리 ↔ 단말 바인딩** 편집을 둔다(등록된 단말 목록에서 고른다).
- 🔴 **자동으로 추측해 채우지 않는다** — IP·이름이 비슷하다고 묶으면 틀린 자리가 고정된다.

### B2. 서버가 자리 주장을 검증한다

인쇄 요청에서 `code` 를 **그대로 믿지 않는다.**

| 상태 | 서버 판정 |
|---|---|
| 단말이 그 자리에 바인딩됨 | 통과 |
| 단말은 등록됐는데 다른 자리를 주장 | 🔴 **거부**(오배송 방지) — 사유를 화면에 말한다 |
| 단말 미등록(비콘·IP 불명) | **정책 선택** — 게이트(§4 결정 1) |
| 단말이 `QUARANTINED` | 🔴 **거부** |

🔴 **처음부터 BLOCK 으로 켜지 않는다.** 이 저장소의 게이트 규약대로 `OFF → WARN → BLOCK`.
WARN 단계에서 "주장한 자리와 단말이 다르다" 를 로그·관제에 쌓고, 실제로 몇 건인지 본 뒤 승격한다.
(바인딩 0건 상태에서 BLOCK 을 켜면 **모든 인쇄가 즉시 멈춘다.**)

### B3. 자리에 형태를 부여한다 — 개인화 / 크루 공용

`WorkstationProfile` 에 **형태**를 둔다(단말의 `mode` 를 복사하지 않고 **자리의 성격**으로):

| 형태 | 예 | 따라오는 것 |
|---|---|---|
| `PERSONAL` | 진료실 | 전담자 기본 세션 · 잠금 타임아웃 김 |
| `SHARED_CREW` | 간호사 스테이션 · 응급실 | 🔴 잠금 짧게 · 교대 시 세션 정리 · 데일리 PIN |
| `SERVICE_POINT` | 검사실·영상실 | 워크리스트 라우팅(`WorkstationConfig`)과 결합 |

🔴 **단말 `mode` 와 자리 `형태` 는 다른 축이다.** 개인 노트북을 간호사 스테이션에 들고 갈 수 있다 —
그때 무엇을 따를지가 §4 결정 2다.

### B4. 격리·폐기가 자리 기능까지 끊는다

`status = QUARANTINED|RETIRED` 인 단말은 자리 해석·인쇄에서 **즉시 제외**한다.
현재 `kill-switch` 는 세션·패스키·PIN·초안까지 지우는데 **자리 기능은 남는다.**

### B5. 크루 교대 세팅

`SHARED_CREW` 자리에서 교대 시:
- 이전 근무자의 **작성 중 임시 보관(L1)** 을 정리한다(임상 기록 초안 축 §4.1 과 같은 축).
- 🔴 **자동으로 지우지 않는다** — "이전 근무자의 작성 중 내용이 있습니다"를 보여주고 인계한다.
  조용히 지우면 인계가 끊기고, 남겨두면 다른 사람 이름으로 저장될 수 있다.

## 4. 사람이 정해야 하는 것

| # | 결정 | 왜 사람인가 | 층 |
|---|---|---|---|
| 1 | **미등록 단말**의 인쇄를 어떻게 할 것인가(허용 / 경고 / 거부) | 막으면 현장이 멈추고, 열면 오배송이 남는다 | 정보보호·진료부 |
| 2 | 단말 `mode` 와 자리 `형태`가 **어긋날 때 무엇을 따르나**(개인 단말을 공용 자리에서 쓸 때) | 보안 대 현장 편의 | 정보보호·간호부 |
| 3 | `SHARED_CREW` 자리의 **잠금 타임아웃**·교대 정리 규칙 | 현장 리듬(응급실 vs 병동) | 간호부·응급의학과 |
| 4 | 자리↔단말 바인딩을 **누가 등록·변경**하나(전산 / 부서장) | 잘못 묶으면 인쇄가 통째로 어긋난다 | 전산·진료부 |

## 5. 단계

| 단계 | 내용 | 선행 |
|---|---|---|
| ✅ **완료** | 전 직군 403 봉합 + 역할 정본화(`EVERY_STAFF_ROLE`) | — |
| **W1** | 자리↔단말 **바인딩 편집 화면** + 현황 표(바인딩 0/27 을 화면이 말한다) | 결정 4 |
| **W2** | 인쇄 자리 검증 게이트 `OFF → WARN` (관제에 불일치 건수 축적) | W1 · 결정 1 |
| **W3** | 자리 `형태`(PERSONAL/SHARED_CREW/SERVICE_POINT) + 잠금·교대 정책 연계 | 결정 2·3 |
| **W4** | 격리·폐기가 자리 기능까지 끊기 · 크루 교대 인계 | W3 |
| **W5** | 게이트 `WARN → BLOCK` 승격(실측 근거로) | W2 실측 |

🔴 **W2 를 BLOCK 으로 시작하지 않는다** — 바인딩 0건에서 BLOCK 은 전 인쇄 중단이다.

## 6. 가드 (착수 시)

- **바인딩 없는 자리는 화면이 "미바인딩"이라고 말한다** — 대조군: 바인딩된 자리는 자동으로 해석된다
- **주장한 자리와 단말이 다르면 게이트 모드대로 동작한다**(OFF 통과 / WARN 기록 / BLOCK 거부)
  — 🔴 대조군: **일치하면 조용하다**(거짓 경보 금지)
- **격리 단말은 자리 해석에서 빠진다** — 대조군: 정상 단말은 빠지지 않는다
- 🔴 **전 직군 EP 목록이 역할 라벨 정본과 집합이 같다**(신설 직군이 생겨도 자동으로 따라온다)
- **관리 EP 는 여전히 ADMIN 전용**(전부 열어버리지 않았다)

## 7. 확인하지 못한 것

- 등록 단말 5대가 **실제로 어느 자리에 놓여 있는지** — 코드로는 알 수 없다(현장 확인 필요).
- 비콘(`beaconId`)이 실제로 쓰이고 있는지 — 필드는 있으나 소비처 미확인.
- `WorkstationConfig`(논리 스테이션)와 `WorkstationProfile`(물리 자리)의 **매핑 정책** —
  두 목록이 별개로 관리되고 있어 같은 검사실이 양쪽에 따로 있을 수 있다.
