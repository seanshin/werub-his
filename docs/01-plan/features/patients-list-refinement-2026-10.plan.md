## 3. 원칙 (판정 규칙의 목록 화면 적용)

1. **권한은 서버가 정한다** — 화면은 서버가 준 응답을 그리고, 서버가 알려 준 능력으로 버튼을 연다. 화면이 따로 숨기는 것은 "마스킹"이라 부르지 않는다.
2. **범위를 말하려면 범위를 실제로 건다** — 걸지 않으면 "전체 환자"라고 말한다(R1). 거는 것은 사람 결정(D1).
3. **조건이 있는 빈 목록은 조건을 말한다** · **품질 지표는 분자·분모 단위를 맞추고 정의를 쓴다**.
4. **위험 행위(병합)는 비교 → 확인 → 기록**, 되돌리기 가능 여부를 그 자리에서 말한다.
5. 열을 늘릴 때 **정본만** 쓴다(나이 `ageOf`·알레르기 4상태·이름 `patient-name`·위치 `current-location` 서버 판정).

## 4. 세련화 묶음 (A)

### A1. 목록 능력표 — 최우선 (R2·R3·R7)
- 서버 `GET patients/list-capabilities`(가칭): `{ canRegister, canImport, canExport, canMerge, contact: 'FULL'|'MASKED'|'NONE', identity: …, insurance: …, scope: 'ALL'|… }` — **RBAC Permission 에서 파생**(새 정본 아님).
- 화면 `DEFAULT_ROLE_ACCESS`·`role-data-access` 덮어쓰기 제거 → 능력표만. 오는 중이면 쓰기 버튼을 그리지 않는다(관리자 폴백 제거 · R7).
- `role-data-access` 설정이 서버 Permission 과 다르게 좁히는 의도라면 그 값을 **서버 마스킹에 반영**한다(화면만 숨기지 않는다) — 넓히는 값은 무시하고 화면에 "적용되지 않음"을 말한다(§운영모드 "런타임은 좁히기만"과 같은 꼴).
- 🔴 가드: 능력표 = Permission 기계 대조(역할 14 전수) · 화면 소스에 역할 이름 리터럴로 열 숨김 0.

### A2. 역할 배너 문구 정직화 (R1·R2)
- D1 결정 전: 모든 역할 "전체 환자 목록 · 연락처는 <서버 마스킹 상태>" — 능력표에서 문장을 만든다.
- 범위 칩(내 환자·내 병동·오늘 처방)은 **필터**로 제공(B1) — 기본 범위가 아니라 사람이 누르는 것.

### A3. 검색 재식별 경로 봉합 (R4)
- 연락처 권한 없는 역할은 `q` 에서 phone 조건 제외. 숫자만 입력하면 "연락처 검색 권한이 없어 등록번호·이름으로만 찾았습니다"를 말한다.
- 전화 검색은 숫자 정규화(하이픈 무시) — 권한 있는 역할에서 형식 섞임(하이픈 33·숫자만 3) 때문에 못 찾던 것.

### A4. 스마트 목록 정리 (R5)
- 응답을 목록과 같은 능력표로 가림 · 검색도 같은 전화 검색 규칙 · 🔴 스마트 목록 검색이 병합된 옛 기록(`validTo` 있음)까지 찾던 것 함께 봉합.

### A5. 빈 상태·검색 (R10·R13·R14)
- 빈 상태 3갈래: 등록 0 / 조건에 맞는 환자 없음(조건 나열 + 초기화) / 조회 실패(기존).
- 검색 300ms 디바운스 · 정렬 `[familyName, givenName, mrn]` 결정적 키.

### A6. 품질 카드 정직화 (R8)
- 중복 의심 = "그룹 N(환자 M명)" — % 를 쓰면 분모 환자 수 · 보험번호 없음은 NHI·MEDICAID 대상만 분모 · 휴면은 **정의를 화면에 쓴다**(마지막 서명 진료 ≥ N개월 — N 은 D3) · 사진은 정책 미정이면 경고색 없이 수만 · 수치 `<Num>` 정본.

### A7. 진료 횟수 정의 (R11)
- "서명된 진료 N회" + 작성 중 M건은 따로(작성 중이 있으면 회색 칩). 진료 횟수 열 이름도 바꾼다.

### A8. 병합 흐름 (R12)
- 중복 그룹 → 두 명 고르면 병합 창에 채워 진입 · **좌우 비교**(등록번호·이름·생년월일·성별·연락처(권한대로)·보험·진료/입원/수납 건수·알레르기) · 남길 쪽 선택 · 사유 필수 · 되돌리기 가능 여부(현재 병합 해제 경로 유무를 코드로 확인해 말함) · `confirm()` 제거.
- 보험 유형 라벨 shared 정본.

### A9. 이름·문구 (R9·R15)
- 내 환자 이름 정본 · 미등재 문구 등재.

### A10. 태그 필터 (R16 · S1)
- 필터 칩은 **실제 데이터의 태그 어휘에서**(서버 집계 상위 N + 전체 수) · 임상 경고 성격(감염주의 등)은 태그가 아니라 **환자 플래그 원장**(23건)이 정본이면 그쪽으로 — 정본 판정은 착수 때 실측.
- 시드 생성기의 "태그 = 진료과"는 생성기에서 고친다(데이터 교정 아님).
