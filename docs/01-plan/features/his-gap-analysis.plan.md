## 2. 미구현 모듈 (3건)

### 2.1 원격진료 (Telehealth) — 우선순위: 높음

```
배경: 코로나 이후 비대면 진료 수요 급증, 2024년 시범사업 확대

필요 기능:
  1. 화상진료 (WebRTC 기반)
     - 의사-환자 1:1 영상 통화
     - 화면 공유 (영상/검사 결과)
     - 진료 녹화 (동의 시)
  2. 비동기 진료
     - 문진표 기반 원격 상담
     - 사진/영상 첨부
     - 의사 회신 + 처방
  3. 원격 처방전
     - 원외 처방전 자동 발행
     - 전자처방전 약국 전송
  4. 진료비 결제
     - 포털/앱 내 결제 연동

연동:
  - encounter.visitType = 'TELEHEALTH' 추가
  - 기존 CPOE/처방/수납 흐름 재사용
  - 포털에서 예약 → 대기 → 진료 → 처방 → 결제

기술:
  - WebRTC (peer-to-peer) 또는 Twilio/Agora SDK
  - STUN/TURN 서버 (NAT 통과)
  - 녹화: MediaRecorder API

구현 규모: 중 (3~5일)
  - 기존 encounter 인프라 위에 WebRTC 레이어 추가
```

### 2.2 호스피스/완화의료 — 우선순위: 중간

```
배경: 2017년 호스피스·완화의료법 시행, 종합병원급 필수

필요 기능:
  1. 호스피스 등록/관리
     - 대상 환자 선별 (PPS ≤ 50%)
     - 등록 기준 평가 (Palliative Performance Scale)
  2. 증상 관리
     - ESAS (Edmonton Symptom Assessment Scale) — 9개 증상
     - 통증 관리 (WHO 3단계)
     - 섬망/불안/우울 평가
  3. 사전의료의향서 (AD)
     - 연명의료결정법 연동
     - 사전의료의향서 등록/조회
     - 연명의료계획서 (POLST) 관리
  4. 돌봄 계획
     - 다학제 팀 회의 기록
     - 가족 상담 기록
     - 영적 돌봄 기록
  5. 임종 관리
     - 임종 전 체크리스트
     - 사망 확인서 발행

모델:
  HospiceRegistration, SymptomAssessment (ESAS),
  AdvanceDirective, CareConference, BereavedCounseling

구현 규모: 중 (3~4일)
```

### 2.3 장기이식 — 우선순위: 낮음 (전문센터만)

```
배경: 장기이식센터 운영 병원만 필요

필요 기능:

  - 대기자 풀 (KONOS 연동)

구현 규모: 대 (5~7일)
로드맵: Phase 5+ (전문센터 요구 시)
```

## 3. 기존 모듈 보완 필요 사항

### 3.1 데이터 정합성 / 연동 갭

| # | 갭 | 영향 | 조치 |
|---|---|------|------|
| 1 | 진료→수납 자동 연결이 일부 경로에서 누락 | 수납 누락 가능 | billing 이벤트 리스너 점검 |
| 2 | 검사 결과→차트 자동 반영 | 의사가 수동 확인 | encounter에 lab/imaging 결과 자동 임베드 |
| 3 | 처방→투약 추적 end-to-end | MAR 완성도 | MedicationAdministration 흐름 점검 |
| 4 | 입원→퇴원 요약 자동 생성 | 퇴원 시 수작업 | AI 기반 퇴원 요약 자동 초안 |

### 3.2 UI/UX 개선

| # | 항목 | 현황 | 개선 |
|---|------|------|------|
| 1 | 대시보드 실시간 데이터 | seed 데이터만 | 운영 데이터 연동 시 자동 반영 |
| 2 | 모바일 반응형 | 데스크톱 최적화 | 태블릿/모바일 대응 필요 |
| 3 | 다국어 지원 | 한국어만 | i18n 프레임워크 (향후) |
| 4 | 인쇄 최적화 | 일부 페이지만 | 처방전/진단서/소견서 인쇄 레이아웃 |

### 3.3 운영/인프라

| # | 항목 | 현황 | 개선 |
|---|------|------|------|
| 1 | 백업/복구 | 수동 | 자동 DB 백업 스케줄 |
| 2 | 로깅/모니터링 | pm2 로그만 | 구조화 로깅 + 대시보드 |
| 3 | 부하 테스트 | 미실시 | 동시접속 100명+ 테스트 |
| 4 | DR(재해복구) | 단일 서버 | 이중화 또는 클라우드 전환 |

## 4. 보완 우선순위

### Phase A: 즉시 보강 (1~2일)
- [ ] 진료→수납 연동 누락 경로 점검/수정
- [ ] 검사 결과 차트 자동 반영 확인
- [ ] 인쇄 레이아웃 미비 페이지 보강

### Phase B: 원격진료 모듈 (3~5일)
- [ ] Telehealth 데이터 모델 (TelehealthSession)
- [ ] WebRTC 기반 화상진료 (또는 외부 SDK 연동)
- [ ] 포털에서 원격진료 예약/참여
- [ ] 원격 처방전 + 수납

### Phase C: 호스피스/완화의료 (3~4일)
- [ ] HospiceRegistration, ESAS, AdvanceDirective 모델
- [ ] PPS(Palliative Performance Scale) 자동 계산
- [ ] 사전의료의향서/연명의료계획서 관리
- [ ] 호스피스 전용 페이지

### Phase D: 운영 안정화 (2~3일)
- [ ] 자동 DB 백업 스케줄
- [ ] 구조화 로깅 (Winston/Pino)
- [ ] 태블릿 반응형 레이아웃 (핵심 페이지)
- [ ] 부하 테스트 + 병목 최적화

### Phase E: 장기 로드맵 (향후)
- [ ] 장기이식 모듈 (전문센터 요구 시)
- [ ] 모바일 앱 (React Native)
- [ ] 다국어 지원 (i18n)
- [ ] AI 퇴원 요약 자동 생성

## 5. 결론

Hospital RUN은 **112개 모듈, 120+ 페이지**로 한국 종합병원 HIS의 필수 기능을 **77% 커버**하고 있으며, 미구현 3건(원격진료/호스피스/장기이식) 중 **원격진료와 호스피스**가 실질적으로 필요합니다.

기존 모듈의 데이터 연동 갭(진료→수납, 검사→차트)을 먼저 점검하고, 원격진료 모듈을 추가하면 **90%+ 커버리지**에 도달합니다.
