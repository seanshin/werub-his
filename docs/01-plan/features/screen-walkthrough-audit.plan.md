# 화면 실사용 전수 점검 (Screen Walkthrough Audit)

- 작성: 2026-08-12
- 대상: nav 도달 가능 화면 **254개 / 25섹션**(Sidebar 실측) + 공개 화면(전광판·포털)
- 성격: **브라우저로 직접 열어봐야 보이는 결함**을 잡는 축. 코드 리뷰·테스트로는 안 잡힌다.
- 관련: [[screen_walkthrough_audit]] 메모리 · `docs/03-analysis/data-integrity-review-2026-08-10.md`

---

## 1. 왜 이 축인가

전수검토 21축이 포화 종결되고 CLI 백로그가 소진된 뒤, **화면을 열어보는 것만으로** 실결함이 계속 나왔다.
2026-08-10~12 사흘간 적발한 것들의 공통점:

- **전부 백로그에 없었다**
- **코드·테스트는 통과 중이었다**(BE 6,857 · web 241 그린)
- **에러도 경고도 없었다** — 화면이 조용히 뭔가를 빠뜨리거나 잘못 말하고 있었다

> 🔴 핵심 통찰: 테스트는 "코드가 의도대로 도는가"를 보고, 이 축은 **"화면이 사실을 말하는가"**를 본다.
> 둘은 다른 질문이다. 값이 `0`이어도 코드는 정상 동작한 것이다.

## 2. 결함 패턴 카탈로그 (적발 실적 기반)

점검 체크리스트의 근거. **새 패턴이 나오면 여기에 추가하고 체크리스트에 반영한다.**

| # | 패턴 | 실제 사례 | 탐지 신호 |
|---|---|---|---|
| **P1** | **아는 것과 모르는 것을 뒤바꿔 말함** — ⓐ표본 부재를 `0`으로 ⓑ자료 부족을 공백으로 ⓒ**진짜 `0` 을 `-` 로** | ⓐ관제 "평균 대기 0m"(실제 196명·352분) ⓑ입원 AI 위험도 열이 통째로 비어 "위험 없음"으로 읽힘 ⓒ**ICU 배설량 0**(무뇨=신부전 신호)이 `-` 로 보여 "기록 없음"처럼 읽힘 | 지표가 `0`인데 원자료가 있음 · 열이 늘 비어 있음 · **`x > 0 ? x : '-'`** |
| **P2** | **상태 전이 후 목록에서 탈락** | 약국 검수 대기 — 조제 끝나면 오더가 COMPLETED 라 큐에서 빠져 **탭이 영원히 0건** | KPI 숫자 > 목록 건수 |
| **P3** | **열거형 일부만 처리** | 병상 보드 — `BedStatus` 6종 중 4종만 세어 **청소·격리가 사라짐**(합 불일치) | 컬럼 합 ≠ 총계 |
| **P4** | **폴백이 정식 표시처럼 노출** — 화면판/**서버판** | 화면: 상황판에 `occupied` 영문 키 · 🔴서버: `STATION_DEPT_MAP[id] ?? 'LAB'` 로 **12개 워크스테이션이 남의 검사 오더를 자기 업무로** 표시(퇴원 WS 가 "퇴원 업무"라며 HbA1c 를 띄움) | 한글 화면에 camelCase · **미등록 키가 조용히 기본값으로 흐름** |

| **P7** | **숫자만 있고 갈 곳이 없음** | 약국 보드 "검수 대기 5"의 목록 부재 | KPI 타일에 딥링크 없음 |

## 3. 화면당 점검 체크리스트

각 화면에서 **아래 순서로** 본다. 10개 항목, 화면당 2~5분.

### 3.1 값의 정직성
- [ ] `0`·빈칸이 **진짜 0인가, 표본이 없는가** (P1) — 의심되면 DB/API로 원자료 대조
- [ ] KPI 숫자와 아래 목록 **건수가 일치**하는가 (P2)
- [ ] 컬럼·버킷의 **합이 총계와 맞는가** (P3)
- [ ] 상태·구분이 **열거형 전체를 덮는가** (P3) — enum 정의를 먼저 읽는다

### 3.2 표현
- [ ] 한글 화면에 **영문 식별자**가 없는가 (P4)
- [ ] 경과 시간이 `분`·`시간` 원시 단위로 남아 있지 않은가 (P5) → `<Duration>`/`durationText`
- [ ] 금액·날짜·환자명·빈상태가 **정본 부품** 경유인가 (`Money`·`KDate`·`PatientName`·`EmptyState`)
- [ ] 버전·건수·소개 문구가 **현행인가** (P6)

### 3.3 조치 경로
- [ ] 모든 KPI에 **워크리스트 딥링크**가 있는가 (P7)
- [ ] 불가 액션이 **숨겨지지 않고 이유와 함께 비활성**인가 (P8)

### 3.4 권한·라우팅 (역할 전환 시)
- [ ] 역할별로 보여야 할/말아야 할 것이 맞는가 (P9)

## 4. 판정 기준 — 고칠 것과 남길 것

🔴 **가장 중요한 규율. 오탐이 실결함보다 많았다.**

| 판정 | 기준 | 조치 |
|---|---|---|
| **실결함** | 코드가 사실을 잘못 말한다 | 즉시 수정 + 가드 테스트 |
| **데모 데이터 특성** | 화면은 정직한데 데이터가 낡음·희소 | **고치지 않는다**. 기록만 |
| **설계 의도** | 마스킹·창(lookback)·게이트 OFF 등 | 확인 후 기록 |
| **사람 몫** | 임상 내용·재무 판정 | 목록화해 담당자에게 |

**오탐 판별 3단계** — 결함으로 보이면 반드시 거친다.
1. **상태를 만드는 경로를 전부 찾았는가?** (병상은 입원·응급 **양쪽**으로 점유된다 — 한쪽만 보면 8건 오탐)
2. **그 상태가 정상인 경우가 있는가?** (`PENDING` 검사결과에 항목 0개는 정상 · 본인부담 0이면 결제액 0이 정상)
3. **시각 역전이면 소급 갱신을 의심했는가?** (데모 크론이 `dispositionAt` 을 소급 설정해 배정보다 이르게 만든다)

   🔴 암호관리자 확장이 포커스를 가로채면 `Cannot access a chrome-extension:// URL` 로 **모든 브라우저 도구가 막힌다**.
   `navigate` 는 동작하므로 navigate → javascript_tool 순으로 우회한다.
2. **훑기** — Wave 내 화면을 순서대로 열고 §3 체크리스트 적용. 의심 지점은 **확대 캡처**로 근거를 남긴다.
3. **대조** — 의심되면 즉시 DB/API 로 원자료 확인(§4 오탐 판별 3단계)
4. **수정** — 실결함만. **정본 부품으로 수렴**하고 로컬 재정의를 만들지 않는다
5. **가드** — 재발 방지 테스트를 같은 커밋에. 🔴 **enum·역할·지표 키가 늘면 실패하는 형태**로 짠다
6. **검증** — 배포 후 **같은 화면을 다시 열어** 눈으로 확인. 스모크 29 PASS
7. **기록** — 커밋 메시지에 "무엇이 왜 틀렸는지". 새 패턴이면 §2 카탈로그에 추가
