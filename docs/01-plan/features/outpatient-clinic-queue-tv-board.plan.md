# 외래 진료과·진료실 대기 현황 TV 보드 — ER 흐름 보드와 동일 디자인 언어

- 작성: 2026-08-05 · 상태: **기획 v2(검토 보완·구현 대기)**
- 요구: ①각 **진료과별** 대기·**진료실별** 대기 현황을 ER 흐름 TV 보드(`/display/er-flow` v2·확인됨)와 유사한 형태로 ②**TV 보드를 설정하는 운영 ID(디스플레이 키)와 관리 기능을 한곳에 모은 관리 화면**.

## 1. 실측 (2026-08-05)

| 자산 | 실측 |
|---|---|
| 기존 전광판 `/display/waiting` | 공개 SSE(`/queue/public/stream`)·과별 그룹·마스킹 — **표현이 구식**(단순 목록)·**진료실 단위 그룹 없음** |
| 데이터(`queue-display.service.getDisplay`) | **이미 완비**: 과별 그룹·행에 `roomName`·`doctorName(마스킹)`·`queueNumber`·`status`(WAITING/CALLED/IN_CONSULTATION/수납/약국)·`waitMinutes`·`callCount` + 과별 stats(대기·호출·진료중·완료·**avgWaitMinutes**) + `lastCall`(TTS 이벤트) + 키 검증 EP·공개 SSE 병행 |
| 진료실 세션 | `clinic-schedule/today`(진료실·의사·오전/오후·waitingCount) — 접수 레일에서 사용 중 |
| 마스킹 계약 | `public-display-masking.spec.ts` 기존 고정(홍○동·의사도 마스킹) |

→ **BE 신규 개발 불요가 기본**: 행에 roomName 이 있어 진료실 그룹핑은 표현 계층에서 가능. 공개 표면 계약(마스킹)도 기존 스펙이 이미 고정.

**검토 보완(v2 — 운영·관리 실측)**:
- 🔴 **디스플레이 키 수명주기 관리 부재**: `DisplayApiKey` 모델(key·name·isActive·lastUsedAt·createdBy)은 있으나 **발급/목록/폐기 EP·관리 화면이 0** — 키를 만들 정상 경로가 없다(현재 키는 시드/수동 유래). 운영 ID 요구의 실체적 갭.
- 단말 생존 신호 = `lastUsedAt`(validateApiKey 가 fire-and-forget 갱신) — 관리 화면의 "마지막 접속" 으로 그대로 쓸 수 있음. 단, **공개 보드(er-flow·waiting 공개 스트림)는 키를 안 쓰므로 생존 신호가 없다** — 관리 화면에는 '공개(키 불요·생존 미추적)' 로 정직하게 구분 표기.
- 기존 워크플로 영향: 없음(신규 표시·관리 표면만). `/display/waiting` 기설치 단말 URL 불변.

## 2. 결정

- **D1 신규 라우트 `/display/clinic-queue`** — 기존 `/display/waiting` 은 유지(호환·기설치 단말), 신규 보드 안정화 후 대체 여부 별도 판단. 데이터는 **기존 공개 SSE/EP 그대로**(신규 공개 표면 0 = 마스킹 계약 재사용).
- **D2 층별 TV 필터**: `?departments=내과,정형외과` 쿼리 — 각 층/구역 TV 가 자기 과만 표시(기존 EP 파라미터 그대로). 미지정=전 과.
- **D3 화면 위계 = 과 섹션 → 진료실 카드**(외래는 인원이 많아 ER 식 환자별 스테퍼는 비적용):
  - 진료실 카드: 진료실명+담당의(마스킹)·**진료 중**(현재 번호·이름 대형)·**호출**(번호 깜빡·재호출 횟수)·대기 상위 4~5(번호·마스킹 이름·대기분)·"외 n명".
  - roomName 없는 대기(방 미지정)는 과 섹션의 '배정 대기' 카드로.
- **D4 흐름 안내는 정적 1줄**: 상단에 `접수 → 대기 → 호출 → 진료 → 수납·약국` 단계 바(개인별 아님 — ER 와 디자인 언어만 공유). 수납·약국 대기(CASHIER/PHARMACY_WAITING)는 과 섹션 하단 요약 칩.
- **D5 호출 배너**: lastCall/스트림 호출 이벤트 시 상단 대형 배너 5초(“3번 홍○동 님 → 내과 1진료실”) — 기존 스트림의 호출 감지 페이로드 재사용.
- **D6 대기시간**: 행별 `waitMinutes`(⏱ n분·ER 와 동일 앰버 칩 톤) + 과별 평균 대기(avgWaitMinutes) 헤더 칩. **예상 대기는 표시하지 않는다**(예측 모델 없이 추정 금지 — 평균은 실측이라 허용).
- **D7 디자인 언어 = ER TV v2 공유**: 다크 카드·대형 타이포·앰버(대기/호출)·에메랄드(진료중)·스카이(진료실 칩)·시계 헤더·개인정보 푸터.
- **D8 TV 디스플레이 관리 = `/admin/displays`(ADMIN) 한곳**:
  - **보드 카탈로그**: 운영 중 TV 보드 전 목록을 한 화면에 — 외래 호출(`/display/waiting`·기존)·외래 진료실(`/display/clinic-queue`·신설)·ER 흐름(`/display/er-flow`)·키오스크(`/display/kiosk`) — 각 보드의 인증 방식(공개/키)·파라미터 빌더(**진료과 다중 선택 → departments 쿼리 자동 조립**)·완성 URL 복사·[미리보기 ↗].
  - **운영 키(운영 ID)**: `DisplayApiKey` CRUD 신설 — 발급(키 서버 자동생성·**name=설치 위치 라벨** 예: "3층 내과 복도 TV")·비활성(폐기 대신 — 이력 보존)·목록(마지막 접속 lastUsedAt·**7일 무접속 배지**)·키는 발급 시 1회 전체 표시 후 목록에선 앞 8자 마스킹.
  - BE: `/api/v1/displays/keys` GET/POST/PATCH(ADMIN·waiting-queue 모듈에 admin 컨트롤러 추가). 발급=`crypto.randomBytes(24)` hex·감사 자동(변이 기본 ON).
  - 사이드바 시스템 관리 절에 "TV 디스플레이 관리" 등재(고아 화면 금지).
- **D9 박스(단말) 지정 운영 — URL 붙여넣기 → 박스 바인딩으로 전환**:
  - 문제: URL 복사 방식은 **설정이 TV 안에만 있다** — 층별 과 구성을 바꾸려면 사람이 TV 앞에 가서 주소를 다시 입력해야 하고, 어떤 TV 가 무엇을 틀고 있는지 서버가 모른다.
  - 해결: **운영 키 = 박스(설치 단말)** 로 승격하고 보드 구성을 서버에 바인딩. 단말에는 **`/display/box/<key>` 한 줄만** 설정한다.
  - 스키마(additive): `DisplayApiKey.boardType`(clinic-queue|er-flow|waiting)·`config` JSONB(`{departments[], tts}`) — 기존 행은 null=미지정(안내 화면).
  - 공개 EP `GET /api/v1/displays/box/:key` — 키 유효성 검증(비활성=401)+**lastUsedAt 갱신 → 공개 보드도 생존 추적이 생긴다**(D8 의 '공개=생존 미추적' 한계 해소). 반환은 보드 구성만(PHI 0).
  - 박스 화면은 **60초마다 구성 재확인** → 관리 화면에서 바꾸면 **TV 를 만지지 않고 반영**(무인 운영).
  - 보드 본체는 컴포넌트로 추출(`_boards/*`)해 직접 URL 경로와 박스 경로가 **같은 구현**을 쓴다(이중 관리 금지).

## 4. Phase

- **P0**: `/display/clinic-queue` 페이지(SSE+폴백·진료실 그룹핑·호출 배너·departments 필터) — BE 무변경. 검증=마스킹 그대로(신규 공개 표면 0)·실 대기 데이터 렌더·호출 이벤트 배너.
- **P0.5(D8)**: `/admin/displays` 관리 화면 + 디스플레이 키 CRUD EP — 보드 카탈로그·URL 빌더·키 발급/비활성/생존 표시. 검증=키 발급→해당 키로 keyed EP 호출 성공→비활성 후 401 왕복.
- **P1** — **음성 호출 ✅완료 / 세션 표기 ✖보류(실측 판정) / 구형 대체 ✖보류**:
  - **음성 호출**: 스트림 call 이벤트에 `ttsText` 가 **이미 실려 온다**(BE 무변경) → FE `speechSynthesis`(ko-KR) 재생. 브라우저 자동재생 정책상 제스처 1회가 필요해 **헤더 [🔊 음성] 토글·기본 OFF·localStorage 유지**(설치 시 한 번 켜면 유지). 문구는 서버 생성이라 화면·음성이 갈리지 않는다.
  - **세션 표기 보류**: `clinic-schedule/today` 는 **JwtAuthGuard 보호**(실측 401) — TV(무인증)에서 쓰려면 공개 표면 신설이 필요. 진료실·담당의는 이미 대기 행에 있으므로 **공개 표면을 늘릴 이득이 없다**고 판정.
  - **구형 `/display/waiting` 대체 보류**: 기설치 단말 URL 안정성 우선(카탈로그에 '구형' 표기로 운영 판단 지원).
- 비범위: 예상 대기 예측·키오스크 통합·모바일.

## 5. 실행 기록 (2026-08-05 — P0+P0.5 당일 완료)

- **P0 `/display/clinic-queue`**: 기존 공개 SSE 단일 소스(BE 무변경·신규 공개 표면 0)·과 섹션→진료실 카드(roomName 그룹·미지정='배정 대기')·진료중/🔔호출(재호출 횟수)/대기 상위 4+외 n명·⏱대기분·과 요약(대기·진료중·평균 대기·수납/약국)·호출 대형 배너 6초·departments 필터·SSE 재연결 폴백. 라이브 렌더 실확인(이비인후과 10·산부인과 20 대기·마스킹 그대로). ※첫 페인트는 스트림 주기(5초)만큼 지연 — 수용(P1 에서 startWith 검토 가능하나 BE 변경이라 보류).
- **P0.5 `/admin/displays`(사이드바 3104)**: 보드 카탈로그 4종(공개/키 구분·**과 다중 선택 URL 빌더**·복사·미리보기) + 운영 키 CRUD(`/api/v1/displays/keys` ADMIN — 🔴종전 발급 경로 0 이던 갭 봉합). 발급 1회 노출 모달·목록 앞 8자 마스킹·lastUsedAt 생존 신호·7일 무접속 배지·비활성=이력 보존.
- **키 수명주기 라이브 왕복**: 발급 → keyed EP 200 → 비활성 → **401** → 목록 마스킹+마지막 접속 기록. 검증용 키는 비활성 상태로 이력 보존.
- **P1 음성 호출**(2026-08-05): 헤더 [🔊/🔇] 토글·`speechSynthesis` ko-KR·서버 `ttsText` 그대로 발화. 층별 필터(`?departments=산부인과`) 렌더 실확인.
- **D9 박스 지정 완료(2026-08-05·사용자 지시 "정해진 박스에 지정"·"키 지정과 세팅되는 별도 화면")**:
  - 스키마 additive 2컬럼(`boardType`·`config` JSONB) · 공개 `GET /displays/box/:key`(비활성 401·**lastUsedAt 갱신=공개 보드 생존 추적 확보**) · 관리 `GET/PATCH /displays/keys/:id` 확장.
  - **세팅 전용 화면 `/admin/displays/[keyId]`**: 상태(생존·무접속 배지·비활성 토글)·**박스 URL**(복사·미리보기)·설치 라벨·보드 라디오(4택)·진료과 다중선택·음성 사용. 목록에는 지정 상태 칩+[세팅] 링크.

  - 라이브 왕복: 발급 → 미지정 조회 → clinic-queue+산부인과+음성 지정 → 박스 화면이 지정대로 렌더(대기 20·호출 배너·음성 켜짐) → 비활성 401 → 재활성.
  - 🔴 동반 봉합 2: ①**첫 SSE 가 호출 이벤트면 목록 미수신 상태를 "환자 없음"으로 오표시**하던 것 → 로딩/빈 상태 분리 ②호출 배너 조사("산부인과 **로** 와주세요") → 진료실 있으면 "…N진료실으로", 없으면 "…접수 창구로"(TTS 봉합과 동일 규약).
- 🔴 **동반 실결함 봉합(TTS 조사 깨짐)**: 실 호출로 스트림을 열어보니 진료실 미배정 시 문구가 **"…전○우님로 오세요"** — `buildTtsText` 의 room=null 분기가 `'로 오세요'` 라 조사가 깨진 채 **구형 전광판에서도 이미 방송되고 있었다**. `', 접수 창구로 오세요'` 로 봉합·스펙을 정확 문자열 비교로 강화(종전 `toContain('로 오세요')` 는 깨진 문구도 통과시켰다). 라이브 재검증="산부인과 2번 최○준님, 접수 창구로 오세요".
