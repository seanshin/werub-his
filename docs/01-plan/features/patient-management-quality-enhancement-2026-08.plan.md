## 3. Track A 상세 — 환자관리 정합·완성

### A1. 이름·전화 저장 정규화 (P0)

**문제**: 검색·중복비교가 저장 원문을 그대로 쓴다. 전화 표기차(하이픈 유무·국가코드)·이름 공백/한자
혼입으로 **같은 사람이 중복 탐지를 빠져나간다**. 중복 스코어링(A 코어)이 이미 있어도 입력이 정규화되지
않으면 무력하다.

**설계**:
- **전화**: 저장 시 E.164 정규화(`+82` 국내 → `01012345678` 정본 컬럼 별도 보관, 표시용 원문/포맷은
  분리). data-quality `C4 전화 정규화`(이미 구현·결정적 규칙·diff 승인·감사로그)를 **등록 경로에도** 적용.
  🔴 기존 데이터는 **소급 일괄변경하지 않는다** — C4 의 사람 승인 diff 를 통해서만(일어난 사실 소급 금지).
- **이름**: 앞뒤 공백·중복 공백 정리만(정본은 familyName/givenName 분리 유지). **한자→한글 변환은 하지
  않는다**(다국어 데모명이 실재·어휘를 지어내지 않는다).
- **중복 스코어링에 정규화 전화 매칭 추가**: `hashNationalId` 블라인드 인덱스 패턴을 전화에도 —
  `phoneNormalized` 컬럼으로 정확 매칭(부분일치 `contains` 는 유지).

**가드**: 정규화 함수 단위테스트(하이픈/공백/국가코드 케이스)+중복 스코어링에 전화정규화 반영 재주입 검증.

### B2. qiValue 반올림 정본 정리 (P0) — ✅ 2026-08-31 구현

🔴 **구현 착수 시 재실측하니 `qiValue` 는 이미 `NUMERIC_POLICIES` 에 등재돼 있었다**(`numeric-policy.ts:54`·
2026-08-18 추가). 에이전트가 `indicator-policy.ts` 의 **낡은 주석**(미등재라 서술)을 읽고 미구현으로
오판한 것 — "실측이 기획을 이긴다"가 내 기획에도 적용됐다. `roundBy(12.3456,'qiValue') === 12.35`
실측 확인. 남은 일은 **낡은 주석 정정 + 잉여 수동보정(`Math.round`) 제거** → 정본 `roundBy` 만 부른다.

### B3. 인증 근거 자동수집 연결 (P1) — 이 트랙의 핵심

JCI/KoHIAS 인증 체크리스트가 **카탈로그 골격**만이고 근거가 전량 수기다. 이미 **실측 근거를 내는 축이
있다** — 연결만 하면 된다:

| 인증 항목 | 자동 근거 원천(이미 존재) |
|-----------|--------------------------|
| IPSG.1 환자확인 | patient-safety `identification-check/stats`(오류율) |
| IPSG.4 수술안전(오부위수술 방지) | qi `surgery-safety`(체크리스트 이행률·좌우/부위 갭) |
| IPSG.6 낙상 | patient-safety 낙상위험평가 |
| 진료기록 완전성 | data-quality CRITICAL(퇴원요약·수술기록·간호기록·중증도분류) |
| 위급값 관리 | data-quality `lab.criticalPending/Unalerted` |

**설계**: `AccreditationItem` 에 `evidenceSourceKey`(선택) 추가 → 항목 조회 시 해당 축의 **실측 지표를
근거로 병기**(사람이 판정은 유지·근거는 자동). 🔴 **자동으로 COMPLIANT 판정하지 않는다** — 근거를 보여줄
뿐, 적합 판정은 심사자 몫(막지 않고 드러낸다·시스템은 권고하지 않는다). 근거 없는 항목은
`available:false` 유지.

### B4. data-quality 도메인 역할 확장 (P1)

전 지표 `roles:[ADMIN]` 을 **산출 주체 역할**로 확장: lab 도메인 → LAB_TECH, safety/nursing → NURSE·
감염관리, billing → 원무. 🔴 **여는 게 항상 답은 아니다** — 임상 소견 성격 지표는 ADMIN 유지, **자기
도메인 워크리스트**만 연다(워크리스트가 없으면 직원은 기억으로 일한다). RBAC 축 규약대로 최소권한.

### B5. Admission 진료과 필드 → 부서 분해 (P2)

`Admission` 에 `departmentName`(또는 attendingDoctor 의 department 파생) 추가 → 재입원율·재원일 부서별
breakdown. 🔴 **파생 가능하면 컬럼을 늘리지 않는다** — attendingDoctorId→User.department 조인으로 먼저
시도하고, 성능/이력 문제 시에만 스냅샷 컬럼. 분모 병기 유지.

### B6. PSI 자동 산출 (P2) — 정직성 최우선

AHRQ Patient Safety Indicators 중 **우리 데이터로 정의 가능한 것부터** 실산출(예: PSI-03 욕창·PSI-08
수술중 낙상 등은 진단코드+입원기간으로 산출 가능). 🔴 **정의를 우리 코드로 재현할 수 없는 지표는
계속 `available:false`** — 값을 지어내지 않는다(qi 모듈이 이미 세운 원칙 준수). 산출한 것은 **분자/분모·
제외기준·모집단 캐비아트**를 함께 낸다. 외부 벤치마크(전국 비교)는 출처 계약 전까지 `available:false` 유지.

### B7. 검진 연결·챗 도구 (P3)

- 검진 결과↔검사/영상 오더 자동수집(`checkup.resultSourceUnlinked` 해소).
- C5: medical-ai ToolRegistry 에 `quality_summary`·`quality_worklist` 도구 등록(챗에서 질 지표 조회).
  🔴 Human-in-loop·`quality.ai.enabled` OFF 기본.

## 7. 판정 규칙 준수 (CLAUDE.md) — 이 기획이 지킬 것

- 🔴 **분모 병기·표본부재→null·`available:false` 정직성** 유지(질 지표에 0 을 산출불가로 쓰지 않는다).
- 🔴 **막지 않고 드러낸다** — 인증 근거는 보여주되 자동 판정 없음·중복은 사람이 병합.
- 🔴 **정본을 늘리지도 억지로 합치지도 않는다** — 3개 질관리 축은 경계만 명확히, 동의/가족 모델은 유지.
- 🔴 **일어난 사실 소급 금지** — 전화 정규화는 C4 사람 승인 diff 로만, 기존 청구·기록 불변.
- 🔴 **거버넌스 연결** — 새 지표·인증 갭은 `ProposeAgendaButton` 으로 위원회 안건 상정 경로 유지.
- 🔴 **가드는 재주입해 실패해야 가드** — A1 정규화·B3 근거연결에 행동 검증.
