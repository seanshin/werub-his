# 온라인 상담 예약 AI — 통합 정리 v1.0

> **작성일**: 2026-06-02
> **목적**: 현재 AI 컨시어지/예약 시스템의 전체 구조를 정리하고, 페르소나/규칙/문제점/개선 방향을 명확화

---

## 1. 시스템 구조

### 1.1 현재 존재하는 2개의 AI 서비스

| 구분 | AgentSession (예약 AI) | ConciergeService (컨시어지) |
|------|:---:|:---:|
| **경로** | `/booking` (홈페이지) | `/concierge` (HIS 내부) |
| **대상** | 환자 (포털 로그인) | 의료진 (HIS 로그인) |
| **핵심 기능** | 증상→진료과→예약 | 환자 데이터 조회+상담 |
| **상태 머신** | 7단계 (IDLE→COMPLETED) | 없음 (LLM-First) |
| **코드** | 2,456줄 | 481줄 |
| **문제** | 코드 중복, 맥락 유실 | 사용 빈도 낮음 |

### 1.2 통합 대상: **온라인 상담 예약 AI** (환자 포털 `/booking`)

이 문서는 환자가 사용하는 `/booking` 페이지의 AI에 집중합니다.

## 2. 메시지 처리 흐름 (현재)

```
환자 입력
  │
  ├─ ⓪ 응급 감지 (키워드 7패턴) → 119/응급실 안내 [하드코딩]
  ├─ ① 에스컬레이션 ("상담원 연결") → 전화번호 안내 [하드코딩]
  │
  ├─ ② isBookingRequest? ("예약해줘")
  │   ├─ 이전 대화에서 진료과 추출 → CONFIRMING 직접 전환
  │   └─ 진료과 못 찾으면 → 상태 머신으로
  │
  ├─ ③ isDeptCorrection? ("아니, 피부과")
  │   └─ 세부진료과 매핑 → CONFIRMING 직접 전환
  │
  ├─ ④ LLM-First (Enhanced Chat + Triage 병렬)
  │   ├─ 일반 질문 → AI 응답 + 진료과 버튼
  │   ├─ 증상 질문 → AI 응답 + triage 점수 + 예약 권고
  │   └─ 실패 → 상태 머신 폴백
  │
  └─ ⑤ 상태 머신 (switch session.state)
      ├─ IDLE/IDENTIFYING_PATIENT → 환자 식별
      ├─ COLLECTING_SYMPTOMS → triage → 진료과 추천
      ├─ FOLLOW_UP → 추가 질문 → 재평가
      ├─ CONFIRMING → 예약 확인 ("네" → 날짜 선택)
      ├─ SELECTING_TIME → 날짜/시간 선택 → 예약 생성
      └─ COMPLETED → 완료 + 추가 예약 가능
```

## 3. 페르소나 정의

### 3.1 이름 및 역할

| 항목 | 정의 |
|------|------|
| **이름** | 위루비병원 AI 상담 |
| **역할** | 온라인 진료 예약 + 의료 상담 안내 |
| **성격** | 병원 안내 데스크의 경험 많은 친절한 직원 |
| **대상** | 환자 및 보호자 (비전문가) |

### 3.2 화법 규칙

| 규칙 | O (맞음) | X (틀림) |
|------|---------|---------|
| **존댓말** | "확인해 드릴게요" | "확인하겠습니다" |
| **이름 호칭** | "김영수님" | "환자님" |
| **질문에 답변 먼저** | "무좀은 피부과에서 진료합니다. 예약할까요?" | "증상을 말씀해주세요" |
| **공감 표현** | "아프시면 걱정되시죠" | "알겠습니다" |
| **진단 금지** | "전문의 상담을 권장합니다" | "디스크인 것 같습니다" |
| **면책 고지** | 자연스럽게 포함 | "이 정보는 AI..." 반복 |
| **한국어 전용** | 한국어만 | 일본어/중국어/영어 혼용 |
| **마크다운 금지** | 일반 텍스트 | **굵게**, --- |

### 3.3 행동 규칙

| 상황 | 행동 |
|------|------|
| 증상 문의 | 질환 설명 + 관련 진료과 안내 + 예약 제안 |
| 예약 요청 | 이전 대화 맥락에서 진료과 자동 추출 → 바로 예약 진행 |
| 세부진료과 | "소화기내과 → 저희 병원에서는 내과에서 담당합니다" |
| 모호한 질문 | 되묻기 (구체적 선택지 2~3개) |
| "응", "네" | 이전 제안의 확인으로 해석 |
| 맥락 바뀜 | 새 주제 답변 + 이전 주제 자연 연결 |
| AI 실패 | "전화(02-000-0000)로 문의해주세요" |
| 불안/걱정 | 먼저 공감 → 정보 제공 |

## 4. 현재 문제점 및 해결 상태

### 4.1 해결 완료

| # | 문제 | 해결 내용 |
|---|------|---------|
| 1 | LLM 인증 실패 (gpuKey) | DB systemConfig → getLlmHeaders 캐시 반영 |
| 2 | Enhanced Chat API 형식 | message → messages 배열 + domain 파라미터 |
| 3 | 태그 노출 ([REFERENCE_NEEDED]) | 정규식 제거 |
| 4 | 외국어 출력 | CJK ≥ 한글 비율 기반 줄 삭제 |
| 5 | 마크다운 노출 | **bold**, ---, *italic* 제거 |
| 6 | 모델명 노출 (qwen2.5:14b) | FE에서 삭제 |
| 7 | 예약 시 맥락 유실 | 이전 8턴에서 진료과 자동 추출 |
| 8 | 세부진료과 미매핑 | 11종 SUBDEPT_MAP (소화기내과→내과) |
| 9 | "응"→응급의학과 | 1글자 진료과 매칭 방지 + positiveExact 확장 |
| 10 | 토큰 부족 | num_predict 1024, 글자수 제한 해제 |
| 11 | 대화 히스토리 미전달 | Enhanced Chat에 최근 6턴 포함 |
| 12 | 예약 패턴 부족 | "예약할/할게/할께/해줘" 추가 |

### 4.2 미해결 / 개선 필요

| # | 문제 | 원인 | 우선순위 |
|---|------|------|:------:|
| A | **대화 맥락 8턴 제한** | 히스토리 윈도우 고정 | 높음 |
| B | **LLM이 한국어 외 출력** | 모델 특성 (완전 방지 불가) | 중간 |
| C | **면책 고지 반복** | LLM 프롬프트에 규칙 있으나 반복 | 중간 |
| D | **코드 중복** (ConciergeService vs AgentSession) | 별도 개발 | 낮음 |
| E | **환자 선호 학습 없음** | 세션별 독립 | 낮음 |
| F | **의사 지정 예약 불가** | 진료과만 가능 | 중간 |

## 6. 후처리 파이프라인

모든 LLM 응답은 사용자에게 전달되기 전 다음 처리를 거침:

```
LLM 원본 응답
  │
  ├─ 1. 태그 제거: [REFERENCE_NEEDED:...], [TRIAGE_NEEDED] 등
  ├─ 2. 마크다운 제거: **bold**, *italic*, ###, ---
  ├─ 3. 외국어 줄 제거: CJK ≥ 한글 비율이면 해당 줄 삭제
  ├─ 4. (번역) 태그 제거
  ├─ 5. 연속 빈 줄 정리: \n{3,} → \n\n
  └─ 6. trim
```
