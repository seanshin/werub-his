## 0. 한 줄 요약

10개 화면은 모두 "규칙을 만든다". 그런데 **만든 규칙을 실행 경로가 읽는지**, **누가 승인했는지**, **언제 바뀌었는지**는 화면마다 제각각이다.
가장 큰 결함은 **CDSS 규칙 화면이 편집하는 표를 판정 엔진이 읽지 않는다**는 것이다(편집해도 아무것도 바뀌지 않는다). 실제 판정 규칙(DUR 55건)은 관리 화면이 없다.

## 4. 개선(A) — 결함을 닫는 것

### A1. CDSS 규칙 정본 하나 (R1·R2)
- 판정이 읽는 표를 화면이 편집한다 — **정본은 `DurRule`**(엔진이 이미 읽고 60초 캐시). CDSS 규칙 화면을 DUR 룰 관리로 바꾸고, 코드 규칙(알레르기·신기능·연령·진단·가이드라인)은 "코드 규칙 — 편집 불가"로 목록에만 보인다.
- `CdssRule` 17건은 내용이 DUR 룰과 다르다 — 이관할지 버릴지는 사람 결정(D3). 결정 전에는 화면 머리에 "이 목록은 판정에 쓰이지 않는다"를 말한다(P0).
- 규칙별 적중 계측: 판정이 규칙 id 를 결과에 싣고 기록에 남긴다 → 적중·무시 수(기존 CPOE 경고 부담 `orders/quality/alerts` 와 같은 원천).

### A2. 판정 기록 경로 (R3·R3-b)
- 진료 작성 배너가 `encounterId` 를 보낸다 · 오더 화면 점검 실패는 "점검 못 함"으로(3상태).
- 가드: 판정 EP 호출처 전부가 `encounterId` 를 싣는지(진료 맥락일 때) 구조 대조.

### A3. 카탈로그 생애주기 공통 정본 (R4·R5·R12)
- shared `catalog-lifecycle.ts` — 상태(DRAFT·검토·ACTIVE·폐기)·전이·**활성화 = 승인자 필수**·**ACTIVE 내용 수정 = 새 판**(이전 판은 폐기 예정으로 남기고 사용 중 참조는 유지) · CP·치료일정 먼저, 차트 공유 템플릿·트리아지 규칙에 같은 정본.
- 기존 ACTIVE 26건(승인자 없음)은 **데이터를 고치지 않는다** — 화면이 "승인 기록 없음 26"을 말하고 사람이 승인 기록을 남기는 경로를 준다.
- 수정 경로도 활성화 게이트(미해석 항목)를 지난다.

### A4. 트리아지 이름·범위·권한 (R7)
- 화면 머리에 "원무 AI 접수 상담의 증상 → 진료과·응급 경고 규칙 — 응급실 KTAS 분류에는 쓰이지 않는다"를 말한다(이름 변경은 사람 결정 D5).
- 응급 경고 규칙 수정은 관리자 또는 승인(D5) · 규칙 판·변경자 기록.

### A5. 처방의 지정 규칙을 결정으로 (R8)
- 등록부에 `prescription.prescriberRules.*`(위임 허용·위임 인증·주치의 한정) 등재 → 설정을 결정에 묶어 결정 보호 대상으로. 화면은 결정 상태를 보이고 설정 직접 변경 때 그 사실을 말한다(기존 결정 엔진 경로).

### A6. 임상도구 검수 진행 (R9)
- 검수 현황판: 89 중 검증·반려·재검수 필요·미검증 · 레지멘(처방 초안을 막고 있는 것) 먼저 정렬 · 4-eyes 정책 표시.
- 서버가 정의 해시를 대조할 수 없다는 한계를 화면이 말한다(정의가 웹 코드에 있다). 정의를 shared 로 옮겨 서버 대조할지는 후속(B 아님 — 별도 판단).

### A7. 폼 정의 판 (R10)
- 정의 수정 = 새 판(판 번호 자동 · 이전 판 보존) · 제출은 판 id 를 든다 · 미사용 직원 EP 2개는 부를 화면을 만들지 회수할지 판정(P5).

### A8. 세트 편집기 처방집 표시 (R11)
- 항목마다 처방집 상태(등재·미등재·중지) · 시행 정책(WARN/BLOCK)이면 저장 때 경고 · 활성화 때 미등재 수 표시(막지는 않는다 — 처방집 결정 몫).

### A9. 약속처방 사용 권한 (R6)
- 간호사 사용(구두 처방 입력 범위)과 서버 역할을 맞춘다 — 직종별 오더 입력 범위 정본(`order.entryScope`)을 따른다.

## 8. 검증 방식

- 각 결함은 **재주입으로 가드가 실패**해야 한다 — 예: 배너에서 `encounterId` 를 빼면 실패 · ACTIVE 세트 `PUT` 이 판을 올리지 않으면 실패 · CDSS 규칙 화면이 엔진이 안 읽는 표를 부르면 실패.
- 대조군: 처방집 게이트·프로토콜 자동 생성·차트 판 기록(이미 정상)은 그대로 통과.
- 🔴 운영 실측을 다시 한다 — `CdssLog` 가 P0 배포 뒤 쌓이는지(0 → N), DUR 룰 적중 수.
- 역할: 의사·간호사·관리자 실화면 확인은 사람 몫(원격 로그인 금지).
- 동결 뒤 BE·web·shared 전체 재실행.

## 9. 하지 않는 것

- 운영 데이터 교정(승인자 없는 ACTIVE 세트를 승인된 것으로 바꾸기·`CdssRule` 일괄 이관) — 결정 뒤 사람이.
- 응급실 KTAS 분류를 이 규칙 표로 옮기기 — KTAS 는 국가 표준 체계라 별도 판단.
- 임상도구 정의를 서버로 옮기는 것(정의 해시 서버 대조) — 범위가 커서 별도 기획.
- 규칙을 AI 가 만들어 바로 활성화하는 것 — 초안까지만(기존 CP AI 초안 원칙).
