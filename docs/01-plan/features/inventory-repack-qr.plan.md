# 의료물품 재포장 관리 및 QR코드 기획서

> 작성일: 2026-05-08
> 대상: 자재팀, 중앙공급실, 약국, 각 부서 물자담당자

---

## 1. 배경

병원 의료물품은 원래 포장 단위(박스, 케이스)로 입고되지만, 실제 사용 시에는 **부서별/환자별 소분(재포장)** 이 필수적입니다.

### 재포장이 필요한 주요 사례

| 사례 | 원포장 | 재포장 | 비고 |
|------|--------|--------|------|
| 주사기 소분 | 박스(100개) | 병동별 20개씩 소분 | 부서별 배분 |
| 수술 세트 포장 | 개별 품목 다수 | 수술 유형별 세트 구성 | 수술 키트화 |
| 드레싱 세트 | 거즈+소독솜+반창고 | 1회분 드레싱 키트 | 처치별 키트 |
| 주사 준비 세트 | 주사기+알코올솜+반창고 | IV 준비 세트 | 간호 편의 |
| 투약 소분 | 약품 대포장 | 1일분/1회분 소분 | 약국 작업 |
| 응급 카트 보충 | 개별 품목 | 응급카트 기준 세트 | 정량 보충 |
| 소독물품 포장 | 멸균 전 | 멸균 후 재포장 | CSSD 연계 |

## 2. 데이터 모델

### 2-1. RepackOrder — 재포장 지시서

```
RepackOrder
├── id              UUID PK
├── orderNumber     VARCHAR(30) UNIQUE  // "RPK-20260508-001"
├── type            VARCHAR(30)         // SPLIT(소분), KIT(키트구성), REPACK(재포장)
├── status          VARCHAR(30)         // DRAFT, IN_PROGRESS, COMPLETED, CANCELLED
├── sourceItems     JSON                // [{itemId, lotId, qty}] 원재료
├── targetItemName  VARCHAR(300)        // 결과물 명칭 "IV 준비 세트 (성인)"
├── targetQty       INT                 // 생산 수량
├── targetUnit      VARCHAR(30)         // 세트, 팩, 키트
├── targetStorageId UUID?               // 보관장소
├── qrCodeData      VARCHAR(500)        // QR 인코딩 데이터
├── instructions    TEXT                // 작업 지시 사항
├── performedBy     VARCHAR(200)        // 작업자
├── completedAt     TIMESTAMP?
├── notes           TEXT
├── createdBy       UUID
├── createdAt       TIMESTAMP
├── updatedAt       TIMESTAMP
```

### 2-2. RepackOrderItem — 재포장 투입 품목

```
RepackOrderItem
├── id            UUID PK
├── repackOrderId UUID → RepackOrder
├── itemId        UUID → InventoryItem
├── lotId         UUID? → InventoryLot
├── quantity      INT                 // 투입 수량
├── notes         TEXT
```

### 2-3. QrLabel — QR코드 라벨

```
QrLabel
├── id            UUID PK
├── labelType     VARCHAR(30)         // ITEM, LOT, REPACK, KIT, STORAGE
├── referenceId   UUID                // 연결 대상 ID
├── qrData        VARCHAR(1000)       // QR 인코딩 데이터 (JSON)
├── qrImageUrl    VARCHAR(500)?       // 생성된 QR 이미지 경로
├── printCount    INT DEFAULT 0       // 인쇄 횟수
├── lastPrintedAt TIMESTAMP?
├── createdBy     UUID
├── createdAt     TIMESTAMP
```

## 3. QR코드 체계

### 3-1. QR코드 데이터 구조

모든 QR코드는 JSON 형태로 인코딩:

```json
{
  "t": "ITEM",           // 유형: ITEM, LOT, REPACK, KIT, STORAGE
  "id": "uuid",          // 참조 ID
  "c": "INV-001",        // 코드
  "n": "주사기 3mL",     // 명칭
  "l": "LOT-A001",       // LOT (해당 시)
  "e": "2028-05",        // 유효기간 (해당 시)
  "q": 100,              // 수량
  "d": "2026-05-08",     // 생성일
  "h": "HR"              // Hospital RUN 식별자
}
```

### 3-2. QR 활용 시나리오

| 시나리오 | QR 부착 대상 | 스캔 시 동작 |
|----------|-------------|-------------|
| **품목 식별** | 물품 선반 라벨 | 품목 상세 + 재고 현황 조회 |
| **LOT 추적** | 입고 물품 라벨 | LOT 정보 + 유효기간 + 보관장소 |
| **재포장 키트** | 소분/키트 패키지 | 구성품 목록 + 유효기간 + 작업자 |
| **보관장소** | 창고/선반 라벨 | 해당 위치 보관 품목 목록 |
| **입고 확인** | 입고 박스 | 발주 정보 + LOT + 검수 기록 |
| **불출 확인** | 불출 물품 | 청구 부서 + 품목 + 수량 확인 |

## 5. API 엔드포인트

### 5-1. 재포장 (6개)

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/v1/inventory/repack-orders` | 재포장 지시서 목록 |
| POST | `/api/v1/inventory/repack-orders` | 재포장 지시서 작성 |
| GET | `/api/v1/inventory/repack-orders/:id` | 재포장 상세 |
| PATCH | `/api/v1/inventory/repack-orders/:id/status` | 상태 변경 (시작/완료/취소) |
| POST | `/api/v1/inventory/repack-orders/:id/complete` | 재포장 완료 (재고 차감 + 결과물 등록) |
| POST | `/api/v1/inventory/repack-orders/:id/qr` | QR 라벨 생성 |

### 5-2. QR코드 (5개)

| Method | Path | 설명 |
|--------|------|------|
| GET | `/api/v1/inventory/qr-labels` | QR 라벨 목록 |
| POST | `/api/v1/inventory/qr-labels` | QR 라벨 생성 (단건) |
| POST | `/api/v1/inventory/qr-labels/bulk` | QR 라벨 일괄 생성 |
| GET | `/api/v1/inventory/qr-labels/:id` | QR 상세 + 이미지 데이터 |
| PATCH | `/api/v1/inventory/qr-labels/:id/print` | 인쇄 카운트 증가 |

## 6. 구현 범위

| 항목 | 내용 |
|------|------|
| 신규 Prisma 모델 | 3개 (RepackOrder, RepackOrderItem, QrLabel) |
| 신규 API | 11개 엔드포인트 |
| 신규 프론트엔드 탭 | 2개 (재포장/키트, QR코드) |
| QR 생성 | 서버사이드 `qrcode` npm 패키지 (SVG/PNG data URI) |
| QR 인쇄 | 브라우저 `window.print()` (라벨 전용 CSS) |
