# 응급 도착 상황 기록 — 미확인 환자 등록 확대·추가 기록(2026-09-29)

> 요청: "응급 미확인 환자 등록 시 도착 상황 메모를 좀 더 확대 기획해서 추가 기록하는 기능 추가".

## 1. 실측 — 메모는 저장된 적이 없다
- 화면(`patients/register/emergency`)은 `arrivalNote`·`injuryType` 을 보냈고 DTO(`EmergencyUnknownDto`)는 검증까지 했다.
- 서비스 `registerEmergencyUnknown` 은 **Patient 행만 만들고 둘을 버렸다** — 컬럼 없음 · 보여주는 화면 없음 · 테스트 없음. 개통 이래 기록 0(판정 규칙 P16 — 받는 척하고 남기지 않음).
- 손상 유형 12종은 화면 안 한국어 배열(번역 안 됨) · 내원 수단은 다른 화면에 서로 다른 목록 둘(`도보/구급차/전원` · 시드 `도보/119구급차/사설구급차/기타`).
- 신원 확인 모달은 성별을 '남'으로 채워 시작했다(쓰기 폼 초기값 규칙 위반).

## 2. 설계
- 어휘 정본 `packages/shared/src/er-arrival.ts` — 내원 수단 8 · 손상 유형 13(옛 한국어 값 → 코드 `injuryTypeFromLegacy`) · 도착 시 의식 AVPU+평가 안 함 · 동행·인계자 8 · 정보 출처 7 · 소지품 보관 5.
- 원장 `EmergencyArrivalNote`(`emergency_arrival_notes` · 추가만) — **첫 기록(INITIAL) + 추가 기록(ADDENDUM)**. 고치지 않고 덧붙인다: 나중에 경찰·보호자에게 들은 사실이 처음 기록을 덮지 않는다.
- 칸: 도착 시각 · 내원 수단 · 구급대/이송 기관 · 도착 시 의식 · 발견 장소·시각·경위 · 손상 유형(복수) · 동행·인계자(유형·이름·연락처·관계) · 소지품(품목+보관) · 신체 특징·착의 · 경찰(있음/없음/모름 · 소속·담당·사건번호) · **이 기록의 정보 출처** · 메모.
- 🔴 정직 규칙: 모든 칸은 미선택으로 시작 · 모르는 시각은 비움(서버가 '지금'으로 채우지 않는다) · 빈 기록은 만들지 않는다 · 보여줄 땐 적힌 칸만(적지 않은 것을 "없음"으로 그리지 않는다) · 어휘에 없는 옛 손상 유형 값은 버리지 않고 메모에 원문으로.
- API: `POST /api/v1/patients/emergency-unknown` 에 `arrival`(구조화 · 옛 `arrivalNote`·`injuryType` 도 첫 기록으로) · `GET/POST /api/v1/patients/:id/arrival-notes`(NURSE·DOCTOR·ADMIN · 변이·열람 감사는 `/patients` 규약).
- 화면: 등록 화면 = 최소 정보 + 도착 상황 기록(6구역) → 등록 후 **그 환자 상세로** · 환자 상세(개요) = 도착 상황 기록 패널(시간순 · 추가 기록) — 응급 미확인 출처이거나 `EMG-` 번호(신원 확인 뒤에도 남는다) · 신원 확인 모달 = **신원 단서**(소지품·신체 특징·동행인·경찰·발견 장소) 펼침 + 성별 미선택 시작.
