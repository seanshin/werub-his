# 기획서 — 문서 충실도(Document Fidelity) UX

> 검사지·진료기록 등 의무기록/출력물을 **실제 종이 양식·출력지와 동일한 형태**로 보여주고 인쇄·PDF로 출력하는 통합 UX 체계.
> 작성일: 2026-06-10 · 상태: Plan v1.3 (실서식·데이터 실조사) · 분류: Frontend + Backend 공통

---

## 1. 배경 / 목적

대학병원 현장은 여전히 **종이 양식의 시각적 관습**(검사 성적서, 진료기록지, 처방전, 제증명, 영수증)에 강하게 의존한다. 의료진·환자·행정 모두 "익숙한 문서 모양"을 기준으로 정보를 읽고 검증한다. 그러나 현재 HIS는 데이터를 **웹 대시보드/카드 UI**로만 표시해, 실제 출력물과 형태가 달라 다음 문제가 있다.

- **인지 부조화**: 화면(웹 카드) ≠ 출력물(PDF/인쇄) ≠ 법정 양식 → 의료진이 "이게 그 서류 맞나" 재확인.
- **출력 품질 편차**: 브라우저 기본 인쇄 시 사이드바·버튼·여백이 섞여 나오고 페이지가 잘림.
- **구현 산발**: 동의서는 HTML→PDF(`consent`), 제증명은 `pdf-lib`(`medical-record-copy`)로 각각 구현 → **공통 양식·머리글·직인·발급번호 체계 부재**.
- **법적 신뢰성**: 진단서·소견서·검사성적서는 양식·발급정보·직인이 법/인증(EMR·JCI) 요건. 현재 일관 보증 약함.

**목적**: 화면 미리보기 = 인쇄 = PDF가 **동일한 "문서"로 보이는 WYSIWYG 체계**를 공통 컴포넌트로 구축하여, 실제 출력지와 유사한 신뢰감 있는 UX를 제공한다.

## 2. 현황 / 문제 (As-Is)

| 영역 | 현재 | 문제 |
|------|------|------|
| 검사 결과(`lab`, 포털 검사결과) | 웹 표/카드 | 검사성적서 양식 아님, 인쇄 시 깨짐 |
| 진료기록(`medical-records`, encounter) | 탭/카드 UI | 진료기록지 형태 아님, 출력 일관성 없음 |
| 처방전(`prescription`) | 목록/폼 | 법정 처방전 양식 미흡 |
| 동의서(`consent`) | HTML→PDF 有 | 개별 구현, 공통 양식 아님 |
| 제증명(`medical-record-copy`) | `pdf-lib` 직접 | 공통 머리글/직인 체계와 분리 |
| 공통 인쇄 시스템 | **없음**(전역 `@media print`/`@page` 미존재) | 화면=인쇄=PDF 불일치 |

→ **핵심 공백: 문서 충실도를 보장하는 공통 레이아웃·인쇄 CSS·PDF 일원화 계층이 없다.**

## 3. 범위 (Scope)

### 대상 문서 (우선순위)
| P | 문서 | 비고 |
|---|------|------|
| P0 | **검사 성적서**(진단검사/영상/병리) | 가장 빈번·법정 양식 |
| P0 | **진료기록지**(SOAP/경과기록/입원기록) | 의무기록 핵심 |
| P0 | **처방전**(원내/원외 OTC·전문) | 법정 양식 |
| P1 | 진단서·소견서·제증명 | 기존 PDF 통합 |
| P1 | 영수증·진료비 세부산정내역서 | 법정 13항목 기존 자산 활용 |
| P1 | 동의서 | 기존 자산 공통화 |
| P2 | 의뢰서·회신서·전원기록(CDA) | 표준 연계 |
| P2 | 입·퇴원 확인서, 투약기록(MAR) | |

### 포함
- 화면 **문서 미리보기**(A4 캔버스, 실제 양식 레이아웃)
- **인쇄**(브라우저 print, 양식 그대로) + **PDF 다운로드**(서버 일원화)
- 공통 **머리글/꼬리글**(병원 로고·주소·발급정보·페이지번호), **직인/서명란**, **발급번호·QR/바코드**, **워터마크**(사본/무효)

### 제외 (Out of Scope)
- 종이 스캔 OCR 역방향 입력(별도)
- 외부 출력장비(라벨/팔찌 프린터) 펌웨어 연동(별도)
- 다국어 양식 전면 번역(1차 한국어, i18n 훅만 확보)

## 4. 핵심 컨셉 — "문서 충실도 3대 원칙"

1. **WYSIWYG 일치**: 화면 미리보기 · 인쇄 · 다운로드 PDF가 **픽셀/레이아웃 동일**. 단일 템플릿 → 3-way 출력.
2. **양식 충실(Form Fidelity)**: 실제 종이 양식의 **표 구조·칸·라벨·서명란·머리글**을 그대로 재현(A4 규격, mm 단위 여백).
3. **신뢰 요소(Authenticity)**: 발급일시·발급번호·발급자·직인/전자서명·QR(원본 검증)·워터마크 — 법/인증 요건 충족.

## 4.5 통합 방식 — **기존 화면 유지 + "문서 보기" 탭 추가 (비파괴)**

> ⚠️ **대원칙**: **현재 구현된 화면/탭은 그대로 유지**한다. 문서 충실도 UX는 **기존 화면을 대체하지 않고**, 각 화면에 **새 탭("문서 보기" 또는 "출력 양식")을 추가**하는 방식으로 도입한다. (프로젝트 "기능 삭제 방지" 규칙 준수)

- **현행 유지**: 검사결과·진료기록·처방 등의 기존 **작업용 UI(카드/표/입력 폼)**는 데이터 입력·실시간 확인에 최적 → **변경 없음**.
- **추가**: 같은 화면에 탭 하나를 더해, 동일 데이터를 **실제 출력지 양식**으로 보여주는 **읽기/출력 전용 뷰** 제공.
- **사용자 선택**: 평소엔 기존 탭으로 빠르게 작업, 출력/검토/발급이 필요할 때 "문서 보기" 탭으로 전환.

```
[ 기존 탭들 .......................... ] [ 📄 문서 보기 ]  ← 신규 추가
  ↑ 그대로 유지(작업용)                    ↑ A4 양식·인쇄·PDF (읽기/출력 전용)
```

예시:
- 검사실/포털 검사결과 화면 → 기존 표 + **「검사 성적서」 탭** 추가
- 진료기록(encounter/medical-records) → 기존 SOAP 카드 + **「진료기록지」 탭** 추가
- 처방(prescription/CPOE) → 기존 처방 폼 + **「처방전」 탭** 추가

- **공통 진입 패턴**: 탭 외에도 목록 행/상세의 "📄 문서" 아이콘으로도 동일 양식 뷰 진입 가능(모달 또는 새 탭). 단, **기존 버튼/동작은 보존**.

## 5. 기능 요구사항 (FR)

- **FR-0 기존 화면 보존 + 탭 추가**: 대상 화면의 **기존 탭/UI는 변경 없이 유지**하고, **"문서 보기"(출력 양식) 탭을 추가**한다. 신규 탭은 읽기/출력 전용. 기존 라우트·컴포넌트·버튼·동작 보존(회귀 0).
- **FR-1 문서 미리보기 캔버스**: "문서 보기" 탭 진입 → A4(210×297mm) 비율 캔버스에 양식 렌더. 여러 페이지 자동 분할.
- **FR-2 공통 머리글/꼬리글**: 병원명·로고·주소·전화·사업자/요양기관번호 / 발급일시·발급번호·페이지(n/N)·담당자.
- **FR-3 인쇄**: "인쇄" 시 사이드바/네비/버튼 제외, **양식만** 출력(`@media print` + `@page` 여백). 페이지 나눔 정확(표 행 잘림 방지).
- **FR-4 PDF 다운로드**: 서버에서 **동일 템플릿으로 PDF 생성**(미리보기와 일치). 파일명 규칙(`{문서종류}_{환자}_{발급번호}.pdf`).
- **FR-5 서명/직인란**: 의료진 서명 이미지·전자서명(기존 블록체인 서명 자산 연계)·병원 직인 영역.
- **FR-6 발급번호·QR**: 문서별 고유 발급번호 + QR(원본 진위 검증 URL). 재발급 이력.
- **FR-7 워터마크/상태**: 사본/재발급/무효/미서명 등 상태 워터마크.
- **FR-8 양식별 템플릿**: 검사성적서/진료기록지/처방전 등 양식별 레이아웃 컴포넌트. 진료과/문서종류별 변형 지원.
- **FR-9 접근권한·감사**: 문서 보기/인쇄/다운로드는 PHI 접근 → 권한 가드 + 감사로그(누가·언제·무슨 문서). 환자 포털은 본인 문서만.
- **FR-10 미리보기-출력 옵션**: 글자 크기/언어/항목 표시 토글, 흑백 인쇄 최적화.

## 7. 기술 설계 방향 (High-level)

### 7.1 프론트엔드 — 공통 문서 계층
- **탭 통합(비파괴)**: 각 화면의 탭 배열에 `{ key: 'document', label: '문서 보기' }`를 **추가만** 함. 기존 탭 컴포넌트·상태·핸들러 불변. 신규 탭 클릭 시 `<DocumentFrame>` 렌더. (탭이 없던 단일 화면은 상단에 "작업 / 문서 보기" 토글 추가)
- **`<DocumentFrame>`**: A4 캔버스(mm→px 환산), 머리글/꼬리글 슬롯, 다중 페이지 자동 분할, 인쇄/다운로드 액션바.
- **전역 인쇄 CSS**: `@page { size: A4; margin: ... }` + `@media print`(앱 크롬 숨김, `.doc-print-only`/`.doc-no-print`).
- **양식 컴포넌트**: `LabReportDoc`, `EncounterRecordDoc`, `PrescriptionDoc`, `CertificateDoc` … 데이터 주입형. 단일 소스로 미리보기·인쇄·PDF.
- **신뢰요소 컴포넌트**: `<DocHeader>`, `<DocFooter>`, `<SignatureBlock>`, `<IssueStamp>`(QR·발급번호·직인).
- 라이브러리: 인쇄는 네이티브 `@media print`(가장 충실). PDF는 가급적 **서버 생성**(폰트/일관성), 클라이언트 즉석은 보조.

### 7.2 백엔드 — PDF 일원화
- 산발된 PDF 생성(`pdf-lib`/HTML)을 **공통 문서 서비스**로 수렴: 동일 HTML 템플릿 → PDF(권장: 헤드리스 렌더 또는 정제된 pdf-lib 빌더) → 미리보기와 동일.
- **발급번호 발급기**·문서 메타(발급자/일시/상태/해시) 저장 → 진위검증 API(QR 대상) + 재발급 이력.
- 기존 자산 연계: 동의서(`consent`)·제증명(`medical-record-copy`)·블록체인 서명·영수증(법정13항목)을 공통 머리글/직인 체계로 통합.

### 7.3 데이터/표준
- 검사성적서: 항목·참고치·플래그(H/L/Panic)·검체정보·검사일시·검사자. 영상/병리는 판독문 양식.
- 진료기록지: SOAP·진단(KCD)·처치·의료진·일시. 입원기록/경과기록 변형.
- 처방전: 약품(성분/함량)·용법·일수·DUR·의료기관/의사 정보(법정).

## 9. 성공 지표 (KPI)
- 화면 미리보기 ↔ 인쇄 ↔ PDF **레이아웃 일치율**(시각 회귀) ≥ 99%
- 인쇄 시 양식 외 요소(네비/버튼) 노출 0건
- P0 문서 3종 발급번호·QR·서명란 100% 적용
- 의료진 "출력물이 실제 서류와 같다" 만족도 향상

## 10. 리스크 / 고려사항
- **브라우저 인쇄 편차**(Chrome/Safari `@page` 차이) → 주요 브라우저 매트릭스 테스트.

- **PHI 출력 통제**: 무분별 다운로드 방지(워터마크·감사·권한).
- **법정 양식 변경** 대응 → 양식 버전 관리.
- 기존 PDF 구현 마이그레이션 시 **회귀**(동의서·제증명) → 점진 전환 + 병행 검증.
- **기존 화면 회귀 위험**: 탭 추가 시 기존 탭 동작 영향 0 보장 → 탭 추가는 배열 append만, 기존 컴포넌트 격리. (P0 문서는 신규 탭 내부에만 구현)

## 12. 법정 서식 근거 (Form Compliance) — **실조사 반영(v1.3)**
실제 출력지 유사성은 **법정 서식 준수**가 전제. 양식별 근거를 실제 법령으로 확인.

### 12.1 처방전 — **의료법 시행규칙 §12, 별지 제9호서식** (law.go.kr 확인)
법정 기재사항(실조사): 환자 **성명·주민등록번호**, **질병분류기호(KCD)**, **본인부담 구분기호**, 의료기관 명칭·전화·**요양기관기호**, 처방 의료인 **성명·면허종류·면허번호·서명**, **교부번호·교부연월일**, 의약품 명칭·**1회 투약량·1일 투여횟수·총 투약일수·용법**, 주사제 처방내역, **사용기간**, (약국)조제내역.

### 12.2 진단서 — **의료법 시행규칙 별지 서식**(상해진단 별지 제5호의3 등)
- **병명은 「통계법」 §22에 따른 한국표준질병·사인분류(KCD)** 준수(실조사 확인).
- 기재: 환자정보·병명(KCD)·발병/진단일·향후 소견·의료기관·의사 면허·발급일·용도.

### 12.3 기타
| 문서 | 근거 | 필수 표기 |
|------|------|-----------|
| 진료비 영수증/세부내역 | 국민건강보험법 시행규칙 별지(법정 13항목) | 급여/비급여·본인부담·요양기관정보(기존 자산) |
| 검사 성적서 | 진단검사의학재단 인증·검사실 표준 | 검체·참고치·단위·플래그·검사/판독일시·검사자/판독의 |
| 의무기록 사본 | 의료법 §21 | 발급사유·신청인·교부일·사본 표기 |
| 동의서 | 의료법 §24-2 | 환자/대리인 서명·설명의사·일시(기존 자산) |

> 출처: 국가법령정보센터(law.go.kr) 의료법 시행규칙 별지 제9호서식(처방전)·진단서 서식, 통계청 KCD(KOICD).
> ⚠️ 서식은 개정될 수 있으므로 **양식 버전(formVersion) + 발급 시점 서식 보존** 필요(§14).

## 13. 문서별 데이터 매핑 + **데이터 갭 분석(실조사 v1.3)**
신규 양식 컴포넌트는 **기존 모델에서 읽기만** 한다(쓰기·기존 화면 불변). 실제 Prisma 모델 필드 감사 결과:

| 문서 | 데이터 소스 | 보유 필드(실조사) | 갭 |
|------|-----------|------------------|----|
| 검사 성적서 | `LabResult`+`LabResultItem` | testName·value·unit·**normalMin/Max**·**flag**·collectedAt·completedAt·technician | ✅ 충분 |
| 진료기록지 | `Encounter`+`EncounterDiagnosis` | SOAP·CC·HPI·PMH·FH·SH·ROS·PE·**진단(KCD)**·signedAt/By·doctor | ✅ 충분 |
| 처방전 | `Prescription`+`MedicationCode`+`Order` | dosage·frequency·duration·quantity·route·rxValidUntil·dispensingType(원외)·약품(성분/제형/보험코드)·면허번호(User.licenseNumber)·진단(KCD) | ⚠️ **요양기관기호 누락** |
| 진단서 | `Encounter`/진단 + Staff 면허 | 병명(KCD)·의사 면허 | 발급사유/용도 입력 필요 |
| 영수증 | billing(법정13 기존) | 급여/비급여·본인부담 | ✅(기존 자산) |

### ⚠️ 발견된 데이터 갭 (실조사)
1. **요양기관기호(ykiho)·병원 법정 마스터 부재**: 처방전·영수증 머리글 법정 필수(요양기관기호·사업자번호·대표자·주소·전화). 현재 `businessNumber` 일부만, **단일 병원정보 마스터/Config 없음** → **신규 `HospitalProfile`(또는 SystemConfig 키군) 필요**.
2. **병원 직인 이미지 자산 부재**: 직인/로고 이미지 업로드·저장소 필요(§5 FR-5).
3. **발급문서 동결 저장소**: 발급본 스냅샷 모델(§14) — 트윈 `TwinDocumentReference` 확장 검토.
4. **진단서 발급사유/용도** 등 일부 입력 필드는 발급 시 수집(폼) 필요.

> 결론: **P0 3종(검사·진료기록·처방)의 핵심 데이터는 대부분 보유**. 처방전/영수증 머리글용 **병원 법정정보 마스터**가 선결 갭. 매핑 상세 필드는 설계서에서 문서별 스키마로 확정.

### 13.1 개발 단계 처리 방침 (Dev placeholder)
- **개발 중에는 갭에 임시값(placeholder) 부여 후 진행**한다. 기능 구현·UX 검증이 목적이므로 실데이터 정확성은 배포 시 교정.
  - 요양기관기호·사업자번호·대표자·주소·전화 → **샘플 상수**(예: `WRB-DEMO-…`, "위루비병원").
  - 직인/로고 이미지 → **데모 이미지**.
  - 발급번호 → 규칙대로 생성하되 데모 데이터.
- ⚠️ **실 배포 시 실데이터로 교정 필요** → 별도 **배포 작업 계획서**(`deployment-readiness.plan.md`)에서 일괄 관리.

## 14. 문서 발급·보존 (Issuance & Retention) — **누락 보완**
- **발급 시점 스냅샷(동결)**: 발급된 문서는 **그 시점의 데이터·서식으로 동결 저장**(추후 원본 데이터/서식 변경돼도 발급본 불변). FHIR `DocumentReference`로 등록 — **트윈 write-back 자산(`TwinDocumentReference`/공통 문서 서비스) 재사용**.
- **보존연한**: 의무기록 법정 보존(진료기록 10년 등) 준수. 발급 이력(발급자·일시·사유·수령인) 보존.
- **정정/취소**: 원본 정정 시 정정본 발급 + 사유, 구본은 "정정 전" 상태 표기(삭제 금지).

## 15. 진위검증(QR) — **누락 보완**
- 발급문서에 **QR**(검증 URL `/verify/document/{발급번호}`) + 문서 **해시**. 검증 페이지에서 발급정보·유효성 표시.
- **위변조 방지**: 기존 **블록체인 서명/해시체인 감사** 자산 연계(서명완료 문서 해시 앵커).
- 비로그인 공개 검증(발급번호+해시만, PHI 비노출) vs 로그인 상세 검증 분리.

## 16. 권한·보안 매트릭스 — **보완**
| 역할 | 보기 | 인쇄 | PDF | 발급(서명) |
|------|:---:|:---:|:---:|:---:|
| 의사 | ○ | ○ | ○ | ○(본인 진료) |

- 모든 보기/인쇄/다운로드 **감사로그**(누가·언제·문서·환자). 다운로드 워터마크에 **열람자ID·시각** 옵션.
- 주민번호 등 민감정보 **마스킹 기본**(권한별 해제). 포털은 `PortalOrPatientGuard` 본인 한정.

## 17. PDF 엔진 결정 (Decision needed)
| 방식 | 장 | 단 |
|------|----|----|
| **A. 헤드리스 렌더**(Puppeteer/Playwright, HTML→PDF) | 미리보기와 **완전 동일**(같은 HTML/CSS) | 서버 리소스·운영 부담(크로미움) |
| B. pdf-lib 빌더(현 제증명) | 경량·의존 적음 | 미리보기와 **별도 레이아웃**(불일치 위험) |
- **권장: A(헤드리스)** — "화면=PDF" 일치가 핵심 가치. 단 서버 리소스·보안(샌드박스) 검토 필요(인프라 협의).
- 절충: P0는 헤드리스로 일치 확보, 단순 문서는 pdf-lib 유지 가능.
> ⚠️ PACS/기존 인프라 영향 없이 별도 렌더 워커로 격리 권장.

## 18. 테스트 전략 — **보완**
- **시각 회귀(Visual Regression)**: 미리보기 vs PDF vs 기준 스냅샷 픽셀 diff(KPI 99% 일치 측정).
- **브라우저 매트릭스**: Chrome/Edge/Safari 인쇄(`@page`) 검증.
- **페이지 나눔**: 장문(다년 검사·긴 기록) 다중 페이지·머리글 반복·표 행 잘림 0.
- **회귀 가드**: 기존 화면 탭 동작 불변(스모크), 기존 PDF(동의서·제증명) 출력 동일.

## 19. 마이그레이션 (기존 자산 점진 통합)
1. 신규 공통 계층(P1) 구축 — **기존 PDF 경로 병행 유지**.
2. 신규 양식(P0)을 **탭으로만 추가** — 기존 화면 무변경.
3. P4에서 동의서/제증명/영수증을 공통 머리글·직인·발급번호로 **점진 흡수**(구 경로 → 신 경로, 출력 동일성 검증 후 전환).

## 20. 용어/문서코드 (Taxonomy)
- `documentType` 코드 체계: `LAB_REPORT`·`ENCOUNTER_RECORD`·`PRESCRIPTION`·`CERTIFICATE_*`·`RECEIPT`·`CONSENT`…
- 발급번호 규칙: `{원} {문서코드} {YYYYMMDD} {일련}` (예: `WRB-LAB-20260610-00012`).

## 21. 오픈 이슈 (결정 대기)
1. **PDF 엔진**(§17) — 헤드리스 도입 여부(인프라).
2. **폰트** — Pretendard/나눔(OFL, 임베드 가능) 중 표준 폰트 확정.
3. **발급 동결 저장소** — 트윈 `TwinDocumentReference` 확장 vs 신규 통합 문서 테이블.
4. **QR 검증 공개 범위** — 비로그인 검증 허용 수준.
