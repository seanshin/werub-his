## 2. 왜 별도 프로세스인가

이 감시를 API 안에 넣는 선택지가 있었다. 넣지 않는다. 근거는 전부 이 저장소의 형상이다.

| 이유 | 실측 근거 |
|---|---|
| **감시자가 대상 안에 있으면 함께 죽는다** | API 는 pm2 fork **단일 프로세스**(`instances: 1`). 순환 의존으로 부팅이 깨져 운영 502 가 난 이력이 있고, 그때 감시도 함께 멈춘다 |
| **스윕이 진료 요청 경로를 먹는다** | 67 불변식 SQL 은 전 테이블 조인이다. API 는 `max_memory_restart 1G` — 스캔이 메모리를 밀면 재시작되고 그게 곧 진료 중단 |
| **배포 주기가 다르다** | 감시 규칙은 자주 바뀌고, API 재배포는 빌드+부트 검증까지 무겁다 |
| **권한을 좁힐 수 있다** | 감시자는 임상 테이블에 **읽기 전용**이면 된다. 자기 원장에만 쓴다 |
| **여유가 있다** | 운영 서버 가용 메모리 8.2GB · load 0.5~0.8 |

### 2.1 그래도 API 안에 남는 것

**요청 경로 안에서만 관측되는 신호**는 감시자가 볼 수 없다. 이것만 API 에 남기고,
API 는 **판단하지 않고 원장에 적기만** 한다. 감시자가 그 원장을 읽는다.

```
API (단일 프로세스)                감시자 (별도·읽기 전용)              CI (push)
──────────────────────            ──────────────────────────         ──────────────
런타임 신호 적재            →      ① 원장 읽기·집계                    정적 오라클
 · 키 불일치                       ② 주기 스윕(불변식·신선도)           (파생 강제)
 · null 접힘                       ③ 능동 프로브(EP·계약)
 · 게이트 미발동                    ④ 파이프 생존(크론·이벤트·배포)
                                          ↓
                                   /admin/sentinel
```

### 2.2 배포 형상

- pm2 프로세스 `sentinel` — `instances: 1`, `exec_mode: fork`, `max_memory_restart: 400M`
- `deploy.sh --sentinel` 추가. `--all` 에 포함한다(감시자가 낡으면 감시가 낡는다)
- DB 역할 분리: 임상 스키마 `SELECT` 만, 자기 테이블에만 `INSERT/UPDATE`
  🔴 기존 `hospital` 사용자 비밀번호는 **건드리지 않는다**(OpenPACS 와 공유 — CLAUDE.md 금지 항목)
- 저장소 소스가 필요하다(정적 오라클) → 배포 시 소스 트리를 함께 rsync

## 3. 네 축 — "전체 데이터와 흐름"

### 축 A · 데이터 정합성

- 67 불변식 스윕(현행 SQL 을 그대로 실행 — 다시 만들지 않는다)
- 신선도 15축(`data-freshness.mjs` 이식)
- 품질 지표 49(현행 크론을 감시자로 이관하되 **일일 스냅샷 계약은 유지**)
- 🔴 **판정은 사람이 한다.** 스캔 헤더가 이미 그렇게 적어 놨다 — ⚪ 항목은 0이 목표가 아니다.
  감시자는 **추이와 신규 발생**을 말하고, 절대값으로 경보하지 않는다.

### 축 B · 흐름 완결성

지금 아무도 보지 않는 축이다. "값은 맞는데 흐름이 멈춘 것"을 본다.

| 무엇 | 판정 |
|---|---|
| 접수→진료→수납→약국→완료 중 **멈춘 건** | 단계별 체류 시간이 그 축의 과거 실측 p95×2 를 넘긴 것 |
| **열린 폐루프** | 위급값 보고·인계 확인·결재·재평가가 열린 채 기한 초과 |
| **오더는 났는데 실행 기록이 없는 것** | 처방 ACTIVE ↔ 오더 부재(현재 244건) |
| **상태는 완료인데 근거가 없는 것** | 롤포워드가 허구 실적을 만든 P16 부류 |

🔴 임계값은 감이 아니라 **그 축의 과거 실측(p95×2)** 에서 뽑는다.
"조건이 참인가"가 아니라 **"얼마나 참인가"** 를 재야 아티팩트와 사실이 갈린다
(1ms 역전 32건이 거짓 경보였던 이력).

### 축 C · 계약 드리프트

같은 날 열 건이 나온 축. 화면이 사람에게 하는 말이 사실과 어긋나는 부류다.

| # | 어긋난 것 | 화면이 한 말 | 사실 |
|---|---|---|---|
| 01 | 롤업이 `bed.total` 을 읽음(생산자는 `totalBeds`) | 산출 불가 — 등록 병상 없음 | 병상 57, 점유 5 |
| 02 | 섹션 조회 실패를 빈 객체로 접음 | 접수 대기 0 · 미수금 0원 | 조회가 실패했다 |
| 03 | 라벨 가드가 3주 전 수기 스냅샷 | (초록) | 영문 키 10개 노출 중 |
| 04 | 표본 창을 읽는 화면 없음 | QI 달성률 88% | 4개월 전 측정 |
| 05 | `scope['imaging']` 생산자 없음 | 열람 범위: 예약/진료/검사/수납 | 판독소견·DICOM 개방 |
| 06 | 수납 후 상태가 집계에 없음 | 오늘 완료 N건 | 수납할수록 N 감소 |
| 07 | 대표값이 `null` 을 `0` 으로 접음 | 병상 가동률 0% | 산출 불가 |
| 08 | `unavailable`·`reason` 미독 | 정산 미완 | 확인하지 못했다 |
| 09 | `implemented: true` 선언 | SMTP 구현 O | 발송 의존성 없음 |
| 10 | `if (queryKey)` 검증 | API Key 인증 | 키 없으면 통과 |
| 11 | '아직 원내' 정본이 둘 | 활성 N명 | 약국 대기 환자가 빠져 있다 |

기전은 셋뿐이다.

1. **타입이 끊긴 자리** — 구조 캐스팅 뒤의 문자열 키는 컴파일러에게 그냥 문자열.
   실측 캐스팅 자리 API 650 · web 1,023.
2. **손으로 베낀 목록** — 정본이 늘어도 안 늚 → 잡으려던 결함을 재현한 채 통과.
   낡음 확정 6 · 파생 아님(위험) 14 · 안전 20.
3. **만들었는데 안 쓰는 것** — 리스너 0 이벤트 17종 · 미소비 응답 필드 6종+.

## 4. 감시자 자신의 정직성

🔴 **감시자가 거짓말하면 그 위의 모든 판단이 무너진다.** 이건 가정이 아니라 오늘 실제로 나왔다 —
품질 일일 스냅샷이 저장 실패분까지 성공으로 세고 "저장 N건"이라 남기고 있었다(같은 날 수정).

규약:

- **미판정을 0으로 그리지 않는다.** 스윕이 안 돌았으면 `—` 다. "위반 0건"과 "안 재봤다"는 다른 화면이다.
- **감시자의 마지막 성공 시각을 화면이 항상 보여준다.** 감시자가 죽으면 그 사실이 먼저 보여야 한다.
- **부분 실패를 전체 성공으로 세지 않는다.** 축마다 `{시도, 성공, 실패, 사유}`.
- **탐지기는 재주입으로 검증한다.** 결함을 되돌렸을 때 실패하지 않으면 그것은 감시가 아니다.
- **막지 않고 드러낸다.** 감시 결과로 임상 행위를 차단하지 않는다. 막으면 방치된다.
- **정본에서 파생하지 않는 목록은 만들지 않는다.**

## 7. 하지 않을 것

- **캐스팅 1,673곳 일괄 제거** — 외부 경계(HTTP·JSON 컬럼·환경변수)의 캐스팅은 타입으로 못 잡는다.
  **내부 경계**(같은 저장소 두 서비스)만 겨눈다.
- **감시 결과로 임상 행위 차단.**
- **런타임 로그 전량 적재** — 같은 드리프트는 한 줄로 접고 횟수로 규모만 말한다.
- **"이상 없음" 초록 배지** — 표본 부재와 진짜 0을 구분하지 못하는 배지는 그 자체가 P17 이다.
- **감시자가 데이터를 고치는 것** — 읽기 전용이다. 교정은 사람이 워크리스트에서 한다.
- **기존 도구 재작성** — 67 불변식 SQL 도 15축 신선도도 그대로 실행한다.

## 7-b. 노출 범위 — **관리자 화면 전용**(2026-09-03 사람 결정)

감시 결과는 `/admin/sentinel` 에만 둔다. **통합 상황판(`/command-center`)에는 붙이지 않는다.**

왜 그렇게 정했나:
- 🔴 상황판은 **임상 직군이 보는 화면**이다. 감시 소음이 임상 경보와 같은 자리에 뜨면
  **진짜 경보가 묻힌다** — P4 에서 알림 대상을 관리자로 좁힌 것과 같은 이유다.
- 상황판이 답해야 하는 질문은 "지금 병원이 어떤 상태인가"이고,
  감시자가 답하는 질문은 "지금 보고 있는 숫자를 믿어도 되는가"다. **다른 질문이다.**
- 후자는 **행동 주체가 다르다**(임상 직원이 아니라 관리·개발 담당).

그래서 상황판은 지금처럼 임상 질(QI·손위생·안전사건)과 환자 흐름(여정·열린 폐루프)만 그린다.
데이터 정합성·계약 드리프트·파이프 생존은 관리자 화면에 남는다.

🔴 이 결정은 가드로 동결한다(`web/test/ui/command-center-labels.spec.ts`) —
   붙이는 것이 편해 보이는 순간이 오기 때문이다. 뒤집으려면 가드를 함께 고쳐야 하고,
   그때 이 문단을 다시 읽게 된다.
