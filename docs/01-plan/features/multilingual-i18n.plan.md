## 0. 현황 / 전제
- **기존 i18n 라이브러리 없음**(greenfield). 전 UI 한국어 하드코딩.
- 대상: **공개 홈페이지(`(homepage)` 43p)** + **환자포털(`/portal`)**. 직원 HIS(내부 업무)는 **범위 외**(한국인 직원).
- 국제병원(WERUBYHOSP) — 외국인 환자 등록·해외환자 기능 존재 → 다국어 수요 명확.

## 1. 목표
```
방문자/환자가 언어를 선택하면 홈페이지·포털 UI와 핵심 콘텐츠가 해당 언어로 표시된다.
SEO(홈페이지)·접근성·의료정보 정확성을 보장한다.
```

## 2. 범위 (D-1 언어)
| 단계 | 언어 |
|------|------|
| **1차** | 한국어(기본), **영어** |
| 2차 | 중국어(간체), 일본어 |
| 3차(수요) | 러시아어, 아랍어(RTL 고려), 베트남어, 몽골어 |

- **포함**: 홈페이지 UI·내비·정적 페이지(이용안내·진료과·검진 등), 포털 UI(탭·폼·알림 문구).
- **부분/후속**: CMS 동적 콘텐츠(병원소식·건강정보) — 언어별 콘텐츠 또는 기계번역(§6).
- **제외**: 직원 HIS 화면, 의료진 작성 진료기록 원문.

## 3. 기술 방식 (D-2)
- **라이브러리**: `next-intl`(Next 15 App Router 네이티브, SSR/SEO 우수) 권장. (대안: react-i18next)
- **홈페이지 라우팅**: **경로 프리픽스**(`/en/...`, `/zh/...`) — SEO 친화(hreflang, 검색엔진 색인). 기본 ko는 프리픽스 없음 또는 `/ko`.
- **포털 라우팅**: 앱(비SEO) → **쿠키/사용자설정 기반 토글**(경로 프리픽스 불필요). 로그인 사용자는 프로필에 선호언어 저장(이미 `preferredLanguage` 필드 존재 — 외국인 등록).
- **번역 리소스**: `messages/{locale}.json`(네임스페이스: common/home/portal/forms…). 빌드 포함.

## 5. 아키텍처
```
next-intl Provider (locale 감지: 경로(홈)/쿠키·프로필(포털))
  ├─ messages/{ko,en,zh,...}.json  (네임스페이스)
  ├─ useTranslations('namespace') → t('key')
  ├─ 홈: [locale] 세그먼트 + middleware(로케일 라우팅) + hreflang
  └─ 포털: 쿠키 NEXT_LOCALE + 프로필 preferredLanguage 동기화
CMS: HomepageContent에 locale 필드 추가 또는 번역본 분리(FR-07)
```

## 5-1. 언어 선택 기반 자동 번역 (공유 엔진) — *v1.1 추가*
```
사용자 언어 선택(헤더/포털/상담실)
  → 인간 번역(카탈로그/CMS 번역본) 있으면 그대로
  → 없으면 자동 번역 엔진 호출: POST /api/v1/i18n/translate { text, source?, target }
       └ Ollama(온프레미스 LLM) 번역 → 캐시(키: hash(text)+target) → 반환("자동번역" 표기)
```
- **공유**: 포털 UI 폴백·CMS 동적 콘텐츠·**[[portal-chat-consultation]] 상담 메시지**가 동일 엔진 사용(중복 구현 방지).
- **캐시**: 동일 문장 재번역 방지(DB/Redis). **용어집**(병원/의료 고정 표현) 우선 적용.
- **품질**: 의료·법률·동의 문구는 자동번역 단독 금지 → 검수본 우선, 자동본은 "참고용·원문 병기"(FR-13).
- **온프레미스**: 외부 번역 API 대신 자체 Ollama → PHI/민감정보 외부 유출 없음.

## 5-2. 자동 번역 적용·성능 전략 — *v1.2 검토 보완*
- **렌더 차단 금지**: SSR 중 Ollama 동기 호출은 지연 큼 → ① **사전 번역(배치/저장)** 우선 ② 미스 시 **온디맨드+캐시**(첫 요청만 번역, 이후 캐시) ③ **타임아웃(예: 1.5s) 폴백 → 원문 노출**.
- **캐시 계층**: 영구 캐시(DB: text-hash+target+엔진버전) + 핫 캐시(Redis). 콘텐츠 수정 시 무효화.
- **레이트리밋·큐**: 번역 API 폭주 방지(사용자/세션 단위), 배치 우선순위.
- **SEO**: **자동번역 동적 콘텐츠는 색인 대상에서 제외**(noindex) 또는 인간번역만 hreflang 등록 → 저품질 자동번역 색인 방지.

## 5-3. 언어 결정·표시 — *v1.2 검토 보완*
- **우선순위**: ①URL 프리픽스(홈) ②로그인 프로필 `preferredLanguage` ③쿠키 `NEXT_LOCALE` ④`Accept-Language` 자동감지 ⑤기본 ko.
- `<html lang>` 동적 설정(접근성·SEO). CJK/아랍어 **웹폰트 fallback** 로딩(성능 고려, subset).
- 외국 **주소/전화/이름 순서** 로캘 포맷(Intl + 폼 가이드).

## 5-4. 거버넌스 — *v1.2 검토 보완*
- **용어집(glossary) 관리 화면**(관리자): 병원명·진료과·법정문구 고정 번역 → 자동번역에 강제 적용(일관성).
- **검수 워크플로우**: 자동번역 초안 → 검수 표시(미검수/검수완료) → 의료·법률은 검수 필수.
- 카탈로그 누락 키 CI 검출(FR-06)·번역 커버리지 리포트.

## 6. 콘텐츠 번역 전략
- **UI 문자열**: 카탈로그 수동 번역(+검수). 1차 ko/en 전량.
- **CMS 동적**(소식·건강정보·진료과 설명): ① 언어별 콘텐츠 입력(관리자) ② 미입력 시 기본(ko) 노출 ③ (옵션) Ollama 기계번역 초안 + 검수.
- **의료 정보**: 기계번역 단독 금지 — **전문 검수 필수**, "번역 참고용, 원문(한국어) 우선" 면책(FR-08).
