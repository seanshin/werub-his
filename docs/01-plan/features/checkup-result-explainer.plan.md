## 0. 규제 게이트 (착수 전 필수 · 개발로 해결 불가)
원 기획서 §3·부록 B의 사람/법무 결정. **본 기획의 모든 구현 범위는 「웰니스(정보 제공)」 가정** 하에 설계되며, 아래가 확정되기 전 소비자 노출은 보류.
- [ ] 규제 포지션(웰니스 vs 의료기기) 확정 + (선택) 식약처 사전질의
- [ ] 콘텐츠 **의료 감수 체계**(감수자·근거·버전·주기) — 쉬운말 콘텐츠는 감수 없이는 노출 불가
- [ ] LLM 배포(온프레미스 vs 클라우드)·개인정보 국외이전 검토
> 개발은 게이트와 **독립적으로 진행 가능한 부분**(데이터 파이프·UI 셸·가드레일 아키텍처·콘텐츠 스키마)까지 선행하고, 콘텐츠 실투입·소비자 활성화만 게이트에 종속시킨다.

## 2. 핵심 설계 인사이트 — 웰니스 가드레일 자동 충족
원 기획 §3.3 최대 위험 = "새 정상/비정상 판정 생성 = 의료기기化". **HIS 내부 검진은 이미 의료진이 finding/grade/interpretation을 생성**해 둠 →
- 소비자 서비스는 **기존 판정을 표시**(재생성 X) + **쉬운말 설명**만 담당 → 가드레일 자연 충족.
- 자체 판정 로직 0 · 새 진단명 0 · 개인 맞춤 처방 0.
- OCR·외부 결과지 파싱(F1)은 **HIS 외부 검진 전용** → MVP 후순위(내부 검진은 구조화 완료).

## 3. 범위·비목표
**목표**: HIS 검진 수검자가 포털에서 결과를 쉬운말로 이해 + 필요 시 진료 권유 안내 + 연도별 추이.
**비목표**: 진단·처방 생성(금지)·외부 OCR(후순위)·직원 판독 대체(별도 SaMD).

## 4. 단계

### MVP (F2 재사용 + F3·F4 + 면책) — 게이트 무관 개발 가능(콘텐츠만 게이트)
- **포털 「검진결과 쉽게보기」** — `_health` 탭 하위 또는 신규 서브. `PortalCheckupController` 재사용(신규 조회 EP 최소).
- **해석 카드**(§6.1 구조): [항목/수치] · 이 검사는? · 내 위치(referenceRange 게이지) · **결과지 판정(finding/grade 그대로)** · 일반적 의미 · 참고 생활정보 · 진료 권유.
- **비의료기기 고지·동의 게이트**(최초 진입) + 카드 하단 상시 면책 문구(원 기획 §3.4).
- **콘텐츠 스키마**: `CheckupExplainerContent`(testCode·plainWhat·plainMeaning·lifestyleInfo·whenToSeeDoctor·sourceRef·**reviewedBy·reviewedAt·version**) — 정의는 코드/DB, **감수 전엔 미노출**(검수 콘솔 패턴 재사용 가능 — [[chart_template_expansion_plan]] verified 체계 응용).
- 파싱 결과 **사용자 확인 단계**(§8) — 내부 검진은 이미 확정이라 표시·이의 경로만.

### v1.1 — F6 후속행동 카드·F8 용어사전·챗봇(RAG 고정)

## 5. AI 가드레일 아키텍처 (원 기획 §7)
- **RAG 고정**: 감수 KB 밖 생성 억제. **금칙 출력 필터**(정규식+분류): 진단 확정·처방·용량 → 차단·치환.
- **면책 자동 삽입**·**로깅/추적성**. 직원용 `ai-interpret`와 **엔드포인트·프롬프트·KB 분리**(소비자 톤·범위 상이).

## 6. 데이터·보안 (원 기획 §9)
- 검진결과=민감정보: 포털 가드(PortalOrPatientGuard)·보호자 위임 흐름 재사용·최소수집·감사로그. 미성년/대리인 동의 흐름 별도.
