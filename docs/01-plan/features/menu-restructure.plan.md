# 사이드바 메뉴 재구성 + 섹션 허브(메뉴 설명 화면) 기획

> 작성 2026-06-16 · v1.0 · 대상 `apps/web/src/components/layout/Sidebar.tsx` (+ 신규 허브 페이지)

## 0. 한 줄 요약
**201개 항목·25개 평탄 그룹**의 사이드바를 **8개 도메인 대분류 + 섹션 허브(설명·이동 카드) 페이지**로 재편하고, **역할별 큐레이션(특히 관리자 과노출 해소)**을 도입한다.

## 1. 현황 진단 (grounded)
| 지표 | 값 | 문제 |
|------|----:|------|
| 사이드바 항목(href) | **201** | 한 화면 스크롤로 다 안 보임 |
| 상위 그룹(title) | **25** | 평탄 나열 → 탐색 비용 큼 |
| 역할 상수 | CLINICAL/DOCTOR_ADMIN/ADMIN_ONLY | `ADMIN`이 거의 모든 목록에 포함 |
| 관리자 노출 | **≈201개 대부분** | 인지 과부하·핵심 동선 묻힘 |

- 25개 그룹: 외래·간호·진료 지원·수술/중환자·전문 진료·특수 치료·의료 질/연구·워크스테이션·클리닉 센터·입원·의무기록·협진/의뢰·CRM·원무/관리·안전/질관리·병원 안내·AI/시뮬레이션·전원/연동·생활/편의·내 설정·경영진·관리자·외부 연동·홈페이지 관리.
- **근본 문제**: ① 평탄한 25그룹(2-depth 없음) ② 역할 필터가 "숨김"만 할 뿐 "큐레이션"이 없음 ③ 그룹 클릭 시 단순 펼침일 뿐 맥락(설명)이 없음.

## 2. 재구성 원칙
1. **2-tier 정보구조**: 8 도메인(대분류) → 그룹/화면(소분류). 상위는 항상 8개만.
2. **그룹 클릭 = 허브 이동**: 외래·간호 등을 누르면 **설명 + 이동 카드** 허브 페이지(인라인 펼침 대체/병행).
3. **역할별 큐레이션**: 역할마다 "기본 펼침(자주 쓰는 2~3 도메인)" + 나머지는 접힘. 관리자도 **운영 핵심만 기본 노출**, 관리 도구는 별도 "시스템 관리" 도메인으로 격리.
4. **즐겨찾기·최근**: 개인별 자주 쓰는 화면 상단 고정(과노출 보완).
5. **화면번호 유지**: 기존 코드배지(1000·1001…) 검색/이동 호환 유지.

## 3. 도메인 대분류 재편안 (25 그룹 → 8 도메인)
| # | 도메인 | 묶는 기존 그룹 | 대상 역할(기본 노출) |
|---|--------|----------------|------|
| 1 | **진료** | 외래·입원·간호·전문 진료·수술/중환자·특수 치료·협진/의뢰 | 의사·간호(기본 펼침) |
| 2 | **진료지원** | 진료 지원·의무기록·워크스테이션·클리닉 센터 | 의사·간호·검사 |
| 3 | **환자·고객** | CRM·병원 안내·(예약/환자관리) | 원무·CRM |
| 4 | **질·안전** | 안전/질관리·의료 질/연구 | QI·간호·의사 |
| 5 | **운영** | 원무/관리·경영진·전원/연동 | 원무·경영(기본 펼침) |
| 6 | **지능형** | AI/시뮬레이션 | 전직 |
| 7 | **시스템 관리** | 관리자·외부 연동·홈페이지 관리 | 관리자 전용(기본 접힘) |
| 8 | **개인** | 내 설정·생활/편의 | 전직 |

> 관리자 과노출 해소 핵심: **관리(시스템 관리)를 별도 도메인으로 격리 + 기본 접힘**. 관리자는 진료/운영 핵심만 펼쳐 보고, 관리 도구는 의도적으로 들어갈 때만.

## 4. 섹션 허브 = "메뉴 설명 화면" 설계
**라우트**: `/menu/[section]` (예: `/menu/outpatient`, `/menu/nursing`). 사이드바의 그룹/도메인 라벨 클릭 → 해당 허브로 이동.

**페이지 레이아웃**
```
[히어로] 섹션 아이콘 + 제목(외래) + 1~2줄 설명("외래 접수·진료·처방·예약 등 외래 진료 전 과정")
[빠른 이동] 자주 쓰는 화면 3~4개 큰 버튼
[화면 카드 그리드] 각 화면: 아이콘 · 이름 · 화면번호 · 1줄 설명 · (역할 배지) → 클릭 이동
[하위 섹션] (도메인 허브일 때) 소분류(외래·간호…) 카드 → 각 그룹 허브로
```

**데이터 모델** (사이드바 정의를 단일 소스로 확장)
```ts
interface MenuScreen { href; label; icon; roles; code?;
  desc?: string;        // ← 신규: 화면 1줄 설명
}
interface MenuGroup { key; title; icon; desc: string;  // ← 신규: 그룹 설명
  domain: DomainKey;    // ← 신규: 8 도메인 매핑
  items: MenuScreen[];
}
```
- `desc`(그룹·화면 설명)를 사이드바 정의에 추가 → 허브가 이 데이터로 자동 생성(중복 정의 없음).
- 허브 페이지는 `MenuGroup`/도메인을 받아 카드 렌더(단일 컴포넌트 재사용).

**동작**
- 사이드바 그룹 라벨 클릭 → `/menu/{key}` 이동(설명+카드). 그룹 펼침(▾)은 옆 화살표로 분리(빠른 인라인 펼침 병행).
- 도메인 라벨 클릭 → `/menu/{domain}`(소분류 카드).

## 5. 사이드바 UX 재설계
- **상단**: 8 도메인만. 각 도메인 아이콘+라벨. 역할별로 기본 펼침 도메인 1~2개(예: 의사=진료, 원무=운영), 나머지 접힘.
- **즐겨찾기/최근**: 도메인 위에 개인 고정 영역(localStorage 또는 user pref).
- **검색**: 기존 ScreenJump(화면번호·이름) 유지·강화 — 200+ 화면은 검색이 1차 동선.
- **관리자**: "시스템 관리" 도메인으로 격리·기본 접힘 → 평상시 화면에서 관리 메뉴 미노출.

## 6. 컴플라이언스/주의
- 화면번호(코드배지) 매핑 유지 — `screen-codes.frozen.ts` 호환.
- 역할 가드(라우트 접근통제)는 사이드바와 별개 — 메뉴 숨김 ≠ 접근차단(서버 가드 유지).
- 기존 즐겨찾기/핫키(ScreenJump·HotkeyProvider) 보존.

## 7. 단계적 구현 로드맵
- **P1 (구조)**: 사이드바 정의에 `domain`·`desc` 필드 추가, 8 도메인 그룹핑(렌더만 2-tier). 기존 항목/링크 무변경. ← 위험 낮음.
- **P2 (허브)**: `/menu/[section]` 허브 페이지 + 카드 컴포넌트. 그룹/도메인 라벨 클릭 시 이동. desc 콘텐츠 채움.
- **P3 (큐레이션)**: 역할별 기본 펼침·즐겨찾기·최근. 관리자 격리.
- **P4 (정리)**: 중복/저빈도 항목 통합·아카이브, 화면번호 정합 점검.

## 8. 기대 효과
- 상위 25 → **8** 도메인: 첫 화면 인지부하 1/3.
- 그룹 클릭 = 설명+카드 허브: 신규 직원·관리자 온보딩 동선 명확.
- 역할 큐레이션: **관리자 평상 화면에서 관리도구 미노출** → 핵심 동선 회복.
