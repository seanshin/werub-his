## 2. 개선 항목

### Phase 1: 임상 워크플로우 완성 (긴급)

| # | 항목 | 설명 | 영향 | 예상 |
|---|------|------|:----:|:----:|
| T1-1 | **진료 종료 시 Encounter 자동 생성** | 종료 → Encounter(SIGNED) + 진단 + 처방 연결 | 높 | 2h |
| T1-2 | **원격 처방전 발행 UI** | 진료실 내 CPOE 패널 (약물 검색 + CDSS 검증) | 높 | 3h |
| T1-3 | **수납 자동 연동** | Encounter 완료 → Billing 자동 생성 (원격진료 수가) | 높 | 1.5h |
| T1-4 | **비동기 진료 FE** | 환자 메시지/사진 → 의사 답변 채팅 UI | 중 | 2h |

### Phase 2: 환자 경험 (중요)

| # | 항목 | 설명 | 영향 | 예상 |
|---|------|------|:----:|:----:|
| T2-1 | **환자 포털 원격진료** | 포털에서 예약 + 대기실 + 화상 연결 | 높 | 3h |
| T2-2 | **예약 알림** | 진료 30분 전 SSE/SMS 알림 | 중 | 1.5h |
| T2-3 | **환자 대기실 UI** | 대기 순서 + 예상 대기시간 + 준비 체크리스트 | 중 | 2h |
| T2-4 | **진료 후 평가 모달** | 별점(1~5) + 피드백 + 재예약 안내 | 낮 | 1h |

### Phase 3: 진료 품질 (강화)

| # | 항목 | 설명 | 영향 | 예상 |
|---|------|------|:----:|:----:|
| T3-1 | **화상 차트 고도화** | 진료실 내 바이탈 입력 + 검사결과 조회 + 영상 뷰어 | 높 | 3h |
| T3-2 | **AI 진료 보조** | 실시간 음성→텍스트 + SOAP 자동 작성 (STT) | 높 | 4h |
| T3-3 | **진료 녹화 동의 + 저장** | 환자 동의 → 녹화 → S3 저장 → 재생 | 중 | 2h |
| T3-4 | **네트워크 품질 모니터** | WebRTC getStats() → 대역폭/지연/패킷손실 표시 | 낮 | 1h |

### Phase 4: 운영 효율 (안정화)

| # | 항목 | 설명 | 영향 | 예상 |
|---|------|------|:----:|:----:|
| T4-1 | **자체 TURN 서버** | coturn 배포 (Jitsi 의존도 제거, 방화벽 우회) | 중 | 2h |
| T4-2 | **진료 시간 관리** | 슬롯 기반 예약 + 자동 다음 환자 호출 | 중 | 2h |
| T4-3 | **대시보드 위젯** | 의사 대시보드에 오늘 원격진료 일정 카드 | 낮 | 1h |
| T4-4 | **리포트** | 원격진료 월별/과별 통계 + 환자 만족도 추이 | 낮 | 1.5h |

## 5. 기술 아키텍처 (TO-BE)

### 5.1 현재 (Jitsi Meet iframe)

```
장점: 즉시 사용, 무료, 별도 서버 불필요
단점: 커스터마이징 제한, 외부 의존, 녹화 불가
```

### 5.2 단기 개선 (Jitsi + API 연동)

```
장점: Jitsi 유지하면서 EMR 연동 강화
- Encounter 자동 생성 (진료 종료 시)
- CPOE 패널 (진료실 내 처방)
- Billing 자동 생성
- 환자 포털 대기실
```

### 5.3 장기 목표 (자체 WebRTC)

```
옵션 A: Jitsi 자체 호스팅 (Docker)
  - 완전 커스터마이징, 녹화 지원
  - 서버 비용: ~$50/월

옵션 B: LiveKit (오픈소스)
  - WebRTC SFU, React SDK, 녹화 내장
  - 서버 비용: ~$30/월

옵션 C: Daily.co (SaaS)
  - API 기반, 즉시 연동
  - 비용: 분당 과금 (~$0.004/분)
```
