# 환자포털 실시간 채팅 상담실 기획서 v1.3

> **요약**: 환자포털에서 환자가 **채팅으로 병원 상담원(원무·간호·코디)과 실시간 상담**하는 상담실. AI 1차 응대(concierge) → 필요 시 사람(직원) 연결. **채팅 중 1:1 화상미팅 전환** 지원. 다국어 환자(자동 번역 옵션).
>
> **프로젝트**: Hospital RUN v3.10.0 · **작성일**: 2026-06-08 · **상태**: Draft · **우선순위**: P2 · **연관**: [[multilingual-i18n]], concierge(AI), crm/consultation, notification(SSE), **telehealth(Jitsi)**

---

## 0. 현황 / 전제
- **기존**: concierge = **AI 챗**(LLM 단방향 도우미), `/crm/consultation`(직원 상담관리), remote-consultation/telehealth(원격진료, 영상). **환자↔직원 실시간 텍스트 채팅 상담실은 없음**.
- **실시간 기반**: 프로젝트가 **SSE**(server→client)를 광범위 사용(notification/portal/queue…). WebSocket 라이브러리 미사용 → **SSE 수신 + REST 송신** 패턴 채택(일관성).
- **화상 기반(재사용)**: **자체 Jitsi**(hospital-jitsi, nginx `/meet/`) + telehealth가 **Jitsi JWT 발급**(직원=모더레이터 `getJitsiToken`, 환자=게스트 `getPatientJitsiToken`) + 포털 CareTab이 **iframe `/meet/{room}?jwt=` 임베드**로 이미 화상 사용. → 상담실 1:1 화상은 **이 패턴 그대로 재사용**(신규 화상스택 불필요).
- 다국어 환자 증가([[multilingual-i18n]]) → 상담도 다국어 필요.

## 1. 목표
```
환자가 포털에서 채팅으로 질문 → AI가 즉시 1차 응대 → 필요 시 담당 직원이 이어받아 실시간 대화.
대화 이력·미읽음·영업시간·다국어를 지원하고, 의료정보 보호(PHI)를 준수한다.
```

## 2. 범위
- **포함**: 환자포털 채팅 위젯·상담세션, 직원 상담 인박스(데스크), AI 1차→사람 에스컬레이션, 이력, 알림, 영업시간/오프라인 메시지, 파일/이미지 첨부, 분류·종료·만족도.
- **연계**: concierge(AI 1차), notification(SSE/알림), crm/consultation(직원 상담관리), [[multilingual-i18n]](다국어).
- **제외(별도)**: 영상/원격진료(telehealth), 진료행위·처방(상담은 행정·안내 중심), 응급(응급은 119/응급실 안내).

## 3. 동작 흐름
```
환자포털 [상담] → 세션 시작
  → AI 1차 응대(concierge: 예약·검진·수납·길안내 등 즉답)
  → "상담원 연결" 또는 AI가 사람 필요 판단 → 직원 인박스 큐 인입
  → 담당 직원이 이어받아 실시간 대화(SSE 수신 + REST 송신)
  → (필요 시) "화상 상담" 전환 → 1:1 Jitsi 룸(직원 모더레이터·환자 게스트) 양측 입장
  → 종료 → 만족도 → 이력 보관(감사)
영업시간 외: 오프라인 메시지 접수 → 다음 영업일 직원 회신(알림)
```

## 5. 아키텍처
```
[환자포털 ChatWidget] --REST POST--> /api/v1/portal/consult/:id/message --> 저장
        ^  SSE /api/v1/portal/consult/:id/stream (수신)
[직원 상담데스크] <-- SSE /api/v1/consult/inbox/stream / :id/stream
        --REST POST--> /api/v1/consult/:id/message
백엔드 consult 모듈:
  ConsultSession(상태·분류·assignee·patient·locale) / ConsultMessage(sender·content·attach·읽음)
  ├─ AI 1차: concierge 호출(LLM) — 사람 연결 전 자동응대
  ├─ SSE 디스패치(notification SSE 패턴 재사용)
  ├─ 번역: [[multilingual-i18n]] 공유 엔진 /api/v1/i18n/translate(Ollama·캐시·용어집) — 환자 선택언어↔직원 한국어 양방향, 원문+번역 저장/표시(FR-09)
  ├─ 화상(1:1): 세션에 jitsiRoom 부여 → 토큰 발급(재사용 패턴: 직원 모더레이터/환자 게스트)
  │    포털·데스크 양측 iframe `${NEXT_PUBLIC_JITSI_URL||'/meet'}/{room}?jwt={token}#config.prejoinPageEnabled=false`
  └─ 가드: 환자=PortalOrPatientGuard(본인), 직원=JwtAuthGuard+역할/부서
```
- 모델: `ConsultSession`(+`jitsiRoom`·`videoStartedAt`), `ConsultMessage`(+첨부는 기존 media/upload 재사용).
- 화상: 신규 스택 없이 **telehealth Jitsi 토큰 발급·iframe 임베드 재사용**(1:1 룸).

## 5-1. 상담 운영 / SLA — *v1.3 검토 보완*
- **배정**: 분류(예약/수납/검진/일반)별 부서 큐 → 라운드로빈/수동 픽업. **동시 상담 한도**(직원당 N건). 부재·근무종료 시 **이관/재배정**.
- **SLA**: 첫 응답 목표시간, 대기열 **앞 N명/예상 대기** 안내. 미배정 장기 대기 → 에스컬레이션(슈퍼바이저).
- **근무 스케줄**: 영업시간/상담원 온오프 상태. 영업시간 외 = 오프라인 메시지(FR-06).
- **상태머신**: `AI응대 → 사람대기 → 진행 → (화상) → 종료/이관/만료`. 무응답 자동 만료·재개.

## 5-2. 의료법 경계 / 면책 — *v1.3 검토 보완*
- 상담실은 **행정·안내(예약·수납·검진·길안내·서류)** 범위. **진단·처방·의료자문 금지** → 진료 필요 시 **예약 또는 telehealth(원격진료, 의료법 §34)로 전환**.
- 상시 면책 고지("행정 상담이며 진료행위 아님"). AI 1차 응대도 동일 경계·면책.
- 화상 상담(행정)과 원격진료(telehealth)는 **명확 구분**(동의·기록 분리).

## 6. 보안 / 프라이버시 (PHI) — *v1.3 보강*
- 채팅에 **민감정보 포함 가능** → 메시지 저장 보호, **접근통제**(환자 본인 / 배정 직원·부서만), **감사 로그**(FR-10).
- **보존/삭제 정책**: PHI 보존기간 정의, 개인정보 삭제요청 처리, 종료 세션 보존·접근 제한.
- **첨부 보안**: 형식·용량 제한, **악성파일 검사**, 인증·만료 URL(기존 media 재사용).
- **화상 보안**: **1:1 보장**(JWT 룸·3자 입장 차단), prejoin off, **녹화 금지(기본)**·녹화 시 사전 동의, 룸 만료.
- **남용 방지**: 레이트리밋·차단·(욕설 필터), AI 1차 오안내 방지(범위 한정·면책·로그).
- 포털 가드: `PortalOrPatientGuard`(/portal/*), 직원: `JwtAuthGuard`+역할.
- **알림/오프라인**: 직원 미배정·환자 오프라인 시 알림(SSE·푸시·필요시 SMS/이메일)으로 회신 도달 보장.
