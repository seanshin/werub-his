# 환자 차트 '큰 화면 보기' (고해상도 멀티패널 뷰) 기획

> 작성: 2026-07-06 / 상태: Plan v1.5 (구현 전 — v1.4에 **인터랙션·컨트롤 UX(§3.10)** 추가: 아이콘 세트·콤보박스 2종·의료진 쉬운 사용 기능·마이크로카피, 전부 원내 기존 컴포넌트 재사용)
> 성격: 현재 환자 차트를 **코드베이스에 그라운딩**해 분석하고, 2배 이상 해상도(2560px·4K)의 대형 모니터에서 **가로 공간을 활용해 핵심 정보를 동시에 인지·작업**할 수 있는 '큰 화면 보기' 모드를 신규 추가. 기존 좁은 뷰는 **비파괴 유지**, 토글만 추가.
> 한 줄: 차트가 `max-w-5xl`(~1024px)로 **자기 제약**되고 **48탭 중 1개만** 표시돼, 넓은 모니터에서 공간의 절반 이상을 낭비하고 검사·투약·바이탈을 **동시에 못 본다**. '큰 화면 보기'는 전폭 멀티패널 대시보드로 전환해 한눈 인지를 제공.
> 진입점: 환자 차트 우상단 **'큰 화면 보기'** 버튼(기존 `인쇄`·`디지털 트윈` 버튼 옆).
>
> **✅ 구현 현황(2026-07-06 · 라이브 배포)**: P0 멀티패널 board + 안전존 sticky + 임상 안전배지(DNR·낙상·EWS) + 컴팩트 헤더 + 패널 접기·빈패널 자동축소 + 회진 밀도 + **역할별 프리셋·레이아웃 편집기(localStorage)** + **신선도/새로고침** + **진료 콕핏(작성+참조 멀티패널·폭 3단 조정)** 완료. **잔여(백엔드 의존·별도 착수)**: 레이아웃 **서버 동기화**(마이그레이션·로밍 단말)·**격리 신호 배지**(ICU/감염 모델 EP). 커밋 `0df589cc`~`197837d8`(브랜치 feat/patient-chart-improvements).

## 2. 목표·비전

**'큰 화면 보기' = 전폭 고밀도 멀티패널 대시보드 모드.**

1. **한눈 인지(At-a-glance)**: 클릭·스크롤 없이 첫 화면에서 환자 핵심(요약·바이탈·검사·투약·문제·알러지·최근 진료)을 **동시 표시**.
2. **공간 활용**: `max-w` 해제 + 뷰포트 폭에 따라 **2 → 3 → 4 컬럼** 자동 확장(2560px 3컬럼, 3840px 4컬럼).
3. **작업 연속성**: 패널 안에서 기존 액션(진료 시작·오더·투약 확인 등) 그대로 수행 → 보기 전용이 아니라 **작업 가능한** 대시보드.
4. **비파괴**: 좁은 뷰(기존)는 100% 유지. '큰 화면 보기'는 **토글**로만 진입/이탈. 기존 탭 컴포넌트를 **재사용**(중복 구현 금지).
5. **역할·상황 적응**: 의사/간호 기본 프리셋 + 사용자 커스터마이즈(패널 on/off·순서) + 회진(원거리 대형) 모드.

**비목표(Out of scope)**: 신규 데이터/차트 종류 추가(기존 탭 재사용만), 모바일 전용 뷰(좁은 화면은 자동 폴백), 백엔드 API 신설.

**범위 확장 — 진료 작성 화면(encounter/new) 참조 '큰 화면' (✅ 구현 2026-07-06)**: 진료 시작 화면은 이미 full-width 2열(SOAP|처방)이고 **참조 드로어 `PatientChartDrawer`(440px 단일 탭)**가 있으나, 넓은 모니터에서 참조가 좁아 한 번에 하나만 봄. → 드로어에 **'큰 화면' 토글**(880px·2열 멀티패널: 바이탈·검사·투약·알러지·문제 동시) 추가 — 넓은 모니터에서 **참조 데이터를 펼쳐 보며 작성**. 기존 탭 컴포넌트 재사용·본문 패딩 연동(`xl:pr-[900px]`)·`xl+`에서만 노출. 차트 board와 동일 아이콘·개념.

## 2.5 임상 안전·인지 설계 원칙 (의료진 UX의 본질 — 최우선)

> 큰 화면의 목적은 "정보를 많이 보여주기"가 아니라 **의료진이 안전하게 빠르게 올바른 판단**을 하도록 돕는 것이다. 밀도·자유도보다 **안전·인지**가 우선한다. 아래는 다른 모든 설계에 우선하는 **불변 제약**.

- **P-1 안전정보 비제거(🔴)**: 알레르기·환자 안전 플래그(`PatientFlagBar` — 주의/격리/VIP 등)·위험 카드(`TwinCdsCards`)·위급치 알림은 **커스터마이즈로 숨길 수 없다**. 편집기에서 잠금(§3.8). 개요 탭이 좁은 뷰에서 항상 표시되는 것과 동일 원칙(`TabSettingsModal`의 `overview` 잠금 선례).
- **P-2 환자 식별 편재(🔴 IPSG-1)**: 이 병원은 **JCI IPSG.1**(환자 확인)을 준수(환자 팔찌·QR에 명시). 멀티패널·**팝아웃 창**·멀티모니터는 **wrong-patient 오류의 대표 원인** → **모든 board 컨테이너와 팝아웃 창 상단에 이름·MRN·생년월일** 상시 노출. 팝아웃은 별 창이므로 특히 필수.
- **P-3 신선도 정직성**: 여러 패널이 한 화면에 모이면 **하나의 현재 스냅샷처럼 오인**된다(실제 staleTime 2~5분). 각 패널에 **마지막 갱신 시각/신선도 배지**(`FreshnessBadge`)를 **P1부터** 표시(P2 아님). 오래된 값으로 의사결정 방지.
- **P-4 판독 안전(오독 방지)**: 숫자·단위 소형화는 오독(1.0↔10·소수점) 위험 → **기본 밀도는 `comfortable`**, `compact`는 사용자 opt-in(§3.6 수정). 임계치 초과 값은 색·굵기로 강조(기존 임계 정책 재사용).
- **P-5 리뷰 우선 + 안전한 실행**: board는 **상황 인지·리뷰가 1차 목적**이며, 오더·처방·서명 등 **되돌리기 어려운 작업**은 board 인라인이 아니라 **해당 워크플로우로 진입**(진료화면·모달)해 컨텍스트·확인 단계를 보존. 실행 진입 시 **오환자 방지 확인**(환자명 명시).
- **P-6 무설정이 완성형**: 의료진은 설정을 기피 → **역할/과 기본 프리셋만으로 즉시 유용**해야 하고 편집은 **선택(파워유저용)**. 관리자 기본 레이아웃(§P1.5)으로 90%는 무설정 사용.
- **P-7 추세 우선**: 임상은 값보다 **추세**로 사고 → 패널은 가능한 delta·sparkline(바이탈·검사·만성)을 우선 표시.

## 3. 설계

### 3.1 진입점 (버튼) — ✅ 확정
- **아이콘(확정 = 후보 B '패널 그리드')**: `큰 화면` = **Squares2×2 그리드**(Heroicons `squares-2x2`, 멀티패널 대시보드를 정확히 지시 — "전체화면"으로 오인되는 확대 화살표 대신), `일반 화면` = **단일 문서**(테두리 rect + 가로줄). 기존 규칙 일관(`fill=none`·`viewBox 0 0 24 24`·`strokeWidth 1.5`·`w-4 h-4`).
  > 판단 근거: 판독 안전(오독 방지) — 확대 화살표(후보 A)는 브라우저 전체화면을 뜻해 P0(페이지 내 레이아웃 전환)와 동작 기대가 어긋남. 그리드가 실제 동작(여러 정보를 펼침)을 정직하게 전달. 시안 아티팩트로 확정.
- **아이콘 + 라벨 병행**: 아이콘 단독 오독 위험 → 라벨(`큰 화면`/`일반 화면`)을 함께(기존 `인쇄`·`디지털 트윈` 아이콘+텍스트 규칙과 동일).
- **위치(확정)**: `PatientHeader` 하단 **뷰 컨트롤 액션 바** 안, 기존 `타블렛 모드`·`시계열(새 창)` 등 **뷰 전환 컨트롤 옆**. 임상 안전 배지(알러지·플래그)와 **분리**(오클릭·스캔 방해 방지). page.tsx의 인쇄/트윈 absolute 오버레이와 충돌 없음.
- **토글**: 클릭 시 board 진입/이탈, `Esc`·`Alt+B`(P1) 병행. 라벨 상태 전환 `큰 화면` ↔ `일반 화면`. active 시 파랑 강조(`aria-pressed`).
- **상태**: `usePatientTabStore.boardEnabled`(localStorage 지속). `no-print`.
- **좁은 화면**: ≤1280px 비활성 + 툴팁('넓은 화면 권장').

### 3.2 동작 방식 — 3안 비교, **A안 권장**

| 안 | 방식 | 장점 | 단점 | 판정 |
|----|------|------|------|------|
| **A. 페이지 내 레이아웃 모드** | 같은 라우트에서 `boardMode` 상태로 컨테이너 클래스·렌더 분기(`max-w-5xl`→`max-w-none` + 그리드) | 가볍다·상태/데이터 공유·구현 최소·뒤로가기 안전 | 페이지 컴포넌트 분기 증가 | **채택** |
| B. 별도 풀스크린 라우트 | `/patients/[id]/board` 신설 | 관심사 분리·URL 공유 용이 | 데이터 재조회·헤더/모달 중복·유지비 2배 | 보류(P2 팝아웃에서 일부 차용) |
| C. 브라우저 Fullscreen API | `requestFullscreen()`로 몰입 | 사이드바까지 제거·**원내 선례 있음**(`consent-device:102` 키오스크) | 브라우저 UI 상실·모달/알림 z-index 충돌·이탈 UX 혼란 | 옵션(P1 '회진 모드' 부가 토글, 검증된 패턴 재사용) |

> A안 근거: 탭 컴포넌트가 자족적이라 **동일 페이지에서 그리드에 얹기만** 하면 되고, `patient`·`encounters`·`billings` 등 이미 로드된 상위 데이터를 공유해 재조회가 없다. URL 공유가 필요하면 `?view=board` 파라미터만 병행(§3.5).

### 3.3 레이아웃 — 반응형 멀티패널 그리드
- 컨테이너: board 모드일 때 `max-w-5xl` → **`w-full`**(또는 `max-w-none`), 패딩 축소.
- 그리드: CSS Grid + Tailwind 반응형
  - `grid grid-cols-1 xl:grid-cols-2 2xl:grid-cols-3` (초광폭은 `min-[2560px]:grid-cols-4` 커스텀).
  - 패널 높이: `max-h-[calc(100vh-Npx)] overflow-y-auto` — **각 패널 독립 스크롤**(전체 페이지 스크롤 대신 패널별 스크롤로 위치 고정).
- 패널 = **카드 래퍼 + 기존 탭 컴포넌트**. 예: `<BoardPanel title="바이탈"><VitalsTab patientId={id}/></BoardPanel>`.
- 상단 고정 영역: `PatientHeader`(압축형) + `TwinCdsCards`(위험 카드)는 **그리드 위 전폭 sticky**로 항상 표시(안전 정보 우선).

### 3.5 상태 지속·URL
- 모드 상태: `usePatientTabStore` 확장(`boardEnabled`, `boardLayout`, `boardDensity`) → 지속(2단 지속 정책은 §3.8).
- URL: `?view=board` 파라미터를 `?tab=`과 동일 패턴으로 동기화(`page.tsx:141~158` 확장) → 새 창/두 번째 모니터 공유 가능(레이아웃 래퍼가 URL 해시 토큰 복원 지원, `layout.tsx:23`).
- **규약**: `?view=board`가 있으면 board 우선(멀티패널). `?tab=`은 board에서 **초기 포커스 패널**(해당 패널을 상단/강조)로 해석하고 좁은 뷰와 상호 배타 아님. board 이탈 시 마지막 `activeTab` 복원.

### 3.6 밀도·타이포 (원거리 판독)
- board 모드 루트에 `data-density="comfortable|compact|round"` 부여 → scope CSS로 폰트·간격 스케일.
  - `comfortable`(**기본** — P-4 오독 방지): 가독성 우선. 숫자·단위가 명확히 읽히는 크기.
  - `compact`(opt-in): 정보 밀도 최대(다과목 환자·화면이 매우 넓을 때). 사용자가 명시적으로 선택.
  - `round`(회진): 폰트 1.25~1.5× 스케일·터치 타겟 확대(원거리·태블릿 겸용). §P1.
- 스케일은 **board scope 안에서만** 적용(전역 오염 금지) — 예: `.chart-board[data-density=round] { font-size: 1.15rem }` + 하위 상대단위 컴포넌트에 파급.

### 3.7 접근성·에러 격리·단축키
- **에러 격리**: 한 패널의 쿼리 실패가 board 전체를 깨지 않도록 `<BoardPanel>`을 **에러 경계(ErrorBoundary)** 로 래핑. 대부분 탭은 이미 자체 `QueryErrorFallback` 보유(확인됨: FamilyHistoryTab·OverviewTab 등) → 경계는 예기치 못한 렌더 예외 대비 이중 안전망.
- **빈 상태 축소**: 데이터 0건 패널은 접힘(collapsed) 헤더만 표시 → 유효 정보에 공간 집중(예: 알러지 없음 → 1줄).
- **단축키**: 기존 `HotkeyProvider`(`layout.tsx:80`) 재사용 — board 토글(예: `Alt+B`)·패널 포커스 순환·`Esc` 이탈. 신규 전역 훅 대신 페이지 스코프 등록.
- **권한 게이팅**: 전문과 패널은 board에서도 기존 조건(`user.role==='ADMIN' || user.department===dept`, `page.tsx:161`) 유지. 프리셋에 전문과 패널이 있어도 무권한 사용자는 자동 제외.
- **안전 정보 우선(비제거·P-1)**: `PatientHeader`(알러지)·`PatientFlagBar`(안전/주의 플래그)·`TwinCdsCards`(위험 카드)·위급치 알림은 그리드 위 sticky로 스크롤 무관 항상 노출 + **커스터마이즈로 숨길 수 없음**(편집기에서 잠금 표시).
- **환자 식별 편재(P-2·IPSG-1)**: board 상단 식별 바에 **이름·MRN·생년월일** 상시. 팝아웃 창(P2)은 별 창이므로 **자체 식별 헤더 필수**. 컬럼 다수여도 어느 패널을 봐도 "누구 차트인지" 즉시 확인 가능.

### 3.8 레이아웃 편집·저장 (개인화 — 개별 의료진)
개별 의료진이 board 레이아웃을 **직접 편집하고 자신의 계정에 저장**한다. 진료과·개인 습관마다 중요 정보가 달라(예: 순환기내과=바이탈·검사 상단, 정형외과=영상·수술이력 상단) 개인화가 핵심 가치.

**편집 가능 항목(레이아웃 정의)**
> ⚠️ **안전정보(알레르기·안전플래그·위험카드·위급치 알림)는 편집 대상이 아님**(P-1 비제거) — 편집기에서 잠금 아이콘으로 표시, on/off 불가.

| 항목 | 내용 |
|------|------|
| 패널 표시 on/off | 프리셋 8종 + 전체 48탭 중 선택(권한 게이팅 유지, **안전정보 제외**) |
| 패널 순서 | 위→아래·좌→우 배치 순서(`TabSettingsModal`의 moveUp/moveDown 재사용, P2에서 드래그) |
| 패널 폭(span) | 1칸/2칸(넓은 패널=검사·바이탈 추이) — 그리드 `col-span` |
| 컬럼 수 선호 | 자동(반응형) / 2 / 3 / 4 고정 |
| 밀도 | compact / comfortable / round(회진) (§3.6) |

**편집 UX**
- board 우상단 **`레이아웃 편집`** 버튼 → 편집 모드 진입: 각 패널에 표시토글·순서·폭·제거 핸들 노출(기존 `TabSettingsModal` 확장 또는 인라인 편집 툴바). `저장` / `취소` / `기본값으로 초기화`.
- 편집 모드에서만 조작 가능(평소엔 읽기 전용) → 오조작 방지.

**저장·지속 — 2단 정책**
1. **P1 (localStorage, 무 BE)**: `usePatientTabStore` 확장으로 `boardLayout`을 기기 로컬 저장(기존 `patient-tab-config` 패턴). 즉시 출시·저위험. 한계=**기기 종속**(회진 태블릿·병동·외래 단말마다 재설정).
2. **P1 후속/P2 (서버 동기화, 로밍 대응)**: **기존 `UserDashboardConfig` 패턴 재사용**으로 계정에 저장 → 어느 단말에서 로그인해도 동일 레이아웃. 병원은 **역할/과별 기본 레이아웃 템플릿**을 배포하고(관리자), 개인이 override(폴백 체인: 개인 → 과 → 역할 → 시스템 기본). 저장 방식 3안:
   - (a) `UserDashboardConfig.config` JSON에 `chartBoard` 키 추가 — **스키마 변경 0**, 단 홈 대시보드 설정과 한 레코드 공유(관심사 결합).
   - (b) `UserChartPreference`에 `boardLayout Json` 컬럼 추가 — 차트 도메인에 의미상 근접·소규모 migration.
   - (c) 전용 per-user 테이블 `UserChartLayout` 신설 — 가장 깔끔, migration 필요.
   → **권장**: 서버 동기화 착수 시 (b) 또는 (c)(도메인 분리). 관리자 기본 템플릿은 기존 `dashboardTemplate`(scope=dept/role) 폴백 로직을 그대로 차용.

**저장 액션**
- `내 레이아웃 저장` / `기본값으로 초기화`(관리자 프리셋 또는 시스템 기본으로) / (P2) **명명된 레이아웃 여러 개**("회진용"·"외래용"·"입원용" 전환).

**비파괴**: 좁은 뷰의 기존 `TabSettingsModal`(탭 순서·표시)은 불변. board 레이아웃은 **별도 config 키**로 분리 저장(상호 간섭 없음).

### 3.9 패널 적합성 (모든 탭이 좋은 패널은 아님)
48탭 전부를 패널로 열 수 있으나, 좁은 셀(1/3~1/2 폭)에서의 가독성·용도는 탭마다 다르다. 편집기는 탭을 **적합도로 분류·안내**한다(강제 아님, 권고).

| 분류 | 탭(예) | board 적합성 |
|------|--------|-------------|
| **요약·카드형(최적)** | 요약·바이탈·검사결과·투약·문제목록·알러지·만성질환·오더추적·간호기록 | ✅ 좁은 셀에서도 정보 응축 잘 됨 → **프리셋 기본** |
| **목록형(가능)** | 진료이력·수술이력·입퇴원·의뢰회신·검진이력 | ○ 세로 목록이라 1칸 패널로 무난 |
| **광폭·전용레이아웃 필요(주의)** | 처방/수납(넓은 표)·영상(PACS 뷰어 링크)·전문과 풀차트·문진표·동의서 | △ **2칸(span) 권장** 또는 별도 창(P2 팝아웃). 좁은 셀에서 표/뷰어 깨질 수 있음 |
| **편집 폼(부적합)** | 환자 정보(수정 폼) | ✕ board는 **읽기·요약 중심** → 편집 폼은 패널 제외 권고(액션은 좁은 뷰/모달에서) |

- 편집기에서 '주의/부적합' 탭 선택 시 **인라인 힌트**("넓은 표 — 2칸 권장" 등) 표시. 기본 프리셋(§3.4)은 '최적' 군에서만 구성.

## 3.10 인터랙션·컨트롤 UX (의료진 친화)

### 3.10.3 콤보박스 2종 상세 (의료진 핵심 편의)
**(A) 레이아웃 선택 콤보박스** — 상황별 배치를 한 번에 전환(회진/외래/입원)
- 트리거: 현재 레이아웃명 + `chevron-down`(예: `회진용 ▾`). **레이아웃이 1개면 숨김**(단순 사용자엔 안 보임).
- 목록: 관리자 기본(과/역할) → 내 레이아웃(들) → 구분선 → `+ 새 레이아웃`·`이름 변경`·`복제`·`삭제`.
- 키보드: `↑↓` 이동·`Enter` 적용·`Esc` 닫기(native select 접근성 or SmartSearchBar 패턴).

**(B) 패널 추가 콤보박스** — 48탭에서 **타이핑으로 찾아 담기**(스크롤·기억 부담 제거)
- 트리거: 편집 모드에서 `+ 패널 추가`.
- 검색 입력: 탭명 실시간 필터(`SmartSearchBar` 재사용 패턴). 예: "검사" → 검사결과.
- **적합도 그룹핑**(§3.9): `최적`(✓ 초록)·`목록`·`광폭(2칸 권장)`·`부적합(제외 권고)`으로 묶어 표시 + 인라인 힌트. 안전정보(알러지 등)는 목록에 없음(항상 표시·P-1).
- 빈 상태: "해당 이름의 탭이 없습니다"(SmartSearchBar 문구 톤 일치).
- Enter/클릭 시 그리드 끝에 추가 + **실행취소 토스트**.

### 3.10.4 의료진 '쉬운 사용' 기능 (Ease-of-use)
| 기능 | 동작 | 왜 의료진에게 쉬운가 |
|------|------|---------------------|
| **무설정 기본** | 로그인 시 역할/과 프리셋 자동 적용 | 설정 0으로 즉시 유용(대부분 사용자) |
| **검색형 패널 추가** | 타이핑으로 탭 찾기(콤보박스 B) | 48탭 위치·이름 암기 불필요 |
| **단축키** | `Alt+B` board 토글·`Esc` 일반 복귀·`1~9` 패널 포커스·`↑↓←→` 이동(`HotkeyProvider` 재사용) | 회진 중 마우스 없이 전환 |
| **패널 최대화** | 패널 `⤢` 클릭 → 임시 단독 확대, `Esc` 복귀 | 한 항목 집중 판독 후 즉시 원위치 |
| **접기/펼치기·빈상태 축소** | 데이터 0건·불필요 패널 접기 | 유효 정보에 공간 집중 |
| **실행취소 토스트** | 레이아웃 변경 후 "변경됨 · 실행취소"(기존 `Toaster`) | 잘못 건드려도 1클릭 원복 → 편집 두려움 제거 |
| **드래그 + 버튼 이동 병행** | 드래그(P2) 못 해도 `▲▼` 버튼(P1) | 접근성·저사양·키보드 사용자 |
| **인라인 힌트·툴팁** | 광폭 탭 선택 시 "2칸 권장" 등 | 실수 전 안내(학습 부담↓) |
| **기본값으로 초기화** | 편집 모드 상시 노출(`resetConfig`) | 꼬여도 한 번에 표준 복귀 |
| **자동 저장** | 편집 즉시 지속(§3.8), 별도 '저장' 강요 안 함 | 저장 잊어 유실 없음 |
| **신선도 배지** | 각 패널 갱신 시각(P-3) | 낡은 값 오인 방지(안전=편의) |

### 3.10.5 상태·어포던스 규약
- **인터랙션 상태**: hover(패널 헤더 컨트롤 노출)·active(파랑)·`focus-visible`(키보드 링 필수)·loading(스켈레톤, 기존 탭 보유)·drag(반투명 프리뷰, dnd-kit).
- **컨트롤 절제**: 평상시 패널 헤더는 제목·신선도만, **컨트롤은 hover/편집 모드에서 등장**(클린 유지).
- **마이크로카피(한글 친화)**: `큰 화면`/`일반 화면`·`보통/촘촘/회진`·`자동/2/3/4`·`패널 추가…`·`넓게(2칸)`·`새 창`·`기본값으로`. 시스템 용어(board·panel) 노출 금지.
- **접근성**: 모든 아이콘 버튼 `aria-label`·토글 `aria-pressed`·콤보박스 `role=combobox`+`aria-expanded`. `prefers-reduced-motion` 존중.

## 4. 비파괴 원칙 (기존 기능 보존)
- 기존 좁은 뷰: 코드·동작 **불변**. board는 `boardEnabled`일 때만 렌더 분기.
- 탭 컴포넌트: **수정 없이 재사용**(패널 래퍼로 감싸기만). 단, 일부 탭이 내부에 자체 `max-w`/여백을 가지면 board에서 좁게 보일 수 있어 **점검 후 필요한 탭만 폭 유연화**(L4, §P1).
- 탭 설정(`TabSettingsModal`)·URL 탭 동기화·인쇄: 회귀 없이 공존.
- 개인 레이아웃 config는 기존 탭 설정과 **별도 키로 분리 저장**(§3.8) → 좁은 뷰 탭 순서·표시 설정과 상호 간섭 없음.

## 6. 성능 설계 — 동시 쿼리 해소 (핵심)

### 6.1 문제 정량화 (측정된 부하)
현재 좁은 뷰는 **활성 탭 1개만** 렌더되어, 부모 페이지 쿼리 + 1탭 쿼리만 발화한다. board는 6~8개 패널이 **동시 마운트**되어 요청이 급증한다.

| 구간 | 발화 쿼리(useQuery) | 근거 |
|------|------|------|
| 부모 페이지 상시 | **~8** | `page.tsx`: `usePatient`·`usePatientHistory`·`usePatientEncounters`·`patient-billings`·`patient-summary-counts`·`patient-specialty-counts`·`twin-consent`·`twin-cds` |
| 현재(좁은 뷰, 1탭) | +2 (예: Overview) | 합계 **~10** |
| P0 board(6패널) | Overview 2 + Vitals 2 + Lab 2 + Med 3 + Problem 2 + Allergy 2 = **~13** | 각 컴포넌트 `useQuery` 실측 |
| **board 진입 순간** | **~21 near-simultaneous** | 부모 8 + 패널 13 |

**추가 결함(중복 조회)**: `OverviewTab`은 내부에서 이미 `lab/results?days=3`·`prescriptions?status=ACTIVE&limit=20`를 조회한다. `LabResultsTab`·`MedicationTab`은 **다른 파라미터**(풀셋)로 재조회 → 쿼리키가 달라 **React Query 자동 dedup이 안 걸림** → board에서 검사·투약을 사실상 2벌씩 요청.

### 6.2 대안 분석 (7안)

| # | 대안 | 효과 | 비용/리스크 | 채택 |
|---|------|------|------|:--:|
| **A** | **쿼리키 정규화 + RQ 자동 dedup** — 동일 queryKey는 RQ가 1요청으로 합침. board에서 Overview의 요약 위젯은 **Lab/Med 패널과 같은 쿼리를 `select`로 파생**(별도 조회 제거) | 중복(6.1) 제거·근본적 | 컴포넌트 데이터 접근 소폭 리팩터 | ✅ P0 |
| **B** | **QueryClient 캐시 공유(컴포넌트 무변)** — 부모가 이미 조회한 `patient/encounters/billings/summary`는 패널이 **같은 queryKey**로 접근 시 캐시 히트(추가 요청 0). prop 주입 대신 캐시로 공유 → 탭 시그니처 불변(비파괴) | 부모↔패널 중복 제거·구현 최소 | queryKey 규약 통일 필요 | ✅ P0 |
| **C** | **뷰포트 지연 로딩(IntersectionObserver + `enabled: inView`)** — 패널이 화면에 들어올 때만 fetch | 초기 버스트↓(스크롤/하단 패널) | 3~4컬럼 첫 화면에 다수 노출 시 효과 제한 | ✅ P0(하단 패널)/P1 |
| **D** | **staggered 게이팅(우선순위 로드)** — 핵심 4패널(요약·바이탈·검사·투약) 먼저 `enabled`, 보조 패널은 다음 tick에 순차 활성화 | 초기 동시성 스파이크 완화 | 보조 패널 표시가 수백 ms 지연 | ✅ P0(경량) |
| **E** | **staleTime 상향 + 캐시 재사용** — 좁은 뷰↔board 전환 시 staleTime 내면 재요청 0. board 패널 staleTime 60s→3~5분 | 전환 왕복 비용 제거 | 신선도↓(바이탈 등 실시간성 항목은 짧게 유지) | ✅ P0(항목별 차등) |
| **F** | **BFF 집계 EP `/patients/:id/board-summary`** — 요약·바이탈 최근·활성처방·문제·알러지를 서버에서 1요청으로 병합 반환(워터폴·요청 수 급감) | 요청 21→수개, 최적 | **신규 BE**(본 기획 "BE 변경 0" 원칙과 상충)·서버 조인 부하 이전 | ⏸ P2 옵션 |
| **G** | **refetchOnWindowFocus=false 확인/유지** — 이미 전역 false(`Providers.tsx`) | 두 번째 모니터 포커스 이동 시 대량 리페치 없음(멀티모니터 유리) | 없음(현행 유지) | ✅ 현행 |

### 6.3 권장 조합 (P0 기본)
**A(중복 dedup) + B(캐시 공유) + E(항목별 staleTime) + C·D(경량 지연/우선순위)** 를 조합하면 **신규 BE 없이** board 진입 시 실요청을 **~21 → ~10~12**로 낮춘다(중복 6~8건 제거 + 지연 로딩). F(BFF)는 실측 후 병목이 남으면 P2에서 도입.

- **staleTime 차등 정책**(E): 바이탈 30~60s(실시간), 검사/투약 2분, 문제/알러지/요약 5분. → 패널별 `staleTime` 명시.
- **동시성 상한 근거**: 브라우저는 오리진당 동시 연결 ~6개로 제한 → 21요청은 자연 큐잉되나 워터폴로 체감 지연. A·B로 **요청 수 자체를 줄이는 것**이 큐잉·서버 부하 양쪽에 최선.
- **측정 우선**: P0에서 네트워크 탭으로 실 요청 수·중복·워터폴을 계측하고, 목표(진입 시 신규 요청 ≤12·중복 0) 미달 시 D 강화 또는 F 착수.
