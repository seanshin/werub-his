## 2. 🔴 지금 화면이 사실과 다르게 말하는 것 (P0)

### 2-1. 아무도 묻지 않은 알레르기를 **"없음"이라고 단언한다**

`PatientHeader.tsx` 는 이렇게 갈린다.

```
allergies.length > 0  →  빨간 "알레르기 N건"
allergies.length === 0 →  🟢 NKDA          ← 초록 배지
```

`NKDA` 는 *No Known Drug Allergy* — **"물어봤고 없었다"**는 임상적 단언이다.
🔴 운영에서 **알레르기 평가를 받은 환자는 0명**이다. 즉 **874명 중 862명이
근거 없는 초록 배지**를 달고 있고, 처방하는 의사가 그것을 본다.

**서버에는 이미 4상태 정본이 있다** (`allergy.service.ts`):

```
NOT_ASSESSED | NO_KNOWN_ALLERGIES | HAS_ALLERGIES | UNABLE_TO_ASSESS
```

`GET /patients/:id/allergies/status` 도 있고, **환자 포털과 진료 입력 화면은 그것을 쓴다.**
🔴 **차트만 안 쓴다** — 모두가 가장 먼저 여는 화면이 유일하게 2상태로 접고 있다.
(`정본을 만든 것과 모든 소비처가 그것을 쓰는 것은 다른 일이다`)

> 이 저장소 규약 그대로다 — **표본 부재의 정답은 폴백이 아니라 "산출 불가"**이고,
> **화면이 실제보다 안전하게 말하는 것도 사실이 아니다.**

### 2-2. 빈 탭과 내용 있는 탭이 **똑같이 생겼다**

`tabCounts` 는 **4종만** 센다(`encounters`·`medications`·`orders`·`billing`).
나머지 22개 기본 탭에는 숫자가 없다. 표본 환자에서 문제목록·알레르기·영상·바이탈·
수술·간호기록·동의서는 전부 0인데 **누르기 전에는 알 수 없다.**

임상의는 그래서 **22번 눌러보거나, 누르지 않고 없다고 가정한다.** 둘 다 나쁘다.

### 2-3. "인쇄"가 문서가 아니라 화면 덤프다

헤더의 인쇄 버튼은 `sanctionedPrint()` — **지금 열려 있는 탭의 DOM**을 찍는다.
실 의료기관이 인쇄하는 것은 화면이 아니라 **문서**다(진료기록 사본·진료의뢰서·소견서·
입퇴원 요약). 무엇을 담았는지 정의되지 않은 출력은 **의무기록 사본으로 쓸 수 없다.**

## 4. 설계 원칙 — "세련되게"는 미학이 아니다

- 🔴 **모르는 것을 없다고 말하지 않는다.** 알레르기·문제목록·수술력은 **3상태**로 그린다

- 🔴 **화면은 판정하지 않고 서버 정본을 그대로 말한다.** 4상태 EP 가 이미 있다.

  없다고 믿는다) — **개수를 붙이고 0인 탭은 흐리게** 둔다.
- 🔴 **한 화면에 정본은 하나.** 헤더가 이미 말한 것을 개요 카드가 다시 말하지 않는다.
- 🔴 **인쇄는 문서다.** 무엇을 담는지 정의되고, 담지 못한 것은 담지 못했다고 적는다.
- **읽는 순서가 설계다.** 안전(알레르기·격리·DNR·임신) → 지금 상태(활력·활성 처방·문제)
  → 최근 흐름(방문·검사) → 나머지. 지금은 이 순서가 카드 배치에 반영돼 있지 않다.
