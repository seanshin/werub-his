## 2. 개선 범위

### Phase 1: 필수 기능 보강 (P0)

#### 2.1 환자 모델 확장

```
Patient (확장 필드)
├── nationalId          VARCHAR(20)   # 주민등록번호 (암호화, 뒷자리 마스킹)
├── nationalIdType      ENUM          # RESIDENT(주민), FOREIGNER(외국인), PASSPORT(여권)
├── photoUrl            VARCHAR(500)  # 환자 사진 URL
├── nationality         VARCHAR(50)   # 국적 (기본: 대한민국)
├── preferredLanguage   VARCHAR(10)   # 선호 언어 (ko, en, zh, ...)
├── maritalStatus       ENUM          # SINGLE, MARRIED, DIVORCED, WIDOWED, UNKNOWN
├── occupation          VARCHAR(100)  # 직업
├── religion            VARCHAR(50)   # 종교 (수혈/식이 참고)
├── deathDate           TIMESTAMPTZ   # 사망일시
├── deathCause          VARCHAR(500)  # 사망원인
├── isDeceased          BOOLEAN       # 사망 여부
├── memo                TEXT          # 관리자 메모
└── tags                VARCHAR[]     # 태그 배열 ['감염주의', '낙상위험', 'VIP']
```

#### 2.2 보호자/응급연락처 모델 (신규)

```
PatientContact (신규 모델)
├── id                  UUID PK
├── patientId           UUID FK → Patient
├── relationship        ENUM          # PARENT, SPOUSE, CHILD, SIBLING, GUARDIAN, OTHER
├── relationshipDetail  VARCHAR(50)   # '어머니', '배우자', '법정대리인'
├── name                VARCHAR(100)  # 연락처 이름
├── phone               VARCHAR(20)   # 전화번호
├── phone2              VARCHAR(20)   # 보조 전화번호
├── address             JSONB         # 주소
├── isEmergencyContact  BOOLEAN       # 응급 연락처 여부
├── isLegalGuardian     BOOLEAN       # 법정 대리인 여부
├── isPrimaryContact    BOOLEAN       # 주 보호자 여부
├── priority            INT           # 연락 우선순위 (1, 2, 3)
└── notes               TEXT          # 비고
```

#### 2.3 환자 정보 수정 UI

**수정 가능 영역:**
- 기본 정보 (이름, 생년월일, 성별 — 사유 필수)
- 연락처 (전화, 이메일, 주소 — 즉시 수정)
- 보험 정보 (유형, 번호 — 사유 필수)
- 보호자/응급연락처 (추가/수정/삭제)
- 의료 정보 (혈액형, 알레르기 — 의사/간호사만)
- 태그/메모 (관리자, 간호사)

**수정 불가 항목:**
- MRN (시스템 생성)
- 주민등록번호 (최초 등록 후 관리자만 변경 가능)

**수정 이력:**
- 모든 변경은 PatientHistory에 자동 기록
- 기본 정보 변경 시 사유(reason) 필수 입력
- 변경 전/후 값 저장 (changedFields JSON)

#### 2.4 주민등록번호 관리

**저장 방식:**
- 앞 6자리(생년월일) + 뒷 1자리(성별코드)만 평문 저장
- 전체 번호는 AES-256-GCM 암호화 저장
- 조회 시: `860513-1******` 형태로 마스킹 표시
- 건보 청구 시에만 전체 복호화 (ADMIN+BILLING 권한)

**검증 규칙:**
- 주민등록번호 체크디짓 검증
- 생년월일 필드와 교차 검증
- 외국인 등록번호: 별도 형식 검증

### Phase 2: 안전/품질 기능 (P1)

#### 2.5 중복 환자 감지

**감지 시점:**
1. 환자 등록 시 (실시간)
2. 배치 검사 (야간 스케줄)

**매칭 알고리즘:**
```
점수 = 0
IF 주민등록번호 일치 → 점수 += 100 (확정)
IF 이름 완전 일치 + 생년월일 일치 → 점수 += 90
IF 이름 완전 일치 + 전화번호 일치 → 점수 += 85
IF 이름 유사(Levenshtein≤1) + 생년월일 일치 → 점수 += 70
IF 전화번호 일치 + 성별 일치 → 점수 += 60

점수 ≥ 90: 자동 차단 + 기존 환자 안내
점수 ≥ 70: 경고 팝업 (등록 허용, 사유 기록)
점수 < 70: 통과
```

**병합 기능:**
- 관리자 전용
- Source 환자의 모든 진료/처방/검사 이력을 Target으로 이관
- Source MRN → Target MRN 매핑 테이블 유지 (이전 MRN으로 검색 가능)
- 병합 취소 불가 (감사 로그에 기록)

#### 2.6 환자 사진 관리

**용도:** 본인 확인 (JCI IPSG.1 — 환자 확인)

**구현:**
- 등록/수정 시 사진 촬영 또는 파일 업로드
- 최대 2MB, JPEG/PNG
- 리사이즈: 200x200px 썸네일 자동 생성
- 저장: 로컬 스토리지 `/uploads/patients/{patientId}/photo.jpg`
- 환자 상세 페이지 프로필 영역에 표시
- 접수/진료/입원 시 팝업에서 사진 확인

#### 2.7 환자 태그 시스템

**기본 태그 (시스템 정의):**

| 태그 | 색상 | 자동 부여 조건 |
|------|------|---------------|
| 감염주의 | 빨강 | 감염관리 모듈에서 격리 대상 등록 시 |
| 낙상위험 | 주황 | 간호 평가에서 낙상위험 HIGH 판정 시 |
| 약물알레르기 | 보라 | 알레르기 모듈에서 DRUG 타입 등록 시 |
| 수혈거부 | 빨강 | 종교 '여호와의 증인' 설정 시 |
| VIP | 금색 | VIP 상태 활성화 시 |
| 미성년 | 파랑 | 만 18세 미만 자동 |
| 고령 | 회색 | 만 65세 이상 자동 |
| 임산부 | 분홍 | 산부인과 진료 중 등록 |
| 다제내성균 | 빨강 | 감염관리에서 MDRO 등록 시 |

**커스텀 태그:**
- 관리자/간호사가 자유 입력
- 색상 선택 가능
- 만료일 설정 가능

**표시 위치:**
- 환자 목록 (이름 옆 배지)
- 환자 상세 (헤더)
- 접수 화면 (경고 팝업)
- 진료 화면 (상단 배너)
- 처방 화면 (약물알레르기 시 차단)

#### 2.8 내/외국인 구분

**외국인 환자 추가 필드:**
- 여권번호 (암호화 저장)
- 비자 유형
- 체류 기간
- 통역 필요 여부
- 보험 유형: 자비(SELF_PAY) 또는 외국인 보험

### Phase 3: 운영 효율화 (P2)

#### 2.9 일괄 등록/내보내기

**Excel 업로드:**
- 템플릿 다운로드 (필수/선택 필드 구분)
- 파일 업로드 → 미리보기 → 검증 → 등록
- 검증 항목: 필수 필드, 형식, 중복 체크
- 결과 리포트 (성공/실패/건너뛴 건수)

**CSV/Excel 내보내기:**
- 현재 필터 기준으로 내보내기
- 개인정보 마스킹 옵션
- 관리자 권한만 허용
- 내보내기 감사 로그 기록

#### 2.10 환자 비활성/사망 처리

**비활성 사유:**
- 타원 전원
- 장기 미내원 (1년+)
- 중복 환자 (병합)
- 기타 (사유 입력)

**사망 처리:**
- 사망일시, 장소(원내/원외)
- 사망원인 (ICD-10 코드)
- 사망진단서 연계
- 사망 후: 예약 자동 취소, 처방 자동 중단
- 목록에서 기본 숨김 (필터로 표시 가능)

#### 2.11 가족 관계 연결

**용도:**
- 소아 환자 ↔ 보호자 연결
- 가족력 관리 (유전질환 추적)
- 가족 동시 예약
- 보험 연대 관계

**구현:**
```
PatientRelation (신규 모델)
├── id             UUID PK
├── patientId      UUID FK → Patient (본인)
├── relatedId      UUID FK → Patient (가족)
├── relationship   ENUM (PARENT, CHILD, SPOUSE, SIBLING)
├── isActive       BOOLEAN
└── notes          TEXT
```

## 7. 참고 기준

- **건강보험심사평가원(HIRA)**: 요양급여비용 청구 시 주민등록번호 필수
- **개인정보보호법 제23조**: 민감정보(건강정보) 별도 동의
- **의료법 시행규칙 제14조**: 진료기록부 기재 사항 (성명, 주소, 주민번호, 병명, 치료내용)
- **JCI IPSG.1**: 환자 확인 — 최소 2가지 식별자 (이름+생년월일 또는 이름+MRN)
- **EMR 인증제 v2.0**: 환자 마스터 관리 필수 항목
- **FHIR R4 Patient Resource**: identifier, name, telecom, gender, birthDate, address, contact
