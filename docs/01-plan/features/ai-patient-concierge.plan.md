## 1. 개요

### 1.1 목적
현재 `/booking` 페이지의 "AI 예약 도우미"를 **AI 환자 컨시어지**로 확대하여, 예약뿐 아니라 진료 이력 조회, 검사 결과 확인, 투약 정보, 병원 안내, 건강 상담 등 환자가 궁금해하는 모든 질문에 대응하는 통합 상담 채팅 시스템을 구축.

### 1.2 현재 vs TO-BE

| 항목 | 현재 (AI 예약 도우미) | TO-BE (AI 환자 컨시어지) |
|------|---------------------|------------------------|
| **기능 범위** | 예약 생성/확인/취소만 | 예약 + 진료이력 + 검사결과 + 투약 + 병원안내 + 건강상담 |
| **데이터 접근** | 예약 세션 API만 | 환자 HIS 데이터 전체 (읽기 전용) |
| **인텐트 분류** | 증상 키워드 매칭 | LLM 기반 자연어 인텐트 분류 |
| **응답 품질** | 단순 텍스트 | 구조화 카드/테이블/차트 |
| **진료 이력** | 미지원 → 키워드 매칭 추가(방금) | 상세 카드 + 필터 + 페이징 |
| **검사 결과** | 미지원 | 결과값 + 정상 범위 + 트렌드 |
| **투약 정보** | 미지원 | 현재 복용약 + 복용법 + 주의사항 |
| **비용 문의** | 미지원 | 비급여 안내 + 예상 비용 |
| **병원 안내** | 미지원 | 진료시간, 오시는 길, 주차, 면회 |

### 1.3 핵심 가치
| 가치 | 설명 |
|------|------|
| **24시간 응대** | 야간/주말에도 환자 질문에 즉시 응답 |
| **개인화** | 환자의 진료 이력/처방/검사 데이터 기반 맞춤 응답 |
| **편의성** | 전화 대기 없이 채팅으로 즉시 해결 |
| **의료진 부담 경감** | 반복적 안내 질문을 AI가 처리 |
| **환자 만족도** | 빠른 응답 + 정확한 정보 → 만족도 향상 |

## 2. 인텐트 분류 체계

### 2.1 1단계: 카테고리 분류

```
환자 메시지 입력
  ↓
┌─────────────────────────────────────────────────┐
│           LLM 인텐트 분류기                      │
│  (Claude Haiku / GPT-4o-mini)                   │
│                                                 │
│  → BOOKING      (예약/일정)                      │
│  → HISTORY      (진료 이력)                      │
│  → LAB_RESULT   (검사 결과)                      │
│  → MEDICATION   (투약/처방)                      │
│  → BILLING      (비용/수납)                      │
│  → HOSPITAL_INFO(병원 안내)                      │
│  → HEALTH_ADVICE(건강 상담/증상)                  │
│  → GENERAL      (일반 대화)                      │
└─────────────────────────────────────────────────┘
```

### 2.2 인텐트별 상세

| 인텐트 | 예시 질문 | 데이터 소스 | 응답 형태 |
|--------|---------|-----------|----------|
| **BOOKING** | "내과 예약하고 싶어요", "다음 예약은 언제?" | Appointment, ClinicSchedule | 예약 폼 / 일정 카드 |
| **HISTORY** | "지난달 진료 내역", "어떤 치료 받았었지?" | Encounter, ProgressNote | 진료 이력 카드 리스트 |
| **LAB_RESULT** | "혈액검사 결과 알려줘", "콜레스테롤 수치" | LabResult, Order | 결과 테이블 + 정상범위 표시 |
| **MEDICATION** | "지금 먹는 약 뭐야?", "약 부작용?" | Prescription, MedAdmin | 투약 카드 + 복용법 |
| **BILLING** | "진료비 얼마야?", "비급여 항목은?" | Billing, NonCovered CMS | 비용 테이블 |
| **HOSPITAL_INFO** | "진료시간?", "주차 안내", "면회 시간" | CMS(HospitalInfoContent) | 텍스트 + 링크 |
| **HEALTH_ADVICE** | "두통이 계속돼요", "혈압 관리법" | AI 의료상담 + CMS 건강정보 | AI 응답 + 관련 글 링크 |
| **GENERAL** | "감사합니다", "안녕" | - | 친절한 대화 응답 |

## 3. 데이터 접근 설계

### 3.1 환자 데이터 API (읽기 전용)

현재 환자 인증(MRN + 생년월일)으로 본인 확인 후 데이터 접근.

```
┌─ 환자 컨시어지 API ──────────────────────────────┐
│                                                  │
│  GET /api/v1/concierge/encounters               │
│  → 진료 이력 (날짜, 진료과, 담당의, 사유, 상태)     │
│                                                  │
│  GET /api/v1/concierge/lab-results              │
│  → 검사 결과 (검사명, 결과값, 정상범위, 날짜)       │
│                                                  │
│  GET /api/v1/concierge/medications              │
│  → 현재 투약 (약품명, 용량, 복용법, 기간)           │
│                                                  │
│  GET /api/v1/concierge/appointments             │
│  → 예약 현황 (날짜, 시간, 진료과, 담당의)           │
│                                                  │
│  GET /api/v1/concierge/billings                 │
│  → 수납 내역 (날짜, 금액, 상태)                    │
│                                                  │
│  GET /api/v1/concierge/vitals                   │
│  → 최근 바이탈 (혈압, 맥박, 체온 등)                │
│                                                  │
│  ※ 모든 API는 환자 본인 데이터만 접근 가능          │
│  ※ 인증: MRN+생년월일 세션 토큰                    │
└──────────────────────────────────────────────────┘
```

### 3.2 보안 원칙

| 원칙 | 설명 |
|------|------|
| **본인 확인 필수** | MRN + 생년월일 인증 후에만 개인 데이터 접근 |
| **읽기 전용** | 데이터 조회만 가능, 수정/삭제 불가 |
| **세션 만료** | 30분 비활동 시 자동 로그아웃 |
| **민감정보 마스킹** | 주민번호, 전화번호 부분 마스킹 |
| **감사 로그** | 모든 데이터 조회 기록 저장 |
| **AI 응답 제한** | 진단/처방 행위 금지 — "담당의와 상담하세요" 안내 |

### 5.2 인텐트 분류 방식

**하이브리드 접근**: 키워드 매칭 (빠른 응답) + LLM 폴백 (복합 질문)

```typescript
// 1차: 키워드 매칭 (FE에서 즉시 처리)
const INTENT_PATTERNS: Record<string, RegExp> = {
  HISTORY:     /진료.*내역|진료.*이력|진료.*기록|치료.*받았|언제.*진료|과거.*진료/,

  VITAL:       /혈압|체중|바이탈|키|체온|맥박/,
};

// 2차: LLM 분류 (키워드 매칭 실패 시)

## 6. 질문 시나리오별 응답 설계

### 6.1 진료 이력

| 질문 예시 | 응답 |
|---------|------|
| "그동안 진료 받았던 내역들은?" | 최근 8건 진료 이력 카드 리스트 |
| "지난달 내과 진료 내역" | 필터링된 결과 (월/진료과) |
| "김내과 선생님한테 마지막으로 언제 갔지?" | 특정 의사 필터 |
| "진료 기록 출력할 수 있어?" | 의무기록 사본 발급 안내 링크 |

### 6.2 검사 결과

| 질문 예시 | 응답 |
|---------|------|
| "혈액검사 결과 알려줘" | 최근 검사 결과 테이블 (정상/이상 표시) |
| "콜레스테롤 수치 추이" | 최근 3회 결과 비교 + 트렌드 표시 |
| "CT 결과 나왔어?" | 영상검사 판독 결과 (있으면 표시, 없으면 대기 안내) |
| "검사 결과가 정상인지 궁금해요" | 이상 항목 하이라이트 + "담당의 상담 권장" |

### 6.3 투약/처방

| 질문 예시 | 응답 |
|---------|------|
| "지금 먹는 약이 뭐야?" | 현재 활성 처방 카드 리스트 |
| "아스피린 부작용은?" | 약물 정보 + 주의사항 |
| "약을 빼먹었는데 어떡하지?" | 일반적 안내 + "약사/담당의 확인 권장" |
| "언제까지 약 먹어야 해?" | 처방 기간 정보 |

### 6.4 비용/수납

| 질문 예시 | 응답 |
|---------|------|
| "진료비 얼마야?" | 최근 수납 내역 |
| "비급여 항목 뭐가 있어?" | CMS 비급여 안내 링크 |
| "보험 적용 되나요?" | 일반 안내 + "원무과 문의" |
| "미수납 내역 있어?" | 미수납 건수 + 금액 |

### 6.5 병원 안내

function classifyMultiIntent(message: string): Intent[] {
  const intents: Intent[] = [];

  // 1차: 모든 키워드 패턴 매칭
  for (const [intent, pattern] of Object.entries(INTENT_PATTERNS)) {
    if (pattern.test(message)) intents.push(intent as Intent);
  }

  // 2차: 인텐트 0~1개면 LLM 폴백
  if (intents.length <= 1) {
    const llmResult = await classifyWithLLM(message);
    return llmResult;
  }

  // 3차: 우선순위 정렬 (응급 > 예약 > 조회 > 안내 > 일반)
  return intents.sort((a, b) => PRIORITY[a] - PRIORITY[b]);
}
```

| 과도한 API 호출 (비용) | 운영비 증가 | 중 | Rate limit (세션당 50회/시간) + 캐싱 |
| 환자 의존성 증가 | 대면 진료 기피 | 낮 | 정기적 "대면 진료를 권장합니다" 안내 |
| 고령 환자 사용 어려움 | 디지털 격차 | 높 | 음성 입력(v2.0) + 큰 글씨 모드 + 전화 폴백 |
