## 2. 제1원칙 — 화면은 사실을 말한다

### 2.1 모르는 것을 아는 것처럼 말하지 않는다

**같은 "비어 있음"이 최소 여섯 가지다. 화면은 이것을 구분해야 한다.**

| 실제 상태 | 올바른 표현 | 절대 쓰면 안 되는 표현 |
|---|---|---|
| 진짜 0건 (분모가 있고 값이 0) | `0` + 분모 병기 (`0 / 24건`) | `-`, 공백 |
| 표본 부재 (분모가 0) | **`산출 불가`** + 왜 없는지 | `0`, `0%`, `100%` |
| 미측정·미관측 | `—` 또는 `미측정` | `0`, 기본값(`false`·`ALERT`) |
| 기능 미배선 | `미배선` + 담당/일정 | 빈 목록(정상처럼 보임) |
| 조회 실패 | `불러오지 못했습니다` + 재시도 | `결과 없음`, 빈 목록 |
| 미래 시각 | 미래임을 명시 | `방금`, `0분 전` |

- 🔴 **분모 0이면 완결률은 100%가 된다.** 비율을 그리기 전에 분모를 화면에 함께 낸다.
- 🔴 **`?? 0` 은 금지에 가깝다.** `null` 을 0으로 접는 순간 "가장 안정적"이라는 뜻이 된다.
  (실측: ICU NEWS2 위젯이 산출 불가를 `0점`으로 표시 — 정반대의 사실)
- 표본 부재 배너의 정본 예시: `/admin/risk-reassessment` 의 `risk-no-sample-banner`.

### 2.1-b 🔴 조건식에서 미측정을 폴백하지 않는다 — 표시보다 조건이 더 위험하다

표시가 틀리면 사람이 알아챌 수 있지만, **조건이 틀리면 경고가 조용히 사라진다.**

```ts
// 🔴 실제 코드 — 미측정 활력을 전부 교과서 정상값으로 접는다
((latestVital.spo2 ?? 100) < 95) || ((latestVital.temperature ?? 36.5) >= 37.5)
((latestVital.heartRate ?? 0) > 100 || (latestVital.heartRate ?? 72) < 60)
```
활력을 **하나도 측정하지 않은 환자가 "활력 정상"으로 판정**된다. 같은 값에 폴백이 둘(`0`/`72`)이라는 것
자체가 임의값이라는 자백이다. 실측: 조건식 `?? 0` **151건 / 70파일**, 그중 임상값 **19건**
(진료 `?? 100`·`?? 36.5` · PACU `spo2 ?? 100` · 병동 `?? 200` · ER `KTAS 미분류 → LEVEL_3`).

**규칙**: 값이 `null` 이면 **판정 자체를 하지 않는다**. `?? 기본값` 대신 `== null` 분기로 쓰고,
셀은 `미측정`으로 그린다. 정본 선례 — `post-op` 의 Aldrete(`!= null && >= 9`, 아니면 `미측정`).

### 2.1-c 🔴 `queryFn` 안에서 `.catch()` 로 기본값을 반환하지 않는다

`useQuery(queryFn: () => api.get(...).catch(() => ({data: []})))` 는 promise 를 resolve 시켜
**`isError` 를 영원히 false 로 만든다.** 화면이 `QueryErrorFallback` 을 아무리 써도 **도달 불가 코드**다.

실측: 관리 **65개소/40파일** · 워크스테이션 28 · 간호 18 · 포털 **52곳/69쿼리**.
그 결과 서버가 죽어도 화면은 `담당 입원 환자가 없습니다` · `낙상 위험 0` · `동의서가 없습니다` 라고 말한다.

**규칙**: 실패는 reject 시키고 **렌더 분기**에서 처리한다. `.catch` 는 "없어도 화면이 사는 부가 데이터"에만,
그때도 부재 사실을 그린다. 문구 정본 — `portal/imaging`: **"영상이 없는 것이 아니라 불러오지 못했습니다."**

### 2.1-d 조회 실패를 **영구 로딩**으로 굳히지 않는다

`.catch(() => setX(null))` + `if (!x) return '불러오는 중…'` → 사용자는 실패를 영원히 인지할 수 없다.
§2.1 표의 **일곱 번째 상태**로 명시 금지한다.

### 2.2 실제보다 **안전하게** 말하지 않는다

안전 화면의 초록은 두 가지 뜻일 수 있다 — "안전하다" 또는 "탐지기가 죽었다".
**둘을 구분하지 못하는 초록은 그리지 않는다.**

- 값이 없을 때 **가장 안전한 값으로 폴백하지 않는다.**
  (`illness || 'STABLE'` → 중증도 미기재가 초록 '안정'으로 표시되던 실측)
- `0건`·`100%`·`이상 없음` 을 그릴 때는 **반드시 분모와 최신 갱신 시각**을 같이 낸다.
- 게이트가 켜져 있다는 표시와 **실제로 무언가를 잡고 있다**는 표시는 다른 지표다
  (실측: DUR 게이트가 BLOCK 인데 55룰 중 43룰이 개통 이래 매칭 0 — 위반 0행이 "안전"이 아니었다).

### 2.2-b 🔴 쓰기 폼의 초기값은 "미선택"이다 — 표시보다 저장이 더 위험하다

§2.2 는 **읽기** 규칙이었다. 실제로 더 나쁜 것은 **입력 폼의 기본값**이다 — 원장에 저장되기 때문이다.

| 실측 | 기본값 | 1탭이면 저장되는 것 |
|---|---|---|
| 간호초기평가 | `의식 명료`·`독립보행`·`통증 0`·`영양 양호`·`피부 정상` | 사정하지 않은 평가가 "전부 정상"으로 |
| 회진 기록 | `patientCondition:'STABLE'` | 모든 회진에 `[상태] STABLE` |
| 검진·심전도 | `finding:'NORMAL'`·`conclusion:'NORMAL'` | 판독하지 않은 정상 판정 |
| 배식 확인 | `patientVerified:true`·`dietVerified:true`·`tempOk:true` (하드코딩) | 아무도 확인 안 한 "확인함" |

**규칙**: 임상 입력의 초기값은 `''`/`null` 이다. 선택을 강제하지는 않되(§6.3),
**미선택은 미선택으로 저장·표시**한다. 정본 선례 — `MedDoubleCheck`(선택 없음이 기본, 우회는 사유+표식).

### 2.3 실제보다 **위험하게**도 말하지 않는다

거짓 경보는 진짜 경보를 죽인다. 알림 읽음률 실측 **8.6%**.

- 확실하지 않으면 **침묵한다.** 애매한 경보를 띄우는 것보다 낫다.
- "조건이 참인가"가 아니라 **"얼마나 참인가"**를 재고 그린다
  (실측: 1ms 시각 역전 32건을 경보로 띄우면 진짜 역전이 묻힌다).
- 임계값은 감이 아니라 **그 축의 과거 실측**에서 뽑는다(p95×2 같은 자기교정).
- 희소한 축의 `0` 을 경보하지 않는다.

### 2.4 값의 **출처**를 말한다

같은 숫자라도 어디서 왔는지에 따라 신뢰가 다르다. 화면은 그것을 구분해 보여준다.

| 출처 | 표시 |
|---|---|
| 사람이 측정·입력 | 그대로 |
| 기기·외부 시스템 보고값 | 출처 라벨. 🔴 **재반올림 금지**(보고값 변조) |
| 시스템 계산 | 근거를 펼칠 수 있게(NEWS2 항목별 점수 등) |
| AI 생성 | §7.4 표기 + §7.5 출처 앵커 **필수** |
| 기본값·추정 | "기본값" 명시. 임상 문자열 자리에 넣지 않는다(`dose ?? '처방 용량'` 금지) |

---

### 2.5 🔴 화면이 값을 지어내지 않는다

원장에 남는 수치·사유·식별자를 **화면이 만들어내면 그 순간 기록이 거짓이 된다.** 실측:

| 지어낸 값 | 위치 | 결과 |
|---|---|---|
| 대기번호 `charCodeAt(0)*7%100` | `workstation/reception` | 화면이 3xl 로 "대기번호"라 부르는 숫자가 날조 · `%100` 충돌 |
| 수혈량 `320` 상수 | `workstation/blood-bank` | 실제 투여량을 묻지 않고 원장에 기록 |
| 처방 `dosage:'1정' · 1일 3회 · 3일` | `tablet/.../encounter` | 1탭으로 실제 처방 생성 · 삭제 UI 없음 |
| 카드승인번호 `KIOSK-${Date.now()}` | `kiosk.service` | PG 호출 없이 **수납 확정** |
| 검사치 게이지 `width:'70%'` 고정 | `portal/_home/HomeTab` | 모든 항목이 같은 막대 — 값과 무관한 시각화 |

**규칙**: 물을 수 없으면 **보내지 않는다.** 서버 기본값에 맡기거나 그 칸을 그리지 않는다.

## 3. 표현 정본 — 새로 만들지 않는다

### 3.1 반드시 쓰는 부품

| 대상 | 부품 | 정본 |
|---|---|---|
| 상태 라벨·색 | `<StatusBadge domain="...">` | shared 상태 라벨 상수 |
| 날짜·시각 | `<KDate>` / `kdate()` | `ui.dateStyle`·`ui.time24h` |
| 금액 | `<Money>` / `money()` | `ui.currencyStyle` |
| 환자명 | `<PatientName maskable>` | `ui.patientNameMasking` |
| 수치 | `<Num domain>` / `formatNum` | `NUMERIC_POLICIES` |
| 나이 · 재원일 | `<Age>`(`ui/BirthDate`) · `<StayDays>` | shared `ageOf` · `stayDays` |
| 모름 3종 | `<Unknown kind="UNRECORDED\|NA\|PENDING">` | — |
| 빈 상태 · 로딩 | `<EmptyState compact>` · `<LoadingState>` | 위젯은 `compact` |
| 조회 실패 | `<QueryErrorFallback>` | 🔴 실패를 "결과 없음"으로 그리지 않는다 |
| 폴링 | `usePollInterval('fast\|normal\|slow')` | `ui.poll.*` |
| 인쇄 | `sanctionedPrint()` 또는 `/print/*` | `window.print()` 직접 호출 금지 |
| 권한 상태 | `<CapabilityBadge mode="write\|delegated\|readonly">` | 왜 그 상태인지(`reason`)를 반드시 채운다 |

### 3.2 금지 목록 (신규 화면은 즉시 적용)

- 로컬 `*_LABEL` / `*_COLOR` `Record` 재정의 — **정본에서 조용히 드리프트한다**
- `toFixed` / `Math.round` 직접 호출 — 구조 가드가 기준선 동결 중
- `toLocaleDateString` / `toLocaleString` 직접 호출
- `refetchInterval: 30000` 같은 숫자 리터럴
- `?? 0` 으로 `null` 을 0으로 접기
- 색만으로 정보 전달 (§4.6)

### 3.3 아직 정본이 없어 이 문서가 정하는 것

| 대상 | 규약 |
|---|---|
| 분모 표기 | 비율·완결률은 **항상 `n / N`** 을 같이 낸다. `N=0` 이면 비율 자리에 `산출 불가` — **정본(2026-08-19)**: shared `ratioOf`/`ratioText` · web `<Ratio numerator denominator pctOnly unavailableHint>`. `xRate != null ? '%' : '-'` 관용구는 가드가 0 동결 |
| 최신성 | 실시간처럼 보이는 화면은 **"기준 시각"**을 함께 낸다(축마다 최신일이 다르다) |
| 절단 | 목록을 자르면 **잘랐다고 말한다**(`상위 10건만 표시 · 전체 137건`) |
| 잔여 작업 | **사라지는 토스트가 아니라 줄어드는 목록**으로 낸다 |

## 4. 의료현장 UX — 어디서, 어떤 손으로 쓰이는가

같은 정보라도 **매체가 다르면 다른 화면이다.** 이 저장소의 라우트 그룹이 이미 그 구분이다.

### 4.1 다섯 가지 사용 맥락

| 맥락 | 라우트 | 사용자 자세 | 지배적 제약 |
|---|---|---|---|
| 워크스테이션 | `(main)/workstation/*` (29) | 앉아서 키보드·마우스 | 정보 밀도 · 다중 작업 · 단축키 |
| 타블렛·병상 | `tablet/*` | 서서 한 손 · 장갑 | 터치 타깃 · 오염 · 중단 |
| 전광판·공개 | `display/*` | 2~5m 거리 · 다수 시청 | 가독 거리 · **PHI 마스킹** |
| 환자 포털·모바일 | `portal/*`·`apps/mobile` | 개인 기기 · 비전문가 | 용어 · 불안 · 오해 |
| 인쇄물 | `print/*` | 종이 · 되돌릴 수 없음 | 워터마크 · 감사 |

### 4.2 맥락별 강제 규칙

**타블렛·병상**
- 최소 터치 타깃 **44×44pt**. 장갑 착용 상태를 기본 가정한다.
- 파괴적 동작(투약 실시·폐기·서명)은 **인접 배치 금지** — 오터치 한 번이 임상 사건이다.
- 스크롤 중 실행 버튼이 손가락 밑으로 들어오지 않게 고정 영역을 둔다.

**전광판·공개 화면**
- 판독 거리 기준 최소 글자 크기를 화면별로 명시한다.
- 🔴 **마스킹은 서버에서 한다.** 클라이언트 마스킹은 원본이 이미 브라우저에 도착한 것이다
  (공개 화면은 계약 테스트 필수 — 이미 있는 규약).
- 새로고침 주기는 `usePollInterval`. 무접촉 반영 60초 규약(박스 지정 운영).

**환자 포털·모바일**
- 임상 용어를 그대로 쓰지 않는다. 다만 **쉽게 쓰다가 사실을 바꾸지 않는다.**
- 불안을 유발하는 값(위급 검사치 등)은 **연락 경로와 함께** 낸다. 값만 던지지 않는다.
- 🔴 세션 만료로 작성 중 내용을 잃게 하지 않는다(실측: 모바일 1시간마다 강제 로그아웃).

### 4.3 중단·재개 — 임상 화면의 기본값

간호·응급 업무는 **중단이 정상**이다. 화면은 그 전제로 설계한다.

- 다단계 입력은 **부분 저장**을 기본으로. 나가면 사라지는 폼은 결함으로 취급한다.
- 되돌아왔을 때 **어디까지 했는지**를 화면이 말한다(진행 표시 + 남은 항목 목록).
- 자동 저장한 것은 **자동 서명이 아니다**(§6.3·§7.6).

### 4.4 손이 바쁠 때

- 바코드·QR·음성은 **대체 입력이지 유일 입력이 아니다** — 스캐너가 죽어도 일이 되게 한다.
- 🔴 QR·바코드에 **PHI 를 넣지 않는다**(실측: 외부 QR API 로 PHI 유출 8곳 + 폐쇄망에서 팔찌 빈칸 인쇄).
- 음성 입력은 확정 전 **되읽기 카드**를 거친다(`VoiceConfirmCard` 패턴).

### 4.5 위급 상황 UI

- 위급 경보는 **색 + 형태 + 문구** 세 가지로 동시에 표현한다.
- 위급 화면에서 **확인 절차를 늘리지 않는다.** 대신 사후 기록을 남긴다(§6.2).
- 코드블루·응급 전환은 **되돌릴 수 있어야** 한다(오발동은 반드시 일어난다).

### 4.6-a 🔴 대상을 잘못 잡고 있었다 (2026-08-20 재실측)

- 폰트 크기는 병원 정책으로 **일괄 조정 가능**해야 한다(`ui.*` 확장 후보).

- 인쇄 시도(차단 포함)는 감사 대상이다.

## 5. 경보·알림 UX — 예산이 있는 자원

**알림은 무한하지 않다. 읽히는 총량이 예산이다**(실측 읽음률 8.6%).

### 5.1 경보의 3요소

모든 경보는 이 셋을 **한 화면 안에서** 답해야 한다.

1. **무엇이** 문제인가 (환자·값·시각)
2. **왜** 지금 뜨는가 (규칙·임계·근거 데이터로 이동)
3. **무엇을 하면 꺼지는가** (embedded action — 화면 이동 없이 처리 가능해야)

> 🔴 3번이 없는 경보는 만들지 않는다. 감시자가 **보되 고치지 못하는** 화면은 무력감만 만든다.

### 5.2 사라지는 알림이 아니라 줄어드는 목록

- 토스트·푸시는 **알림이지 작업 목록이 아니다.** 놓치면 끝나는 것을 유일 경로로 두지 않는다.
- 잔여 작업은 **줄어드는 목록**으로 존재해야 한다(미확인 위급값·미서명 차트·미이행 중재).

### 5.3 억제와 예산

- 같은 대상·유형은 **N시간 내 재발송 억제**(이미 `dedupWithinHours` 규약 존재).
- 새 경보를 추가할 때는 **무엇을 끌지 함께 제안한다**(One-in-One-out).
- 경보별로 **override율·확인 소요시간**을 재고, 임계 미달이면 자동 강등을 검토한다.

### 5.4 라우팅

- 경보는 **역할로** 간다. 전량 주치의 직행은 주치의를 무디게 만든다(약사·RRT·전담간호사 우선순위).
- 통보 대상이 없으면 **그 사실 자체가 경보다**(실측: EWS 통보 대상 부재를 아무도 몰랐다).

## 6. 안전 개입 UX — 막을 것인가, 기록할 것인가

### 6.1 3상 게이트의 화면 규약

| 모드 | 화면 | 원칙 |
|---|---|---|
| `OFF` | 아무것도 하지 않는다 | 켜져 있다고 표시하지 않는다 |
| `WARN` | 경고 + **사유 입력** + 진행 가능 | 사유는 선택지가 아니라 서술 |
| `BLOCK` | 차단 + **대안 경로 제시** | 대안 없는 차단은 우회를 만든다 |

- 게이트 상태는 **관제 화면에서 실측 위반 건수와 함께** 보여야 승격 판단이 된다.
- 🔴 override 모달은 서버 payload 를 받아야 그린다 — 예외 필터가 payload 를 버리면 죽은 코드가 된다(실측 54개소).

### 6.2 막으면 방치된다

봉쇄는 더 나쁜 우회를 만든다(계정 공유·위급값 방치). **기본은 기록과 가시화다.**

- 권한이 없어도 **확인 자체는 막지 않는다** — 대신 누가 했는지 남기고 목록에 띄운다.
- 이중확인 우회는 차단이 아니라 **`[BYPASS]` 표식 + 사유 + 집계**로 다룬다.

### 6.3 필수로 강제하면 거짓 데이터가 된다

- 전 술식 laterality 필수 → 아무 값이나 골라 통과 → **원장이 거짓이 되고 진짜 좌우 경보가 죽는다.**
- 강제 대신: **해당하는 경우에만 요구**하고, 미기재를 **미기재로 보이게** 한다.
- 🔴 **숨기는 방향으로는 자동이 없다.** 사람이 확인해야 하는 것을 시스템이 대신 "일치" 처리하지 않는다.

### 6.4 이중확인·복창 UI

- 복창·이중확인 체크는 **기본값을 참으로 두지 않는다.** 미확인이 미확인으로 남아야 지표의 분모가 산다.
- 체크박스 옆에 **"확인하지 않았다면 체크하지 마세요 — 그대로 기록됩니다"**를 명시한다.

## 7. 에이전트와의 관계 UX ★

> 이 절이 이 문서의 신설 핵심이다. 규제·스코프 판단은 `agent-emr-alignment.plan.md` 가 정본이고,
> 여기서는 **화면이 에이전트를 어떻게 다루는가**만 정한다.

### 7.1 전제 — AI 는 사용자가 아니라 도구이자 기록 주체

- AI 는 **책임 주체가 될 수 없다.** 모든 임상 결정의 서명은 사람이다.
- 그러나 AI 는 **기록을 만든다.** 따라서 AI 가 만든 것은 **누가·언제·무엇으로 만들었는지** 남아야 한다.

### 7.1-b 🔴 실측 — AI 지점 81곳 중 **자동실행인데 그렇게 안 보이는 곳이 6곳**

2026-08-19 전수 검토(AI/에이전트/음성 EP 호출 FE 파일 66 + 서버 산출물 렌더 15 = **81지점**, 그중 72 열람).

| 자동실행인데 화면이 안 밝히는 곳 | 무엇이 일어나는가 |
|---|---|
| 🔴 **공개 예약 챗** `agent-session` | **무인증**으로 MRN 한 줄에 알레르기·문제목록·최근 진료를 반환하고 예약 취소·환자 생성까지 (§C1) |
| AI 퇴원요약 | 생성 즉시 원장에 `POST` — 미리보기 0. **같은 기능의 다른 화면은 폼에 채우고 사람이 저장**(모드가 화면마다 다르다) |
| 코드 자동매핑 · 약가 HIGH 자동확정 | `autoConfirm` 기본 `true` · 확인창 없음 · 청구액 직결 · 롤백 UI 없음 |
| 음성 구술(DICTATE) | 확인 카드를 우회해 SOAP `S` 를 **치환**. 의문문·미분류가 DICTATE 로 폴백 |
| 음성 활력 | 버튼 라벨은 `확정 → 초안` 인데 실제로는 **정본 `vitals.record()`** · 취소 창 없음 |
| 포털·모바일 환자 AI 6종 | 생성 즉시 환자에게 표시(검토 단계 없음) |

**규칙**: 관계 모드는 **행위가 아니라 화면이 밝힌다.** 같은 행위가 화면마다 다른 모드면 그것이 결함이다.

### 7.2 다섯 가지 관계 모드 — 화면은 모드를 숨기지 않는다

| 모드 | 뜻 | 화면 규약 |
|---|---|---|
| **감시(Monitor)** | 사람이 놓친 것을 찾아 띄운다 | 경보 3요소(§5.1) 그대로 적용 |
| **보조(Suggest)** | 후보를 제안한다 | 사람이 고르기 전에는 **아무것도 입력되지 않는다** |
| **초안(Draft)** | 문서를 미리 쓴다 | **초안 표식 유지** · 서명 전까지 법정기록 아님(§7.6) |
| **실행제안(Propose)** | 실행 가능한 행위를 만든다 | 실행 버튼은 **사람의 것** · 미리보기 필수 |
| **자동실행(Auto)** | 사람 개입 없이 실행 | 🔴 기본 금지. 켤 때는 config 게이트 + 감사 + **되돌리기** |

- 🔴 실측 교훈: `aiMode` 기본값이 `AUTO` 라 **환자에게 AI 답변이 자동 전송**되고 있었다.
  자동실행은 **명시적으로 켠 것만** 자동이어야 한다.

### 7.3 자율성 등급과 화면 표현

`L0(제안만) → L1(사람 승인 후 실행) → L2 → L3(자율)`

- 화면은 **현재 등급을 항상 보이게** 한다. 등급이 바뀌면 UI 도 바뀌어야 한다.
  → 선례는 이미 있다: `<CapabilityBadge mode reason>` 이 **사용자**의 쓰기 권한을 사유와 함께 표시한다.
    에이전트 자율성도 같은 형태로 낸다(새 부품을 만들기 전에 이 패턴을 확장한다).
- L2 이상은 **사후 통지 목록**(§5.2 줄어드는 목록)이 반드시 있어야 한다.
- 🔴 **에이전트 권한 ⊆ 사용자 권한.** 사용자가 볼 수 없는 환자를 AI 가 요약해 주면 안 된다.
  (권한 검사는 AI 호출 **뒤**가 아니라 **앞**에서 한다.)

### 7.4 표기 — 무엇이 AI 산출물인지 언제나 보인다

- AI 가 만든 텍스트·값은 **시각적으로 구분**한다(배지·좌측 띠·배경). 본문에 섞어 넣지 않는다.
- 면책 문구는 **생성 지점마다** 동봉한다(`ai.disclaimer` 정본).

### 7.4-b 표기 실측 — "AI"라는 단어가 화면에 거의 없다

AI EP 를 부르는 `.tsx` **35개 중 사용자에게 "AI"가 보이는 곳 5개.** 나머지는 "WeRU.B"·"자동분석"·"진료 보조".
**"인공지능"은 전 프론트엔드에 단 1파일**(`DrugExplainSheet` — 「AI기본법」 명시).
🔴 그리고 이것이 **의도된 설계로 문서에 남아 있다**(`f7-pharmacy-review`: "'WeRU.B' 브랜드(**AI 단독 라벨 금지**)").
→ §7.4 의 사람 게이트가 정확히 여기를 조준한다. 결정 전까지 **신규 화면은 병기**한다.

🔴 부수: 앱마다 표기가 **정반대**다 — 포털은 "WeRU.B" 단독 30여 곳, 모바일은 "AI" 단독 20여 곳,
공개 사이트는 "AI". **같은 환자가 앱을 바꾸면 다른 이름을 본다.**

### 7.5 출처 앵커링 — 근거로 되짚을 수 없으면 표시하지 않는다

- AI 문장은 **어느 기록에서 나왔는지** 클릭으로 이동 가능해야 한다(`citations` 패턴 — 간호 SOAP 초안이 선례).
- 🔴 **근거가 없으면 만들지 않는다.** 실측: 빈 영상 URL·`'pending'` 검사값·진료 횟수로 만든 건강점수 —
  **보지 않은 것을 판독한** 사례 10곳이 있었고 그중 일부는 폐지됐다.
- AI 가 모르면 **"산출 불가"**라고 말한다. §2.1 의 규칙은 AI 에도 그대로 적용된다.

### 7.5-b 🔴 출처는 **3상태**다 — `AI` / `FALLBACK`(불렀으나 실패) / `UNAVAILABLE`(원자료가 없어 부르지 않음)

정본이 이미 있다(`medical-ai/ai-grounding.ts` — reasonCode 4종). 서버는 **17곳**에서 이 3상태를 배출하는데
**FE 소비는 3곳뿐**이고, 공용 부품 `AiSuggestionPanel` 은 `UNAVAILABLE` 을 **모른다**(배지 없이 원시 덤프).

🔴 그리고 근거 게이트가 **프롬프트 조립 층에서 뒤집힌다**: `알레르기: … || '없음'` (약물 추천 프롬프트 포함).
FE 는 NKA 3상태(미문진/없음/확인불가)를 지키는데 **AI 에게는 "없음"이라고 말한다.**

**규칙**: AI 에 넣는 "없음"도 **세 가지를 구분**한다 — `없음(확인됨)` / `미문진` / `조회 실패`.
공용 AI 부품 계약에 `UNAVAILABLE` 을 1급으로 넣고, 없으면 "산출 불가 + 사유"로 그린다.
→ **✅ 적용(2026-08-19 저녁)**: BE `ai-grounding.ts` 에 `promptList`/`allergyPromptLine`(NKA 정본 `AllergyService.getStatus` 경유·미주입/실패=
"조회 불가") — 프롬프트 층 `|| '없음'` **26 → 0**(mobile 클라 프롬프트 포함) · `AiSuggestionPanel` 이 `UNAVAILABLE`(사유 문장·JSON 덤프 금지·
적용 버튼 없음)·`FALLBACK`("데이터 부족" 아니라 "AI 미응답·규칙 대체")·`error`(침묵 금지)를 다르게 그린다.
가드: `api/test/medical-ai/ai-prompt-three-state-guard.spec.ts`(실제 나간 프롬프트 검사·구조 0건) · `web/test/ui/ai-suggestion-panel-source-contract.spec.tsx`.

### 7.6 초안 ≠ 확정 (draft ≠ commit)

- 에이전트 산출물은 **초안 저장소**에 들어간다. 사람이 서명해야 법정기록이 된다.
- 화면은 그 경계를 **시각적으로** 표시한다(초안 배경·"서명 전" 배지·서명 버튼 분리).
- 🔴 자동 저장을 자동 서명으로 읽히게 만들지 않는다.

### 7.6-b 🔴 초안을 **폼에 넣는 순간 표식이 사라진다**

패널 안에서는 "AI 제안"으로 구분되지만, 적용 후에는 사람이 쓴 글자와 동일해진다
(진료 AI 보조 · 스크라이브 · 앰비언트 · 퇴원요약 · VoC 답변). 퇴원요약은 저장 후 화면이 `작성: {의사명}` 이라 말한다.

**규칙**: 적용 시 **프로비넌스를 함께 옮긴다.** 정본 선례가 이미 있다 —
간호 AI 초안(`aiAssisted`·`aiModel`·`aiPromptVersion`·`aiEditDistance` + HMAC 스푸핑 차단).
🔴 그런데 `Encounter.aiScribed`/`aiEditDistance` 는 **스크라이브 전용**이라 진료 AI 보조로 적용한 것은 흔적이 없다.
→ **✅ 1차 적용(2026-08-19 저녁)**: 공용 부품 `components/ai/DraftBanner.tsx`(`<DraftBanner provenance signLabel>` —
"AI(WeRU.B) ○○ 초안 적용됨 — 서명 전 · 확정 아님" + 감사 기록 여부를 **정직하게**(recorded true/false/null))
+ `POST /api/v1/ai/draft-applied`(스키마 필드가 없는 자원의 프로비넌스를 **감사 원장** `AiDraftApply` 로 — 환자 모르면 ZERO_UUID).
적용 5화면: 진료 AI 보조·스크라이브→SOAP(encounter/new) · 자동 퇴원요약 2화면 · VoC 답변(`VocMessage.aiDraft` 로 전송·스레드 "AI 초안 기반" 배지) ·
동의서 위험·대안·설명. 가드 `web/test/ui/draft-banner.spec.tsx`(적용 지점 목록)·`api/test/medical-ai/ai-draft-provenance.spec.ts`.
**잔여(스키마·사람 게이트)**: Encounter 프로비넌스 일반화(`aiAssistSource`·`aiDraftSnapshot`·`aiEditDistance` 를 스크라이브 외로) ·
DischargeSummary/Consent 에 `aiAssisted` — 승인 전까지 감사 원장이 유일한 흔적이다(§11).

### 7.7 사람이 얼마나 고쳤는가 (human_edit_ratio)

- AI 초안이 **그대로 서명되는 비율**을 잰다. 100% 무수정 승인은 도구가 아니라 자동실행이다.
- 이 지표는 관리 화면에 **분모와 함께** 낸다(§2.1).

### 7.8 되돌리기와 취소 창

- 에이전트가 만든 행위는 **되돌릴 수 있어야** 한다. 되돌릴 수 없으면 L1(사람 승인) 아래로 내린다.
- 자동 전송·자동 게시처럼 외부로 나가는 행위는 **취소 창(delay window)**을 둔다.

### 7.9 대기 시간

- 3초 이상 걸리는 생성은 **부분 결과 스트리밍**을 기본으로 한다.
- 실패·타임아웃은 **실패라고 말한다.** 조용히 빈 결과를 그리지 않는다(§2.1 조회 실패).
- 🔴 접힌 패널이 열리지 않았는데 AI 를 호출하지 않는다(실측 함정 — 비용·부하·감사 소음).

### 7.10 환자 대면 에이전트

- 환자에게 나가는 AI 답변은 **기본 SUGGEST**(직원 검토 후 발송).
- AUTO 로 내리는 결정은 운영·상담 정책의 몫이며, 화면은 **현재 모드를 환자에게도 밝힌다.**
- 의료 판단으로 읽힐 수 있는 문장은 **연락 경로**를 항상 함께 낸다.

## 10-c. 🔴 `queryFn` 침묵 폴백 회수 결과와 남은 것 (2026-08-20)

### 실측
| 시점 | `queryFn` 안 `.catch` | 가드 지표(`clinical-ux-rules`) |
|---|---:|---:|
| 착수 전 | **384** (146파일 · **재throw 0 = 전부 삼킴**) | 503 |
| 1차(에러 UI 가 이미 있던 것만) | 346 | 465 |
| 2차(에러 표시를 만들고 뗀 것) | **13** | **146** |

회수 방식은 **순서가 규약**이다 — **에러 표시를 먼저 만들고 `.catch` 를 뗀다.**
반대로 하면 실패가 조용해지고, `!data` 로 로딩을 판정하는 화면은 **영구 로딩**이 된다.

🔴 **가드 지표는 "거짓말 개수"가 아니라 "패턴 개수"다.** 남은 13 은 대부분 정당하다 —
진짜 폴백 체인(receipt 실패 시 billing 원본) · 404 만 접고 나머지는 재throw 하는 것
(`OpNotePanel` — 통째로 떼면 "아직 안 씀"이 거짓 경보가 된다) · 렌더 표면이 없는 config 훅.
**0 을 목표로 삼지 않는다.**

### 이 축에서 드러난 대표 거짓말 (봉합 완료)
- 포털 접수동의서: 조회 실패가 `requiredComplete=false` 로 접혀 **이미 서명한 환자에게
  "필수 N건 미동의" 재서명 요구**. 부수로 `cert/my` 실패를 "인증서 없음"으로 읽어
  **블록체인 인증서를 자동 재발급**하던 `useEffect` 도 함께 막았다
- 입원 중간정산: 실패 시 합계가 `0원` → **미수납이 0원으로** 보였다
- 위급검사값 배너: `if (!alerts.length) return null` 이라 서버가 죽으면 **배너가 조용히 사라졌다**
- 인수인계 패널: 실패가 `✅ 미확인 인계가 없습니다` 초록 체크로 보였다
- `/admin/er-beds` 설정 카드: 실패 시 boolean 을 **"ON (분리)"**, 게이트를 **"WARN"** 으로 단정
  (안전 게이트 관리 화면이 모르는 상태를 특정 모드로 말했다) → 키별 실패 표시 + 편집 차단
- 치료 캘린더: 하루치 실패가 **"예약 없음"** → 날짜별 표시 + 집계에 `N일 제외`
