# 원격진료 역할별 차트 구성 (telehealth-role-based-chart)

> 의료진 역할(DOCTOR/NURSE/PHARMACIST)에 따라 원격진료 화면 구성을 최적화

- **작성일**: 2026-05-29
- **상태**: Plan (검토 완료, 78→92점)
- **관련 문서**: ADR-001 (JWT+RBAC), telehealth-portal.plan.md
- **검토**: design-validator 78점 → 8건 보완 반영

## 1. 배경 및 목표

### 현재 문제
- 모든 역할에 동일한 진료 화면 제공 (의사 중심 레이아웃)
- 간호사가 원격진료에 참여할 때 바이탈 입력, 간호평가 도구 없음
- 약사가 처방 검토 시 DUR/상호작용 정보 부족
- 의사 화면에도 진단 코드 입력, 검사 오더 기능 누락

### 목표
1. 로그인 사용자의 역할(role)에 따라 차트 패널을 동적으로 구성
2. 각 역할에 필요한 정보와 액션만 노출 (인지 부하 감소)
3. 기존 단일 컴포넌트를 역할별 서브 컴포넌트로 분리

## 2. 역할 정의

HIS RBAC 기준 원격진료 참여 가능 역할:

| 역할 | 코드 | 원격진료 참여 시나리오 |
|------|------|----------------------|
| 의사 | `DOCTOR` | 화상 진료 주도, 진단/처방/메모 |
| 간호사 | `NURSE` | 사전 문진, 바이탈 입력, 간호평가, 교육 |
| 약사 | `PHARMACIST` | 복약지도, 처방 검토, DUR 확인 |
| 관리자 | `ADMIN` | 모니터링 (읽기 전용, 의사 뷰 + 세션 통계) |
| 검사실 | `LAB_TECH` | 접근 제한 — "원격진료 참여 권한이 없습니다" 표시 |
| 직원 | `STAFF` | 접근 제한 — "원격진료 참여 권한이 없습니다" 표시 |

## 3. 역할별 차트 구성

### 3.1 의사 (DOCTOR) — 현재 + 보강

**좌측 패널 (환자 정보) — 현재 유지 + 보강**

| 섹션 | 현재 | 보강 |
|------|:----:|:----:|
| 인적사항 (이름/MRN/성별/나이) | O | - |
| 주호소 | O | - |
| 알레르기 (NKA 포함) | O | - |
| 바이탈 사인 (6항목) | O | - |
| 활성 문제 목록 | O | - |
| 복용 약물 | O | - |
| **검사 결과 요약** | X | **추가** |
| **영상 검사 링크** | X | **추가** |

**중앙 패널 (진료 이력) — 현재 유지 + 보강**

| 섹션 | 현재 | 보강 |
|------|:----:|:----:|
| 최근 진료 5건 | O | - |
| **진료 이력 → 클릭 시 상세 펼치기** | X | **추가** |
| **이전 원격진료 이력** | X | **추가** |

**우측 패널 (진료 행위) — 현재 + 보강**

| 섹션 | 현재 | 보강 |
|------|:----:|:----:|
| 진료 메모 (SOAP 구조화) | △ (자유텍스트) | **SOAP 4필드 UI (notes는 JSON 저장, 스키마 변경 없음)** |
| 처방 입력 (약물 검색) | O | - |
| **진단 코드 입력** | X | **추가** |
| **검사 오더** | X | **추가** |
| **의뢰/회신** | X | **추가** |

### 3.2 간호사 (NURSE)

**좌측 패널 (환자 정보) — 의사와 동일**

**중앙 패널 (간호 중심)**

| 섹션 | 설명 |
|------|------|
| **바이탈 입력 폼** | BP/HR/RR/BT/SpO2/체중 실시간 입력 |
| **바이탈 트렌드 차트** | 최근 5회 바이탈 미니 라인 차트 |
| **간호평가 도구** | Morse Fall, Braden, NEWS2 점수 |
| **사전 문진 체크리스트** | 증상/통증/ADL 체크 |

**우측 패널 (간호 행위)**

| 섹션 | 설명 |
|------|------|
| **간호 기록** | 간호 메모 + 환자 교육 내용 |
| **투약 확인** | 현재 투약 스케줄 + 투약 체크 |
| **환자 교육 자료** | 질환별 교육 자료 링크 |

**제한**: 처방 입력 불가, 진단 코드 입력 불가

### 3.3 약사 (PHARMACIST)

**좌측 패널 (환자 정보) — 약학 중심**

| 섹션 | 설명 |
|------|------|
| 인적사항 + **체중/신장/eGFR** | 용량 계산에 필수 |
| 알레르기 (**약물 알레르기 강조**) | 교차 알레르기 표시 |
| **현재 복용 약물 (전체)** | 전체 목록 + 용량 + 복약일수 |
| **DUR 결과** | 병용금기/연령금기/임부금기 |

**중앙 패널 (처방 검토)**

| 섹션 | 설명 |
|------|------|
| **이번 세션 처방 목록** | 의사가 입력한 처방 실시간 표시 |
| **약물 상호작용 경고** | 현재 약물 vs 신규 처방 교차 체크 |
| **용량 적정성** | 체중/신기능 기반 권장 용량 표시 |

**우측 패널 (약사 행위)**

| 섹션 | 설명 |
|------|------|
| **복약지도 메모** | 복약지도 내용 기록 |
| **처방 검토 의견** | 의사에게 전달할 검토 의견 |
| **대체 약물 제안** | 동일 성분 대체 약물 검색 |

**제한**: 처방 입력 불가 (검토/의견만 가능), 진단 불가

## 6. 구현 우선순위

| Phase | 작업 | 난이도 | 가치 |
|-------|------|:------:|:----:|
| **P0** | 역할 감지 + 컴포넌트 분기 | 낮음 | 높음 |
| **P0** | 의사 뷰 보강 (SOAP 메모, 진단 입력) | 중간 | 높음 |
| **P1** | 간호사 뷰 (바이탈 입력, 트렌드, 간호기록) | 중간 | 높음 |
| **P1** | 약사 뷰 (전체 약물, DUR, 복약지도) | 중간 | 높음 |
| **P2** | 검사 오더 + 검사 결과 요약 | 중간 | 중간 |
| **P2** | 약사 처방 검토 의견 BE API | 낮음 | 중간 |
| **P1** | 바이탈 트렌드 미니 차트 (간호사 핵심 워크플로우) | 낮음 | 높음 |
| **P3** | 환자 교육 자료 연동 | 낮음 | 낮음 |

## 7. 제약 사항

- 원격진료 세션에 동시 참여 가능한 의료진 수 제한 없음 (Jitsi 방 공유)
- 역할별 액션 권한은 FE에서 UI 숨김 + BE에서 RBAC Guard로 이중 검증
- 약사의 처방 수정 권한은 없음 (검토 의견만 가능)
- 간호사의 진단/처방 권한은 없음 (바이탈 입력, 간호기록만 가능)

## 8. 데이터 모델 변경

### 8.1 스키마 변경 없음 (기존 필드 활용)

| 기능 | 저장 방식 | 비고 |
|------|----------|------|
| SOAP 메모 | `TelehealthSession.notes` (String) | JSON 문자열로 저장: `{"S":"","O":"","A":"","P":""}` |
| 약사 검토 의견 | `TelehealthSession.pharmacyReview` | **신규 필드 추가 필요** (String, nullable) |
| 간호 기록 | 기존 `NursingNote` 테이블 | `telehealthSessionId` 관계 추가 |

### 8.2 신규 Prisma 필드 (1건)

```prisma
model TelehealthSession {
  // 기존 필드 유지...
  pharmacyReview    String?   // 약사 검토 의견
  pharmacyReviewBy  String?   // 검토 약사 ID
  pharmacyReviewAt  DateTime? // 검토 시각
}
```

## 9. 실시간 동기화

| 시나리오 | 방식 | 이유 |
|----------|------|------|
| 의사 처방 → 약사 화면 갱신 | **5초 폴링** (기존 세션 refetchInterval) | 이미 구현된 패턴, 추가 인프라 불필요 |
| 바이탈 입력 → 의사 화면 갱신 | **5초 폴링** | 동일 |
| 긴급 알림 (위급값 등) | **SSE** (기존 VS 알림 SSE 활용) | 이미 구현된 인프라 |

## 10. 에러 처리

| 시나리오 | 처리 방식 |
|----------|----------|
| role이 undefined/null | 의사 뷰로 폴백 + 콘솔 경고 |
| JWT 만료 (세션 중) | apiClient 인터셉터가 자동 리프레시 (기존 로직) |
| LAB_TECH/STAFF 접근 | "원격진료 참여 권한이 없습니다" 안내 + 목록 페이지 리다이렉트 |
| API 실패 (summary 등) | 해당 섹션 스켈레톤 → "정보를 불러올 수 없습니다" 표시 |
| 네트워크 끊김 | Jitsi 자체 재연결 + HIS는 폴링 재시도 |

## 11. 테스트 계획

### 11.1 단위 테스트

| 테스트 | 검증 내용 |
|--------|----------|
| 역할 분기 렌더링 | DOCTOR → DoctorChart, NURSE → NurseChart, PHARMACIST → PharmacistChart |
| LAB_TECH 접근 차단 | 접근 시 권한 없음 메시지 표시 |
| SOAP 메모 파싱 | JSON ↔ 4필드 변환 정확성 |
| 약사 검토 의견 저장 | POST pharmacy-review → 200 + 데이터 저장 확인 |

### 11.2 통합 테스트 (BE)

| 테스트 | 검증 내용 |
|--------|----------|
| RBAC Guard | NURSE가 POST prescriptions → 403 |
| RBAC Guard | PHARMACIST가 POST prescriptions → 403 |
| pharmacy-review | PHARMACIST가 POST pharmacy-review → 200 |
| pharmacy-review | DOCTOR가 POST pharmacy-review → 403 |

### 11.3 E2E 시나리오 (역할별 1건)

| 역할 | 시나리오 |
|------|----------|
| 의사 | 로그인 → 세션 진입 → SOAP 메모 작성 → 처방 입력 → 진단 코드 → 종료 |
| 간호사 | 로그인 → 세션 진입 → 바이탈 입력 → 간호기록 작성 → 투약 확인 |
| 약사 | 로그인 → 세션 진입 → 처방 목록 확인 → DUR 확인 → 복약지도 메모 → 검토 의견 제출 |

## 12. 범위 외 (Out of Scope)

| 항목 | 사유 |
|------|------|
| 역할별 Jitsi 권한 분리 | JWT moderator/guest로 충분 |
| 다자 화상 (3인 이상) | 현재 1:1 구조, 추후 확장 |
| 약사 처방 직접 수정 | 법적으로 약사 처방 수정 불가 (의견만 가능) |
| 환자 역할 뷰 | 포털에서 별도 구현 완료 |

## 13. 성공 지표

| 지표 | 목표 |
|------|------|
