## 1. 현황

### 현재 구현
- 증상 → 진료과 추천 (키워드 매칭 + AI 오케스트레이터)
- 인사/잡담 감지 → 간단 응답
- 건강검진/원격진료 의도 → 전용 흐름 분기
- 직접 예약("내과 예약해줘") → 즉시 확인

### 부족한 부분
| # | 유형 | 예시 | 현재 |
|---|------|------|------|
| 1 | **병원 정보 질문** | "진료과는?", "진료시간?" | ~~미처리~~ → **이번 커밋에서 수정** |
| 2 | **의사 정보 질문** | "내과 의사 누구?", "김 선생님 진료일?" | 부분 (CONFIRMING에서만) |

## 2. 개선 방향: RAG vs 규칙 기반

### RAG가 필요 없는 이유
| 질문 유형 | 데이터 출처 | RAG 필요? |
|---------|-----------|:---------:|
| 진료과/의사/시간 | DB (User, ClinicSchedule) | ❌ |
| 예약 현황 | DB (WaitingQueue, Appointment) | ❌ |
| 진료비 | DB (config-runtime, BillingCode) | ❌ |
| 증상→진료과 | 이미 오케스트레이터가 처리 | ❌ |
| 약 정보 | DB (MedicationCode) + DUR | ❌ |
| 병원 위치/주차 | config-runtime | ❌ |

**결론**: 현재 DB에 모든 정보가 있으므로 **규칙 기반 + DB 조회**로 충분합니다. RAG는 외부 의학 지식이 필요할 때(예: "이 증상이 암인가요?")만 필요하며, 그것은 의료 AI 영역(별도 프로젝트)입니다.

## 3. COLLECTING_SYMPTOMS 상태 대화 확장

### 3.1 의사 정보 질문

```
패턴: /의사|선생님|누구|담당|전문의/
처리:
  - "내과 의사 누구?" → User WHERE department='내과' AND role='DOCTOR'
  - "김 선생님 진료일?" → User WHERE familyName='김' → ClinicSchedule 조회
  - 결과 + 퀵 리플라이 (해당 의사로 예약)
```

### 3.2 예약 상태 질문

```
패턴: /내 예약|예약 확인|다음 예약|예약.*있/
처리:
  - ctx.patient.id로 WaitingQueue/Appointment 조회
  - 예약 없으면 → "예약이 없습니다. 예약하시겠어요?"
  - 예약 있으면 → 날짜/시간/진료과/의사 표시
```

### 3.3 진료비 질문

```
패턴: /비용|가격|얼마|진료비|수가|초진|재진/
처리:
  - 일반 외래: "초진 약 15,000~20,000원, 재진 약 8,000~12,000원 (보험 적용 시)"
  - 검사 별도: "검사 비용은 항목에 따라 다릅니다"
  - config-runtime에서 copayRate 활용
```

### 3.4 증상 후속 질문

```
패턴: /검사|MRI|CT|초음파|내시경|어떤.*해야|뭘 해야/
처리:
  - 이전 증상 컨텍스트 참조 (ctx.reception.reason)
  - "두통 → MRI, CT 등 정밀 검사가 필요할 수 있습니다. 진료과 예약 후 의사 상담을 권장합니다."
  - 단, 의학적 진단/판단은 피하고 "의사 상담을 권장합니다" 안전 문구
```

### 3.5 약 관련 질문

```
패턴: /약|타이레놀|진통제|항생제|부작용|복용/
처리:
  - DB MedicationCode 검색 (약품명)
  - 기본 정보만 제공 (성분, 용법)
  - "약물 상담은 약사 또는 담당의에게 문의해주세요" 안전 문구
```

### 3.6 병원 서비스 질문

```
패턴: /입원|응급|수술|건강검진|주사|물리치료|재활|검진|투석/
처리:
  - 입원: "입원이 필요하시면 외래 진료 후 담당의 판단으로 진행됩니다."
  - 응급: "응급실은 24시간 운영됩니다. 위치: 1층"
  - 물리치료: "재활의학과에서 진행합니다."
  - 해당 진료과 예약으로 안내
```

### 3.7 맥락 유지 (대화 히스토리 활용)

```
현재: ctx.reception에 마지막 증상만 저장
개선:
  - msgs 배열에서 최근 3-5개 대화 참조
  - "그 의사 선생님으로 예약해줘" → 이전 의사 정보 참조
  - "아까 말한 증상에 추가로..." → ctx.reception.reason에 병합
```

## 4. 안전 가드레일

```
금지 응답 패턴:
  - "~입니다" (진단)
  - "~을 드세요" (처방)
  - "~하면 됩니다" (치료법)

필수 안전 문구:
  - "정확한 진단은 의사 진료가 필요합니다."
  - "약물 관련 질문은 약사에게 문의해주세요."
  - "응급 상황 시 119에 연락해주세요."

응급 키워드 감지:
  /가슴.*통증|숨.*못.*쉬|의식.*잃|출혈|골절|화상|경련|자살|자해/
  → "⚠ 응급 상황으로 판단됩니다. 119에 즉시 연락하시거나, 가까운 응급실을 방문해주세요."
```

## 6. Out of Scope

| 항목 | 사유 |
|------|------|
| RAG/벡터DB | DB 데이터로 충분, 의학 지식은 별도 |
| LLM 직접 호출 | 현재 규칙 기반 + 오케스트레이터로 충분 |
| 의학적 진단/처방 | 법적 제한, 의사만 가능 |
| 자연어 이해(NLU) | 현재 키워드+정규식으로 충분한 수준 |
