> 작성: 2026-07-06 / 상태: Plan v1.2 (구현 전 — 부모 v1.4 임상안전 검토 반영: 팝아웃에 환자식별 헤더(P-2·IPSG-1) 필수화)
> 부모 문서: [`patient-chart-large-screen-view.plan.md`](./patient-chart-large-screen-view.plan.md) (v1.4) — 본 문서는 그 **P2 단계를 항목별로 상세화**한 후속 기획. 부모 **§2.5 임상 안전·인지 원칙**(안전정보 비제거·환자식별 편재·신선도·오독방지)은 P2 전 항목에 상속. P0(멀티패널 토글)·P1(레이아웃 편집·개인 저장)·P1.5(서버 동기화)가 선행 완료됨을 전제.

## 1. ① 드래그 재배치 (패널 순서·배치)

### 현황·근거
P1 편집기는 `moveUp/moveDown` 버튼으로 순서 변경(`TabSettingsModal` 패턴). 넓은 2D 그리드에서는 버튼 이동이 비효율 → 직접 드래그가 자연스럽다. 원내 **`DashboardShell`이 동일 요구를 이미 해결**(위젯 그리드 드래그).

### 설계
- 편집 모드(`isEditing`)에서만 드래그 활성 — `useSortable({ id, disabled: !isEditing })`(DashboardShell과 동일 가드) → 평소 오조작 방지.
- `DndContext`(sensors=Pointer/Keyboard, `collisionDetection=closestCenter`) + `SortableContext`(`rectSortingStrategy` — 2D 그리드용, DashboardShell과 동일).
- `onDragEnd` → `arrayMove(panelKeys, from, to)` → `boardLayout.order` 갱신 → 저장(P1 지속 경로 재사용).
- **키보드 접근성**: dnd-kit `KeyboardSensor`로 드래그를 키보드로도 수행(접근성 필수).
- 폭(span) 조절: 드래그와 별개로 패널 우상단 `⇔`(1칸↔2칸) 토글 유지(드래그는 순서만).

### 재사용/비파괴
- P1의 `moveUp/moveDown`은 **폴백으로 유지**(키보드·저사양). 드래그는 상위 UX.
- 저장 스키마 불변(`order` 배열만 재정렬).

### 리스크
- 독립 스크롤 패널(부모 §3.3) 내부 스크롤과 드래그 제스처 충돌 → 드래그 핸들을 **패널 제목바로 한정**(본문 스크롤과 분리, DashboardShell 방식).

## 2. ② 명명된 다중 레이아웃 (상황별 전환)

### 현황·근거
P1.5는 **사용자당 단일 레이아웃**. 실제 워크플로우는 상황별로 다르다(회진=바이탈·투약·간호기록 / 외래=검사·처방·문제 / 입원=오더·I/O·경과). 부모 §10-7에서 "필요성 확인"으로 남긴 항목 → P2에서 상세.

### 설계
- 데이터: `boardLayout`(단일 객체) → `boardLayouts: { id, name, order, spans, columns, density }[]` + `activeLayoutId`.
- UI: board 상단에 **레이아웃 셀렉터**(칩/드롭다운) — "회진용 ▾" 클릭으로 즉시 전환. `+ 새 레이아웃`·`이름 변경`·`복제`·`삭제`.
- 기본 제공 프리셋(관리자 템플릿, P1.5 폴백 재사용): 과별 "회진/외래/입원" 시드 → 개인이 복제·수정.
- 저장: P1.5 서버 config의 배열화(스키마 (b)/(c) 중 택1, JSON 내부 구조라 컬럼 변경 불요).

### 리스크·완화
- **과설계 우려**(부모에서 지적): 대부분 사용자는 1개로 충분 → **단일 레이아웃이 기본, 다중은 opt-in**. 셀렉터는 레이아웃이 2개 이상일 때만 노출(1개면 숨김) → 단순 사용자 UX 불변.

## 3. ③ 패널별 새로고침 & 자동 갱신

### 현황·근거
board는 다수 패널이 캐시된 데이터를 표시(부모 §6 staleTime 차등). 실시간성 필요 장면(응급·중환자 회진)에서 전체 새로고침 없이 **개별 패널만 즉시 갱신**하고 싶다.

### 설계
- 패널 제목바에 `↻` 버튼 → 해당 패널 `queryClient.invalidateQueries({ queryKey })`(전역 react-query 채택 패턴) → 그 패널만 리페치.
- **자동 갱신 옵션**(패널별): 바이탈·오더 등 실시간 패널에 `refetchInterval` 토글(예: 30·60s). 기존 command-center가 `refetchInterval: 30000` 사용(`command-center/page.tsx:57`) — 동일 패턴.
- 전체 새로고침: board 상단 `전체 ↻`(모든 활성 패널 invalidate).
- 마지막 갱신 시각 표시(`FreshnessBadge` 공용 컴포넌트 재사용 — 원내 존재, 🟢🟡🔴 stale 색).

### 리스크
- 자동 갱신 다패널 동시 폴링 → 부모 §6 동시성 재발. **자동 갱신은 기본 off**, 실시간 패널만 사용자가 켬 + 폴링 패널 수 상한 경고.

## 4. ④ 멀티모니터 팝아웃 (패널을 새 창으로)

### 현황·근거
판독의·중환자실은 듀얼/트리플 모니터 운용. board 패널(예: 검사추이·영상)을 **별도 모니터 창으로 분리**해 차팅과 병행하고 싶다. 원내 **`record-timeline/patient/[patientId]`가 정확히 이 패턴**을 이미 구현: `(main)` 레이아웃 밖 독립 라우트 + `auth=TOKEN` 해시 자가 복원(새 창은 localStorage 토큰 미공유 가능성 대비).

### 설계
- 패널 제목바 `⧉ 팝아웃` → `window.open('/patients/[id]/panel/[panelKey]#auth=<token>', 'chart-panel-<key>', 'width,height')`.
- 신규 라우트 `app/patients/[id]/panel/[panelKey]/page.tsx` — **`(main)` 그룹 밖**(사이드바·탑바 없이 패널만 전체창). `record-timeline` 방식으로 해시 토큰 복원(`hash.match(/auth=([^&]+)/)`).
- 라우트는 부모 §3.2 **B안(별도 풀스크린 라우트)** 을 이 팝아웃 용도로만 차용 — 패널 컴포넌트 그대로 렌더(재사용). **`(main)` 밖 독립 셸은 타블렛 모드**(`app/tablet/layout.tsx` "독립 셸")**도 이미 사용** → 라우트 격리 패턴 검증됨.
- 창 이름 고정(`chart-panel-<key>`)으로 중복 오픈 방지(같은 패널 재클릭 시 기존 창 focus).
- **적합 패널 우선**(부모 §3.9): 팝아웃은 광폭·전용레이아웃 탭(영상·처방수납·전문과 풀차트)에서 특히 유용(별도 모니터에 넓게). 편집 폼 탭은 팝아웃 대상 제외.

### 리스크·완화
- **🔴 wrong-patient(부모 §2.5 P-2·IPSG-1)**: 팝아웃은 **별 창**이라 오환자 위험 최고 → 창 상단에 **이름·MRN·생년월일 식별 헤더 필수**(부모 P-2). 여러 팝아웃 창을 띄웠을 때 각 창이 누구 것인지 즉시 구분.
- **PHI 이중 창 노출**: 팝아웃 창도 인증 게이트 통과(무토큰 시 로그인). 방치 창 자동 잠금은 기존 단말 보안(DailyPin) 정책 승계 여부 확인.
- **모달/알림 부재**: 팝아웃은 Toaster·CriticalValueAlert 밖 → 위험 알림 누락 가능. **읽기 전용 뷰**로 제한(액션은 메인 창에서, 부모 P-5) + 위험 배너·신선도는 팝아웃에도 최소 표시.

## 5. ⑤ 다크 / 고대비 모드 (컨퍼런스룸·야간)

### 현황·근거 (중요 제약)
Tailwind v4이나 **`dark:` variant가 전역 0회** → 원내에 **다크모드 인프라가 없다**(greenfield). 전역 다크모드는 312 페이지·수천 컴포넌트 색상 감사가 필요한 **별개 대형 과제** → 본 기획 범위 밖.

### 설계 (board scope 한정)
- **전역 다크모드를 만들지 않는다.** board 컨테이너에 `data-theme="dark|high-contrast"` scope 부여 → **board 내부에서만** 색 오버라이드(CSS 변수 or scoped 규칙). 나머지 앱은 라이트 유지.
- 용도: 야간 병동·판독실 저조도, 컨퍼런스룸 프로젝터(고대비).
- 고대비: 폰트 가중치↑·경계선 강화·상태색(위험 적/경고 황) 채도↑ — 원거리 판독(부모 §3.6 회진 밀도와 결합).
- 밀도(§3.6)와 동일하게 `boardLayout`에 `theme` 저장(개인 지속).

### 리스크·완화
- 패널 = 기존 탭 컴포넌트(라이트 전제 하드코딩 색 다수) → board scope 다크에서 **색 대비 깨짐** 가능. **완화**: 패널 본문은 라이트 카드 유지 + board **셸(배경·헤더·여백)만 다크**(하이브리드) → 저비용·저위험. 완전 다크 패널은 범위 밖(전역 다크 과제로 이연).
- → **판정**: P2 내 **최하 우선순위·옵션**. 셸 다크(저비용)만 우선, 완전 다크는 보류.

## 6. ⑥ BFF 집계 EP (성능 — 조건부 승격)

### 현황·근거
부모 §6은 board 진입 동시 쿼리 ~21 → 캐시·dedup으로 ~10~12 감축(BE 변경 0). **BFF는 P2 옵션으로 격리**했다: P0~P1 실측에서 목표(진입 신규요청 ≤12·중복 0) 미달·워터폴 체감 시에만 착수.

### 설계
- 신규 `GET /api/v1/patients/:id/board-summary` — 요약·바이탈 최근·활성 처방·문제·알러지를 **서버 1요청으로 병합**(도메인 서비스 조합, 신규 데이터 없음).
- 프런트: board가 이 EP를 1회 조회 → 각 패널은 board-summary에서 `select`로 자기 몫만 파생(개별 패널 쿼리 제거). 상세/전체는 패널 확장 시 개별 EP.
- 기존 `/patients/:id/summary`(카운트) 확장 or 신규 분리 — 응답 크기·캐시 정책 고려.

### 승격 조건(게이트)
- P0~P1 계측에서 ①진입 신규요청 > 12 또는 ②워터폴로 초기 렌더 체감 지연 or ③서버 부하 경보 → **그때 착수**. 미달 없으면 **구현하지 않음**(YAGNI).

### 리스크
- 서버 조인 부하가 클라 → 서버로 이전. 캐시(Redis) 계층·과별 응답 크기 상한. 부분 실패 시 패널별 폴백(개별 EP 재조회).

## 9. 검증 계획
- **드래그**: 편집 모드 드래그로 순서 변경 → 저장 → 재진입 유지, 키보드 드래그 동작, 비편집 시 드래그 불가.
- **다중 레이아웃**: 회진/외래 전환 즉시 반영, 1개일 때 셀렉터 숨김, 관리자 프리셋 복제·수정.
- **새로고침**: 패널 `↻`가 해당 패널만 리페치(네트워크 탭), 자동갱신 토글·동시 폴링 수 확인.
- **팝아웃**: 새 창 인증 복원, 창 이름 중복 방지(focus), 무토큰 시 로그인, 위험 배너 표시.
- **다크/고대비**: board scope만 적용(나머지 앱 라이트 불변), 상태색 대비 확인.
- **BFF(착수 시)**: board 진입 요청 수 급감·부분 실패 폴백.
- **회귀**: P0~P1.5 기능(토글·편집·개인/서버 저장)·좁은 뷰 무변.

## 10. 열린 결정 (P2 착수 전)
1. **팝아웃 라우트 범위**: 패널 단위(`/panel/[panelKey]`)인지 board 전체(`/board`)인지 — 판독 워크플로우 확인.
2. **자동 갱신 대상**: 어떤 패널을 실시간 폴링 허용(바이탈·오더·간호)할지 화이트리스트.
3. **다크 모드 범위**: 셸만(저비용) 확정인지, 완전 다크를 전역 다크모드 과제로 별도 기획할지.
4. **BFF 착수 여부**: P0~P1 실측 결과 대기 — 목표 달성 시 미착수(YAGNI).
5. **다중 레이아웃 도입 여부**: 부모 §10-7과 연동 — 실제 상황별 전환 수요 검증 후.
