> 한 줄: **외래·입원 환자의 접수→진료→검사/처치→수납→퇴원 전 여정을 환자 단위로 한 화면에서 보고, 단계별 중간 진료비까지 실시간 관제하는 경영진 레벨 콘솔.**

## 1. 배경 · 문제 정의

현재 환자 여정의 각 단계는 **개별 화면·모듈에 분산**되어 있다.
- 접수/대기 → `waiting-queue`, 진료 → `encounter`, 입원 → `admission`, 수납 → `billing`, 위치 → `floor`, 경영지표 → `executive`/`dashboard`.
- 데이터(여정 이벤트·중간 진료비·위치)는 이미 발행/집계되고 있으나, **"이 환자가 지금 어느 단계이고 누적 진료비가 얼마인지"를 한 곳에서** 보는 통합 뷰가 없다.
- 특히 **중간 진료비(interim)**는 ERP가 D-6 인터페이스로 계산해 제공(`GET .../billing/invoice?interim=true`, HIS 프록시 `getErpInvoice` 구현 완료)하지만, **수납 상세 화면에서 1건씩만** 볼 수 있어 경영/원무 관점의 전체 조망이 불가능하다.

**결과**: 경영진·원무팀장은 "지금 원내에 몇 명이 어느 단계에 정체돼 있고, 미수납·장기재원·고액 미정산이 어디인지"를 실시간으로 파악할 수단이 없다.

## 2. 목표 (Goals)

| # | 목표 |
|---|------|
| G1 | **단일 화면**에서 외래+입원 **활성 환자 전원의 현재 여정 단계**를 보드/칸반으로 조망 |
| G2 | 환자 클릭 시 **여정 타임라인 + 누적/중간 진료비(ERP interim) + 위치**를 통합 드릴다운 |
| G3 | 경영 KPI(재원/대기/미수납/병상가동/평균체류) **실시간** 집계 + 임계 알림(정체·장기재원·고액미수) |
| G4 | **기존 자산 재사용** 중심 — 신규 도메인 모델 없이 집계 API + 콘솔 UI로 구현(비파괴) |
| G5 | 경영진은 **읽기 전용 안전 뷰**(개인정보 마스킹·권한 분리), 원무는 운영 액션 연계 |

## 3. 비목표 (Non-Goals)

- 신규 진료/수납/입원 **업무 로직 변경** (각 모듈은 그대로, 본 콘솔은 **읽기 집계 + 딥링크**)
- ERP의 **확정 진료비 산정** 대체 (진료비 SoT는 ERP D-6, 콘솔은 표시·관제만)
- 환자 앱/포털 노출 (본 건은 **내부 경영/원무 전용**)
- 실내 측위 하드웨어(RTLS) 도입 — 위치는 기존 여정 이벤트 기반 `PatientLocation` 활용

## 4. 사용자 · 페르소나

| 페르소나 | 니즈 | 콘솔 사용 |
|----------|------|-----------|
| **병원장/경영진** | 원내 전체 흐름·매출·정체 한눈에 | KPI 보드 + 임계 알림(읽기) |
| **원무팀장** | 미수납·수납대기·정산 정체 관리 | 수납 단계 칸반 + 중간진료비 + 딥링크 |
| **병동 수간호사** | 입원환자 단계·퇴원예정·장기재원 | 입원 트랙 + 재원일수 |
| **외래 운영 관리자** | 접수→진료→수납 정체·대기시간 | 외래 트랙 + 대기 SLA |

## 5. 핵심 기능 요구사항 (FR)

### 5.1 환자 흐름 보드 (G1)
- **FR-1** 외래/입원 **2개 트랙**을 단계별 칸반으로 표시:
  - 외래: `접수(대기)` → `호출/진료중` → `검사·처치 대기` → `수납 대기` → `수납 완료`
  - 입원: `입원` → `재원(병동)` → `퇴원 예정` → `퇴원/정산`
  - 단계 매핑: `PatientJourneyEvent.eventType`(RECEPTION_CHECKIN·ENCOUNTER_START·BILLING_PAID·ADMISSION·DISCHARGE 등) + `WaitingQueue.status` + `Admission.status` 조합.
- **FR-2** 각 카드: 환자(마스킹), 진료과/병동·병상, 담당의, 현재 단계 **체류시간**, **중간 진료비 배지**(미수납 잔액), 위험 플래그.
- **FR-3** 필터: 진료과·병동·보험구분·체류시간 임계·미수납액 구간.

### 5.2 환자 드릴다운 (G2)
- **FR-4** 환자 카드 클릭 → 우측 패널:
  - **여정 타임라인**(`GET /journey/:patientId/timeline`) — 접수~현재 이벤트 시간순.
  - **중간 진료비 패널** — `getErpInvoice(encounterId, interim=true)`: 총액·보험부담·본인부담·기수납·**미수납 잔액**·사전심사 BLOCK 경고. ERP 미가동 시 graceful.
  - **현재 위치/동선**(`floor` 엔티티·이력) — 선택.
  - **딥링크**: 진료기록·수납상세·입원상세로 이동(원무 권한).

### 5.3 경영 KPI · 실시간 (G3)
- **FR-5** 상단 KPI: 원내 활성환자(외래/입원), 평균 외래 대기, 평균 재원일수, **미수납 총액/건수**, 병상가동률, 오늘 매출(확정+중간). → `executive`/`operational-stats`/`journey.getMetrics` 재사용.
- **FR-6** **임계 알림 위젯**(룰):
  - 단계 정체(예: 수납대기 > N분, 진료중 > N분)
  - 장기재원(재원일수 > 과별 ALOS×배수)
  - 고액 미수납(중간 진료비 잔액 > 임계)
  - → 카드 하이라이트 + 알림 카운트.
- **FR-7** **실시간 갱신**: SSE(`/dashboard/stream`·`/floor/events`·신규 `/journey-console/stream`)로 보드/KPI 자동 갱신(폴백: 폴링).

### 5.4 통합 집계 API (G4, 신규 최소)
- **FR-8** **신규** `GET /api/v1/journey-console/board` — 활성 환자별 {현재단계, 트랙, 체류시간, 진료과/병동, 담당의, 미수납잔액(중간), 위험플래그} 1회 집계 반환(외래+입원).
  - 내부: WaitingQueue(활성) + Admission(active) + 최신 PatientJourneyEvent + Billing(미수납) + (옵션) ERP interim 캐시.
- **FR-9** **신규** `GET /api/v1/journey-console/kpi` — 상단 KPI 집계(기존 서비스 조합).
- **FR-10** **신규** `GET /api/v1/journey-console/stream` (SSE) — 보드/KPI 변경 푸시.
- **FR-11** 중간 진료비는 **성능 위해 캐시**(환자/encounter별 TTL ≤60s, 보드는 잔액만·드릴다운서 상세 호출).

### 5.5 권한 · 보안 (G5)
- **FR-12** 역할:
  - `EXECUTIVE`(읽기 전용·KPI·마스킹 강) — 신규 역할 또는 ADMIN 하위 권한.
  - `원무/운영`(보드+드릴다운+딥링크 액션).
- **FR-13** 경영진 뷰는 **환자명 마스킹**(홍*동)·주민번호 미표시·진료내용 요약만. 딥링크는 권한 게이트.
- **FR-14** 모든 드릴다운 조회 **감사 로그**(누가 어느 환자 진료비/여정 열람).

## 8. 비기능 요구사항 (NFR)

- **성능**: 보드 집계 ≤1.5s(활성 ~200명 가정), 중간진료비는 **잔액만 캐시**·상세는 온디맨드. N+1 방지(배치 조회).
- **실시간**: SSE 5~15s 갱신 + 변경 이벤트 푸시, 폴백 폴링.
- **개인정보**: 경영진 뷰 마스킹·최소노출, 드릴다운 감사로그(C-1 마스킹 정책 준수).
- **회복력**: ERP interim 미가동 시 `{available:false}` graceful, 보드는 HIS Billing 값으로 폴백 표시.
- **확장성**: 단계 정의·임계 룰을 **설정(ConfigRuntime)** 로 외부화.

## 10. 성공 지표 (KPI)

- 경영/원무가 **단일 화면**에서 활성 환자 단계·미수납·중간진료비 파악(현재 N개 화면 → 1개).
- 수납대기/장기재원 **정체 인지 시간** 단축(임계 알림).
- 중간 진료비 **조회 동선** 단축(수납 1건씩 → 보드에서 일괄·드릴다운).

## 11. 오픈 이슈

1. `EXECUTIVE` 역할 신설 여부 vs ADMIN 권한 분리(CRED_* 패턴 재사용?).
2. 중간 진료비 캐시 TTL/무효화(수납·정정 이벤트 연계) 정책.
3. 단계 칸반의 **단계 정의 표준화**(외래 5단계·입원 4단계 확정) — 진료과별 변형 허용?
4. 임계 룰 기본값(정체 분, ALOS 배수, 고액 기준) — 운영 합의.
5. SSE 부하(활성 환자 다수 시) — 변경분만 푸시 vs 주기 스냅샷.
6. ERP interim 대량 조회 성능(보드 N명) — ERP 벌크 invoice API 필요 여부(ERP 협의).
