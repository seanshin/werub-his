## 1. 현황 분석

### 1.1 현재 구조 (카테고리 기반)

```
홈 | 진료 | 건강 | 서비스 | 내 정보
         └─ 예약/대기, 진료이력, 문진표, 동의서, 소통
                  └─ 검사결과, 영상, 투약, 건강검진
                           └─ 수납, 서류, 원격진료, 병원안내
```

### 1.2 문제점

| 문제 | 영향 |
|------|------|
| **카테고리 분류가 환자 사고방식과 다름** | "검사결과 보러 왔는데 '건강' 탭인지 '진료' 탭인지 모름" |
| **정보 과다** | 홈에 6개 퀵액션 + 4개 요약 카드 + AI + 복용약 + 공지 + 판독 알림 |
| **깊은 탐색** | 원하는 정보까지 2~3번 클릭 필요 |
| **상황 인식 부재** | 진료 예정일과 무관한 고정 레이아웃 |
| **모바일 최적화 부족** | 데스크톱 사이드바 구조를 모바일에 그대로 적용 |

## 2. 설계 원칙

### 2.1 환자 중심 3원칙

```
① 상황 기반 (Context-First)
   → "지금 나에게 필요한 것"을 먼저 보여준다
   → 예약 전: 문진표+동의서 → 방문일: 접수+대기 → 진료 후: 결과+수납

② 1탭 원칙 (One-Tap Access)
   → 가장 많이 쓰는 기능은 홈에서 1번 탭으로 도달
   → 검사결과, 예약 확인, 수납은 홈에서 바로

③ 안내형 (Guided)
   → 환자에게 "다음에 할 일"을 알려준다
   → "문진표를 작성해주세요" → "검사결과가 나왔습니다" → "수납이 필요합니다"
```

### 2.2 벤치마크

| 앱 | 특징 | 참고 |
|-----|------|------|
| **가상서울병원** 앱 | 진료 여정 타임라인, 실시간 대기 번호 | 여정 중심 |
| **카카오 헬스케어** | 건강 데이터 대시보드, AI 건강 분석 | 건강 중심 |
| **MyChart (Epic)** | 메시지 중심, To-Do 리스트 | 할 일 중심 |
| **HealthHub (SG)** | 예약→검사→결과→수납 플로우 | 플로우 중심 |

## 3. 신규 UX 구조

### 3.1 네비게이션 (하단 3탭으로 단순화)

```
현재 5탭:  홈 | 진료 | 건강 | 서비스 | 내 정보
변경 3탭:  홈 | 내 건강 | 더보기
```

| 탭 | 내용 | 이유 |
|-----|------|------|
| **홈** | 상황 기반 카드 스트림 (To-Do + 알림 + 퀵액션) | 진입점, 1탭 접근 |
| **내 건강** | 건강 대시보드 (검사결과 + 투약 + 활력징후 + AI 요약) | 환자가 가장 궁금한 것 |
| **더보기** | 서류발급, 병원안내, 원격진료, 설정, 내 정보 | 자주 안 쓰는 기능 |

## 4. 상황 기반 시나리오

### 4.1 신규 환자 (첫 방문 전)

```
홈 카드 순서:
1. 🔴 동의서 미완료 (최우선)
2. 📋 문진표 미작성
3. 🏥 다음 예약 정보
4. 📍 병원 찾아오는 길 + 주차 안내
5. 🤖 AI 예약 도우미 소개
```

### 4.2 진료 당일 환자

```
홈 카드 순서:
1. 🏥 오늘 진료 (접수 상태 + 대기 번호)
2. ⏱ 실시간 대기 현황 "앞에 3명 / 약 15분"
3. 📍 진료실 위치 안내
4. 💊 복용약 알림 (공복 주의사항)
5. 💳 예상 진료비 안내
```

### 4.3 진료 후 환자

```
홈 카드 순서:
1. 🔬 검사결과 알림 (새 결과 도착)
2. 💳 수납 안내 (미수납 내역)
3. 📄 처방전 출력/약국 전송
4. 💊 새 처방약 복용 안내
5. 📅 다음 예약 안내 (재진)
6. 🤖 AI 건강 요약
```

### 4.4 만성질환 관리 환자

```
홈 카드 순서:
1. 💊 오늘 복용 체크 (아침/점심/저녁)
2. 📈 혈당/혈압 기록 입력
3. 🔬 정기 검사 리마인더
4. 📅 다음 정기 진료
5. 🤖 AI: "혈압이 2주 연속 높습니다. 내원을 권장합니다"
```

## 6. 기존 기능 매핑

| 현재 위치 | 신규 위치 | 접근 방법 |
|----------|----------|----------|
| 진료 > 예약/대기 | 홈 카드 (자동) | 예약 있으면 홈에 표시 |
| 진료 > 진료이력 | 더보기 > 진료이력 | 또는 내 건강에서 날짜별 |
| 진료 > 문진표 | 홈 To-Do (자동) | 미작성이면 홈에 표시 |
| 진료 > 동의서 | 홈 To-Do (자동) | 미동의면 홈에 최우선 표시 |
| 진료 > 소통 | 홈 카드 (메시지) | 새 메시지면 홈에 표시 |
| 건강 > 검사결과 | 내 건강 (메인) | 1탭 접근 |
| 건강 > 영상검사 | 내 건강 > 영상 | 또는 홈 카드 (판독 완료) |
| 건강 > 투약관리 | 내 건강 > 복용약 | + 홈 복용 리마인더 |
| 건강 > 건강검진 | 내 건강 > 검진 | 또는 홈 카드 (검진 안내) |
| 서비스 > 수납 | 홈 To-Do (자동) | 미수납이면 홈에 표시 |
| 서비스 > 서류발급 | 더보기 | |
| 서비스 > 원격진료 | 더보기 | 또는 홈 카드 (예약 시) |
| 서비스 > 병원안내 | 더보기 | |
| 내 정보 | 더보기 > 내 정보 | |

**결론: 조건부 적합 — "더보기" 탭 설계가 핵심 변수**

현재 5탭(홈/진료/건강/서비스/내 정보) 구조와 제안된 3탭(홈/내 건강/더보기)을 비교했을 때:

| 항목 | 5탭 | 3탭 (제안) |
|------|-----|-----------|
| 1탭 접근 가능 기능 수 | 1 (홈) | 1 (홈) |
| 핵심 기능 가시성 | 탭 레이블에서 "진료", "건강" 구분 명확 | 홈 카드가 동적으로 대체 |
| 고령자 탐색 부담 | 탭 5개 × 서브메뉴 4개 = 최대 20개 목적지 | "더보기" 내부가 유사한 혼잡도 위험 |
| 기능 발견 가능성 (Discoverability) | 탭 레이블 = 힌트 | 더보기에 숨겨진 기능은 자발적 탐색 필요 |

**보완 필요 사항:**

1. "더보기" 탭 내부를 **그리드 8칸 고정**이 아닌 **카테고리 섹션 분리** 방식으로 변경해야 함.
   - 현재 기획: 8개 아이콘 나열 + 설정 섹션
   - 권장: "진료 관련 / 서류 · 수납 / 설정 · 계정" 3개 섹션으로 그룹화

2. "내 건강" 탭이 영상검사(DICOM/PACS 링크 포함) · 건강검진 · 투약 · 검사결과를 모두 담을 때, 해당 탭 내부 구조도 상세히 기획 필요. 현재 기획(§3.4)은 레이아웃 스케치 수준으로 서브 탐색 패턴이 누락됨.

3. 데스크톱(태블릿) 환경에서 기존 사이드바 5항목을 3항목으로 줄이면 사이드바 공간이 낭비됨. **데스크톱에서는 5탭 사이드바를 유지하고 모바일에서만 3탭 적용**하는 반응형 이중 전략이 현실적임.

### 10.2 누락된 카드 시나리오

현재 4개 시나리오(신규/당일/진료후/만성질환) 외 추가 필요한 시나리오:

**5. 입원 환자 (Inpatient)**

```
홈 카드 순서:
1. 🏥 현재 병실 + 주치의 + 입원 일수
2. 📋 오늘 예정 검사/처치 스케줄
3. 💊 금일 투약 현황 (간호 투약 기록)
4. 🍽 오늘 식단 (영양부서 연동)
5. 📞 간호사 호출 버튼 (FAB 대체)
6. 📄 퇴원 예정일 + 퇴원 준비 체크리스트
```

**6. 건강검진 수검자 (당일)**

```
홈 카드 순서:
1. 🔬 오늘 검진 코스 안내 (코스명 + 검사 수)
2. 📍 검진 순서 및 현재 위치 (몇 번째 검사)
3. ⚠️ 금식 여부 확인 / 주의사항 알림
4. 🕐 예상 완료 시간
5. 📄 검진 결과 발송 안내 (수일 내)
```

**7. 원격진료 예약 환자**

```
홈 카드 순서:
1. 📹 원격진료 D-N일 (또는 "지금 입장 가능")
2. 🔧 장치 테스트 (카메라/마이크 확인 링크)
3. 📋 사전 문진표 작성
4. 💊 복용 중인 약 목록 준비 안내
```

**8. 보호자 대리 접근 (위임 계정)**

```
홈 카드 순서:
1. 👤 현재 열람 중인 환자 전환 UI (상단 배너)
2. 🔴 위임받은 항목만 표시 (의료법상 제한 범위)
3. 📄 동의서/서류 대리 서명 가능 항목
```
이 시나리오는 법적 요건(의료법 제21조 대리열람)과 직결되므로 별도 기획 필요.

### 10.4 의료법·개인정보보호법 관점 UX 이슈

**이슈 1: 홈 카드에 진단명·검사수치 노출**

카드 미리보기(§5.1)에서 "혈당 98 정상 ✅ | 혈압 128/82 ⚠️" 등 민감 의료정보가 홈 화면에 즉시 표시됨.

- 법적 근거: 개인정보보호법 제23조 (민감정보), 의료법 제22조 (진료기록 보호)
- 위험: 타인이 화면을 훔쳐볼 경우 (어깨 너머 노출, Shoulder Surfing)
- 대응 방안: 수치를 기본으로 **마스킹** 처리 후 탭하면 확인 (iOS Health 앱 방식), 또는 잠금 화면 복귀 후 재인증 요구 (5분 비활성 시)

**이슈 2: 동의서 미완료 카드의 법적 의미**

동의서를 "오늘 할 일"로 게임화(체크박스 + 진행률)하는 UX는 동의의 자발성 원칙을 훼손할 수 있음.

- 의료법 제24조의2: 의료행위 설명 및 동의 (자발적·충분한 설명 후 동의)
- 대응 방안: To-Do 카드에서 "완료" 체크 방식이 아닌 별도 동의서 화면에서 내용 확인 후 서명 처리. 진행률 표시는 접근 현황 안내용으로 제한.

**이슈 3: AI 건강 요약의 의료적 판단 경계**

"AI: 혈압이 2주 연속 높습니다. 내원을 권장합니다" (§4.4)는 의료 조언에 해당할 수 있음.

- 의료법 제27조: 무면허 의료행위 금지 (AI 생성 의료 조언 포함 여부 법률 해석 진행 중)
- 대응 방안: AI 문구를 "관찰된 데이터입니다. 자세한 상담은 의료진에게 문의하세요"로 면책 문구 추가. 현재 WeRU.B AI 서버 응답에도 면책 문구 포함 여부 확인 필요.

**이슈 4: 미성년자 포털 접근**

미성년 환자(14세 미만)의 경우 법정대리인 동의 없이 본인 계정으로 민감정보 열람 시 법적 문제.

- 대응 방안: 연령 확인 후 14세 미만은 보호자 연동 계정 필수 처리 로직 명시.

### 11.11 마이크로인터랙션 상세

**검사결과 수치 표시:**
```
수치 등장: 0 → 98 (카운트업 600ms)
프로그레스 바: width 0 → 78% (800ms ease-out)
상태 배지: scale(0) → scale(1) + bounce (300ms delay)
```

**복용 체크:**
```
탭 → ☐ → ✅ (scale 0.8 → 1.2 → 1.0, 300ms)
   → 줄긋기 텍스트 (width 0 → 100%, 400ms)
   → 미세 confetti 파티클 (8개, 500ms fade-out)
   → 프로그레스 바 업데이트 (width animate, 300ms)
```

**카드 스와이프 (모바일):**
```
좌로 스와이프: 액션 버튼 노출 (삭제/숨기기)
   → 배경 빨간색 fade-in
   → 아이콘 slide-in from right
```

**풀다운 새로고침:**
```
당기기 시작: 로고 등장 (opacity 0→1, scale 0.5→1)
임계점 도달: 햅틱 피드백 (모바일)
새로고침 중: 로고 360° 회전 반복
완료: 로고 축소 + fadeOut + 카드 fadeInUp
```
