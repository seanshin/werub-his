## 1. 기획 배경

### 1.1 현재 상태

| 항목 | 현재 | 문제 |
|------|------|------|
| 메시지 구조 | 플랫 리스트 (스레드 없음) | 대화 맥락 파악 어려움 |
| 의사 → 환자 | 미구현 (환자 → 의사 단방향) | 진료 후 안내/지시 불가 |
| HIS 연동 | 미구현 | 의사가 HIS에서 답변 불가 |
| 수납 | 없음 (무료) | 지속 불가능한 모델, 남용 위험 |
| 동의서 | 없음 | 원격의료 동의 없이 상담 진행 |
| 읽음 확인 | isRead 필드만 존재, UI 미노출 | 의사가 확인 여부 모름 |
| 보안 | HTTPS만 (전송 암호화) | 저장 시 평문, 감사 로그 없음 |
| 첨부파일 | 미지원 | 사진/서류 공유 불가 |

### 1.2 목표

```
환자와 담당 의료진이 의료법에 부합하는 방식으로
비동기 보안 메시지를 주고받되,
① 첫 소통 시 원격의료 동의 프로세스를 거치고
② 의사 상담에 대해 적절한 수납이 이루어지며
③ HIS에서 의사가 직접 답변할 수 있는 구조를 갖춘다.
```

### 1.3 서비스 포지셔닝

```
                   무료                  유료
              ┌──────────────────┬──────────────────┐
   단방향     │ 시스템 알림       │                  │
   (읽기만)   │ (검사결과 도착,   │                  │
              │  예약 리마인더)   │                  │
              ├──────────────────┼──────────────────┤
   양방향     │ 단순 문의        │ ★ 비대면 상담 ★  │
   (대화)     │ (예약 변경,      │ (증상 상담,      │
              │  주차 안내)      │  검사결과 해석,  │
              │                  │  복용약 상담)    │
              ├──────────────────┼──────────────────┤
   실시간     │                  │ 원격 진료         │
   (화상)     │                  │ (Jitsi WebRTC)   │
              └──────────────────┴──────────────────┘
                                    ↑
                             이번 기획 범위
```

### 1.4 왜 수납이 필요한가

```
1. 의료법 제33조: 의료기관 내에서 의료 행위
   → 비대면 상담도 의료 행위에 해당할 수 있음 → 수가 청구 근거

2. 남용 방지: 무료이면 불필요한 질문 폭주
   → 의사 업무 과부하 → 서비스 지속 불가능

3. 건강보험 비급여 항목:
   → "전화/인터넷 등을 이용한 의료 상담" 은 비급여 허용
   → 병원 자체 수가 책정 가능

4. 환자 인식: 유료 = 전문 상담 → 더 구체적 질문 → 더 나은 답변
```

## 2. 법적 근거 및 제약

### 2.1 관련 법률

| 법률 | 조항 | 적용 |
|------|------|------|
| **의료법 제24조** | 의료인의 설명 의무 | 메시지로 진료 결과/주의사항 안내 가능 |
| **의료법 제24조의2** | 충분한 설명 후 동의 | 중요 의료 결정은 메시지만으로 불가 (대면/원격 필수) |
| **의료법 제33조** | 의료기관 내 의료 행위 | 메시지는 "의료 상담"이며 "진료"는 아님 — 명확한 경계 필요 |
| **의료법 제34조** | 원격의료 | 비동기 메시지는 원격의료에 해당하지 않음 (실시간 아닌 상담 보조) |
| **의료법 제22조** | 진료기록부 기재 | 의료적 판단이 포함된 메시지는 진료 기록으로 보존 |
| **개인정보보호법 제23조** | 민감정보 처리 | 건강정보 포함 메시지는 암호화 저장 필수 |
| **개인정보보호법 제29조** | 안전성 확보 조치 | 접근 통제, 암호화, 접속 기록 보관 |
| **전자문서법 제5조** | 전자문서의 효력 | 의사의 메시지도 서면과 동일한 법적 효력 |

### 2.3 면책 문구 (필수 표시)

```
이 메시지는 의료 상담 보조 목적이며, 정식 진료를 대체하지 않습니다.
증상이 악화되거나 응급 상황 시 즉시 병원을 방문하거나 119에 연락하세요.
의료진의 메시지는 진료 기록의 일부로 보존됩니다.
```

|------|------|------|

## 3. 첫 소통 동의 프로세스

### 3.1 첫 메시지 전송 시 필수 단계

환자가 **처음으로** 의료진에게 메시지를 보낼 때, 다음 동의 절차를 거칩니다.

```

        │
        ▼
   ┌─ 비대면 상담 서비스 안내 ────────────────────────┐
   │                                                  │
   │  비대면 의료 상담 서비스                           │
   │                                                  │
   │  이 서비스는 담당 의료진과 비동기 메시지를 통해     │
   │  의료 상담을 받을 수 있는 유료 서비스입니다.        │
   │                                                  │
   │  ── 서비스 안내 ──                                │
   │  • 담당 의료진이 영업일 기준 24시간 내 답변         │
   │  • 검사결과 해석, 복용약 상담, 증상 문의 가능       │
   │  • 정식 진료를 대체하지 않습니다                    │
   │  • 응급 상황은 119 또는 응급실 이용                 │
   │                                                  │
   │  ── 이용 요금 ──                                  │
   │  • 1건당 20,000원 (비급여)                        │
   │  • 의사 답변 완료 시 자동 수납 처리                 │
   │  • 48시간 내 미답변 시 자동 환불                    │
   │                                                  │
   │  ── 필수 동의 ──                                  │
   │  ☐ 원격의료 서비스 이용 동의 (의료법 제34조)       │
   │  ☐ 비대면 상담 비급여 수가 안내 확인               │
   │  ☐ 개인(건강)정보 처리 동의                        │
   │  ☐ 메시지 내용 진료기록 보존 동의                  │
   │                                                  │
   │  ⚠️ 4개 항목 모두 동의해야 서비스 이용이 가능합니다 │
   │                                                  │
   │  [동의하고 시작하기]  [취소]                        │
   └──────────────────────────────────────────────────┘
        │
        ▼ (동의 완료 → 이후 재동의 불필요, 1년 유효)
   새 질문 작성 화면으로 이동
```

### 3.2 동의서 모델 (기존 RegistrationConsent 확장)

기존 10종 동의서에 **TELEHEALTH_MESSAGING** 유형을 추가합니다.

```
type: 'TELEHEALTH_MESSAGING'
version: '1.0'
required: true (서비스 이용 전 필수)
expiresAt: 1년
법적근거: 의료법 제34조, 개인정보보호법 제23조
```

### 3.3 재동의 트리거

| 상황 | 재동의 필요 |
|------|-----------|
| 1년 경과 | 자동 갱신 안내 → 재동의 |
| 수가 변경 | "수가가 변경되었습니다" → 재동의 |
| 약관 변경 | 변경 내용 안내 → 재동의 |
| 첫 이용 후 90일 미사용 | 재이용 시 재확인 |

### 4.1 상담 유형별 수가

| 유형 | 수가 | 과금 시점 | 비고 |
|------|------|----------|------|
| **기본 상담** | 20,000원 | 의사 답변 완료 시 | 비급여 |
| **검사결과 해석** | 30,000원 | 의사 답변 완료 시 | 검사 연동 시 자동 분류 |
| **사진 첨부 상담** | 30,000원 | 의사 답변 완료 시 | 피부/상처 사진 등 |
| **퇴원 후 추적 상담** | 무료 (1회) | - | 퇴원 후 7일 이내 1회 무료 |
| **단순 문의** | 무료 | - | 예약/주차/위치 등 비의료 |

```

  feeAmount         Int?     // 수가 (원)

  billingId         String?  // → Billing 테이블 연결
```

### 4.4 환불 정책

| 상황 | 환불 |
|------|------|
| 48시간 내 의사 미답변 | **자동 전액 환불** |
| 의사가 "단순문의" 재분류 | 무료로 변경 (차액 환불) |
| 환자 취소 (답변 전) | 전액 환불 |
| 환자 취소 (답변 후) | 환불 불가 |
| 시스템 오류 | 전액 환불 |

## 5. HIS 의사 워크플로우

### 5.1 의사의 메시지 접근 경로

```
HIS에서 의사가 환자 메시지에 접근하는 3가지 경로:

① 환자 차트 > 메시지 탭
   → 해당 환자의 전체 스레드 목록
   → 답변 + 진료기록 연동

② 알림 센터 > 환자 메시지
   → 미답변 메시지 클릭 → 바로 답변
   → SSE 실시간 알림

③ 전담 메시지 대시보드 (/messages)
   → 내 담당 환자 전체 메시지 관리
   → 필터: 미답변/긴급/오래된 순
   → SLA 현황 (응답률, 평균 시간)
```

### 5.5 의사 주도 발송 vs 환자 질문

| 항목 | 환자 질문 | 의사 주도 안내 |
|------|----------|--------------|
| 시작자 | 환자 | 의사 |
| 수가 | 유료 (20,000~30,000원) | **무료** |
| 수납 | 답변 완료 시 확정 | 없음 |
| 진료기록 | 선택적 연동 | 자동 연동 권장 |
| 사례 | "이 약 부작용?" | "검사결과 안내드립니다" |

## 6. 소통 유형 정의

### 3.1 대화 스레드 (Conversation Thread)

기존 플랫 리스트를 **스레드 기반 대화**로 전환합니다.

```
┌─────────────────────────────────────────────────┐
│ 스레드 = 1 환자 + 1 의료진 + 1 주제             │
│                                                  │
│ 예: "6/4 혈액검사 결과 문의"                      │
│     ├─ 환자: "혈당이 120인데 괜찮은 건가요?"      │
│     ├─ 의사: "정상 범위입니다. 식이 조절..."       │
│     ├─ 환자: "감사합니다. 운동은 어떻게..."        │
│     └─ 의사: "하루 30분 유산소 권장합니다"         │
└─────────────────────────────────────────────────┘
```

### 3.2 소통 유형

| 유형 | 시작자 | 설명 | 예시 |
|------|--------|------|------|
| **질문** | 환자 | 진료/검사/복용 관련 질문 | "이 약 부작용이 있나요?" |
| **안내** | 의사 | 검사 결과, 복용법, 주의사항 | "혈당 안정, 식이 유지" |
| **지시** | 의사 | 추가 검사, 내원 권고 | "재검 필요, 내주 내원" |
| **응답** | 양측 | 기존 메시지에 대한 답변 | 스레드 내 연속 대화 |
| **시스템** | 시스템 | 자동 알림 메시지 | "검사 결과 도착", "예약 변경" |

### 3.3 카테고리 태그

메시지에 카테고리를 지정하여 관리 효율성을 높입니다.

| 카테고리 | 아이콘 | 색상 | 우선순위 |
|---------|--------|------|---------|
| 검사결과 | 🔬 | 보라 | 보통 |
| 복용/투약 | 💊 | 초록 | 보통 |
| 증상상담 | 🩺 | 파랑 | 높음 |
| 예약/일정 | 📅 | 회색 | 낮음 |
| 수술/시술 | ⚕️ | 빨강 | 높음 |
| 퇴원안내 | 🏠 | 청록 | 보통 |
| 일반문의 | 💬 | 회색 | 낮음 |

## 4. 데이터 모델

### 4.1 대화 스레드 (신규)

```prisma
model MessageThread {
  id              String    @id @default(uuid()) @db.Uuid
  patientId       String    @map("patient_id") @db.Uuid
  doctorId        String    @map("doctor_id") @db.Uuid
  
  // 스레드 메타
  subject         String    @db.VarChar(200)
  category        String    @default("GENERAL") @db.VarChar(30)
  status          String    @default("OPEN") @db.VarChar(20)  // OPEN, ANSWERED, CLOSED, ARCHIVED
  priority        String    @default("NORMAL") @db.VarChar(10) // LOW, NORMAL, HIGH, URGENT
  
  // 연결 (선택)
  encounterId     String?   @map("encounter_id") @db.Uuid   // 관련 진료
  admissionId     String?   @map("admission_id") @db.Uuid   // 관련 입원
  labResultId     String?   @map("lab_result_id") @db.Uuid  // 관련 검사
  
  // 통계
  messageCount    Int       @default(0) @map("message_count")
  lastMessageAt   DateTime? @map("last_message_at") @db.Timestamptz()
  lastSender      String?   @map("last_sender") @db.VarChar(10)
  
  // 의사 응답
  doctorReadAt    DateTime? @map("doctor_read_at") @db.Timestamptz()
  doctorRepliedAt DateTime? @map("doctor_replied_at") @db.Timestamptz()
  
  // 자동 종료
  autoCloseAt     DateTime? @map("auto_close_at") @db.Timestamptz()
  closedReason    String?   @map("closed_reason") @db.VarChar(100)
  
  createdAt       DateTime  @default(now()) @map("created_at") @db.Timestamptz()
  updatedAt       DateTime  @updatedAt @map("updated_at") @db.Timestamptz()
  
  patient         Patient   @relation(fields: [patientId], references: [id])
  doctor          User      @relation("ThreadDoctor", fields: [doctorId], references: [id])
  messages        ThreadMessage[]
  
  @@index([patientId, status])
  @@index([doctorId, status, lastMessageAt])
  @@map("message_threads")
}
```

### 4.2 스레드 메시지 (기존 PatientMessage 확장)

```prisma
model ThreadMessage {
  id              String    @id @default(uuid()) @db.Uuid
  threadId        String    @map("thread_id") @db.Uuid
  
  sender          String    @db.VarChar(10)    // PATIENT, DOCTOR, SYSTEM
  senderId        String?   @map("sender_id") @db.Uuid
  content         String    @db.Text
  contentEncrypted Boolean  @default(true) @map("content_encrypted")
  
  // 첨부파일
  attachments     Json?     @db.JsonB          // [{type, url, name, size}]
  
  // 의료 태그
  isMedicalAdvice Boolean   @default(false) @map("is_medical_advice")
  disclaimerShown Boolean   @default(false) @map("disclaimer_shown")
  
  // 읽음 확인
  isRead          Boolean   @default(false) @map("is_read")
  readAt          DateTime? @map("read_at") @db.Timestamptz()
  
  createdAt       DateTime  @default(now()) @map("created_at") @db.Timestamptz()
  
  thread          MessageThread @relation(fields: [threadId], references: [id])
  
  @@index([threadId, createdAt])
  @@map("thread_messages")
}
```

### 5.1 환자 → 의사 질문

```
환자 포털                                  HIS (의사)
   │                                         │
   ▼                                         │
① [+ 새 질문] 버튼                            │
   │                                         │
   ▼                                         │
② 담당의 선택                                 │
   (최근 진료 의사 자동 추천)                   │
   │                                         │
   ▼                                         │
③ 카테고리 + 제목 + 내용 작성                  │
   (첨부파일 선택)                             │
   │                                         │
   ▼                                         ▼
④ 전송 → 면책 문구 확인 후 발송           ⑤ 알림 수신
   │                                    "환자 박철수 님이 질문했습니다"
   │                                         │
   │                                         ▼
   │                                    ⑥ 답변 작성 + 전송
   │                                         │
   ▼                                         │
⑦ 답변 도착 알림 (푸시 + 포털)                 │
   "김내과 교수가 답변했습니다"                  │
```

|--------|------|--------|
| 환자 새 질문 | SSE + HIS 알림 | "박철수 님이 질문했습니다: 혈액검사 결과 문의" |
| 24시간 미답변 | HIS 배지 | 미답변 카운트 배지 표시 |
| 48시간 미답변 | 이메일 | "미답변 메시지 2건이 있습니다" |
| 증상상담 (HIGH) | SSE 즉시 | "⚠️ 증상 관련 긴급 질문" |

### 7.3 응답 시간 SLA

| 카테고리 | 목표 응답 시간 | 에스컬레이션 |
|---------|--------------|-------------|
| 증상상담 (HIGH) | 4시간 | 24시간 미답 → 과장에게 에스컬레이션 |
| 검사결과/복용 | 24시간 | 48시간 미답 → 과장에게 에스컬레이션 |
| 예약/일반 | 48시간 | 72시간 미답 → 자동 안내 메시지 |

## 8. 보안 요구사항

### 8.1 메시지 보안

| 항목 | 구현 |
|------|------|
| 전송 암호화 | HTTPS (TLS 1.3) |
| 저장 암호화 | AES-256 (content 필드) |
| 첨부파일 암호화 | S3 SSE (서버 측 암호화) |
| 접근 통제 | 환자 본인 + 해당 스레드 의사만 |
| 감사 로그 | 모든 읽기/쓰기 행위 기록 |
| 보존 기간 | 10년 (의료법 시행규칙 제15조) |
| 삭제 정책 | 소프트 삭제만 허용 (물리 삭제 금지) |

### 8.2 첨부파일 제한

| 항목 | 제한 |
|------|------|
| 파일 수 | 스레드당 최대 5개 |
| 파일 크기 | 개당 10MB 이하 |
| 허용 형식 | JPG, PNG, PDF, HEIC |
| 금지 형식 | 실행 파일, 스크립트 |
| 바이러스 스캔 | 업로드 시 ClamAV 스캔 |
| 저장 위치 | 서버 로컬 + 암호화 |

### 8.3 의료적 판단 경계

```
메시지에 다음 키워드 포함 시 자동 경고 표시:
  "처방 변경", "약 바꿔", "투약 중단", "수술", "입원"
  → "⚠️ 이 내용은 메시지로 결정할 수 없습니다.
      대면 또는 원격 진료를 예약해주세요. [예약하기]"
```
