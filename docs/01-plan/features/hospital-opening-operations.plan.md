# 의료기관 개원·운영 단계 관리 — 실무 이름과 흐름으로

작성 2026-08-28 · 사람 지시: *"의료기관 운영 초기에 설정해야 할 의결사항, 흐름, 결정 사항들을
관리하는 기능이 분리되어 있는지 체크하고, 병원 개원 전·개원 후 운영 단계의 흐름을
실제 업무에서 사용되는 이름과 흐름으로 정리된 기능이 필요함."*

---

## §1 실측 — 무엇이 있고 무엇이 없는가 (2026-08-28)

### 있는 것 — **분리는 되어 있다. 다만 전부 전산 축 이름이다**

| 화면 | 관리 대상 | 항목 | 이름의 축 |
|------|-----------|-----:|-----------|
| `/admin/go-live` | HIS 시스템 개시 | 58 (A~H) | 안전게이트·외부연동·인프라·서비스 플래그 |
| `/admin/decisions` | 사람 결정 등록부 | 38 (3층) | SystemConfig 키 |
| `/admin/governance` | 위원회·의결·집행·결정 경로 | 위원회 9 | 거버넌스 |
| `/admin/phase0-cutover` | MRN 가명화 컷오버 | 1축 | 전산 |

`go-live` 58항목의 영역: A 임상 안전게이트 8 · B 외부 연동 15 · C 가명화 1 · D 데이터 1 ·
E 보안/인증 10 · F 인프라 3 · G 하드웨어 5 · H 서비스 개시 플래그 15.

### 없는 것 — **의료기관 개원 그 자체의 업무 흐름**

전역 문자열 실측(apps/api/src · apps/web/src · packages/shared/src):

| 실무 용어 | 파일 수 |
|-----------|-------:|
| 개설허가 · 개설신고 · 의료기관 개설 | **0 · 0 · 0** |
| 마약류취급자 | **0** |
| 진단용 방사선(발생장치) | **0** |
| 의료폐기물 · 세탁물 | **0 · 0** |
| 면허신고 | **0** |
| 법정교육 | **0** |
| 요양기관 | 16 — **전부 청구용 기호·종별**이지 신고 절차가 아니다 |

`go-live` 58항목 중 개원 업무를 **가리키기만** 하는 것 2건:
- D `data.hospitalInfo` — "기관 기본정보 완비(기호·사업자번호·대표자·주소)"
- E `요양기관 종별 설정(개설 허가와 일치)` — 개설 허가를 **전제로만** 언급

🔴 **개원 후 주기 업무도 축이 없다.** `Committee.meetingCycle` 은 저장·표시만 하고
**준수를 계산하는 코드가 0개**다 — 월간 위원회(DTC·IC·QPS·OPS)가 이번 달에 열렸는지
아무도 세지 않는다. 운영 실측: 위원회 9개, 그중 의결 누적 0건이 2개(ETH·NUT).

### 관점의 문제 — 이것이 핵심이다

세 화면 전부 **전산·거버넌스 이름**으로 되어 있어, 원무과장·행정부장·간호부장이
**자기 일로 읽을 수 없다.** "DUR 처방 게이트 targetMode" 는 전산의 언어이고,
"의료기관 개설신고 → 요양기관 기호 지정 → 개원" 은 병원의 언어다.
사람 지시의 "실제 업무에서 사용되는 이름과 흐름"이 정확히 이 지점이다.

## §2 판단 — 만들 것과 **만들지 않을 것**

### 🔴 만들지 않을 것 (먼저 못박는다)

1. **기존 항목을 복제하지 않는다.** 개원 화면이 go-live 58항목을 자기 목록으로 베끼면
   **정본이 둘이 된다**(§규약 P12 — 이 저장소에서 반복해 나온 유형). 새 축은
   **업무 이름의 레이어**이고, 상태는 **기존 정본에서 파생**한다.
2. **법정 절차를 시스템이 대행하는 것처럼 그리지 않는다.** 개설신고는 보건소에 사람이
   내는 것이지 HIS 가 전송하는 것이 아니다. HIS 가 하는 일은 **목록을 들고 있는 것**과
   **완료를 사람이 증빙과 함께 기록하는 것**뿐이다. "신청" 버튼을 만들면 §대외발신 위반.
3. 🔴 **법령 조문·처리기한을 내가 지어내지 않는다.** 항목의 **실무 명칭**(개설신고·
   요양기관 기호 지정·마약류취급자 허가)은 업무 상식이라 안전하지만, "의료법 제OO조",
   "처리기한 O일" 은 내가 검증할 수 없다. **근거는 미기재(`undefined`)가 기본**이고
   화면이 "근거 미기재"라 말한다(shared `decision-basis.ts` 3상 정본을 그대로 쓴다).
   시드가 조문을 넣으면 그것이 정책이 된다(§시드 함정 4).
4. **목록이 완전하다고 말하지 않는다.** 기관 종별·지역·특례(이 기관은 가상 국제병원이라
   특례 적용 여부 자체가 사람 확인 사항)에 따라 달라진다. 레지스트리는 **기본 목록**이고,
   화면은 "이 목록은 전수가 아니다 — 기관이 확정한다"를 상시 표시한다.
5. **절대 날짜를 박지 않는다.** 개원일이 아직 없다. 기존 `dueBy` 가 이미 상대 표현
   (`BEFORE_GO_LIVE`/`WITHIN_30D`/`NONE`)을 쓴다 — 같은 규칙을 따른다.

### 만들 것

**개원 단계 축(`/admin/opening`)** — 병원 업무 이름으로 된 **단계별 흐름 하나**.
각 항목은 셋 중 하나로 상태를 얻는다:

| 상태 출처 | 방식 | 예 |
|-----------|------|----|
| `goLiveKey` | go-live 정본에서 파생 | 시스템 개시 항목 |
| `decisionKey` | 결정 등록부에서 파생 | 사람 결정 항목 |
| `committeeCode` | 위원회 대장에서 파생 | 필수 위원회 구성 |
| (없음) | **사람이 완료 기록**(증빙 첨부) | 개설신고·기호 지정 등 |

🔴 파생 항목은 **자기 상태를 갖지 않는다.** 저장하면 갈라진다.

## §3 설계 — 단계와 흐름

### 3.1 단계(Phase) — 실제 업무 순서

```
[개원 전]
  O1 설립·시설     법인/개설자·시설 기준·소방·폐기물·세탁물·급식 운영 형태
  O2 인허가        의료기관 개설신고(허가)·사업자등록·마약류취급자·진단용 방사선
  O3 보험·청구자격  요양기관 기호 지정·의료급여·자동차보험·산재보험·종별 확정
  O4 인력·조직     의료인/의료기사 면허 확인·필수 담당자 지정(감염관리·CPO·안전보건)
  O5 위원회·규정   필수 위원회 구성·규정(charter) 제정·원내 지침
  O6 시스템 개시   ← 기존 go-live 58항목을 **연결**(복제 아님)
  O7 시험운영      ← 기존 운영 모드(개발/리허설/리얼) 축을 연결

[개원]
  O8 개원일        개원일 확정 · 개시 신고 완료

[개원 후]
  O9 개시 직후     개시 후 확인 항목(기관이 정한다 — 기본 미기재)
  O10 정기 운영    위원회 주기 준수 · 정기 점검 · 법정 교육 · 정기 보고
  O11 인증 준비    의료기관 인증(기관이 시기를 정한다)
```

🔴 **단계는 게이트가 아니다.** O2 가 안 끝나도 O5 를 할 수 있다(실제로 병행한다).
단계는 **순서를 보여주는 것**이지 막는 것이 아니다 — 막으면 사람이 우회한다(§4 규약).
다만 **선행 관계**(`dependsOn`)는 사실이므로 표시한다: 예) 요양기관 기호 지정은
개설신고 완료를 전제한다.

### 3.2 항목이 드는 것

```ts
interface OpeningTask {
  phase: OpeningPhase;      // O1~O11
  key: string;              // 'open.license.facility' 등
  title: string;            // 🔴 **실무 명칭 그대로**
  owner: string;            // 역할·부서(사람 이름 아님)
  authority?: string;       // 🔴 어디에 내는가(보건소·세무서·건보공단…) — 모르면 생략
  /** 🔴 근거는 **미기재가 기본** — 조문을 내가 지어내지 않는다 */
  basis?: DecisionBasis;
  /** 기존 정본 연결 — 셋 중 최대 하나 */
  goLiveKey?: string; decisionKey?: string; committeeCode?: string;
  dependsOn?: string[];
  /** 🔴 상대 표현만 — 개원일이 없다 */
  dueBy: 'BEFORE_OPENING' | 'AT_OPENING' | 'AFTER_OPENING' | 'RECURRING';
  /** 주기 항목만 — 위원회 주기 준수 등 */
  cycle?: 'MONTHLY' | 'QUARTERLY' | 'SEMIANNUAL' | 'ANNUAL';
  note?: string;
}
```

### 3.3 상태 — 4상

| 상태 | 뜻 | 누가 정하는가 |
|------|-----|--------------|
| `DERIVED` | 연결된 정본이 상태를 말한다 | go-live·decisions·committees |
| `RECORDED` | 사람이 완료를 기록했다(증빙 있음) | 담당 부서 |
| `NOT_RECORDED` | 아직 아무도 기록하지 않았다 | — |
| `NOT_APPLICABLE` | 이 기관에 해당하지 않는다(사유 필수) | 담당 부서 |

🔴 **`NOT_RECORDED` 를 "미완료"라 단정하지 않는다.** 병원이 이미 했는데 시스템에
안 적었을 수 있다 — 화면은 "기록 없음"이라 말한다(모르는 것과 안 한 것은 다른 사실).
🔴 **`NOT_APPLICABLE` 에 사유를 강제**한다. 사유 없이 지우면 빠뜨린 것과 구분되지 않는다.

### 3.4 개원 후 주기 준수 — 실측 가능한 것부터

지금 데이터로 **계산 가능한 것 하나**가 있다: 위원회 회의 주기 준수.
`Committee.meetingCycle` + `CommitteeMeeting.heldAt` → "이번 주기에 회의가 있었는가".

🔴 **분모를 함께** 낸다: "월간 위원회 4개 중 이번 달 회의 기록 N개".
🔴 **회의 기록이 0인 위원회를 '위반'이라 부르지 않는다** — 시스템에 안 적혔을 뿐일 수 있다.
"기록 없음"이라 쓴다.

## §4 단계별 구현

| 단계 | 내용 | 산출 |
|------|------|------|
| **P0** | 항목 정본(`opening.registry.ts`) + 상태 파생 EP + 화면 `/admin/opening` | 흐름이 보인다 |
| **P1** | 사람 기록(완료·해당없음·증빙) 저장 — 새 테이블 `OpeningTaskRecord` | 기록이 남는다 |
| **P2** | 주기 준수 계산(위원회 회의 주기) — 분모 병기·3상 | 개원 후 축이 생긴다 |
| **P3** | 기관이 항목을 추가/비활성 — 목록이 전수가 아니라는 사실의 구현 | 기관이 확정한다 |

### ✅ P3 완료 (2026-08-28)

🔴 **착수 전 재실측이 절반을 지웠다.** "추가/비활성" 중 **비활성은 이미 있었다** —
`OpeningTaskRecord.state = NOT_APPLICABLE`("이 기관에 해당 없다" · 사유 강제)가 P1 에서
들어갔고 화면 버튼까지 있다. 남은 것은 **추가** 하나였다.

🔴 **그런데 그 자리는 화면이 이미 약속하고 있었다.** 레지스트리는 스스로 "기본 목록이며
전수가 아니다"라고 말하고, 개원 직후(`O9_POST`)는 **기본 목록을 아예 비운 채**
"기관이 정한다"고 적어 뒀다. 정하는 통로만 없었다.

**새 표 `OpeningCustomTask`** — 코드 레지스트리와 **다른 표**에 둔다. 하지 않는 것 셋:

① 🔴 **연결 키를 갖지 않는다**(컬럼조차 없다). 기관이 `goLiveKey` 를 들면 **남의 상태를
   자기 상태인 척**한다. 그래서 기관 항목의 상태는 언제나 사람 기록이고, 파생 계산을
   아예 거치지 않는다. DTO 에도 없으므로 전역 `whitelist:true` 가 지워 **서버에 닿지도 않는다.**

② 🔴 **레지스트리 항목을 내리지 않는다.** 코드 항목을 내리는 길은 이미 있다
   (`NOT_APPLICABLE`). 여기서 또 내리면 같은 사실에 정본이 둘이 된다.

③ 🔴 **키를 사람이 짓지 않는다** — `inst.<hex 10>` 로 발급한다. 사람이 지으면 레지스트리
   키와 부딪히거나 의미를 담아버린다(의미가 담기면 그것이 정책이 된다). 레지스트리가
   `inst.` 접두어를 쓰지 못하도록 가드가 막는다.

**출처를 갈라 든다** — 모든 항목이 `origin: REGISTRY | INSTITUTION` 을 들고, 화면이
보라색 **기관 항목** 배지로 구분하며, 단계마다 `institutional`(분모 중 기관 항목 수)을 낸다.
🔴 안 밝히면 두 방향으로 거짓말한다: 기관이 정한 것을 **법정 의무**로 읽거나,
법정 항목을 **지울 수 있는 것**으로 읽는다.

**삭제가 아니라 내리기** — 기록·증빙이 붙어 있을 수 있다. 내릴 때 **사유 필수**,
삭제는 **기록이 하나도 없을 때만**(오타 회수용) 그리고 **선행으로 걸려 있지 않을 때만**.
🔴 내려둔 항목은 분모에서 빠지되 **개수와 사유를 화면이 밝힌다** — 조용히 사라지면
"그런 항목이 없다"로 읽힌다.

**강제하는 것과 안 하는 것을 갈랐다** — 어휘(단계·기한·주기·국가)는 정본이 정한 것이라
막는다. 제출처·비고·증빙은 강제하지 않는다(필수로 만들면 아무 값이나 채워진다).
🔴 "주기 반복인데 주기를 모른다"도 **막지 않는다** — 모르는 것을 강제하면 거짓 데이터가 되고,
주기 미설정은 이미 판정 대상에서 빠지는 정직한 상태다. 반대로 **주기 반복이 아닌데 주기를
드는 것**은 모순이라 막는다.

**국가** — 최소 1개 필수(비면 "모든 나라"인지 "안 정했는지" 구분되지 않는다) ·
🔴 **선행은 국가를 공유하는 항목에만**(레지스트리에서 실제로 겪었다 —
`open.system.hospitalInfo` 가 한국 전용 선행을 들어 UAE 에선 영영 안 풀렸다).
화면의 선행 후보 목록도 같은 나라만 보여준다(서버가 거절할 것을 권하지 않는다).

**EP 4개** — `POST /custom-tasks` · `PATCH /custom-tasks/:key` ·
`PATCH /custom-tasks/:key/active` · `DELETE /custom-tasks/:key` (전부 ADMIN).
기록·증빙·AI 판독 경로는 `resolveTask()` 로 **두 출처를 함께** 찾는다 —
🔴 한쪽만 고치면 기관 항목이 조용히 404 가 된다(증빙 판독은 제목을 못 찾아
전부 '행정 증빙 문서'가 될 뻔했다).

## §5 가드 (재주입 역검증 필수)

1. **항목이 상태를 저장하지 않는다** — 연결 키가 있는 항목에 자기 상태를 쓰면 실패
2. **연결 키가 실재한다** — `goLiveKey`/`decisionKey`/`committeeCode` 를 양쪽 정본과 기계 대조
3. **근거를 지어내지 않는다** — 레지스트리에 `법 제`·`조` 패턴 조문이 있으면 실패
4. **절대 날짜 금지** — `dueBy` 외 날짜 리터럴이 있으면 실패
5. **`NOT_APPLICABLE` 에 사유 강제**
6. **"전수 아님" 캐비아트가 화면에 있다**
7. **주기 준수는 분모와 함께** · **기록 0을 '위반'이라 쓰지 않는다**
8. **단계가 게이트가 아니다** — 앞 단계 미완료로 뒤 단계를 막는 코드가 있으면 실패
9. **기관 항목이 연결 키를 못 든다** — DTO·스키마·파생 계산 세 층에서 각각 확인(P3)
10. **출처를 밝힌다** — 모든 항목이 `origin` 을 들고, 단계마다 기관 항목 수를 센다(P3)
11. **내려둔 항목이 조용히 사라지지 않는다** — 분모에서 빠지되 개수·사유가 응답에 남는다(P3)
12. **기록이 있으면 삭제되지 않는다** · **내릴 때 사유 강제**(P3)
13. **국가 간 선행 금지** — 다른 나라 항목을 선행으로 걸면 실패(P3)

## §6 국가 축 — 다른 나라로 이전할 때 (2026-08-28)

사람 지시: *"각 단계별로 국가단위(차후 다른 국가 이전시)의 거버넌스에 대해서 검색하고
검토해서 반영. 일단 한국, UAE 기준으로 하고 다른 국가는 추후 추가되는 형태로."*

### 구조

`OpeningTaskDef.countries: CountryCode[]` — **모든 항목이 나라를 밝힌다.**
비워두면 "모든 나라"인지 "아직 안 정했는지" 구분되지 않으므로 가드가 빈 값을 막는다.
나라 추가는 `CountryCode` 에 코드 하나, `COUNTRY_META` 에 라벨·관할 설명 하나,
그리고 그 나라 항목을 붙이는 것으로 끝난다.

기관 국가는 설정 `hospital.country`(기본 `KR`). 🔴 **설정이 없으면 그 사실을 화면이 말한다** —
조용히 기본값을 쓰면 다른 나라 기관이 자기 항목을 못 보고도 모른다.

### 🔴 국가 간에 선행을 걸지 않는다

`open.system.hospitalInfo`(기관 기본정보)를 처음에 국가 무관으로 뒀더니 선행이
**요양기관 기호·사업자등록**(한국 전용)이라 UAE 에서는 영영 안 풀리는 상태가 됐다.
가드가 잡았고, 국가별로 갈랐다 — UAE 는 **보건당국 면허번호·상업 면허**가 들어간다.
항목 이름이 그 나라 어휘를 담고 있으면 그것은 이미 국가 항목이다.

### 🔴 UAE — 관할이 하나가 아니다

두바이 **DHA** · 아부다비 **DoH**(TAMM 포털) · 북부 에미리트(샤르자·아즈만·RAK·
후자이라·UAQ) **MOHAP**. 그래서 `open.ae.jurisdiction`(관할 확정)이 **첫 항목**이고,
제출처가 갈리는 항목은 `authority` 에 *"관할에 따라 다름"* 이라고 적는다 —
한 곳으로 단정하면 다른 에미리트에서 그대로 틀린 말이 된다(가드가 강제).

반영한 UAE 항목(14): 관할 확정 · 상업 면허/소유·임대 서류 · 도면 사전 승인 ·
보건의료시설 면허 · 초기·최종 실사 · **FANR** 방사선 취급 면허(연방 소관 — 보건당국과
별개) · RPO 지정/RPP · e-Claim 개통(두바이 DHPO / 아부다비 Shafafiya) · 개인 면허 ·
마약류 담당자 지정 · **HIE 연동**(두바이 NABIDH / 아부다비 Malaffi / 북부·연방 Riayati —
면허 조건으로 요구된다) · Tatmeen 연동 · 기관 기본정보 · 소비 보고(통제약 **월간** /
마약류 **분기**).

### 🔴 적지 않은 것

**조문·수수료·처리기한을 적지 않는다.** 검증할 수 없고 자주 바뀐다 — 시드에 들어가면
그것이 정책이 된다. 가드가 `제N조`·`Federal Law No`·`N일 이내`·`N주 소요`·`AED N` 을 막는다.
한국 항목과 대응하는 UAE 규정 중 **확인하지 못한 것**(의료폐기물·세탁물 등)은 **적지 않았다** —
목록이 전수가 아니라는 사실은 화면이 상시 표시한다.
