Hospital RUN 문서 허브 v3.97.0
Overview · 경영진 · 전 독자

한국형 대학병원급 통합 병원정보시스템 (HIS)

Hospital RUN은 접수·진료·처방·검사·수납·입원·간호·약국·건강검진·환자포털을 하나의 플랫폼으로 잇는 엔터프라이즈 HIS입니다. HospitalRun·EtherCIS·Medplum의 설계를 참고하되, 한국 의료 표준(KCD-8·EDI·DUR·HIRA·KTAS·EMR 인증)과 FHIR R4에 정합하도록 자체 구축했습니다.

무엇인가

단일 모노레포(Turborepo) 위에 Next.js 15 웹, NestJS API, Expo 모바일이 올라간 웹·모바일 통합 HIS. 204 백엔드 도메인, 3,094 API, 433 화면.

특징

Enterprise Clean Architecture · RBAC 기반 접근제어 · WeRU.B 의료 AI 연동 · FHIR R4/openEHR · 원격진료 · 블록체인 증명서 · 메타버스 여정.

운영 현황

his.example.org 라이브 운영. 기획서 221건 100% 구현. PACS는 OpenPACS로 분리 운영. pm2 + nginx + PostgreSQL 16.

이 문서의 정본성모든 수치는 2026-08-10 코드베이스 실측 기준입니다. 저장소 canonical(README.md·docs/INDEX.md·API-REFERENCE.md)도 동일 기준으로 동기화돼 있습니다.

계층 아키텍처 — Enterprise Clean Architecture

의존성은 항상 안쪽(Domain)을 향합니다. Presentation·Application은 Domain에 의존하고, Infrastructure는 Domain이 정의한 인터페이스를 구현합니다(의존성 역전). 도메인 규칙은 프레임워크·DB·외부 시스템으로부터 격리됩니다.

  • API 프리픽스 /api/v1/(내부) · /fhir/R4/(FHIR)
  • 응답 { data, meta } / 오류 { error: { code, message, details }, meta }
  • 인증 Custom JWT + RBAC Guard (ADR-001)
  • 환자명 familyName/givenName (ADR-002, FHIR 호환)

  • 외부 상호운용 FHIR R4 (fhir · fhir-full · SMART on FHIR)
  • 내부 임상 모델 openEHR 패턴 (ClinicalChartResult · 아키타입 4종)
  • 표준 코드 KCD-8 · EDI · DUR · HIRA · KTAS · OMOP-CDM · CDA · HIE

배포 파이프라인

배포는 ./infra/scripts/deploy.sh로 수행하며 자동 DB 백업을 포함합니다. git 커밋이 아닌 working tree rsync 방식이라 미커밋 변경도 배포됩니다(stash 격리).

명령동작
deploy.sh --apiAPI만 배포
deploy.sh --schema --api스키마 변경 + API (자동 백업)
deploy.sh --all전체 배포
deploy.sh --backupDB 백업만
BE 수정 후 필수nest build 필수 — pm2가 dist/main.js를 실행하므로 src 수정만으로는 반영되지 않습니다.
신규 Prisma 모델deploy.sh --api는 prisma generate를 하지 않습니다. 신규 모델은 prisma/ rsync + 서버에서 generate + build + restart(안 하면 크래시).
데이터 소실 금지prisma db push --accept-data-loss 절대 금지. 플래그 없는 db push는 손실 시 거부되어 안전.
빌드 환경변수NEXT_PUBLIC_API_URL='' 필수 — 브라우저가 상대경로를 사용하도록. Self-healing: MediaService가 서버 시작 시 파일시스템 스캔 → DB 자동 복구.
