01로그인 · 계정

구분계정비밀번호비고
관리자admin@hospital.example.orgstaff1234!ADMIN 권한
직원(공통)역할별 계정staff1234!DOCTOR·NURSE·PHARMACIST·LAB_TECH·STAFF
환자환자 계정patient1234!포털·모바일
계정 잠금비밀번호 반복 실패 시 15분 잠금됩니다. 잠긴 계정은 시간 경과 후 재시도하거나 관리자에게 초기화를 요청하세요. 비밀번호 추정 반복은 금지입니다. 상세 계정은 docs/05-reference/TEST-ACCOUNTS.md.

직원은 향후 패스워드리스 SSO(WebAuthn·생체·디바이스 신뢰)로 전환됩니다. 차트 서명·처방 등 민감 작업은 step-up 생체 승인이 요구될 수 있습니다(관리자 config에 따라).

02화면 이동 · 핫키

빠른 이동

  • g 입력 → 화면 코드 입력 → 즉시 이동
  • Cmd/Ctrl+K 통합검색(환자·화면·기능)
  • 최근/즐겨찾기 화면, 사이드바 코드 배지
  • 치트시트 인쇄 /settings/shortcuts

화면 내 액션 핫키

  • ⌘/Ctrl+Enter 주요 액션(저장·제출)
  • Alt+문자 보조 액션
  • ? 현재 화면 핫키 도움말
  • 접수·처방·수납·간호 화면 적용 (IME 가드)

03역할별 워크플로우

원무 · 접수접수 데스크 · 수납
  1. 환자 검색(동명이인 AI 인지) 또는 신규 등록 — 주소검색·주민번호 암호화·신분증 OCR(비저장)·환자 사진
  2. 자격조회(공단) → 본인확인 → copay 자격 전환(차상위·입원 등)
  3. 접수(직접·QR 스캔·길안내) → 진료 대기열 등록
  4. 수납 — 분할납부·미수금·예치금, 영수증 발급(진위 QR)
의사환자차트 · CPOE · 콕핏
  1. 진료 시작 → 환자차트(전문과별 특화 레이아웃 16과)
  2. 주상병 입력 — KCD-8 필터·확실도·청구 구분 (제한검증: 주상병 불가·성별·연령)
  3. 오더/처방 — 오더세트·포뮬러리(원내 배지)·DUR·CDSS 경고, 고위험 약물(ISMP/LASA)
  4. 차트 서명 — 필요 시 step-up 생체 승인. 수정 후 재서명(AMENDED)
큰 화면 board · 콕핏회진·병동 관리는 큰 화면 board(마소너리 배치·패널 핀 고정)와 진료 콕핏을 활용하세요.
간호사간호 스테이션 · 태블릿 · 간호기록
  1. 병동 재원 실시간 보드 — EWS·낙상·투약지연·미서명 배지
  2. 라운드(태블릿 라운드보드·QR) → 바이탈/EWS 측정
  3. 투약 — MAR(투약기록), 구두처방 Read-back
  4. 간호기록 — AI 초안 → 검토·서명(책임 서명 간호사 불변). NANDA/NIC/NOC
약사약국 · 조제 · 마약류
  1. 처방 검토 — DUR·용량 검증, 원내/원외 구분
  2. 조제 — 바코드(GS1/KD)·배치(로트)·유효기간, 마약류 이중확인
  3. 복약지도·대체조제·ADR 보고
  4. AI 약물설명 승인 — /admin/drug-explain(PHARMACIST/ADMIN). 승인분만 환자에게 노출, 재생성 시 승인 리셋
검사 · 영상
  • 오더 접수 → 결과 입력/판독 → 리포트
  • 영상은 /pacs/ 링크로 OHIF·Orthanc 조회
  • 병리·혈액은행(교차시험)·검사실 WS
환자
  • 포털/모바일(31화면) — 예약·검사결과(쉽게보기)
  • 의무기록 발급·원격진료·셀프 체크인
  • 동의서 모바일 서명·건강검진 결과
관리자Admin 105p
  • 권한/부서 — 기능 접근 매트릭스(access-control), 4-eyes 승인
  • 코드마스터 — 약품·상병·수가, 포뮬러리 위원회 7영역
  • 시행게이트 — 포뮬러리·상병제한 OFF/WARN/BLOCK
  • CMS — 홈페이지·팝업·배너, 대시보드 템플릿, 통합 매뉴얼(/custom/<slug>)

04config 게이트 운영

신규·민감 기능 대부분은 config 플래그로 게이트되며 기본 OFF로 배포 후 점진 활성화합니다. 관리자 콘솔에서 SystemConfig로 조정합니다.

플래그기능값기본
ai.server.enabledWeRU.B AI 서버 kill-switch(끄면 503)on/off환경별
formulary.enforce원내 처방집 시행(영역별)OFF/WARN/BLOCKOFF
diagnosis.restrictionEnforce상병 제한(주상병 불가·성별·연령)OFF/WARN/BLOCKOFF
stepUpActions생체 승인 요구 작업(차트서명·처방)목록환경별
dev.demoDateRoll데모 데이터 자정 오늘로 시프트on/offOFF
시행게이트 3단계OFF=표시만 · WARN=경고 동봉(진행 가능) · BLOCK=차단(400). 파일럿은 WARN으로 시작해 안정화 후 BLOCK 전환을 권장합니다.

05서버 운영 런북

서비스 재시작 · 배포

# 개별 서비스만 재시작 (전체 restart 금지 — OpenPACS 공유)
docker compose restart api web

# 배포 (자동 백업 포함)
./infra/scripts/deploy.sh --api          # API만
./infra/scripts/deploy.sh --schema --api # 스키마 변경 + API
./infra/scripts/deploy.sh --all          # 전체
./infra/scripts/deploy.sh --backup       # DB 백업만
BE 수정 후nest build 필수 — pm2가 dist/main.js 실행. 신규 Prisma 모델은 서버에서 prisma generate + build + restart(안 하면 크래시).
데이터 보호db push --accept-data-loss 금지. DB 비밀번호(hospital/secret) 변경 금지 — OpenPACS 공유. PACS(orthanc/ohif/nginx /pacs/) 수정 금지.

데이터 · 시드

  • 시드: npm run db:seed (멱등 · 15,588줄)
  • 데모 날짜 롤포워드: config dev.demoDateRoll 또는 ADMIN /dev/demo/roll-forward
  • Self-healing: 서버 시작 시 MediaService가 파일시스템 스캔 → 미디어 DB 자동 복구

상세 런북: docs/OPERATIONS.md · DEPLOYMENT.md · go-live-checklist-security.md · fcm-push-activation-runbook.md · terminal-zero-trust-production-ops.md.
