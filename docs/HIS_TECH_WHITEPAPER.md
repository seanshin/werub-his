# Hospital RUN 병원정보시스템(HIS) 기술백서

> **버전** v4.15.0 (2026-09-06 기준) · **문서 성격** 홈페이지/파트너 공개용 기술 소개 자료(화이트페이퍼)
> **대상 독자** 기술 검토자·도입 검토 기관·연동 파트너·규제 검토 담당
> **요지** 한국형 대학병원급 통합 병원정보시스템의 기반 구조, 임상 도메인 커버리지, 데이터 정직성 설계 원칙, 상시 감시 체계, 거버넌스, AI 통합, 보안·개인정보 보호를 정리한다.

## 1. 개요 (Executive Summary)

Hospital RUN 은 **외래·입원·수술·응급·검사·약제·급식·건강검진·경영지원을 단일 시스템으로 다루는 한국형 엔터프라이즈 HIS** 다. HospitalRun·EtherCIS·Medplum 의 설계를 참고하되, 한국 의료 제도(건강보험 청구·KCD-8·DUR·의료법 서식·EMR 인증 기준)를 정본으로 삼아 처음부터 새로 구축하였다.

시스템 규모(재현 가능한 계측 스크립트 기준):

- Prisma 데이터 모델 **556종** · 백엔드 도메인 모듈 **211개** · REST API 엔드포인트 **3,228개**(+SSE 15)
- 프론트엔드 화면 **447면**(스태프 본화면 347 · 관리자 117 · 워크스테이션 29) · 모바일(환자 앱) 32화면 · 공개 홈페이지 별도 앱
- 운영 코드 마스터: 의약품 **24,022품목**(성분 정보 98.2%) · KCD-8 진단 코드 **18,184종**(전량 챕터 분류)
- 자동화 테스트 **1,000+ 파일 / 12,500+ 케이스**(백엔드·웹·공유 패키지)

핵심 설계 원칙은 다음 네 가지다.

1. **데이터 정직성(Honesty by Design)** — 화면은 모르는 것을 아는 척하지 않는다. 표본이 없으면 0 이 아니라 "산출 불가"를, 조회 실패는 "없음"이 아니라 실패를 말한다(§5).
2. **정본 하나(Single Source of Truth)** — 같은 사실의 정본은 한 곳이며, 어휘·수치 정책·상태 라벨은 공유 패키지 하나에서 나와 시드·화면·API 가 기계 대조된다.
3. **가드는 재주입으로 증명** — 구조 가드·계약 테스트는 결함을 재주입해 실패하는 것을 확인한 뒤에만 가드로 인정한다(§10).
4. **AI 는 보조, 판단은 사람** — 모든 AI 산출은 출처 3상태(AI/FALLBACK/UNAVAILABLE)로 표시되고, 초안은 확정과 분리되며, 자동실행은 기본 금지다(§7).

### 2.3 운영 모드 — 빌드가 상한, 런타임은 좁히기만

개발/리허설/리얼 3모드를 **두 층**으로 강제한다. 빌드 시점 모드가 상한이고 런타임 설정은 그 안에서 좁힐 수만 있다. 숨긴 것과 없는 것은 다르므로(조건부 렌더는 값이 번들에 남는다) **리얼 전환은 재배포**로만 이뤄지며, 런타임이 상한을 넘으려 하면 "저장했지만 적용되지 않았다"를 그 자리에서 말한다.

### 2.4 배포 파이프라인

- 배포 스크립트가 자동 백업·워크트리 동기화·빌드·무중단 스왑·**배포 후 스모크(29종)** 를 수행한다.
- **부트 검증**: 순환 의존은 타입 검사·테스트가 잡지 못하므로, 빌드 산출물로 실제 부트(NestFactory.create→close)를 배포 전에 검증한다.
- 공개 홈페이지는 별도 아티팩트 발행 경로를 가지며, 배포 스크립트가 매번 공개 사이트의 **빌드 스탬프 최신성**을 표본 확인해 알린다(확인 불가를 '낡음'이라 말하지 않는다).

## 4. 임상 도메인 커버리지 (Clinical Domain Coverage)

### 4.1 진료 흐름 전 구간

접수→진료(차트·SOAP·상병)→오더(약물·검사·영상·치료·간호·식이·활동)→수납→약제(조제·불출·복약)→결과(검사·영상 판독)→입원(병상·간호·MAR·인수인계)→수술(체크리스트·Op Note·PACU)→퇴원(게이트·미수납)→사후(검진·CRM·포털). 응급실은 24병상 5구역 베드 보드와 자동 해제 4경로를 갖춘다.

### 4.2 처방 안전 — 공유 초크포인트(choke point)

모든 처방 발행 경로(신규·복사·재처방·원격협진)는 **하나의 게이트 체인**을 지난다:

```
DUR(상호작용·금기·용량) → CDSS(알레르기·신기능·연령) → 원내 처방집(포뮬러리)
  → 처방의 결정(위임 시 지정의 1회용 승인 토큰) → 사전승인(마약류 등 고위험)
```

- 게이트는 OFF/WARN/BLOCK 3상으로 운영하며 위반은 **게이트 위반 원장**에 남아 관제 화면에서 승격을 판단한다.
- 차단은 갈 곳을 남긴다 — 마약류 사전승인 차단 화면은 그 자리에서 **상신 동선**을 열고, 응급은 사유와 함께 우회 발행 후 **사후 결재**로 이어진다(요청자=승인자 금지).
- 이중확인·위급값 확인 같은 안전 행위는 봉쇄가 아니라 **기록과 가시화**로 관리한다(막으면 방치된다).

### 4.3 안전·질 관리

- **안전 게이트 관제**: 배선 게이트 12종+ 의 위반 통계·승격 가이드를 한 화면에서.
- **위급값(Critical Value)**: 판정은 기준치 마스터 정본, 통보는 read-back(복창) 원장으로 추적, 영구 기록은 통보 실패와 무관하게 트랜잭션 안에서 확정된다.
- **Code Blue/RRT**: 소생 경과(팀도착·CPR·ROSC·제세동)와 신속대응팀 SLA 를 기록 — 시각은 자동 각인이 아니라 명시 입력이다.
- **UDI 기기 추적**: GS1 바코드 파싱→삽입 기록→리콜 시 로트/일련번호로 환자 역추적.
- 낙상/욕창 재평가·격리/강박·수혈·항암 레지멘·감염 관리 등 인증 기준(Ver 5.0) 축을 도메인 모듈로 갖춘다.

## 5. 데이터 정직성 설계 (Honesty by Design)

이 시스템의 가장 큰 차별점은 기능 수가 아니라 **화면이 사실을 말하도록 강제하는 규칙**이다. 아래는 문서가 아니라 구조 가드(테스트)로 강제된다.

| 원칙 | 구현 |
|------|------|
| 표본 부재 ≠ 0 | 비율·완결률은 분모를 병기하고, 분모 0 이면 숫자 대신 **"산출 불가"**(공유 정본 문구) |
| 조회 실패 ≠ 없음 | `.catch(() => 기본값)` 금지 — 실패는 3상태로 전파, 에러 폴백 컴포넌트 렌더를 전 화면 가드 |
| 미측정 폴백 금지 | `(spo2 ?? 100) < 95` 류의 조건식 금지 — 활력을 안 잰 환자를 "정상"으로 판정하지 않는다 |
| 기록 ≠ 적용 | 결정·설정의 이행은 5상태(미결/반영됨/반영대기/반영실패/수동확인)로 구분 표기 |
| 전송 흉내 금지 | 미구축 대외 채널은 `LOCAL_RECORDED`+시각 null — 모르는 시각을 원장에 박지 않는다 |
| 값 날조 금지 | 대기번호·게이지·건강점수 등 화면 상수/난수 생성 금지 — 수치 정책은 공유 정본 하나 |
| 절단 고지 | 서버가 자른 목록(최근 N건)은 화면이 그 사실을 말한다 |
| 안 먹는 설정 0 | 읽는 코드가 없는 설정 키는 기준선으로 동결하고 화면에 "미배선"을 고지 — 배선 시에만 기준선을 낮춘다 |

## 6. 상시 감시자 (Sentinel)

운영 데이터의 거짓을 사람보다 먼저 찾는 **별도 프로세스**의 상시 감시 체계다.

- **네 축**: ① 데이터 정합성 불변식 67종 ② 흐름 완결성(표본 부족 시 "관측 불가"로 판정 보류) ③ FE↔서버 계약 드리프트 ④ 파이프 생존. 여기에 1분 펄스 7지표(자기 이력 대비 급변 감지)를 더한다.
- **구현 ≠ 판정**: 관측점 안의 0 을 전체의 0 으로 말하지 않으며, 미판정을 0 으로 그리지 않는다.
- **판정 원장**: 적색 판정은 append-only 원장에 판정 시점 값 스냅샷과 함께 기록되고, 판정 이후 수치가 다시 늘면 자동으로 "재판정 필요"로 되돌린다(안심의 유통기한을 시스템이 관리).
- 알림은 신규/재발만 — 거짓 경보는 진짜 경보를 죽이므로 확실하지 않으면 침묵한다.
- 관리자·의료진·행정 소관 구분과 AI 해결 방안 보조(출처 표시·확정 아님)를 제공한다.

## 7. AI 통합 (AI Integration)

온프레미스 의료 AI 플랫폼(WeRU.B — 별도 기술백서)과 연동하며, HIS 측은 **AI 를 쓰는 방식**을 규약으로 강제한다.

- **관계 모드 5종**: 감시/보조/초안/실행제안/자동실행 — 화면이 자신의 모드를 밝히고, **자동실행은 기본 금지**.
- **권한 검사는 AI 호출 앞에서** — AI 가 권한 우회 경로가 되지 않는다.
- **출처 3상태**: 모든 AI 산출은 `AI`/`FALLBACK`/`UNAVAILABLE` 을 표시한다. 정본 데이터(위급값·법령 등)를 AI 가 지어내는 경로는 없다.
- **초안 ≠ 확정**: 앰비언트 스크라이브·기록 초안·증빙 판독은 초안 저장소에 머물며 사람 확정으로만 정본이 된다.
- **AI 생성물 표시**: AI 기본법 §31 대응 — 표시 문구는 공유 정본 하나에서 나와 전 화면·인쇄물에 병기된다.
- AI 관련 엔드포인트 66종: 진료 보조·검진 결과 해석·복약 설명·번역·회의록·비전 판독 보조 등.

## 9. 보안·개인정보 보호 (Security & Privacy)

- **RBAC**: 역할 14종, 가드는 role **AND** permission. 최소권한은 정적 분석이 아니라 **역할별 실로그인 전역 점검**으로 검증한다(nav 숨김 ≠ 권한 회수).
- **감사(Audit)**: 변이는 **기본 감사 ON**(면제만 명시 선언). 환자 지목 조회는 열람 감사로 남고, FHIR 직원 접근은 반출 건수(`returned=N`)까지 기록한다. 외부 SMART 앱 접근은 별도 원장으로 관리·리포트한다.
- **응급 접근(Break-the-Glass)**: 환자 차트 응급 열람과 **로그인 응급접근**(책임자 승인·시간제한 토큰)을 별개 원장으로 관리하며, 둘 다 **의무 사후검토** 화면을 갖는다. 게이트 설정 조회 실패 시 발급을 거부한다(fail-closed).
- **보유·파기(Retention)**: 리소스별 보존 정책(법정 최소와 보존일수 중 **긴 쪽** 클램프)·DRY-RUN 집계·**4-eyes(2인) 승인**을 갖추되, 법정 보존 대상(감사 로그 등)은 파기 핸들러를 의도적으로 두지 않는다 — 화면이 그 사실을 정직하게 표기한다.
- **개인정보 보호**: 환자 식별자 암호화, 환자 응답 민감 필드 생략 정본, PHI 로그 유출 스캐너, 신고자 신원 경로 차단(환자안전법 §17), 정적 파일은 HMAC 서명 URL.
- **비밀번호·세션**: 정책 정본 한 곳(12자+복잡도·설정은 강화만 가능), 계정 잠금·세션(sid) 단위 즉시 무효화, 2단계 인증·생체 승인(Tier2) 지원.

## 10. 신뢰성·운영 (Reliability & Operations)

- **테스트**: 백엔드 828 파일·웹 149 파일·공유 25 파일, 통과 케이스 12,500+ · 실패 0 · 타입 오류 0 을 배포 기준선으로 유지한다.
- **가드의 가드**: 구조 가드는 **결함 재주입→실패 확인→복원 확인**을 거쳐야 가드로 인정한다. 재주입은 주입 성공부터 확인한다(치환 무동작이 "통과"를 증거로 만드는 함정을 차단).
- **계약 테스트**: FE↔서버 응답 모양, 서버 마스킹(공개 전광판), 어휘 집합 일치(shared↔시드)를 기계 대조한다.
- **관측·크론**: 크론 54종 생존 감시, 여정 이벤트 발행, 알림 도달(발송≠도달) 구분 기록.
- **백업·복구**: 배포 전 자동 DB 백업, 미디어 자가 복구(서버 기동 시 파일시스템 스캔→DB 정합).

## 11. 책임 있는 운영 / 한계 (Responsible Operation)

- **현재 운영 DB 는 가상 병원 시드 데이터**다. 실환자를 받은 적이 없으며, 본 문서의 운영 수치는 그 전제 위에서 읽어야 한다. 실서비스 전환 시 시드 전량 제거·격리와 감사 결론 재검증 절차가 정의되어 있다.
- **AI 는 자문 보조 도구**이며 처방 차단·진단 확정 시스템이 아니다. 최종 판단과 책임은 의료진에게 있다.
- **결정의 세 층은 고정**이다 — 허가권자(법적)/원내 위원회/직원 건별. 하위가 상위를 대체하지 못하며, 시스템은 권고하지 않고 선택지와 결과만 제시한다.
- 안전 게이트·대외 발신은 **기본 OFF** 로 배포된다. 켜는 것은 구현이 아니라 **사람의 결정**(구현+설정+승인 3조건)이다.
- 미구현·미배선은 숨기지 않고 화면·문서에 고지한다 — 기능 공백 스캔과 회수 트랙을 상시 운영한다.
